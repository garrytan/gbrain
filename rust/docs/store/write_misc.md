# The brain store: page-write reads

Part of the store contract in [rust/README.md](../../README.md) ("The brain store"): the rules there apply to every method here.

These are statements that a page write ran through `executeRaw` and that belong to no other storage domain
([docs/research/rust-put-write-path.md](../../../docs/research/rust-put-write-path.md)). PGLite and Postgres run the
same SQL as before, now in `src/core/engine-sql/write-misc.ts`. The store answers the source read
and the path attach from its source records, and the reader-naming page list from its page records (`crates/gbrain-store/src/write_misc.rs`) and has no keys of its own. The folder
access reads go to the `access_rules` family ([access_rules.md](access_rules.md)). The TypeScript
members (`src/core/rust-engine/store-members/write-misc.ts`) answer the others for state the store does not keep.

| JS | Resolves | Mirrors |
| --- | --- | --- |
| `brain.readSourceState(sourceId)` | `{ incarnation, archived, local_path, config }`, or `null` for an unknown id | `readSourceState` |
| `brain.attachSourcePath(sourceId, localPath, name, federated)` | `true` after it sets `local_path`, replaces the name when `name` is not `null` and sets `config.federated` when `federated` is not `null`; `false`, with no change, for an unknown id | `attachSourcePath` |
| `brain.listPagesNamingReader(principal, limit)` | `[{ slug, source_id }]`, by (source, slug), at most `limit` | `listPagesNamingReader` |

The link endpoint read (`listLinkEndpointPages`) is in [link_queries.md](link_queries.md).

## TypeScript members

| Member | Answer on this engine | Why |
| --- | --- | --- |
| `readSourceState(sourceId, { lock: 'share' })` | `brain.readSourceState`; the lock is dropped | The store runs one write transaction at a time, so a read never overlaps a source change. |
| `readScopeSourceConfigs(ids, lock?)` | `brain.readSourceState` once per distinct id, in id order; an unknown id is left out; `{ id, config }` per source; the lock is dropped | The scope-source check of a grant write (`src/core/access/attest-sources.ts` `markedScopeSources`). The SQL engines run `engine-sql/access-credentials.ts` (FOR SHARE or FOR UPDATE in id order); the store runs one write transaction at a time. |
| `attachSourcePath(sourceId, localPath, opts)` | `brain.attachSourcePath`; resolves nothing | The SQL engines return no rows either. |
| `readAdmissionSource(sourceId)` | `brain.readSourceState` with `kind` and `role` as `config->>'kind'` and `config->>'role'` read them (text as is, `null` when missing, JSON text otherwise); `guest_writers` and `guest_trust_ceiling` `null`; `guest_sources_hidden` `false` | The store has no `guest_sources` table and no row-level security; a guest source is one whose config says guest (see [cli-reads-import.md](cli-reads-import.md)). |
| `sharedSkillPackTablePresent()` | `true` | The answer of a current schema: the store is never on a schema from before shared skills. It keeps no pack, so `listSharedSkillPackRoots` returns `[]`. |
| `listSharedSkillPackRoots(hostId)` | `[]` | No shared skillpacks exist. |
| `getWorktreeBinding(sourceId, hostId)` | `null` | The store keeps no writer bindings. A brain on this engine is never managed (`readManagedModeRows`), and the binding writers (`claimWorktree`) run raw SQL, which this engine refuses, so no source is bound on any host. PGLite answers the same for a source with no binding. |
| `isSourceClaimed(sourceId)` | `false` | No source is bound on this engine (see `getWorktreeBinding`), so no binding claims a source and classic sync never meets the pre-activation claim refusal. On PGLite and Postgres the read is the `EXISTS` over `persistence_source_bindings` that `sync-authority.ts` ran through `executeRaw` (`engine-sql/sources.ts`). |
| `hasExtractedEvents(sourceId, pageId)` | `false` | The store keeps no chronicle extraction state. |
| `listActiveAccessMembers()` | `brain.listActiveAccessMembers` | The members neither disabled nor removed, by id ([access-members.md](access-members.md)). |
| `hasLabelledOnlyMember()` | `brain.readAccessMembers({ includeRemoved: true })` has a `labelled_only` row | The store keeps access members ([access-members.md](access-members.md)); any member, live or not, that carries the labelled-only grant answers true, as the SQL engines read `SELECT 1 FROM access_members WHERE labelled_only LIMIT 1`. |
| `notifierCoverageRecorded()` | `false` | The store keeps no notifier state: a resident notifier refuses to start on a Rust brain, so no source has recorded coverage. Search carries the freshness notice only when `sync.on_commit` is on. |
| `readOpCheckpointKeys(op, fingerprint)` | the op's banked keys | Served by the store with the checkpoint writes (persistence.md, "Op checkpoints"); a resumable op stopped on this engine resumes with the keys it banked. |
| `readHealthMemoClock()` | `<brain id>/<commit sequence>` | The `readProjectionReadinessGeneration` value. Every commit advances it, a page write among them, so the get_health memo reuses an answer only while nothing was written. The SQL engines answer `<brain id>:<page clock>`; only equality between two reads of one engine matters. |
| `listSynopsisSourceIds()` | `[]` | The store keeps no source contextual-retrieval mode (only `sources` admin raw SQL writes it), so no source selects the synopsis tier. |
| `isFolderRestricted(sourceId, slug)` | `brain.isFolderRestricted` | Folder rules and pending prefixes are store records ([access_rules.md](access_rules.md)). The store has no row-level security, so the unreadable part is always false. |
| `listAppliedPolicyRevisions()` | `brain.listAppliedPolicyRevisions` | Each source with policy state and its newest applied revision ([access_rules.md](access_rules.md)). On PGLite and Postgres the read is the `access_policy_state` scan that `access/caller.ts` `appliedAccessSummary` ran through `executeRaw` (`src/core/engine-sql/access-control.ts`). |
| `readLiveMember(via, key)` | `brain.readAccessMembers({ id })`, live only | By `member` the key is the id; by `stdio_config` the id is the config value `brain.getConfig(key)` names, edge whitespace trimmed; a disabled or removed member reads null. The store keeps no access tokens and no OAuth clients, so `legacy_token` and `oauth_client` read null, as for an unbound caller. On PGLite and Postgres the read is the statement `liveIdentity` ran through `executeRaw` (`LIVE_MEMBER_SQL`, one per route); a disabled member, a removed member, a revoked token and a deleted client are filtered out in the statement, and a member carries only its own groups. |
| `readFolderAccess(readers)` | `brain.readFolderAccess` | The folder rules whose readers name any of `readers` and every pending prefix ([access_rules.md](access_rules.md)); no `'!unreadable'` row, since the store has no row-level security. On PGLite and Postgres the reads are the two statements `access/caller.ts` `folderAccessForAll` ran through `executeRaw` (`FOLDER_RULES_FOR_READERS_SQL`, `FOLDER_COVERAGE_SQL`). |
| `readMayActFor(via, key)` | the config value for `stdio_config`, `null` otherwise | A stdio server's may_act_for is a config value, which the store keeps (`getConfig`). The store keeps tokens and clients ([access-tokens.md](access-tokens.md), [oauth-clients.md](oauth-clients.md)) but this member reads no may_act_for list from them (a follow-up), so a token or a client permits nothing, as a revoked token or a deleted client does. On PGLite and Postgres the read is the statement `access/caller.ts` `mayActForOf` ran through `executeRaw` (`src/core/engine-sql/access-control.ts` `MAY_ACT_FOR_SQL`). |
| `readAudiencePrincipals(memberIds, groupIds)` | the asked members that are not disabled, and the asked groups that exist | Two store reads ([access-members.md](access-members.md)): `brain.readAccessMembers({ includeRemoved: false })` filtered to the asked ids with no `disabled_at`, and `brain.readAccessGroupIds(groupIds)`. A read is skipped when its id list is empty. On PGLite and Postgres the reads are the two statements `access/caller.ts` `resolveAudienceIdentities` ran through `executeRaw` (`AUDIENCE_MEMBERS_SQL`, `AUDIENCE_GROUPS_SQL`). |
| `readAccessMembers(by)` | `brain.readAccessMembers` | The member rows: by id (any status), by email (the members that declare it, by id) or every member by id, each with its group ids sorted; removed members only when `includeRemoved` ([access-members.md](access-members.md)). On PGLite and Postgres the reads are the statements `access/members.ts` `getMember`, `memberByEmail`, `assertEmailFree` and `listMembers` ran through `executeRaw` (`ACCESS_MEMBER_SQL`). |
| `readAccessCredentials(by)` | `[]` | The store keeps access members ([access-members.md](access-members.md)) and tokens and clients ([access-tokens.md](access-tokens.md), [oauth-clients.md](oauth-clients.md)), but no member binding on a token or a client, and this read stays empty for a token name too (a follow-up), so no token name and no member binding names a live credential here. On PGLite and Postgres the reads are the statements `access/members.ts` `legacyTokenByName` and `boundCredentials` (tokens, then clients) ran through `executeRaw` (`ACCESS_CREDENTIAL_SQL`); revoked tokens and deleted clients are filtered out in the statement. |
| `listAudienceAccessMembers()` | `brain.readAccessMembers({ includeRemoved: false })` filtered | The ids of the members of kind `audience` with no `disabled_at`, by id ([access-members.md](access-members.md)). On PGLite and Postgres the read is the statement `access/members.ts` `audienceMemberIds` ran through `executeRaw` (`AUDIENCE_KIND_MEMBERS_SQL`); a person, a disabled member and a removed member are filtered out in the statement. |
| `readAccessGroups(id)` | `brain.readAccessGroups(id)` | Every group with its member ids, groups and members in byte order, or the one group with exactly that id ([access-members.md](access-members.md)). On PGLite and Postgres the read is the statement `access/members.ts` `listGroups` ran through `executeRaw` (`ACCESS_GROUP_SQL`, every group or the one `$1` names); a group carries only its own member ids, in id order, and a group with none carries an empty list. |
| `listPagesNamingReader(principal)` | `brain.listPagesNamingReader(principal, 51)` | The pages in every source whose normalized readers (`gbrain_access_readers`, the `page_readers` column: trimmed, lower-cased, a bare id read as `member:<id>`, an invalid value read as `!nobody`) name exactly `principal`, by (source, slug), at most 51 (`PAGES_NAMING_READER_LIMIT`: `access/members.ts` shows 50 and reads one more to see a cut). A soft-deleted page counts and a page with no `readable_by` key does not, as in the statement `access/members.ts` `pagesNaming` ran through `executeRaw` on PGLite and Postgres (`PAGES_NAMING_READER_SQL`). Today no Rust path reaches it: `access member remove` and `access group remove` find no member or group first. |
| `expireMemoryProposals(reason)`, `purgeMemoryProposals(days)` | `0` | The store keeps no memory proposals. |
| `listAwaitingMemoryProposals(limit)` | `[]` | The store keeps no memory proposals. |
| `readPendingProposalSummary()` | `{ n: 0, oldest: null }` | The store keeps no memory proposals, so `gbrain status` and `gbrain doctor` report none pending. |
| `listMemoryProposalRows(query)` | `[]` | The store keeps no memory proposals, so `gbrain memory-proposals list` lists none, on every page. |
| `listOwnerProposalRows(requestId)` | `[]` | No request id names a proposal, so `gbrain memory-proposals show`, `approve` and `deny` answer `not_found`. |
| `readMemoryProposal(principalKind, principalId, requestId)` | `null` | The store keeps no memory proposals, so `get_write_request` and `cancel_write_request` answer `not_found` for a request id with no write request. |
