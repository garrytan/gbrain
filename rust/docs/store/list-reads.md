# Page lists, slug sources, access and connector-status reads

The reads below ran as raw SQL in their callers; each is now one typed engine member whose PGLite and
Postgres SQL lives in `src/core/engine-sql/`, and the store answers it from its records. Text keys
compare as bytes, as PGLite and the `COLLATE "C"` the SQL names compare them.

| JS | Resolves | Mirrors |
| --- | --- | --- |
| `brain.readRetainedSources(sourceIds)` | the listed ids naming a stored source whose `persistence_source_bindings` row points at a worktree that a write request still holds a recovery record for, each once, by id; `[]` for an empty list | `readRetainedSources` (persistence/connector-status.ts) |
| `brain.listLiveSlugSourceIds(slug)` | the ids of the sources holding a live page at `slug`, archived sources included, by id | `listLiveSlugSourceIds` (trust/refs.ts, quarantine.ts, extract-conversation-facts.ts) |
| `brain.resolveChainAnchorRows(slug, scope)` | `[{ id, source_id }]` of every live copy of `slug` the page read scope admits (the `pageReadFilter` of the policy, with its live filter: not deleted, not quarantined, source not archived), by source id | `resolveChainAnchorRows` (search/relational-chain.ts resolveChainAnchors) |
| `brain.probeTargetRows(slug, scope, chunkManifest)` | `[{ source_id, chunks, embedded, current, chunker_version }]` for the same copies: the live-body chunk count (`chunkGenerationFilter`; with `chunkManifest` false only the inline chunks of a page that is not segmented), how many of those have a vector, whether the text projection revision equals the knowledge revision, and the chunker version | `probeTargetRows` (search/explain-target.ts probeTarget) |
| `brain.readCompanyBrainEvidenceRows(sourceId)` | `{ owner, decision, page }`: the first `owned_by` link (`{ from_slug, from_title, to_slug, to_title }`) between live pages of the source written from frontmatter or markdown and held by its from page (or a markdown link with no origin), a `customer` from page first, then by from slug and to slug; the first `supersedes` link between two decision pages, chosen the same way without the customer rule; and the first live page (`{ slug, title }`) by slug. Each is `null` when there is none | `readCompanyBrainEvidenceRows` (company-brain/evidence.ts) |
| `brain.listCardRows({ sourceId, pageType, filters, scope, limit, offset })` | `{ total, cards }`: the count of the source's pages of `pageType` that the read scope (with its live filter) and the card filters (`status`, `store` among the `storage.locations`, `onSourceMachine`) admit, and the cards at `offset`, at most `limit`, by slug. A card is `{ id, title, status, kind, stores, original_path, on_source_machine, updated_at }` from `frontmatter.storage`: `stores` names each location's store once in byte order (one `null` last when a location names none), `on_source_machine` is `true`/`false` only for those texts, `updated_at` is the `timestamptz` text in UTC | `listCardRows` (storage-manifest/find.ts listCards) |
| `brain.readShelfPageRows(sourceId)` | `[{ slug, title, type, frontmatter }]` of every live page of the source, by slug, the frontmatter keys in jsonb order | `readShelfPageRows` (storage-manifest/find.ts readShelfCards) |
