# PMBrain Desktop 设计风格指南

本文档定义 PMBrain 桌面端原生 Electron Renderer 的视觉语言。后续新增或调整桌面界面时，应先阅读本文档，并在不改变原有业务流程和信息结构的前提下复用现有组件样式。

## 1. 设计定位

- 气质：专业、安静、可信赖的个人知识控制台，不使用高饱和霓虹色或厚重拟物效果。
- 信息：保留现有五步导航、设置分组、状态信息和操作入口，不为装饰增加无业务价值的内容。
- 层级：以背景、侧栏、卡片、控件四层表面建立纵深；主要依靠明度、细边框和轻阴影区分层级。
- 一致性：桌面端与 Admin Console 共用紫色品牌主色及绿、橙、红语义色，但保持桌面设置工具应有的紧凑密度。

## 2. 颜色与主题

所有颜色必须通过 `style.css` 顶部的 CSS 变量引用，不在组件选择器中散落品牌色。

| 用途 | 深色主题 | 浅色主题 |
| --- | --- | --- |
| 页面背景 | `#0c121a` | `#f7f8fb` |
| 侧栏背景 | `#0f1621` | `#fbfcff` |
| 主卡片 | `#141c27` | `#ffffff` |
| 品牌主色 | `#938aff` | `#6b5de8` |
| 成功 | `#55c89c` | `#28a976` |
| 警告 | `#ff9b57` | `#f1833a` |
| 错误 | `#ff7e8e` | `#e35f6f` |

- 紫色只用于品牌、当前导航、主操作和焦点反馈。
- 绿色只表示连接正常、保存成功、可用等正向状态。
- 橙色用于等待、提醒和需要关注的信息；红色用于失败和危险操作。
- 深浅主题必须保持相同的信息结构、间距与语义，不能只给某一主题做特例布局。

## 3. 布局与表面

- 桌面端使用固定步骤侧栏与滚动主内容区；侧栏负责流程定位，不承载额外说明。
- 页面主体使用单一内容容器，卡片圆角以 `13px` 为主，控件圆角以 `9px` 为主。
- 一级卡片使用 `--surface`、`--border` 和轻阴影；卡片内部区域优先使用 `--surface-soft`，避免重复套用同等强度的边框。
- 页面间距遵循 8px 基准：紧凑间距 8px、组件间距 12–16px、区块间距 20–24px。
- 状态、标题、说明和操作必须按阅读顺序对齐；不以任意绝对定位制造视觉效果。

## 4. 组件规范

### 按钮

- 主按钮：紫色渐变、白色文字、轻微品牌阴影；悬停上移 `1px`，按下恢复原位。
- 次按钮：使用表面色和细边框，悬停时变为浅紫背景与品牌边框。
- 危险按钮：仅危险行为使用红色语义，不能用红色替代普通取消操作。
- 所有按钮保持清晰的 `focus-visible` 焦点环，禁用状态只降低透明度，不改变布局。

### 导航

- 当前步骤使用浅紫表面、紫色边框和品牌文字；非当前步骤保持低对比度。
- 步骤编号仅用于真实的配置流程，不把普通菜单伪装成流程。
- 品牌标识使用紫色知识节点图形，不使用旧版绿色柱形标识。

### 表单与卡片

- 输入框、选择框和文本域统一为 40px 基础高度、9px 圆角和紫色焦点环。
- 表单说明使用次级文字色；校验结果紧邻对应字段，不用弹跳或强闪烁吸引注意。
- 连接、模型、系统和更新卡片共用同一套边框、圆角和状态色，不为单页创建独立视觉语言。

## 5. 交互与验收

- 交互反馈控制在 120–180ms，使用颜色、边框、阴影和最多 `1px` 位移表达状态。
- 不改变原有按钮事件、IPC 调用、配置字段和状态判断；视觉调整不得引入新的业务分支。
- 每次修改至少验证五个页面、深浅两种主题、键盘焦点、禁用态和错误/成功状态。
- 提交前运行 `bun run typecheck`、`bun test test` 和 `bun run build`；Windows 安装包仍由用户执行仓库根目录的 `bun run build:win`。
