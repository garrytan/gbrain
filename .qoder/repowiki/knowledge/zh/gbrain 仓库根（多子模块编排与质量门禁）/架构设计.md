- 顶层 package.json 将 `src/core/index.ts` 暴露为 npm 包入口并声明 `bin/gbrain` CLI，同时通过 `exports` 把 core_engine_and_cli 的子路径（engine、types、operations、minions、ingestion 等）作为独立子包导出，供 admin_frontend、recipes、evals、examples_skillpack_reference 等消费。
- tsconfig.json 的 `@/* → src/*` 路径别名与 `include: ["src", "test"]` 使所有子模块共享同一套 TypeScript 解析与类型契约；bunfig.toml 在全局 preload 中注入 legacy embedding 默认值，保证 test_suite 与 evals 的 fixture 行为一致。
- scripts/ 是跨子模块的编排层：run-unit-parallel.sh / run-e2e.sh / run-heavy.sh 驱动 test_suite 与 evals；build-admin-embedded.ts 在 build:admin 后把 admin_frontend 产物内嵌进 CLI；check-* 系列脚本对 skills_registry、core_engine_and_cli、admin_frontend、recipes 施加统一的隐私、可执行性、WASM 嵌入、JSONB 模式与 worker-pool 原子性等门禁。
- docker-compose.ci.yml / docker-compose.test.yml 提供 Postgres + PGLite 运行环境，被 scripts/ci-local.sh 与 test:e2e 复用，确保 core_engine_and_cli 与 test_suite 在同一数据库拓扑下验证。
- gbrain.yml、openclaw.plugin.json、llms.txt 等元数据文件由 scripts/build-llms.ts 与 publish:clawhub 脚本集中生成/发布，贯穿 core_engine_and_cli 与外部分发渠道。
