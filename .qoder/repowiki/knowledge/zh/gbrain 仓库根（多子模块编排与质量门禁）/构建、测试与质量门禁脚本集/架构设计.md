脚本按职责分为四类，彼此通过 shell 管道与 `bun run` 组合：
- 测试编排层：`run-unit-parallel.sh` 是入口，自动探测 CPU、以最多 4 个并发子进程调用 `run-unit-shard.sh`；后者再委托 `test-shard.sh` + `sharding.ts`（LPT 权重分片）产出文件列表并 `xargs bun test`。串行用例由 `run-serial-tests.sh` 统一处理。
- E2E 选择层：`select-e2e.ts` 基于 git diff 与 `e2e-test-map.ts` 做 fail-closed 的变更→测试映射，供 `ci-local.sh` 的 --diff 快速路径使用；`run-e2e.sh` 负责在 postgres-1..4 上并行执行选中的 e2e 用例。
- 质量门禁层：`check-*.sh` 系列为独立 grep/awk 守卫（隐私、JSONB 模式、WASM 嵌入、PGLite 快照、worker 锁形状等），被 `ci-local.sh` 在容器内顺序执行于 typecheck 之前。
- 构建/生成层：`build-schema.sh` 将 `src/schema.sql` 注入为 TS 常量；其余 `build-*.ts` 生成 LLM 索引、skillpack 解剖图、PGLite 快照等产物。
依赖方向单向：shell 脚本 → Bun TS 工具（`sharding.ts`、`select-e2e.ts`、`mine-shard-weights.ts` 等），TS 工具仅依赖 Node fs/path/child_process，不反向引用 shell。`ci-local.sh` 作为总控，通过 `docker compose -f docker-compose.ci.yml` 拉起 4 个 postgres shard 并在 runner 镜像中串联上述所有步骤。
