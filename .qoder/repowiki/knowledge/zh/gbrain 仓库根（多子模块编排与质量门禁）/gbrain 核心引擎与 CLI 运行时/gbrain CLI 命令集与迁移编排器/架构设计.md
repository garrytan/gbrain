本模块是 gbrain CLI 的扁平命令目录，每个 `.ts` 文件对应一个 `gbrain <cmd>` 子命令，统一导出 `runXxx(args: string[])` 函数供顶层路由调用。

- 命令分层：大部分命令（如 `auth.ts`、`init.ts`、`config.ts`）直接通过 `../core/config.ts` + `../core/engine-factory.ts` 获取引擎并执行；少数命令（`apply-migrations.ts`、`migrate-engine.ts`）作为编排器，协调多个阶段并在需要时以子进程方式调用自身（`execSync('gbrain ...')`）。
- 迁移子系统集中在 `migrations/` 子包：`types.ts` 定义 `Migration` / `OrchestratorOpts` / `OrchestratorResult` 契约；`index.ts` 按语义化版本顺序注册所有 v0.11.0…v0.32.2 迁移模块并提供 `getMigration()` 与 `compareVersions()`；`in-process.ts` 提供 `runMigrateOnlyCore`（在进程内完成 schema bring-up，避免 Windows+bun 子进程 DNS 失败）和 `runGbrainSubprocess`（诊断包装器，捕获子进程 stderr）。每个 `vX_Y_Z.ts` 实现一个幂等的 `orchestrator(opts)`，由 `apply-migrations.ts` 驱动运行并维护 `~/.gbrain/migrations/completed.jsonl` 账本。
- 依赖方向：命令 → core（config、engine-factory、ai/gateway、preferences、sql-query），不反向依赖其他命令；跨命令共享逻辑通过 `./migrations/*` 或 `../core/*` 暴露，而非互相 import。
- 启动模式：多数命令顶部带 `#!/usr/bin/env bun` shebang，既可通过编译后的二进制被路由，也可独立 `bun run src/commands/<file>.ts` 运行。
