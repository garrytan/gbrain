模块按评测主题拆分为三个并列子目录，每个子目录遵循同一分层：
- `harness.ts` 暴露纯函数指标（precision@k / recall@k / MRR / top-1 stability）和统一的 `run*Eval` runner，输出带 schema_version 的 JSON 报告；
- 引擎耦合点通过接口隔离：`code-retrieval/strategies.ts` 定义 `RetrievalStrategy` 接口并由 `BaselineStrategy`（调用 `core/search/hybrid.ts`）与 `WithCodeIntelStrategy`（v0.34 W3 前的空实现）分别注入；`retrieval-quality/harness.ts` 以 `SearchFn` 回调注入搜索器；`longmemeval/harness.ts` 则直接持有 `PGLiteEngine` 实例并在问题间 TRUNCATE 公共表。
- 数据适配层与评测逻辑分离：`longmemeval/adapter.ts` 将 HuggingFace _s 或 oracle 两种 haystack 形状归一化为 gbrain page，`intent.ts` 复用 `core/think/intent.ts` 的正则分类器并优先使用数据集自带的 `question_type` 标签。
- 每个 harness 同时导出 `DEFAULT_GATE` + `evaluateGate`，由上层 CLI 消费作为 ship gate；`code-retrieval` 的门还额外计算两次运行间的 top-1 stability rate 用于对比 baseline vs with-code-intel。
