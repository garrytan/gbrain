模块按三层组织：
- `src/core/search/` 是检索管线核心，以 `hybrid.ts` 为入口，串联 `keyword.ts` + `vector.ts`（或 `by-image.ts`）→ `rerank.ts` → `dedup.ts` → `runPostFusionStages`（依次调用 `applyBacklinkBoost`/`applySalienceBoost`/`applyRecencyBoost`/`applyTitleBoost`/`graph-signals.ts`/`alias-resolved boost`），并通过 `mode.ts` + `intent-weights.ts` 按意图/模式动态调整权重与预算；`query-cache.ts` + `query-cache-gate.ts` 提供语义缓存层，`two-pass.ts` 负责锚点展开与 chunk 水合。
- `src/core/embedding.ts` 作为对外统一门面，薄封装 `core/ai/gateway.ts` 的 `embed`/`embedQuery`/`embedMultimodal*`，并集中处理批分页、成本估算、同步/延迟嵌入模式决策与模型签名，屏蔽 provider 差异。
- `src/core/context/` 中的 `retrieval-reflex.ts` 在对话侧运行确定性实体解析（alias 优先 → title/slug-suffix），产出带 arm 置信度的 `PointerBlock`，由 `volunteer.ts`/`reflex.ts` 注入系统提示，与检索管线共享 `normalizeAlias` 但保持零 LLM、无原始正文泄露的边界。
依赖方向单向：context → search（仅复用 `normalizeAlias`），search → embedding，embedding → ai/gateway；所有 DB 访问经 `BrainEngine` 接口，避免直接 SQL 泄漏到上层。
