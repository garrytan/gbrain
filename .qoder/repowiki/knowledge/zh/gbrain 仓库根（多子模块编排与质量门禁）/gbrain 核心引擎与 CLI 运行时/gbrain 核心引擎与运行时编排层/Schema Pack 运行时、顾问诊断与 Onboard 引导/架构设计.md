本模块由三个并列子域组成，彼此通过 `BrainEngine` 和共享类型耦合：

- `schema-pack/`：以 `index.ts` 为唯一对外导出桶，内部按职责拆分为 manifest 校验（`manifest-v1.ts` + zod）、pack 生命周期（`loader.ts` → `registry.ts` → `load-active.ts`）、查询扩展（`closure.ts` + `per-source.ts`）、可提取/专家路由能力（`extractable.ts` / `enrichable.ts` / `expert-types.ts`）、安全边界（`redos-guard.ts` / `op-trust-gate.ts`）、变更与审计（`mutate.ts` + `mutate-audit.ts` + `pack-lock.ts`）以及诊断工具（`stats.ts` / `sync.ts` / `lint-rules.ts`）。`base/*.yaml` 是内置 pack 清单，`best-effort.ts` 提供降级加载入口。
- `advisor/`：纯读型诊断管线。`types.ts` 定义 `AdvisorCollector` / `AdvisorFinding` / `AdvisorReport` 契约；`run.ts` 维护硬编码的 `COLLECTORS` 数组并串行执行，每个 collector 独立 try/catch 保证健壮性，最后按 severity 与 collector 顺序稳定排序输出。各 `collect-*.ts` 文件对应一个采集器。
- `onboard/`：面向用户首次使用的轻量引导。`checks.ts` 实现四个 brain-wide SQL 聚合检查（embed 陈旧度、实体链接覆盖率、时间线覆盖率、takes 数量），返回统一的 `OnboardCheckResult`（check + RemediationStep[]）；`init-nudge.ts` 在 init 后以 3s 预算并行跑这些检查并通过 stderr 输出一行提示，严格 fail-open（A18/A20）；`render.ts` / `impact-capture.ts` / `types.ts` 负责渲染与影响面捕获。

依赖方向：`advisor` 与 `onboard` 均只消费 `core/schema-pack` 暴露的 API 与 `engine.ts`，不反向依赖 schema-pack 内部实现；schema-pack 自身也不依赖 advisor/onboard，保持单向依赖。
