本模块由三个相互独立但被上层共同消费的内核子域组成：
- `remediation/`：以 `types.ts` 定义稳定 JSON 契约（`RemediationPlan`、`RemediationResult`、`StepResult`、`RemediationHooks`），`plan.ts` 基于当前 brain_score 与目标分数生成步骤序列，`run.ts` 通过 hooks 驱动预算检查、checkpoint 恢复、依赖级联与每步重检；`context.ts` 加载推荐上下文。`index.ts` 作为 barrel 暴露给 doctor CLI、onboard CLI 与 MCP run_onboard。
- `resolvers/`：以 `interface.ts` 定义 Resolver SDK（`Resolver<I,O>`、`ResolverContext`、`ResolverResult<O>`、`ResolverError`），强调每条结果必须携带 confidence(0-1) 与 source 溯源；`registry.ts` 提供进程内 `ResolverRegistry` 单例（`getDefaultRegistry` / `_resetDefaultRegistry`），统一 resolve 流程（lookup → available → invoke）；`builtin/` 下按能力分目录存放内置实现（如 `x-api/handle-to-tweet.ts`、`url-reachable.ts`）。
- `storage/`：在 `../storage.ts` 中声明 `StorageBackend` 接口与 `createStorage(config)` 工厂，根据 `backend: 's3'|'supabase'|'local'` 动态 `import()` 对应实现类，使 gbrain 对底层存储完全无感知。
依赖方向单向：`resolvers/interface.ts` 仅依赖 `../engine.ts` 与 `../storage.ts` 的类型；`storage/*.ts` 只实现接口；`remediation/` 不直接依赖 resolvers，二者通过上层编排组合。
