- 每个评估子包以 `runner.ts` 作为唯一编排入口，返回包含 receipt/report 的结构化结果，CLI 层负责写文件与 banner 输出，runner 本身保持无 I/O 纯编排。
- 对外 JSON 契约通过显式的 `schema_version` 常量（如 `SCHEMA_VERSION`、`RECEIPT_SCHEMA_VERSION`、`RUBRIC_VERSION`）声明，字段只允许追加，改名或类型变更需 bump version。
- 多模型并行一律使用 `Promise.allSettled` 而非 `Promise.all`，单个 provider 5xx 不会杀死整个 cycle，未成功的 slot 以 `{ ok: false, error }` 形式进入聚合。
- 当启用 `--budget-usd` 时采用「失败关闭」策略：在下一轮调用前用 `estimateCost`/`estimateUpperBoundCost` 投影成本，超预算则提前中止并设置 `budgetAborted`/`capHitMidRun` 标志。
- LLM judge 的输出统一经 `parseModelJSON`（或 eval-shared 同名函数）解析，解析失败归入 slot error 计数而非抛错中断流程。
- 可复现性通过 SHA-8 指纹绑定：rubric_sha8、corpus_sha8、models_sha8、prompt_sha8、output_sha8 等字段记录到 receipt 中，使同一份输入可被精确重放。
