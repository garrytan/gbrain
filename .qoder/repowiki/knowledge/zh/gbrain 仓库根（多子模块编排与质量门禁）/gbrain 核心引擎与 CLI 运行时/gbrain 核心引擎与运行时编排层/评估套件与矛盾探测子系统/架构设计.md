本模块由四个并列的子包构成，每个子包围绕一个 `runner.ts` 编排入口组织，遵循「runner 编排 + 独立聚合/收据/提示词」的横向分层：
- `eval/`：共享基础设施——`cycle-default.ts` 统一 TTY/非 TTY 的 cycles 默认值（3 vs 1），`drift-watch.ts` 维护检索相关文件的变更白名单供 doctor 检查，`metric-glossary.ts` 是单一真相源，驱动 `gbrain search stats` 的 `_meta.metric_glossary` 块与自动文档生成。
- `eval-contradictions/`：LLM judge 驱动的矛盾探针。`types.ts` 定义稳定 wire 契约（`SCHEMA_VERSION`、`PROMPT_VERSION`、`ProbeReport`、`ContradictionPair/Finding` 等）；`runner.ts` 按「搜索→pair 生成（cross-slug + intra-page chunk/take）→日期预过滤→排序→缓存命中→judge 调用→错误收集→聚合」流水线执行，并通过 `JudgeCache` 持久化 judge 结果以 `prompt_version` 作为失效键；`cost-tracker.ts` 做软上限预算拦截，`calibration.ts` 计算 Wilson CI，`severity-classify.ts` 产出 hot pages，`auto-supersession.ts` 把 judge verdict 映射为带 resolution_command 的 finding。
- `takes-quality-eval/`：三模型面板对随机采样 takes 打分。`runner.ts` 通过 `engine.executeRaw` 从 DB 抽样，用 `Promise.allSettled` 并行调用三个 provider，`aggregate.ts` 按维度取均值+最小值判定 pass/fail/inconclusive，`receipt.ts` 定义稳定 JSON 形状，`pricing.ts` 提供每模型定价以便 --budget-usd 失败关闭式拦截。
- `cross-modal-eval/`：对任意 TASK+OUTPUT 进行多模型评分。`runner.ts` 循环最多 3 个 cycle，每个 cycle 用 `DEFAULT_SLOTS`（openai/anthropic/google）并行打分，`aggregate.ts` 采用「至少 2/3 成功且所有维度 mean≥7、min≥5」的 pass 条件，`receipt-write.ts` 将 CycleReceipt 写入磁盘并以 slug+output sha8 命名。

依赖方向单向向外：runner → aggregate/receipt/pricing/rubric/json-repair → 上层 `../engine.ts`、`../ai/gateway.ts`、`../search/hybrid.ts`、`../model-pricing.ts`；各子包之间不互相 import，仅 `takes-quality-eval/runner.ts` 引用 `../eval/cycle-default.ts` 共享 cycles 默认值。
