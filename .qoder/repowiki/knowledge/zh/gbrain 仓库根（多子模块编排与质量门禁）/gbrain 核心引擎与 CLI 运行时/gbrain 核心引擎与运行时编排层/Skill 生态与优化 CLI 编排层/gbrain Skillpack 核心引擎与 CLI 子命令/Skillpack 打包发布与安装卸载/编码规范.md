- 所有对外抛出的异常都是具名 Error 子类（PackPublishError / InstallError / UninstallError / BundleError / CopyError），并在构造时附带一个字面量 code 字段用于调用方分支处理。
- I/O 操作采用 plan/apply 两阶段模式：先构建不触盘的计划（planInstall / walkSourceDir），再在 apply 中加锁并执行写操作，dryRun 仅填充计划而不触碰文件系统。
- 受管状态通过 HTML 注释 fence（`<!-- gbrain:skillpack:begin/end -->`）配合 receipt 行（`cumulative-slugs` + `version`）持久化，并用 `writeAtomic`（tmp+rename）保证原子更新。
- 安全相关的前置校验（symlink 拒绝、realpath 包含、D8/D11 内容差异）一律在循环内一次性完成，抛出错误前不执行任何写操作，遵循“原子拒绝”契约。
- bundle 枚举函数接受统一的 `{ gbrainRoot, skillSlug?, manifest }` 选项对象，skillSlug 为 undefined 表示全量，非空则按 `skills/<slug>` 后缀精确过滤并报错未知 slug。
