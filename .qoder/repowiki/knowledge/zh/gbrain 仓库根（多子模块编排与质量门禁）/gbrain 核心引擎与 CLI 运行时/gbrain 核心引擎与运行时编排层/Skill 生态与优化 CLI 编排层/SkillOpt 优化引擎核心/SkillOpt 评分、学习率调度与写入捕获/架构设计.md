本模块由四个职责正交的纯函数/轻量工具文件组成，被上层 orchestrator 组合使用：
- `score.ts`：实现 `scoreTrajectory` 统一入口，按 `judge.kind` 分派到 rule / llm / qrels 三个子评分器；rule 通过 `applyCheck` 对 `contains|regex|section_present|max_chars|min_citations|tool_called|tool_not_called` 做布尔判定并取通过率；llm 调用 `gateway.chat` 并以 `parseJudgeJson` 容错解析 `{score, rationale}`，失败回退 score=0 并记录 `judge_error`；qrels 复用 `../search/eval.ts` 的 `ndcgAtK`，从 `trajectory.tool_calls` 中用 `extractRetrievedSlugs` 抽取候选 slug。
- `lr-schedule.ts`：纯函数集合，暴露 `cosineLr`/`linearLr`/`constantLr` 及 `resolveLrSchedule`，返回值始终 ≥ MIN_LR=1，供优化循环控制每步最大编辑数。
- `write-capture.ts`：F10 写模式支撑，`buildWriteCaptureRegistry` 基于 `operations` + `BRAIN_TOOL_ALLOWLIST` 构建只读 base defs/handlers，再注入 `brain_put_page`/`brain_submit_job`/`brain_file_upload` 三个虚拟 handler，将写操作以 `CapturedWrite` 形式存入内存 Map，返回 `WriteCaptureRegistry` 供 rollout 替换真实 engine。
- `held-out.ts`：F11 独立信号，读取 `~/.gbrain/skillopt-captures/<skill>/<run>.jsonl` 并通过 `loadHeldOut` + `validate-gate.scoreSkillOnTasks` 对比 baseline/candidate 在 held-out 集上的得分，空集时真空通过；`MIN_HELD_OUT_SIZE` 与 `D_SEL_MIN_SIZE` 同源防止脱节。
依赖方向单向向外：本模块仅依赖 `../ai/gateway.ts`、`../search/eval.ts`、`../operations.ts`、`../engine.ts`、`../config.ts` 等基础设施，不反向被同层其他文件引用。
