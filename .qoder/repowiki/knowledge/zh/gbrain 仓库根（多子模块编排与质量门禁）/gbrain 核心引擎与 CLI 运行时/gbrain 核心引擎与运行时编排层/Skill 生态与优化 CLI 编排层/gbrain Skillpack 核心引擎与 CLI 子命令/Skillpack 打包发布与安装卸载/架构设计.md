本模块围绕 skillpack 生命周期提供四层协作：
- `bundle.ts`：读取 gbrain 根目录下的 `openclaw.plugin.json` 作为 bundle 清单，提供 `loadBundleManifest` / `enumerateBundle` / `enumerateScaffoldEntries` 等枚举 API，并支持按 skill slug 过滤、shared_deps 依赖闭包、frontmatter `sources:` 配对源码发现，以及基于 git rev-parse/log 的 `changedSlugsSinceVersion` 增量扫描。
- `pack-publish.ts`：`runPackPublish` 是 CLI `skillpack pack` 的编排入口，顺序执行 manifest 加载 → `runDoctor(--quick)` 门禁（`tier_eligibility=blocked` 时拒绝并审计到 audit log）→ 可选 dry-run → 调用 `tarball.packTarball` 生成 `<name>-<version>.tgz`，返回带 `schema_version: 'skillpack-pack-v1'` 的结构化结果。
- `installer.ts`：安装/卸载的核心。`planInstall` 先计算每个 BundleEntry 在目标 skills 目录中的存在性与字节级相同性，`applyInstall` 再在 `.gbrain-skillpack.lock` 守护下原子写入；卸载路径 `applyUninstall` 对称地做 D8（cumulative-slugs receipt 白名单）+ D11（内容哈希守卫）前置检查后再删除。受管块通过 `<!-- gbrain:skillpack:begin/end -->` fence 与 `<!-- gbrain:skillpack:manifest cumulative-slugs="..." version="..." -->` receipt 维护已安装 slug 的累积历史，`updateManagedBlock` 使用 tmp+rename 原子替换。
- `copy.ts`：被 scaffold/harvest 复用的纯函数式拷贝原语，`walkSourceDir` 生成 `{source,target}` 对，`copyArtifacts` 在写之前统一校验（可拒 symlinks、confine realpath），遵循“先全部验证、后批量写入”的原子拒绝契约。

依赖方向：`pack-publish` → `bundle` + `doctor` + `tarball` + `audit`；`installer` → `bundle` + `resolver-filenames`；`copy` 无内部依赖。错误均通过具名 `*Error` 类（`PackPublishError` / `InstallError` / `UninstallError` / `BundleError` / `CopyError`）携带 code 字面量区分分支。
