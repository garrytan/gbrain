本模块由四个职责清晰的文件组成，围绕 `orchestrator.ts` 中的 `runSkillOpt` 单入口展开：
- `orchestrator.ts`：实现完整的 SkillOpt 运行时状态机（start → lock_acquire → preflight → resume_or_init → epoch_loop → final_test → run_end），封装 LR 余弦退火调度、D7 双 reflect 反向传播、D12 验证门（median-of-3 + ε=0.05）、F11 held-out 门、D6 slow_update、D8 checkpoint 持久化与 D14 per-skill 锁；支持 `--optimizer-mode one-shot-rewrite` 消融路径。
- `batch.ts`：在 orchestrator 之上提供两层聚合——`runBatchAll` 顺序遍历 skillsDir 下所有含 `skillopt-benchmark.jsonl` 的技能并以 brain-wide BudgetTracker 统一封顶；`runFleet` 对同一 skill 并行发起 N 个不同 targetModel 的优化，通过合成 per-model staging 目录避免 DB 锁冲突，最终选出 best_model。
- `benchmark.ts`：纯函数式 JSONL 加载/校验/拆分层，强制 D17（D_sel ≥ 5）与 D15（BOOTSTRAP_PENDING_REVIEW sentinel），按 task_id 排序保证 split 确定性，并提供 `parseSplit` 供 CLI 复用。
- `bootstrap-benchmark.ts`：两种 LLM 驱动的 benchmark 生成器（基于 routing-eval 与基于 SKILL.md），均输出带 BOOTSTRAP_PENDING_REVIEW 尾行的 JSONL，配合 `loadBenchmark` 的 D15 守卫形成“生成→人工审查→删除哨兵→正式运行”的闭环。
依赖方向单向向外：orchestrator 消费 batch/benchmark/bootstrap 导出的 API，不反向依赖它们；三者共同依赖 types.ts、apply-edits.ts、checkpoint.ts、validate-gate.ts、reflect.ts 等 skillopt 子模块，但不直接访问 AI gateway（仅 bootstrap 通过可注入的 `chatFn` 测试桩）。
