- 所有生成函数以 `runXxx(opts)` 形式暴露纯函数接口，opts/result 使用显式 TS interface，错误通过自定义 `*Error extends Error` 并附带字面量联合类型的 `code` 字段区分分支。
- 文件落盘一律先构造 `{ path, content }[]` 计划数组，再交给 `applyWritePlan` 或 `copyArtifacts` 执行，禁止在业务函数里直接调 `writeFileSync`，从而集中实现“跳过已存在文件”的幂等语义。
- 包名/技能 slug 校验统一用正则 `/^[a-z][a-z0-9-]{1,63}$/` 并在失败时抛出带 `invalid_name` code 的错误，保持名称约束在所有入口一致。
- 生成的 `skillpack.json` 始终携带 `api_version: SKILLPACK_API_VERSION`、`gbrain_min_version`、`skills`、`runbooks.bootstrap`、`changelog` 等必填字段，并通过 `JSON.stringify(..., null, 2) + '\n'` 格式化落盘。
