本模块是 SkillOpt 优化循环的 I/O 与执行边界，按职责拆分为四个文件：
- `rollout.ts`：通过 `gateway.toolLoop` 驱动 LLM agent 在只读工具集（`READ_ONLY_BRAIN_TOOLS`，从 `BRAIN_TOOL_ALLOWLIST` 剔除 `put_page`）上执行一次 skill 评估，返回 `Trajectory`；支持可选的 write-capture 模式（动态 import `write-capture.ts`），并通过 `OperationContext.remote=true` + `sourceId='default'` 让底层 ops 走远程收紧策略。
- `version-store.ts`：实现 D8 历史意图优先的两阶段提交——按顺序写 `history.json(pending)` → `versions/vNNNN_eE_sS.md` → `best.md` → `SKILL.md` → `history.json(committed)`，并提供 `revertAllPending` 做崩溃恢复；所有文件写入统一走 `apply-edits.ts` 的 `atomicWrite`。
- `checkpoint.ts`：以 `skills/<name>/skillopt/checkpoint-<run_id>.json` 记录单 run 进度（epoch/step/best_sel_score/cost），供 `--resume` 跳过已完成阶段，并带 7 天 GC。
- `lock.ts`：对 `src/core/db-lock.ts` 的薄封装，以 `skillopt:<skillName>` 为 id 跨主机互斥，默认 TTL 60min + 15min 自动续期，`withSkilloptLock` 包装 try/finally 释放。
依赖方向单向向外：本模块被 orchestrator 调用，不反向依赖上层编排逻辑；仅依赖 `../ai/gateway`、`../operations`、`../db-lock`、`../errors` 等核心原语。
