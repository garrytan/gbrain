模块以 `gateway.ts` 为唯一对外入口，暴露 `configureGateway()` / `embed()` / `chat()` / `expand()` / `isAvailable()` 等函数，内部按职责分层：
- 配置层：`AIGatewayConfig`（types.ts）+ `configureGateway()`/`reconfigureGatewayWithEngine()` 单例持有 `_config`，禁止在调用期读 `process.env`。
- 路由层：`model-resolver.ts` 解析 `provider:model` 字符串，查 `recipes/index.ts` 静态注册表得到 `Recipe`，再用 `assertTouchpoint` 校验是否支持该 touchpoint；`_extendedModels` 允许用户通过配置绕过 native recipe 的白名单。
- 实现层：`recipes/` 下每个 provider 一个纯数据 `Recipe` 对象（如 `openai.ts`），gateway 根据 `implementation`（`native-openai` / `native-google` / `native-anthropic` / `openai-compatible`）在 `gateway.ts` 内 switch 到对应 SDK 工厂或 `createOpenAICompatible` + 自定义 fetch shim（Voyage、ZeroEntropy 的 `voyageCompatFetch` / `zeroEntropyCompatFetch` 负责请求体/响应体改写与 OOM 防御）。
- 辅助层：`errors.ts` 统一 `AIConfigError`/`AITransientError`；`dims.ts` 维护各 provider 的 Matryoshka 维度映射；`defaults.ts` 导出默认模型避免重型依赖被 schema 模块加载；`probes.ts` 暴露 `runExplain()` 用于 `gbrain providers` 探测；`build-gateway-config.ts` 把 CLI/engine 配置折叠成 `AIGatewayConfig`。
- 测试钩子：`__setEmbedTransportForTests` / `__setChatTransportForTests` 注入 transport 以跳过真实网络；`AsyncLocalStorage` 线程传递 `input_type` 给 openai-compatible shim。
依赖方向：gateway → model-resolver → recipes/index → 单个 recipe 文件；gateway 反向依赖 `../budget/budget-tracker.ts`、`../guardrails.ts`、`../model-config.ts`，不反向被 recipes 引用。
