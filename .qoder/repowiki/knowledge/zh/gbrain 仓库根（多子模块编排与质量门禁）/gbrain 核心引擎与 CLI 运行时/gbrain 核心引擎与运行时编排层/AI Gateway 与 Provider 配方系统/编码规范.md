- Provider 以纯数据 `Recipe` 对象声明（id/name/tier/implementation/auth_env/touchpoints/setup_hint），由 `recipes/index.ts` 集中 static import 注册，新增 provider 只需加文件并在此处加入数组。
- 认证头统一走 `defaultResolveAuth` + `applyResolveAuth` 管线，recipe 仅声明 `auth_env.required/optional`，特殊 provider（Azure）通过可选的 `resolveAuth` 覆盖。
- 对非 OpenAI 兼容后端的差异通过 `resolveOpenAICompatConfig` 返回自定义 `fetch` wrapper 在请求/响应两侧做字段重写（如 Voyage 的 `encoding_format`/`output_dimension`、ZE 的路径 `/models/embed`）。
- 所有对外错误归一化为 `AIConfigError` / `AITransientError`，并在 message 中附带 `setup_hint` 指向 provider 文档 URL。
- 测试通过 `__set*TransportForTests` 注入函数替换 SDK 调用，生产路径绝不读取这些变量，保持可测性与运行期零开销。
- 模型 ID 一律采用 `provider:model` 格式，经 `parseModelId` 解析并由 `assertTouchpoint` 对照 recipe 的 `touchpoints.*.models` 白名单校验，用户显式配置的模型通过 `_extendedModels` 豁免。
