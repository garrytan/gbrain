纯文档仓库，按读者角色与主题分层组织：
- `docs/architecture/`：核心架构参考（KEY_FILES.md 作为“每文件入口索引”，RETRIEVAL.md 描述检索管线，infra-layer/topologies/type-taxonomy 等覆盖系统边界）。
- `docs/guides/`：面向使用者的分步教程与排障手册（minions、enrichment、cron、RLS 等），附带可复用的部署片段（`guides/minions-deployment-snippets/` 中的 Procfile/fly.toml/systemd.service）。
- `docs/mcp/`：各 MCP 客户端（Claude Code / Desktop / Codex / ChatGPT / Perplexity）的接入指南与生产部署模式。
- `docs/ethos/` + `docs/designs/` + `docs/proposals/` + `docs/plans/`：产品理念、设计决策记录、提案与计划，体现从理念到实现的演进脉络。
- `docs/eval/` + `docs/issues/` + `docs/incidents/`：评估方法论、已知问题与事故复盘，与 `src/core/search/eval.ts`、`src/core/cross-modal-eval/` 等代码模块一一对应。
- 根级 `INSTALL.md`、`GBRAIN_SKILLPACK.md`、`GBRAIN_V0.md`、`UPGRADING_DOWNSTREAM_AGENTS.md` 等作为全局入口与版本契约。
依赖方向单向：文档引用源码路径（如 `src/core/engine.ts`、`src/core/search/hybrid.ts`），源码不反向引用本目录；所有事实以 KEY_FILES.md 为单一权威索引，禁止在架构文档中混入发布历史（由 CI `scripts/check-key-files-current-state.sh` 强制）。
