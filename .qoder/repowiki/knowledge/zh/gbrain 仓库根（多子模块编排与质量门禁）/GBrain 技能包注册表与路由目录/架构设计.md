本模块是纯数据/文档型技能包仓库，不含可执行代码，由宿主 gbrain CLI 在运行时发现并加载：
- `manifest.json` 是根清单，声明 `skills[]`（每个条目含 name/path/description）、`conformance_version`、`dependencies.runtime= bun`、`setup.skill=setup`、`resolver=RESOLVER.md`、`conventions_dir=conventions/` 等元数据，是 skillpack scaffold/reference/harvest 等 CLI 命令的权威索引。
- 每个 `<slug>/SKILL.md` 是一个技能的完整契约：YAML frontmatter 定义 `name`、`triggers:` 数组（用户短语匹配）、可选 `mutating`/`writes_pages`/`sources`；正文用 `## Phases` / `## Workflow` 描述步骤，被 agent 在执行时全文读取。
- `RESOLVER.md` 是顶层调度器，把自然语言意图映射到具体 `skills/<slug>/SKILL.md`，并规定“always-on”（signal-detector、brain-ops）和分组（脑操作、内容摄取、思考技能、运维、身份访问等）以及多技能链式调用规则。
- `conventions/` 存放横切约定（brain-routing、schema-evolution、cross-modal.yaml、quality.md、subagent-routing 等），所有写脑技能都通过引用而非复制来复用这些规则。
- `_AGENT_README.md` 是冷启动协议：告诉 agent 如何扫描 `triggers:`、何时运行 `gbrain skillpack reference --all` 对比上游 bundle、如何处理 `differs/missing`。
- `migrations/` 按版本号（v0.5.0 … v0.41.11.0）记录 schema/行为变更，配合 `gbrain apply-migrations` 使用。
- 依赖方向单向：skill 只读 conventions 与 RESOLVER；manifest 不反向引用任何 skill 实现；CLI 通过解析 manifest → 定位 SKILL.md → 按 triggers 匹配 → 执行该文件描述的流程。
