本模块由三个独立的 Bun 测试文件组成，分别覆盖三类不同粒度的回归防护：
- `fix-wave-structural.test.ts`：通过 `readFileSync` 直接读取 `src/` 下的源文件并用正则断言关键 API 签名、调用顺序与存在性（如 `registerBackgroundWorkDrainer`、`finishCliTeardown`、`runMigrateOnlyCore`），属于“源码形状”回归守卫，用于防止后续重构删掉某行关键代码。
- `remediation-step.test.ts`：对 `src/core/remediation-step.ts` 导出的 `canonicalJson` / `idempotencyKey` / `makeRemediationStep` 进行纯函数行为测试，并验证从 `brain-score-recommendations.ts` 的 `Remediation` 别名仍指向同一类型（编译期 + 运行期双重检查）。
- `repair-jsonb.test.ts`：仅覆盖 `repair-jsonb` 命令在 PGLite 引擎下的短路分支（不连库、返回 0 修复行且列出 5 个目标列），完整 E2E 放在 `test/e2e/postgres-jsonb.test.ts`。
依赖方向单向指向 `src/`，测试之间无共享 fixture，各自独立 `describe` 块按版本/issue 编号分组。
