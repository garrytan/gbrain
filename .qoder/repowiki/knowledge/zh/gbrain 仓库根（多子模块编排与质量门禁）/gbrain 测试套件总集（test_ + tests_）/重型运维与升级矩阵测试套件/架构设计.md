本模块是独立于 `bun test` 的 shell-first heavy-test 层，由顶层 `scripts/run-heavy.sh` 发现并顺序执行 `tests/heavy/*.sh`（跳过 `_*.sh` 前缀的 helper），失败即停。

- 编排入口：`measure_rss.sh`、`read_latency_under_sync.sh`、`pg_upgrade_matrix.sh`、`sync_lock_regression.sh`、`sync_timeout_rescue.sh`、`frontmatter_scan_wallclock.sh` 等顶层 `.sh` 脚本；每个脚本负责一个 ops-shape 场景（内存预算门、写放大下的读延迟、Postgres 升级矩阵、同步锁回归、超时救援、frontmatter 扫描耗时）。
- 可复用子程序：以 `_` 前缀命名的 `.ts` / `.sh` 文件（`_measure_rss_workload.ts`、`_read_latency_workload.ts`、`_build_legacy_fixtures.sh`、`_sync_timeout_rescue_workload.ts`）作为被 sibling 脚本调用的库，不单独被 runner 拾取。
- 数据固定集：`fixtures/` 存放历史 schema 的 down-mutate SQL（`down-mutate-pre-v0.13.sql`、`down-mutate-pre-v0.18.sql`），配合 `_build_legacy_fixtures.sh` 通过 `gbrain doctor` 把空库推到 LATEST 再回滚到目标 shape，从而驱动 `pg_upgrade_matrix.sh` 的 walk-forward 矩阵。
- 基线契约：`rss-baseline.json` 保存 Linux `/proc/self/status` 测得的 peak RSS，`measure_rss.sh` 用 grep 解析 JSON 字段做 delta_pct 比较；macOS 因走 `process.memoryUsage().rss` 回退路径而被拒绝刷新基线。
- 依赖方向：shell 脚本 → 调用 `bun run src/cli.ts` 或 `bun run tests/heavy/_*.ts`；TS workload 仅通过动态 `import('../../src/core/pglite-engine.ts')` 和 `../../src/core/search/hybrid.ts` 访问 gbrain 核心，无跨进程共享状态，保证测量自包含。
- CI 边界：默认 PR CI 不包含此目录，改由 `.github/workflows/heavy-tests.yml` 在 nightly 08:17 UTC 及带 `heavy-tests` label 的 PR 上触发；失败产物写入 `~/.gbrain/audit/heavy-<script>-<ts>.log` 供上传。
