本模块是位于 `test/` 根目录下的单元测试集合，按被测子系统分文件组织：
- `engine-*.test.ts`：围绕 `src/core/engine-factory.ts` 的 `createEngine` 工厂（返回 `PGLiteEngine` / `PostgresEngine`）以及 PGLite 引擎上的 `upsertFile`、权重舍入、slug 解析等 API 行为。
- `resolver-*.test.ts` + `resolvers.test.ts`：覆盖 `src/core/resolvers/index.ts` 中的 `ResolverRegistry`、`getDefaultRegistry`、`_resetDefaultRegistry` 以及内置 resolver（`url_reachable`、`x_handle_to_tweet`），通过 `makeCtx` 构造最小 `ResolverContext` 并 mock `globalThis.fetch`。
- `relational-*.test.ts`：验证 `src/core/search/relational-intent.ts` 的 `parseRelationalQuery` 四种原型（who_rel / who_at / intro / connects）、精度优先防误报、`validateVocab` 词汇集扩展，以及 `relational-ab.test.ts` 使用 `src/eval/retrieval-quality/harness.ts` 的 `runRetrievalQuality` 在 PGLite 上跑 A/B recall@10 对比。
- `orphans-*.test.ts`：断言 CLI `runOrphans` 的 `--json` / `--count` 输出与纯函数 `findOrphans` / `getOrphansData` 返回值字节级一致，并通过 `shouldExclude` 回归伪页面过滤规则。

所有需要持久化的测试均通过 `new PGLiteEngine()` + `connect({})` + `initSchema()` 在内存中启动，配合 `beforeAll/afterAll` 生命周期管理；状态清理统一走 `test/helpers/reset-pglite.ts` 或直接 `executeRaw('DELETE FROM ...')`。无网络依赖，外部 I/O 通过替换 `globalThis.fetch` 或 `console.log` 捕获来隔离。
