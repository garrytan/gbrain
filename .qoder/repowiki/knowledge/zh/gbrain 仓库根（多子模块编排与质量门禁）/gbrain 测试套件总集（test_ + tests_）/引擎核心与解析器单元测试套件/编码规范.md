- 每个 describe 块聚焦一个子模块或单一 API，测试用例名采用「场景描述」风格（如 'happy path'、'Eng-3E: ON CONFLICT idempotency'），而非仅写 'returns true'。
- 需要数据库状态的测试统一在 `beforeAll` 中 `new PGLiteEngine()` → `connect({})` → `initSchema()`，在 `afterAll` 中 `disconnect()`，并在 `beforeEach` 中用 `resetPgliteState(engine)` 或 `executeRaw('DELETE FROM ...')` 清空数据。
- 对外部副作用（网络、日志）采用就近替换策略：`globalThis.fetch = originalFetch` 配合 `afterEach` 恢复，或通过 `captureConsoleLog` 临时挂接 `console.log` 再在 finally 中还原。
- 对全局单例（如默认 ResolverRegistry）使用 `_resetDefaultRegistry()` 在 `beforeEach`/`afterEach` 中重置，确保测试间隔离。
- 关键契约以 IRON RULE 注释形式声明，并用 deep-equal 断言 CLI 输出与纯函数返回值严格一致，防止后续重构引入漂移。
