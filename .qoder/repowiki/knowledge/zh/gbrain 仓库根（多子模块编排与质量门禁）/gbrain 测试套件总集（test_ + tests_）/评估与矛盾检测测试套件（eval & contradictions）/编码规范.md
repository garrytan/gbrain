- 每个测试文件顶部注释标明所覆盖的源码版本（如 v0.21.0、v0.32.6、v0.41.16.0）与被测方法清单，便于追踪变更影响面。
- 基于 PGLite 的测试统一采用 `beforeAll(new PGLiteEngine().connect().initSchema())` + `afterAll(disconnect())` 生命周期，并在 `beforeEach` 中调用 `resetPgliteState(engine)` 或手动 `DELETE FROM` 清理表。
- CLI 行为测试通过 `mkdtempSync(join(tmpdir(), '...'))` 创建临时 JSONL 文件，并在 `afterEach` 中递归删除，保证无外部状态残留。
- LLM 网关交互通过 `mock.module('../src/core/ai/gateway.ts', () => ({ chat: async (opts) => {...} }))` 在导入 runner 之前注入假实现，返回包含 `text`/`blocks`/`usage`/`model`/`providerId` 的结构体。
- CLI 测试同时断言退出码（0=全通过、1=有失败、2=USAGE 错误）与 `--json` 输出 envelope 的 `schema_version`、`total_fixtures`、`passed`、`failed`、`recall_mean`、`pattern_coverage`、`failed_fixture_ids` 字段。
- 破坏性/全局状态污染的测试文件以 `.serial.test.ts` 结尾，强制串行执行以避免 bun test shard 间的 mock 泄漏。
