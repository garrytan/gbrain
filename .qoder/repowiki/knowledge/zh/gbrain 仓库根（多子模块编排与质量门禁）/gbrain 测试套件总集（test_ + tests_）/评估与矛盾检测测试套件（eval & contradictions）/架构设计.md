本模块是纯测试代码，按被测子系统横向切分为若干命名空间：
- `test/eval/*.ts`：围绕 `src/core/pglite-engine.ts` 的 PGLite 内存数据库层做 round-trip 验证（候选采集、捕获失败、导出、回放、schema 等），通过 `beforeAll/connect/initSchema` + `afterAll/disconnect` 生命周期管理单例引擎实例。
- `test/eval-candidates.test.ts`、`test/eval-capture*.test.ts`：针对 v0.21.0 的 eval-capture 五件套 API；`test/eval-replay*.test.ts`、`test/eval-export.test.ts`、`test/eval-prune.test.ts` 分别覆盖回放、导出、清理流程。
- `test/eval-contradictions-*.test.ts`：按矛盾探测子功能拆分（engine、judge、runner、cache、calibration、cost、trends、severity、cross-source、fixture-redact、integrations、date-filter、auto-supersession、judge-errors），全部以 PGLite 为隔离后端，复用 `test/helpers/reset-pglite.ts` 的 `resetPgliteState` 在 `beforeEach` 中清空表。
- `test/routing-eval*.test.ts`：直接 import `src/core/routing-eval.ts` 的函数式 API（normalizeText、extractTriggerPhrases、indexResolverTriggers、structuralRouteMatch、lintRoutingFixtures、runRoutingEval），用临时目录 + `fs` 构造 resolver 表格与 fixture JSONL，不依赖 DB。
- `test/eval-conversation-parser-cli.test.ts`：调用 `src/commands/eval-conversation-parser.ts` 的入口函数，断言 exit code 0/1/2 与 `--json` envelope 结构，使用 `tmpdir()` 下的 JSONL 文件作为输入。
- `test/eval-takes-quality-*.test.ts`：围绕 `src/core/takes-quality-eval/runner.ts` 与 `rubric.ts`，通过 `bun:test` 的 `mock.module('../src/core/ai/gateway.ts', ...)` 注入假 `chat` handler，再驱动 `runEval(engine, { models, limit, cycles, budgetUsd })` 断言 receipt verdict（pass/inconclusive/fail）与预算中止分支；其中 `eval-takes-quality-runner.serial.test.ts` 因 mock 泄漏被标记为 `.serial.test.ts` 强制串行执行。
- 慢速 E2E 用例（`eval-longmemeval.slow.test.ts`、`eval-longmemeval-e2e.slow.test.ts`）独立于上述单元层，用于跨进程端到端场景。

依赖方向单向指向 `src/` 中的实现与 `test/helpers/reset-pglite.ts`，测试之间互不引用，仅共享 PGLite 启动模式与 `mkdtempSync` 临时文件约定。
