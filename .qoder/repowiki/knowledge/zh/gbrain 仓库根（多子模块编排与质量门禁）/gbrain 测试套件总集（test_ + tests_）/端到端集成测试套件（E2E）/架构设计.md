本模块是顶层 E2E 层，直接依赖 `src/core/*` 中的运行时实现，不经过 mock：
- 共享基础设施集中在 `helpers.ts`：提供 `setupDB()` / `teardownDB()`（连接 Postgres、执行 `db.initSchema()` + `engine.initSchema()` 应用迁移、按 `ALL_TABLES` 顺序 TRUNCATE）、`importFixtures()`（递归扫描 `fixtures/` 下所有 `.md` 并通过 `importFromContent` 注入）、`runMigrationsUpTo()` / `setConfigVersion()`（用于 v15→v23 等链式迁移场景），以及 `.env.testing` 自动加载。
- 每个 `*.test.ts` 文件自包含一个 `describe` 块，使用 `hasDatabase()` 做 `DATABASE_URL` 存在性门控，配合 `describe.skip` 在无 DB 时静默跳过；HTTP 类测试在 `beforeAll` 中用 `child_process.spawn('bun', ['run','src/cli.ts','serve','--http',...])` 拉起真实服务，轮询 `/health` 就绪后再运行用例，`afterAll` 中 SIGTERM/SIGKILL 清理并调用 `auth revoke-client` 回收 OAuth 客户端。
- `bench-vs-openclaw/` 子目录是与 OpenClaw 对比的基准套件，`harness.ts` 暴露 `openclawDispatch`（spawn `openclaw agent --local`）与 `minionsHandler`（直调 Anthropic SDK）两个等价入口，`durability.bench.ts` 等通过插入 `status=active`+过期锁的行模拟 worker 崩溃，衡量 Minions 的 stall 恢复能力。
- 依赖方向单向向下：`test/e2e/*` → `src/core/*`（PostgresEngine、MinionQueue/Worker、migrate、import-file、markdown 等），不反向引用任何业务逻辑以外的代码。
