本模块按被测对象划分成若干平铺的 `bun:test` 用例文件，全部直接 import `src/commands/migrations/*` 和 `src/core/migrate.ts` 等实现源码，不依赖外部数据库或 CLI 进程。

- 注册表契约层：`migrations-registry.test.ts` 校验 `src/commands/migrations/index.ts` 导出的 `migrations` 数组非空、每项具备 `version`/`featurePitch.headline`/`orchestrator` 字段且按 semver 升序排列，并验证 `getMigration` 与 `compareVersions` 的行为。
- 具体版本迁移：每个 `migrations-v0_XX_Y.test.ts` 对应一个已发布的迁移（如 v0_13_1、v0_21_0、v0_27_1、v48、v94、v99），通过 `import('../src/commands/migrations/v0_XX_Y.ts')` 动态加载 orchestrator，断言其 `featurePitch`、`__testing` 暴露的 phase 函数、dry-run 行为及在注册表中的排序位置。
- 运行时核心：`migrate-retry.test.ts` 通过 `_hooks` 测试 seam 注入假 `hasPending`/`initSchema`，覆盖 `tryRunPendingMigrations` 的死锁重试、轮询超时、race_resolved/persistent/error/not_needed 状态机；`migrate-extensions.test.ts` 校验 `isMigrationIdempotent` 默认 true、`LATEST_VERSION` 与 `MIGRATIONS` 最大值一致，以及 `MigrationDriftError`/`MigrationRetryExhausted` 的错误消息格式。
- 文件系统迁移：`file-migration.test.ts` 用临时目录 + `LocalStorage` 模拟本地→Supabase 存储的 MIRROR/REDIRECT/RESTORE/CLEAN 生命周期，并通过 `resolveFile` 验证 `.redirect` 面包屑的回源逻辑。
- 特殊场景：`migration-resume.test.ts`、`migration-in-process.serial.test.ts`、`migration-orchestrator-v0_21_0.test.ts`、`migrations-cjk-wave.test.ts`、`migrations-v0-29-1.serial.test.ts` 分别覆盖 CJK 分词迁移、串行化迁移、v0.21.0 编排器契约、v0.29.1 特定路径等边界用例。

依赖方向单向指向 `src/`，测试之间互不引用，由 bun test runner 并行执行（带 `.serial.` 后缀的用例除外）。
