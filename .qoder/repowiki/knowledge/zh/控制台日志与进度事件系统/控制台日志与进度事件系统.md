gbrain 未引入第三方日志框架，而是基于 Node.js console API 自建了两层轻量机制：按来源前缀的 stderr 输出与结构化进度事件。

## 1. 按来源前缀的控制台输出（src/core/console-prefix.ts）
- 使用 AsyncLocalStorage 在并发同步/嵌入任务中为每行输出自动加上 [source.id] 前缀，避免多源并行时 stdout/stderr 交错。
- 提供 slog() / serr() 作为 console.log / console.error 的前缀感知替代；在 withSourcePrefix(id, fn) 作用域内生效，作用域外退化为裸 console，保证向后兼容。
- 对 Error、对象分别走 stack/message 或 JSON.stringify，多行字符串逐行加前缀。
- 仅用于人类可读的诊断信息，不用于结构化数据输出。

## 2. 进度事件子系统（src/core/progress.ts）
- 所有长耗时 CLI 命令（doctor、embed、sync、extract、eval-* 等）统一通过 createProgress(opts) 创建 reporter，以 start/tick/heartbeat/finish/child 生命周期驱动。
- 支持四种渲染模式：auto（TTY → human-tty，管道 → human-plain）、human、json、quiet；默认写入 process.stderr，stdout 保持纯净供 JSON/数据消费。
- JSON 事件模式产出稳定 NDJSON 流，字段包括 event（start/tick/heartbeat/finish/abort）、phase（snake_case 点分路径）、done/total/pct/eta_ms/elapsed_ms/ts/note/reason 等，详见模块注释中的 schema。
- 内置进程级 SIGINT/SIGTERM 协调器：每个 reporter 注册到全局 liveReporters，收到信号后向所有活跃阶段广播 abort 事件，然后移除自身，不吞掉信号。
- TTY 模式下使用 \r\x1b[2K 原地重写单行，并自动将当前 source prefix 注入到重写后的行首；JSON 模式不做前缀，以免破坏消费者解析。
- 提供 startHeartbeat(reporter, note, intervalMs?) 辅助函数，适合无迭代进度的长时间查询。

## 3. 调用约定与覆盖范围
- 命令入口统一通过 cliOptsToProgressOptions(getCliOptions()) 把 CLI 参数映射为 ProgressOptions，再 createProgress。
- 并发场景下用 withSourcePrefix(source.id, () => performSync(...)) 包裹执行体，内部改用 slog/serr 输出，确保每行带来源标签。
- 直接 console.warn/error/log 仍散见于配置加载、DB 连接、cycle 锁等基础设施处，属于非结构化诊断用途，不在 per-source 前缀范围内。

## 4. 规则与建议
- 面向人类的可读输出：优先使用 slog/serr + withSourcePrefix；仅在不需要来源隔离的初始化/错误路径直接使用 console.*。
- 面向机器消费的指标/状态：一律使用 createProgress 的 JSON 模式，不要往 stdout 写任何非数据内容。
- 长任务必须暴露 start/finish 生命周期，并在阻塞操作期间用 heartbeat 保活。
- 不要在 JSON 模式下依赖前缀——消费者会按固定字段解析。
