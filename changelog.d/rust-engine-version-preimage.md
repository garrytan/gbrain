**On an experimental Rust brain, updating a page now works: the old page is saved as a version, the update commits, and a date in a page's frontmatter keeps its value. PGLite and Postgres brains behave as before.**

### Fixed
- On a Rust brain, a page update saved through the background writer stayed pending, because the Rust engine refused the old page the writer hands it to save as a version. The Rust engine now saves that page as it was read: the same title, body, frontmatter, tags and change reason that PGLite and Postgres save. `get_versions` and `get_page --as-of` read the same history on all three engines. A preimage the engine cannot match (a NUL byte, a revision that is not an id, another page's id) is refused with a named error before anything is written, and a segmented page's preimage stays refused.
- On a Rust brain, a page update with a reason (`put_page ... reason: "..."`) stayed pending, because the check that keeps a reason only on a world-visible page ran raw SQL. The check is now a typed engine member, `readPageWorldVisible`, which the Rust store answers. PGLite and Postgres send the same statement as before.
- On a Rust brain, a date in a page's frontmatter (for example `valid_from: 2024-01-01`) was saved as an empty object, so the page lost the date and `get_page --as-of` could not find its valid time. The date is now saved as its ISO text, as PGLite and Postgres save it.
- On a Rust brain, a page judged by the empty identity (the world-visibility check, a fact's provenance page) ignored the caller's pending or invalid folder prefixes, so a page under such a prefix could count as readable. The Rust store now hides it, as PGLite and Postgres do.
