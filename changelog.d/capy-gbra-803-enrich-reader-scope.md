**Filling a thin page (`gbrain enrich` and the autopilot thin-page phase) now uses only facts, link context and search hits that every reader of that page can already see.**

<!-- behavior-change: enrich_evidence_page_readers_gst3815 -->

### Fixed
- Enrichment gathered its evidence with no reader check: every fact about the entity (private facts and facts held on pages that name fewer readers included), the context of every link into the page, every search chunk that mentioned it, and the page's own stub with its private fact rows and takes. The model's text was then written onto the page under that page's own `readable_by` and `visibility`, so something only some readers could see could be copied onto a page more people read. Evidence now comes only from pages every reader of the target page reads: world facts held on such pages or on the page itself, and link context and search chunks from such pages (search skips chunks not yet sealed against private fence rows). A page that names readers or sits under a folder rule is filled only from pages labelled for all of its readers, and only with facts those pages' bodies show as world rows (held rows left out), so members who read only labelled pages see nothing new. A fact whose holding page is quarantined or deleted is never used, as normal fact reads never show it, and neither is a link or search hit from a quarantined page. A link's stored context is an excerpt of the linking page's body, so it is used only when it still reads in that page as remote readers see it, with private and held fact rows removed; otherwise it is dropped. The stub reaches the model as remote readers see it, held rows removed too. Owner-only data never fills a page that is not owner-only. If any evidence stops qualifying while the model runs, nothing is published and the page is retried on the next run (`pages_skipped_evidence_narrowed`, now also in the totals across sources and in the autopilot thin-page phase). Private facts are never used. This works the same on a brain with no git repository.
