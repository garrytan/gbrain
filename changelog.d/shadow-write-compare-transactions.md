**Shadow mode can now compare a page write that ran inside a transaction, which is how `put_page` and sync imports write.**

### Changed
- A sampled `put_page` or import page write inside a transaction used to be counted as uncomparable. It is now compared after the transaction commits, with the same checks as a page write outside one: the rows it touches are read on the transaction's own connection before the write (in a savepoint that is rolled back, so the write is never changed), and the result is replayed on a throwaway Rust store. A transaction that rolls back is never compared. Any earlier write to the page, its links, chunks, tags or versions in the transaction (a version row for the same page is allowed), two writes to one page, or an option the Rust store does not take makes the sample uncomparable with a named reason; so does a page write that is not alone on its transaction (`in_transaction_busy`), because the comparison's savepoint could otherwise roll back another call's statements. A pass of the swap's write check still covers page and link writes only: chunks, tags, aliases, timeline entries and takes are not compared.
- Limits: a sync import sends the contextual-retrieval option (on by default), which the Rust store does not take from this path yet, so on a default brain those samples are counted uncomparable (`unknown_option`); and a new page whose import adds tags comes out uncomparable as `moved`, because the tag write moves the page's revision; an update through `put_page` or a managed sync on Postgres is usually busy; and the warm single-write lane is not sampled at all.
