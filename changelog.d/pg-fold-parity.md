**A Postgres brain now folds claims, fence lines and repair checks the way PGLite and the Rust engine do, on every server locale.**

### Fixed
- Forgetting or purging a claim that holds a letter a glibc Postgres lowers but PGLite keeps (for example the circled capital letters, U+24B6 to U+24CF) no longer also hides its lower-case form on Postgres, and the other way round. The fact fingerprint, withdrawal discovery, and the page-read and export withdrawal overlays now use PGLite's case map (`src/core/pg-fold.ts`) instead of the server's `lower()`.
- `gbrain repair` counts of conversation label facts and of facts from purged pages no longer depend on the Postgres server's locale. A label line or a page slug that holds U+0085 (next line) or U+1680 (ogham space mark) now gets the same answer on Postgres, PGLite and the Rust engine. These checks use the explicit whitespace class (`FACT_SPACE_CLASS`) instead of `[[:space:]]`.
- Upgrading never brings a forgotten or purged claim back where the old record can only mean that claim. A withdrawal or purge row stored before the upgrade still matches through the earlier fingerprint when no other claim can share it (a claim with U+0085). Upgrading also adds a current-fingerprint row for withdrawals stored before v174 whose claim is still in a fact or a fence.

### Changed
- Migration v332 changes the fingerprint functions in place. `gbrain_fact_fingerprint_v1` and `gbrain_fact_fingerprint_v2` now answer NULL where the earlier fold made a claim equal to another spelling (U+1680, or a letter only glibc lowers), so a record of one spelling never reaches the other.
- v332 replaces each fact and take guard function in its own block. When another role owns one, the upgrade still finishes and prints one `guards:` line naming the function and the `ALTER FUNCTION ... OWNER TO` fix; the next migration run by a role that owns it installs the new body. `gbrain doctor` (`guard_ledger_checks`) now names such a guard too.
- Known limit: until that guard is replaced, a Postgres brain whose migrating role does not own `gbrain_refuse_purged_fact` stores a purged claim holding U+0085 again.
- Known limit: a withdrawal or purge that Postgres stored before the upgrade for such a claim, where the claim is in no fact and no fence, now matches only the spelling the earlier fold produced (for example the lower-case letter). A purge keeps only the hash of the claim, so the upgrade cannot add a current-fingerprint row for it.
- Tests: `test/pg-fold.test.ts` (every code point on both SQL engines, the Rust store's tables, and the fingerprint of letters only the server lowers), `test/engine-parity/fact-fingerprint-case.test.ts` (every engine arm), and new cases in `test/engine-parity/facts-repair.test.ts`. `test/engine-parity/fact-fingerprint-ambiguous.test.ts` now runs in the Postgres unit-arm lane. On the Rust arm the cases that seed ledgers with SQL stop on a typed refusal, as pinned in `test/engine-parity/rust-tally.tsv`.
