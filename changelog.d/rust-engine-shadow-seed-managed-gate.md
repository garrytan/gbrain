**`gbrain engine shadow seed` now refuses a brain that uses managed storage, before it creates anything.**

### Changed
- The Rust engine never holds managed storage, so a seed of such a brain copies data nothing can use. Brains made by a default `gbrain init` use managed storage and cannot be shadowed or swapped yet. `gbrain engine shadow seed` (and `seed --json`, which also prints the error on stdout) now refuses it with `engine_shadow_refused` (`managed_storage`, exit 3) and tells the agent to ask the user. It checks first: a refused seed creates no shadow directory, no Rust store and no `seed.json`, and never starts its snapshot.
- The refusal names the ways out that exist today: for a new brain, `gbrain init --db-only` creates one without managed storage; for an existing managed brain, `gbrain sources writer deactivate --dry-run` previews converting it back to classic mode, and the real deactivate needs the user's consent.
- A brain whose storage mode cannot be read, or that cannot be opened, is still refused (exit 3, `managed_storage`) instead of passing, but the message says "gbrain could not confirm that this brain does not use managed storage" and names the failure; only a mode read as managed says the brain uses managed storage. When another gbrain holds a PGLite brain (`pglite_busy`), the next step is to stop `gbrain serve`, run the command again, then restart serve.
