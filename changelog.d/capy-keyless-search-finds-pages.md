**Keyless search finds pages that hold most of the question's words.** On a brain with no embedding key, a question used to miss any page that lacked even one of its words whenever another page held all of them: "SSO Starter plan" found the pricing and decisions pages and never the call transcript that mentions SSO and Starter. Now, when the first page of results comes back shorter than the limit, search runs the same request once more with the keyword search allowed to match pages that hold only some of the words, and adds that run's new pages after the first run's rows. Every row the first run returned stays exactly where it was, with the same score. The added rows went through every check an ordinary row goes through (the caller's read policy, redirects, superseded-page warnings, and the evidence and injection checks when they are on), never repeat a page or a collapsed copy of one, score below the last row above them, carry `keyword_fill: true` (also in lean remote rows), and `--explain-target` says the page matched only some of the words. Later pages (an offset above zero) are unchanged. On LongMemEval S run keyless, recall_all@10 rose from 80.6% to 91.1% with no question ranking worse; the second run fired on 105 of 500 questions and added a median 35 ms (p95 51 ms) on PGLite. With the evidence or injection check on, the second run asks the provider about its rows too. Brains with embeddings are unchanged.

### Itemized changes

- `src/core/search/hybrid/any-word-fill.ts` (new): on the keyless path, a short first page runs the same request again with the any-word fill on in the keyword arm and appends that run's rows whose page, collapsed family or redirect target the first page does not hold, in that run's order, scored below the first page's last row, within the limit and the token budget.
- `src/core/search/hybrid.ts`, `src/core/search/hybrid/arms.ts`: the keyless path hands its rows to the fill; the second run sets `orFill` on the keyword arm's own options and changes nothing else.
- `src/core/search/keyword-identifier-probe.ts`: with `orFill`, a short set of all-words rows runs the any-word retry and returns its rows tagged `keyword_relaxed` and `keyword_fill`; a failed retry keeps the all-words rows and reports the keyword arm incomplete.
- `src/core/search/lean-rows.ts`: lean rows keep `keyword_fill`.
- `src/core/search/alias-fanout.ts`: a page the fill added moves up as the alias row when the alias search finds it.
- `src/core/search/explain-target.ts`: the fill shows as the `keyword_fill` arm, marked `relaxed`, and the reason says the page matched only some words.
- Tests: new `test/search/keyless-any-word-fill.test.ts` (PGLite and Postgres), including a property test that the rows with the fill on begin with exactly the rows returned with it off, and redirect and superseded-page cases; new `test/search/keyless-any-word-fill-gates.serial.test.ts` for the evidence gate, the injection detector and finite scores when the gate empties the first page; the C5 and evidence off-path goldens gain the appended rows only, and the export-surface golden gains the new fields.
