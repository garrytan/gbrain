**`gbrain lint` now finds dead and ambiguous links between your pages, and can print JSON and fail a CI run; an uploaded file is never overwritten by a different file with the same name; recalled facts say how solid they are; `gbrain inbox` turns dropped files into pages; `gbrain nav` writes index, log and hot pages; `gbrain filing` picks how each source files new pages; the product is now called Foresights.**

### Added
- `gbrain lint <dir>` reports `dead-link` (a link to a page that does not exist) and `ambiguous-link` (a bare `[[name]]` that matches more than one page, which the graph leaves unlinked), each with its file and line. A link counts as live when any resolution the link extractor tries finds a page, so a link the graph links is never reported. Links in code, attachments, web addresses, frontmatter fields and `[[source:slug]]` links into another source are out of scope, and pages skipped with `--exclude` still count as targets. `--no-links` turns the checks off; the scheduled cycle's lint phase does not run them.
- `gbrain lint --json` prints the whole report as one JSON document on stdout (progress stays on stderr), with every issue's rule, line and message and the run's counts.
- `gbrain lint --strict` exits 1 when any issue is left after the run, for CI.
- An attached file is never overwritten. When `gbrain files upload`, `gbrain files upload-raw` or the `file_upload` tool gets a different file under a name a page already uses, the first file keeps its bytes and its record, and the new one is stored beside it with the start of its content hash in front of the name (`notes/x/1a2b3c4d5e6f-contract.pdf`); `file_upload` says so in `kept_original`. The same bytes again are still a no-op, and a record whose bytes are gone from storage is still repaired in place.
- Every fact `recall` returns carries `claim_status` (`accepted`, `provisional`, `contested`, `unsupported` or `stale`) and a one-sentence `claim_status_reason`, worked out from the fact's own dates, source, trust tier and any pending dispute each time it is read. It never hides a fact or refuses a save. See [How solid each fact is](docs/guides/memory-trust.md#how-solid-each-fact-is).
- `gbrain inbox` wires up the drop folder (`~/.gbrain/inbox/`): `gbrain inbox` shows what is waiting, `gbrain inbox run --once` turns every waiting text, markdown, HTML or JSON file into an `inbox/` page and moves the original to `.archived/<date>/`, and `gbrain inbox run` keeps watching. PGLite brains write the page right away; Postgres brains queue it for the job worker. The same bytes apply once. A PDF, image, audio or video file stays in the inbox with a note to convert it to text first, and `--once` archives a file only after its capture landed. The inbox source now hashes a binary file's bytes, so the same file dedups wherever it lands.
- `gbrain nav` writes three Markdown files: `index.md` (every page by folder with a one-line summary), `log.md` (recent operations, newest first) and `hot.md` (what changed in the last 7 days, at most 500 words). Only the block between the `gbrain:nav` markers is rebuilt, so your notes in those files stay, and a file without the markers is never overwritten. Private and git-ignored pages are never named. They go to the source's folder, or to `~/.gbrain/nav/<source>/` when gbrain manages that folder. Sync now skips `hot.md` at a source's root (`notes/hot.md` is still a page). See [nav files](docs/guides/nav-files.md).
- `gbrain filing` chooses how a source files its NEW pages: `generic` (by type, in the schema pack's folder), `para` (projects, areas, resources, archives), `lyt` (atomic notes in `notes/`, maps of content in `maps/`) or `zettelkasten` (flat in `zettel/`, named by a time id that never changes). `gbrain filing set <mode>` stores it per source; `gbrain filing route <type> <title>` says where a new page goes, with the frontmatter that mode wants, and never suggests a slug the source already uses. Changing the mode never moves an existing page. See [filing modes](docs/guides/filing-modes.md).
- The product is now called Foresights and its command is `foresights`. The `gbrain` command still works and runs the same program, so nothing installed earlier needs editing. Every `GBRAIN_*` setting also answers to `FORESIGHTS_*` (a set `GBRAIN_*` wins). Names saved outside the program keep their spelling: the `~/.gbrain` folder, `GBRAIN_*` settings, markers in your notes, schema pack, plugin and skill names, and the `[gbrain notice ...]` lines agents read. Upgrades and install links now point at this project's repository. See [the Foresights name](docs/guides/foresights-name.md).

### Changed
- For contributors: CI runs on GitHub-hosted runners. Every job that asked for a Ubicloud runner (`ubicloud-standard-*`) now uses `ubuntu-latest`, and the arm64 lanes `ubuntu-24.04-arm`; `.github/actionlint.yaml` declares no custom labels. The bounded checkout-and-retry pairs stay.
- For contributors: the product's names (command, MCP server name, home folder, environment-variable prefix) now live in one module, `src/core/brand.ts`. The home folder and the MCP server name already read from it; nothing a user sees changes. A future rename keeps reading an existing install's `GBRAIN_*` variables.
