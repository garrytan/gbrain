**`gbrain setup claude-code --template team --members bob-example,carol-example` (or `codex`) sets up a small team on one brain in one command: a private folder and a key file for each person, a team group, and shared `company/` and `rules/team/` folders. It previews every step first and applies only with `--yes`.**

### Added
- `gbrain setup <harness> --template team --members <id,...> [--guests <kind>:<id>,...] [--team-group <id>] [--yes]` sets the brain up as a company brain, then adds each member with a `people/<member>/` folder only they read and one key in a 0600 file (never printed), the `team-members` group with the owner and the members, and `company/` plus `rules/team/` readable by the owner and that group. `--guests` also sets up the guest source for those writers. `gbrain access template team` runs the brain side on its own.
- The template never changes a group or folder rule it did not make, never removes a group member, and never makes a group that pages or rules already name as a reader: that line reads BLOCKED with the command that fixes it, and the template writes nothing. On an existing brain, setup runs this preview before it changes anything; when it refuses with `setup_team_blocked`, nothing was written, the harness entry included. When the preview cannot run first (a brain created in the same run, or one this connection's own running server holds), a BLOCKED line from the template leaves earlier setup writes in place.
- A brain that serves one person and holds notes no rule restricts needs `--labelled-only` (keep them from the members) or `--open-history` (let them read them) first, and so does a brain that already serves several people with no team receipt on this machine. The choice is kept, so a later run that adds people keeps it.
- `--template team` refuses `--shape both` and `--transcripts`: calls are imported after the team exists, so they are kept to their attendees (`gbrain import <dir> --calls --prefix company/calls --source company`).
- Each applied run writes a receipt with no key values; it names the brain it ran on. `--status` compares what each member's key reads in the team folders and their own folder, up to 100 pages per folder, against what the access rules expect, flags a key file holding someone else's key, and lists DRIFT when a team rule, a member's folder rule or the team group no longer matches what the template set up. A read that fails for a reason other than a denial, or a folder over 100 pages, makes that member's proof NOT ok rather than a pass. `--resume <receipt id> --yes` finishes a stopped run, including a folder rule left half-applied.
- New refusals: `setup_team_blocked` and `setup_team_unbound` (the brain would serve several people while this harness's connection, a plugin connection included, stays bound to nobody).
