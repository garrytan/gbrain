- On the Rust engine, `gbrain recall` and the `recall` operation now refuse by name when they cannot read slot ends, instead of quietly skipping them and showing a value a later fact ended (an old employer, city or role) as current. The refusal names `listSlotRows`, which the Rust engine does not serve yet. Readers that already treat a failed fact read as best effort keep doing so there: entity saved facts show no facts, hot memory adds no payload to the reply, and question recall reports its ranking as unavailable. PGLite and Postgres answer as before; a database error during the slot read still leaves the facts as stored.
