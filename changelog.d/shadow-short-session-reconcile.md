**Shadow mode now reaches and keeps a valid coverage watermark when the brain is only used through short serve sessions, such as MCP stdio sessions that last 10 to 20 seconds.**

### Fixed
- Every session that owned the shadow store started with an invalid watermark, and the full reconcile pass that proves it again ran only a minute after start, so a session shorter than that never ended valid and the swap check's clean-reconcile count never grew. A session that closed during a pass also recorded a failed pass, which reset that count.
- The first reconcile check now runs 5 seconds after a serving process starts. A full pass saves its progress after every interval; a session that closes during a pass records no pass, and the next session with the same continuity, seed and evidence epoch finishes it. A stopped pass that already repaired rows is recorded at once as a stopped full pass, so the repair stays on record when the next pass starts fresh, and it makes the next full pass due (status shows it as due at once). If that record cannot be written, the saved progress keeps the repair: status and writer coverage count it, and the next pass records it before discarding the progress, or fails with `pending_repair_unrecorded`. Otherwise only a finished full pass is recorded, and only a clean one counts.
- A serving process that closes with everything handed over and applied seals the follower. The next session carries the watermark on only when the follower files are unchanged and, on Postgres, the database's own write counters show nothing written since (see the seal change token entry). Any doubt, read failure or timeout leaves the watermark invalid until a full pass, as before. PGLite never carries a seal over (`pglite_no_db_continuity`): nothing there proves that no other process wrote between two sessions.
- The seal cannot outlive what it covers: any event after it removes it from disk first; taking it over removes it in the same write that shows the watermark invalid; a write made by a later shutdown callback, after the shadow child stopped, is still recorded as lost; a lost-write record that cannot be written is retried and keeps the close from sealing (`lost_write_unrecorded`); a start that refuses a seal never empties the invalidation file while that seal may still be on disk. A confirmation that was sent but not acknowledged is withdrawn (`seal_confirm_unacknowledged`), every withdrawal leaves a line the child reads on its own and is sent again until acknowledged, and a confirmation still in doubt (no withdrawal acknowledged) makes the first check withdraw it again and run a fresh full pass, never a resumed one. A close does not seal while the confirmation is still running (`seal_confirm_pending`). Each seal decision and its reason is shown by `engine shadow status` (`seal: <outcome> (<reason>)`).
- Eight named persistence-journal members (`declarePersistence` and the journal's counter, completion, effect and lock members) no longer invalidate the whole watermark: they publish the tables their statements write. `onCheckout`, a pool listener that sends no statement, is ignored. Every other member the write map does not cover still invalidates it.

### Changed
- Swap readiness criterion 1 now also needs the newest clean full reconcile pass to have finished under 24 hours ago. Three clean passes followed by days without one no longer read as ready. A carried seal or a half-done pass is never such a pass. The rule is applied by the readiness check itself: the readiness policy, its hash and the shadow evidence epoch are unchanged. `engine shadow status --json` shows the time as `reconcile.last_clean_full_pass_at`; a status from an older build without it reads as missing evidence.
