**On a Postgres brain whose database locale is not C, page lists, writer and persistence admin lists and doctor findings now come back in byte order, the same order PGLite and the Rust store use; and on an experimental Rust brain, a Wakeshift forget queued for a member's user now waits while that member still exists.**

### Fixed
- Postgres sorted text keys (slugs, source ids, client ids, paths, fingerprints) by the database locale, so on an en_US database `a.b, a_b, ab, a-z, B` came back in that order while PGLite and the Rust store returned `B, a-z, a.b, a_b, ab`. The engine-sql reads, the persistence admin and diagnostic lists and the doctor checks now sort those keys with `COLLATE "C"`, so every engine and every locale returns the same order. Paging cursors compare with the same collation as their sort, so a page walk on an en_US database neither skips nor repeats rows. Row-lock orders (`ORDER BY id FOR UPDATE` on sources and the topology locks) stay as they were; writer activation sorts its source list by byte after the locked read.
- Migration v338 builds two byte-order slug indexes, online on Postgres: `idx_pages_source_slug_c` on `pages (source_id, slug COLLATE "C")` and `persistence_requests_source_slug_c` on `persistence_requests (source_id, slug COLLATE "C")`. Without them the byte-order sort made Postgres read and sort the whole table: on 200,000 pages, `gbrain list --sort slug` with a cursor took 17.0 ms, against 0.1 ms with the index and 0.1 ms before the byte-order sort, and the canonical-source reconcile walk took 19.4 ms, against 0.2 ms and 0.3 ms. The drift-conflict audit page now groups by the same byte-order slug it sorts by; its rows do not change.
- The fact dedup lookup, the takes vector search and the semantic query cache lookup again let Postgres use their HNSW vector index. A second sort key (`ORDER BY distance, id`) made Postgres read and sort every row instead; now the inner query sorts by distance alone and an outer sort breaks distance ties by id inside the returned rows. The query cache lookup gains that id tie-break for the first time. Which rows tie at the cut-off stays approximate, as with any nearest-neighbour index.
- One read is still slower on a large Postgres brain: the full page list behind import (every page, sorted by source and slug) sorts its rows instead of reading an index, 248 ms against 75 ms before on 200,000 pages. The results are the same rows.
- `queueWakeForget` with a member id on a Rust brain reads the access member in the same write: it queues only when no member with exactly that id is still there (a disabled member counts, a removed one does not). A member id with a NUL byte is refused. PGLite and Postgres send the same SQL as before.
