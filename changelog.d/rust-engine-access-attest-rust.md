**On the Rust engine, `gbrain auth rescope --client <id> --attest-sources` lists scope sources for an OAuth client, as on PGLite and Postgres.**

### Fixed
- On a brain with the Rust engine, `gbrain auth rescope --client <id> --attest-sources <list>` checks the list and marks each new scope source, and re-marks a listed source that lost its mark, with the same refusals as PGLite (the credential still reads a dropped source, holds the private-pages or private-facts grant, or the source is default, federated, archived, missing, the credential's own write source, or already readable by another credential), and `--dry-run` checks without writing. On Rust, these checks run where the caller passes the engine (bindCredential --attest-sources and the read check when a key is minted); the --token and OAuth-client grant commands stay behind rows 32k and 32d-2. Before, they stopped with an engine error and wrote nothing.
- `gbrain auth rescope --token <name>` and `gbrain auth rescope <name>` (a legacy token) still stop with an engine error on the Rust engine, before anything is written; that follows with the OAuth and token work in row 32k.
