**A member with the labelled-only grant can create and capture pages on a Rust brain, and a write over a deleted page is refused the way it is on PGLite and Postgres.**

### Fixed
- On a Rust brain, a labelled-only member's remote create or capture used to stop with `engine_capability_missing`. The labelled-only create check now agrees with PGLite and Postgres: it passes when the page names the member (or a group it is in), or a folder or page rule over the slug lists the member. The write still has to pass the other source, access and revision checks. When this check runs on a page that names nobody and has no covering rule listing the member, it returns `access_labelled_only_unnamed`, with the same error body and nothing written.
- On a Rust brain, an ordinary member's write over a page whose only row is soft-deleted and whose reader list or covering rules make it unreadable to that member, was refused with `engine_capability_missing`. It is now refused as an unseen page (`page_not_found`), as on PGLite and Postgres.
- Two raw statements of the remote write check became typed reads. On PGLite and Postgres the create check now reads the folder rules that cover the slug (`readSlugFolderRules`) and judges the overlap itself instead of asking the database to compute the overlap, with the same answers; the deleted-row check sends the same statement as before.
