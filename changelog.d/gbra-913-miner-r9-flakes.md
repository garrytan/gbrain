**The shard-timing miner picks runs by whether their test jobs passed, the PostgreSQL-arm shards are rebalanced from measured times, tonight's unit and E2E weight refresh is in, and two tests that failed at random on busy runners are fixed at the cause.**

### Fixed
- `bun run weights:mine --latest N` now takes the newest master runs whose jobs for that lane all passed, whatever the rest of the run concluded. Before, it listed only runs whose whole workflow succeeded, so a nightly that turned red on a later check (the weight-coverage check itself, or the race hunt) was skipped even though its unit and serial jobs had recorded every timing. It now also reads past runs that skipped the lane (a master push that reused an earlier full run) up to 500 runs back, and skips a run that ran the lane only in part instead of stopping.
- A coverage-only refresh of a map last written from one full E2E run says it merged files in and keeps that run's hashes under `baseline`, so the metadata no longer claims the merged map came from that run alone.
- The weight-coverage warning for the unit lane says the coverage-only command only adds missing files, and names the full refresh to run after a large test wave or when a shard runs 25% past the mean.
- `test/large-pages/remember-cost.test.ts` failed at random on loaded runners when a `remember` reply came back before its write committed. The shared test helper meant to send the same request again until the write settled, but it looked for the wrong field in the reply, so it never did. It now replays such a reply with the same request id, and a new test forces a reply before the write runs and checks the fact is saved once.
- The Hermes hook test that feeds a 5 MB conversation history failed at random on busy runners (51.8 ms against a 50 ms bound). It compared two wall-clock turn times, which a loaded machine stretches by however long the process waits for a CPU. It now compares the hook process's CPU time, under the same 50 ms bound, so a reader that buffers or rescans the history still fails it.

### Changed
- `scripts/postgres-arm-weights.json` is re-mined from the per-file timings of the four newest 32-shard master Test runs, each file's median. 132 listed files had no weight and were packed at the 75th-percentile estimate, and on measured times the old packing put one shard at 579 s, over the 570 s budget. The new weights cover all 968 listed files and bring the largest shard to 441 s.
- Unit and E2E shard weights are refreshed from tonight's runs (35 new unit files, and a full E2E refresh from the nightly), keeping each lane's unweighted share under half a percent.
