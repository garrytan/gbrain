**Re-adopting a shared-skill pack after you accept a reviewed `SKILL.md` edit no longer deletes a skill's other files from your checkout or makes a private skill visible; it now refuses that skill by name and changes nothing.**

### Fixed
- When the v0.53.0 shared-content migration re-adopted a pack after a reviewed inventory edit, it republished each skill from its `SKILL.md` alone. A skill's reference, asset or script files were deleted from the content checkout, a skill published with `private: true` became visible to readers, and requirements, a description or triggers set through `put_skill` were dropped. Adoption now refuses such a skill by name (`local_conflict`): it writes nothing and deletes nothing, and it points to `import_skill_proposal`, which publishes the reviewed change with the skill's full file set. New skills and prose-only skills adopt as before.
- Adoption publishes only the bytes whose hashes you reviewed. A `SKILL.md` or `skillpack.json` changed between the review and the publication is refused.
