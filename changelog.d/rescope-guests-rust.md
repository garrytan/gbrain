**On a Rust-engine brain, `gbrain auth rescope <name>` and `gbrain guests grant-owner-clients` now work.**

### Fixed
- `gbrain auth rescope <name> ...` with a bare name (a token name, an OAuth client id or a client name) stopped on a Rust brain with "does not support executeRaw yet", so `--attest-sources`, `--member` and the grant flags only worked with `--token` or `--client`. The bare name now works on Rust and answers as on PGLite and Postgres. A token alone and a client alone are found, a name that matches both is refused (you pass `--token` or `--client`), and a name nobody has is refused. `gbrain auth rescope --migrate-legacy` also works on Rust (a test now proves it).
- `gbrain guests grant-owner-clients` and the doctor `guest_source` check read the owner's credentials without raw SQL, so they work on Rust. The credentials still list in the same byte order (an upper-case name before a lower-case one, a non-ASCII letter last). PGLite and Postgres now read the token row once into memory to do this, and drop its hash at once; nothing prints or stores it.
- Still not working on Rust (named loss 32m-2): `gbrain agent register --preset coding-agent` into a `<name>-workspace` source that already exists stops with `engine_capability_missing` and writes nothing, because the check that the source is empty counts its pages, facts and files with raw SQL. Workaround: pick another agent name, or pass `--source <id>`. PGLite and Postgres are unchanged.
