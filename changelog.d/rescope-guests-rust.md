**On a Rust-engine brain, `gbrain auth rescope <name>` now works.**

### Fixed
- `gbrain auth rescope <name> ...` with a bare name (a token name, an OAuth client id or a client name) stopped on a Rust brain with "does not support executeRaw yet", so `--attest-sources`, `--member` and the grant flags only worked with `--token` or `--client`. The bare name now works on Rust and answers as on PGLite and Postgres. A token alone and a client alone are found, a name that matches both is refused (you pass `--token` or `--client`), and a name nobody has is refused. The lookup reads only a token's id and name, so it also works on a brain that has not yet run migration v282 (no `access_tokens.member_id`). `gbrain auth rescope --migrate-legacy` also works on Rust (a test now proves it).
- `gbrain guests grant-owner-clients` answers on a Rust brain as on PGLite and Postgres: `rust-engine/main` checks the guest source through a typed read that a Rust brain serves, so a source that is not a guest source prints "not a guest source", exits 2 and changes nothing on every engine. A test pins it on every engine. The owner's credential listing was made Rust-capable by `rust-engine/main` (commit 685d02ee18, the typed `listOwnerCredentialRows`); this branch adds a test that pins it on every engine: clients and tokens list together in byte order (an upper-case name before a lower-case one, a non-ASCII letter last) and no token hash or client secret appears. The doctor `guest_source` check reports a missing guest-source row for a config-marked guest source on Rust: `listGuestSourceRows` returns `writers: null`, so the check returns before the raw-SQL per-writer credential reads.
- Still not working on Rust (named loss 32m-2): `gbrain agent register --preset coding-agent` into an existing `<name>-workspace` source stops with an `engine_capability_missing` raw-SQL refusal and writes nothing. The pin reaches the first raw page count in `ensureWorkspaceSource`; source validation is typed and Rust skips the advisory lock. Choosing a name whose derived workspace source does not exist, or passing `--source <id>` to reuse an existing source explicitly, avoids this loss. PGLite and Postgres are unchanged.
