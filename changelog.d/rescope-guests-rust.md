**On a Rust-engine brain, `gbrain auth rescope <name>` now works.**

### Fixed
- `gbrain auth rescope <name> ...` with a bare name (a token name, an OAuth client id or a client name) stopped on a Rust brain with "does not support executeRaw yet", so `--attest-sources`, `--member` and the grant flags only worked with `--token` or `--client`. The bare name now works on Rust and answers as on PGLite and Postgres. A token alone and a client alone are found, a name that matches both is refused (you pass `--token` or `--client`), and a name nobody has is refused. The lookup reads only a token's id and name, so it also works on a brain that has not yet run migration v282 (no `access_tokens.member_id`). `gbrain auth rescope --migrate-legacy` also works on Rust (a test now proves it).
- `gbrain guests grant-owner-clients` still stops on a Rust brain, because it checks that the source is a guest source with raw SQL, so it refuses with `engine_capability_missing` before it lists or changes anything. It does not say "not a guest source" for a real guest source. PGLite and Postgres are unchanged. A test pins the refusal. The owner's credential listing was made Rust-capable by `rust-engine/main` (commit 685d02ee18, the typed `listOwnerCredentialRows`); this branch adds a test that pins it on every engine: clients and tokens list together in byte order (an upper-case name before a lower-case one, a non-ASCII letter last) and no token hash or client secret appears. The doctor `guest_source` check's per-writer verdicts still read a credential through raw SQL, so with a writer registered it still stops on Rust.
- Still not working on Rust (named loss 32m-2): `gbrain agent register --preset coding-agent` into a `<name>-workspace` source that already exists stops with `engine_capability_missing` and writes nothing, because the check that the source is empty counts its pages, facts and files with raw SQL. Workaround: pick another agent name, or pass `--source <id>`. PGLite and Postgres are unchanged.
