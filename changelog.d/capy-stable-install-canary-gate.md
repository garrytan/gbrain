**Stable releases now wait until the install canary has installed each release into the supported agent harnesses and passed it.**

### Changed
- The daily stable check promotes a release only after the install canary has posted a pass for that exact tag (a `gbrain/install-canary` commit status). A release the canary failed, or has not tested yet (no status, or a newest status still `pending`), is skipped, and an older release that passed is promoted instead. Only when no older release qualifies does the check wait and name the release that is not tested yet. It dispatches and pushes nothing while it waits, and raises a warning once stable is past the weekly floor. When the newest release has no soak yet, the soak is dispatched as usual. When the only candidate failed the canary, stable holds and a warning goes up.
- A manual `promote-stable` run refuses a release the canary failed or has not tested yet unless a maintainer gives the new `canary_waiver` input. The stable record keeps the waiver as `install_canary: waived: <reason>`. A scheduled run never takes a waiver. A rollback to an older release, or back to a release that was stable before, is not checked.
- Only statuses posted by an account on the `STABLE_CANARY_POSTERS` repository variable count. The variable is a comma-separated list and defaults to the Capy GitHub App's bot. The status must also name the tag being promoted. If the statuses can't be read, both workflows refuse. `stable.json` and the stable tag now record `install_canary`.
