**On the Rust engine, `gbrain recall` with a trust policy now answers, and remote timeline, chronicle, tag, take, raw-data, version, wanted-page, chunk, anomaly and expert reads no longer stop on read options they did not support.**

### Fixed
- On the Rust engine, `gbrain recall` and the MCP `recall` tool now apply a read trust policy to the fact list: a fact below the trust floor, a flagged agent-written fact and a fact from a quarantined page are left out, the same as on PGLite and Postgres. Before, they stopped on a missing-capability refusal.
- On the Rust engine, the timeline and chronicle reads behind the MCP `get_timeline`, `chronicle_day`, `chronicle_since`, `chronicle_on_this_day` and `chronicle_last_seen` tools accept the extra read options a remote caller sends and answer as PGLite and Postgres do. Before, they stopped on those options, which the reads do not use.
- On the Rust engine, the tag and take reads behind the MCP `get_tags`, `takes_list`, `takes_search`, `takes_scorecard` and `takes_calibration` tools now apply the private-page policy, including a caller's reader identity and private-readable grant. A tag or take of a page the caller cannot read is left out, the same as on PGLite and Postgres. The scorecard and calibration reads also accept the copy of the holder allow-list that a remote caller sends.
- On the Rust engine, the raw-data, version and wanted-page reads behind the MCP `get_raw_data`, `get_versions` and `wanted_pages` tools now apply the private-page policy, including a caller's reader identity and private-readable grant. Raw data and versions of a page the caller cannot read are left out. A version whose own saved fields were private, reader-restricted or a pinned question is left out too, the same as on PGLite and Postgres. A wanted page that only a hidden page asks for is left out, and a hidden page does not count as an existing match. Before, these reads stopped on a missing-capability refusal.
- On the Rust engine, the MCP `get_chunks`, `find_anomalies`, `get_raw_data` and `get_versions` tools accept the rest of the read policy a remote caller sends (the holder allow-list and the safe-chunk flag). `gbrain whoknows` no longer stops on its own options (the topic, the explain flag, the result limit) when it reads salience and page dates. None of these reads uses those options, and the answers match PGLite and Postgres.
- A brain that enforces member read rules still refuses these remote reads on the Rust engine. That refusal is a separate gap.
