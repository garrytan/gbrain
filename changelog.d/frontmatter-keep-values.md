**Frontmatter values are kept exactly as you wrote them: dates, timezone offsets, zip codes like 02134 and versions like 1.10 no longer change when a page is stored, read, exported or edited.**

### Fixed
- Dates in frontmatter stay the text written instead of a UTC timestamp, timestamps keep their offset, and numbers whose text does not print back the same (02134, 1.10, 1.0) stay as written. get, export and write-back files show them as written, and a one-word body edit no longer rewrites them in your Git file. API and MCP callers now get values such as 1.0, 0.80 and 10.50 as the strings "1.0", "0.80" and "10.50"; convert them with Number(value) or float(value) where you need a number. Files gbrain writes quote such values (zip: '02134'), so every YAML reader gets the same text. A valid_from or valid_until written as midnight UTC in any YAML timestamp form counts as its date. Pages stored by an earlier release get their written values back on the next sync or the first write, once per page, with no paid calls for pages whose meaning did not change. Before that, an older page still takes an edit: editing one nested value keeps the written text of the values beside it, and a page with an id like 007, a title like 1.10 or a value like .inf is no longer refused.
