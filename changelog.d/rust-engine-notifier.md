**On an experimental Rust brain, a serve or worker now starts the commit notifier: it claims the host lease, lists the brain's sources and records each source's state and coverage. Search on a Rust brain now says whether each source is current, behind or not watched, and the notifier records, reads and clears its wanted markers (what a source should reach) instead of refusing them. `gbrain sync trigger`, the push webhook and a sync that finds the lock busy now record their marker there, a sync keeps the commit it reached, and a sync can take the drain lease. PGLite and Postgres brains send the same SQL as before.**

### Changed
- The notifier's host lease and its source list are typed engine calls: `claimNotifierLease`, `readNotifierLease`, `holdsNotifierLease` (the check before each start), `releaseNotifierLease` (a clean stop) and `listNotifierHostSourceRows`. Postgres and PGLite send the same SQL text as before, byte for byte, from `src/core/engine-sql/notifier.ts`.
- On a Rust brain the lease is one record per host, with the same fence rules as Postgres: the first claim wins, a renewal keeps the fence, and a takeover after expiry bumps it. A release expires only the caller's own lease. Each lease change is one store write. A host id with a NUL byte is refused.
- The notifier's per-source rows are typed engine calls too: `readNotifierSources`, `writeNotifierState`, `writeNotifierCoverage` and `recordNotifierSyncerHost`, and the freshness reads `readNotifierStatusRows` and `hasNotifierCoverage`. Postgres and PGLite send the same SQL text as before.
- On a Rust brain each source's notifier row is one record, with the same keep and clear rules as Postgres, and a source delete removes it. With `sync.on_commit` on, or once a resident has recorded coverage, search carries the freshness notice. A source whose observed head matches the commit its last sync reached reads current.
- The notifier's wanted markers are typed engine calls: `upsertWantedMarker`, `attachWantedMarkerJob`, `readWantedMarkers`, `readDueWantedMarkers`, `pruneSatisfiedWantedMarkers`, `clearWantedMarker`, `settleFreshnessMarker` and `listSourceWantedMarkers`. Postgres and PGLite send the same SQL text as before.
- On a Rust brain each marker is one record per source and intent, with the same generation, first-due and job rules as Postgres, and a source delete removes them. A freshness marker that names the commit the source's last sync reached is not due, and a finished sync prunes it.
- A sync request reads its source's shape through one typed call, `readSourceSyncShape`, so `gbrain sync trigger`, the push webhook and a sync that finds the lock busy record their wanted marker on a Rust brain. A Rust brain has no worktree binding, so the source reads unbound.
- The oldest unsynced commit read (doctor `managed_sync_latency` and the source lag) is one typed call, `readNotifierFirstDue`, and answers on a Rust brain.
- A sync advances its source's commit through one typed call, `advanceSourceCommit`. On a Rust brain the source record keeps `last_commit` and the newest content time in one write, and the notifier rows, the due-marker read, prune and settle compare markers with it.
- The resident notifier's reads are typed calls: `readLiveJobIds` (which marker jobs are still live), `readSourceLastCommit` (the commit a run reached) and, for whether a drain holds the source, `readDrainLeaseBeacon` and `readDrainHolderProgress`. The drain lease's holder record is typed too: `writeDrainLeaseHolder`, `refreshDrainLeaseHolder` and `releaseDrainLeaseHolder`. On a Rust brain a sync takes the drain lease, the notifier sees its holder's kind and id, and the holder record is one store write per change. A Rust brain keeps no managed commit journal, so a holder's progress reads zero commits there.
- On a Rust brain with waiting jobs and no worker, the readiness fix now says the job supervisor keeps a worker running "for this brain", not "for this Postgres brain". PGLite and Postgres text is unchanged.

### Added
- Caller tests on all three engines for the backup coverage check and the readiness worker and sync probes, and one that pins the worker fix text on each engine.
- Parity cases on all three engines for the sync request's source shape, the first-due read, the last commit advance and the resident notifier's reads and drain lease.
