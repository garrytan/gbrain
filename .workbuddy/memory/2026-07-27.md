## 向量化模型被重置风险分析（代码审查）

用户问：老用户已配置的向量化模型是否还有被自动"重置"的风险。

结论：**已配置 embedding_model 的老用户不会被自动重置**。逐路径核查：

- `gbrain upgrade`（src/commands/upgrade.ts runPostUpgrade）只跑 apply-migrations + initSchema + chunker-bump reindex，**不触碰 embedding_model**，不调用 ze-switch。
- ZE 切换（retrieval-upgrade-planner/ze-switch）仅由显式 `gbrain ze-switch` 触发，交互式且默认=保留（Enter）。desktop/src、admin/src 均无自动调用。
- doctor 仅做诊断（embedding_width_consistency），不写 config。
- gateway 运行时用 `config.embedding_model ?? DEFAULT`（zeroentropyai:zembed-1/1280），缺省才回退，不写回。
- initSchema 用 gateway 值做 schema 兜底，不写 config。

残留风险（非预期触发）：
1. 环境变量 `GBRAIN_EMBEDDING_MODEL`/`GBRAIN_EMBEDDING_DIMENSIONS` 优先级最高，静默覆盖文件+DB 配置——历史 716K 事故（PR #1421）根因。现已在 ze-switch 前置检测 env override 并拒绝 apply，但普通 embed 仍会被静默覆盖。
2. `gbrain config set embedding_model <与当前相同>` 会 unsetConfig 回退到默认值；若默认维度与实际不符，下次对齐会清空向量。
3. 读回退默认值不一致：gateway.ts 用 ZE 1280，planRetrievalUpgrade 用 openai 1536（仅当 config 缺失时显现）。
4. `gbrain ze-switch --force/--non-interactive` 会绕过交互直接切换，勿放进自动更新脚本。
5. 仅手工改 config 切到同维度不同模型而不跑对齐，会出现"混合向量空间"，需靠 alignEmbeddingDimension(targetModel) 触发失效。

参考：PMBrain 知识库 original note "Embedding 模型切换时的向量失效模式"（2026-07-16）。

## 向量化模型链路 Code Review（续）—— 实测 bug 清单
详见 `.workbuddy/memory/review-embedding-2026-07-27.md`。实测确认的真实 bug：
- 🔴 BUG A：`planRetrievalUpgrade`（retrieval-upgrade-planner.ts:247-250）只读 DB plane 的 embedding_model（getConfig 不读 file plane），且回退写死 openai:1536；真实默认是 ZE 1280（defaults.ts:20-21）。已 ZE 化的新脑被误判为 legacy 并错误估算 re-embed 成本。
- 🔴 BUG B：`switchEmbeddingModel`（config.ts:52-58）同值时 unsetConfig 且不跑对齐就 return，重设当前模型会回退默认并可能在下次 embed 维度不匹配报错。
- 🔴 BUG C：普通 `gbrain embed` 仍经 `loadConfig`（config.ts:381-382）静默套用 env 覆盖，detectEnvOverride 只在 ze-switch 拦截——716K 事故同源路径仍开着。
- 🟡 BUG D：doctor 只查 GBRAIN_* 不查 PMBRAIN_*（doctor.ts:2218-2219），envCompat 两者都接受 → 监控盲区。
- 🟡 BUG E/F：detectEnvOverride 仅比对 target；alignDerivedEmbeddingStores 把 facts/query_cache 重建到文本 targetDim，需核实 facts 是否独立定维。
- 佐证：init 只用 saveConfig（file plane），从不 engine.setConfig('embedding_model')，证实模型权威值在 file plane，DB plane 常空 → 放大 BUG A。
