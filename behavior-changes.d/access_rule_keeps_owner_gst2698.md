gbrain access rule add now refuses a reader list that leaves out the brain owner when one is set (gbrain access owner), the same refusal gbrain repair visibility --readers already gives (readers_omit_owner), because such a rule closes the folder or page to the owner's own keys. Add the owner to --readers, or pass --allow-without-owner when the owner should not read it. A group that holds the owner does not count. Rules already in place are not changed, and a brain with no owner set behaves as before.
