gbrain doctor no longer creates an empty brain when your brain's folder is missing. When the config names a PGLite datastore that is not there (an unmounted drive or a moved folder), every doctor run that opens the database (plain, --json, --only connection and the other database checks, --remediation-plan, --remediate) now stops before it connects, exits 1 and prints the brain_missing error with reason missing_brain, the same reason gbrain serve gives. Before, doctor built a new empty brain at that path and reported it healthy with a score of 100. A failed check now says it could not read the brain instead of answering that the brain is empty. Mount the drive, move the folder back, or update database_path; gbrain init makes a new empty brain only when you choose to. doctor --fast and file-only checks never open the database and run as before. The same holds when the folder still has a leftover `.gbrain-lock` whose metadata is unreadable, and when the folder is moved or unmounted while doctor waits for the datastore's lock: doctor looks again once it holds the lock, refuses, releases it and creates nothing. With `--alert` (and `--alert --json`) the refusal is the alert contract: exit 17, `alert.level` `act`, and an `alert.items` entry with code `brain_missing` and the same ask-the-user fix, so a monitor pages on it instead of seeing a bare exit 1.
