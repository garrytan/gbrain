The mention pass (gbrain extract --stale, the cycle's extract phase) now always says why it stopped and no longer gets stuck on a large source. A throw or an abort in the alias refresh, the name-list save or the reconcile now records state failed with the step and the error on the source's mention index status; before, the status kept saying pending with no error, so a pass that died every run looked like a slow one. The scan for pages naming a newly added name now has half the time left in the run. When it stops early, the name list is still saved and the pages it did not reach are marked for the reconcile, which works through them in batches across runs; before, that scan had no time limit, so on a large source it could use up every run and nothing drained. A pass with no time left does not start that scan, and a source whose changed name list it left unsaved stays pending with its last pass time unchanged, instead of reading complete. Nothing to do; a source stuck pending since an earlier release starts draining on the next runs.
