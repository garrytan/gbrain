Slug reads now normalize a slug the way writes do: lowercase, with accented letters composed (Unicode NFC). Writes already lowercased slugs, but reads did not, so gbrain get People/Alice-Example answered page not found for the page stored as people/alice-example. Every command and tool that takes a slug now reads it in the stored form, so a capitalised slug, or an accented slug copied in decomposed form (as macOS file names are), finds the page. A put with the decomposed spelling of an existing accented slug no longer creates a second page that prints the same name. A put by the exact decomposed spelling of a page stored that way before this release is now refused (`invalid_params`, detail `legacy_slug_spelling`), with or without `expected_revision`: nothing changes and no second page is created, until a later fix moves such pages to the composed slug. A decomposed body link now links the existing page instead of being listed as a wanted page, and a fact saved for an accented entity before its page exists keeps the accented slug. Pages stored in decomposed form before this release still open, and keep their tags and timeline, with the spelling gbrain list prints; deleting, tagging, untagging, adding a timeline entry to, editing or appending to such a page by that spelling is refused the same way (`legacy_slug_spelling`) and changes nothing, and a managed import that would write a composed twin of it stops with an error that says how to fix it. When a brain stores two pages under spellings of one slug (for example `notes/café` composed and decomposed) and a read names neither exactly, the read is refused (`invalid_params`, detail `ambiguous_slug`) with a message naming both stored spellings; sending either exact spelling reads that page. Facts saved under an accent-folded slug before this release still show on recall and the card.
