Slug reads now normalize a slug the way writes do: lowercase, with accented letters composed (Unicode NFC). A read keeps the page the old read found, then tries the normalized spelling, so gbrain get People/Alice-Example finds people/alice-example and a decomposed accented slug (as macOS file names are) finds its page. A put with the decomposed spelling of an existing accented slug no longer creates a second page that prints the same name; a put by the exact capitalised or decomposed spelling of a page stored that way before this release is refused (`invalid_params`, detail `legacy_slug_spelling`), even when its composed twin exists, until a later fix moves it. Pages stored under capitals or decomposed form still open by that exact spelling, and deleting, restoring, tagging, untagging, adding a timeline entry to, editing or appending to one by that spelling changes that page in place; a file upload, an ontology fact or `gbrain takes horizon set|clear` by that spelling acts on that page too. For a page stored with capitals, those writes by its exact spelling answered page not found before; they now change that page, and no lowercase second page is written. A slug prefix reads every spelling that holds pages, so no stored page hides. A managed import that would write a composed twin of such a page stops with a message saying how to fix it. A read of the normal form that finds nothing now opens the one other stored spelling, honouring alias, source and include_deleted. Only when no page is found that way and two readable stored pages normalize to the slug is the read refused (`invalid_params`, detail `ambiguous_slug`), naming the first two spellings; before, that read answered page not found. remember through an entity alias writes to the page in place. Facts saved under an accent-folded slug before this release still show on recall and the card.
