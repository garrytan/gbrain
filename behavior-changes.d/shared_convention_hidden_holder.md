Shared skills: a file under skills/conventions/ that only skills hidden from readers hold, because their SKILL.md audience is narrower or they are private, can no longer be published to more callers through another skill, including through a public skill that a rewrite of a shared file gives it to. import_skill_proposal and put_skill now refuse with local_conflict and write nothing. Before, the other skill published the file to its own wider audience. Give the file an audience no wider than the hidden skill gives it, or fork it under the publishing skill's own directory and point depends_on there, then submit again with a new request_id. A file that another skill already shows to readers still publishes. A publication in which a skill that holds the file narrows its own SKILL.md audience, while another skill in the same publication would show the file to the callers it stops showing it to, now also refuses; before, it published. Keep the holder's audience, or fork the file. The refusal's reason is shared_file_holder_narrowed for that case and shared_file_hidden_holder otherwise; the code stays local_conflict, and a refused queued publication keeps the reason in the waiter's answer and in a replay.
