Rust engine shadow mode: a brain used only through short serve sessions (for example MCP stdio sessions of 10 to 20 seconds) now reaches a valid coverage watermark and keeps it from one session to the next. A full reconcile pass is checked for 5 seconds after a serving process starts instead of a minute; a session that closes during a pass no longer records a failed pass, and the next session finishes it (a stopped pass that already repaired rows is recorded at once as a stopped pass, so the repair is kept and the next full pass is due; if that record cannot be written, the saved progress keeps it and it still counts until a later pass records it). A serving process that closes cleanly seals the follower at its verified point (the counters read before a full pass that restored the watermark, or a carried seal it committed). It does not seal when the counters moved since, its own writes included (`writes_since_verified`), or when no full pass restored the watermark and no carried seal was committed (`no_verified_mark`), so a brain served only by short writing sessions reaches valid only after a session completes a full pass. Otherwise the next session trusts the seal only after the seal's own file checks pass and the Postgres primary's write counters show nothing written since it; otherwise a full pass runs as before. PGLite never carries a seal over (`pglite_no_db_continuity`), so every PGLite session needs its own full pass. The seal is removed before any later event and when it is taken over, a write during shutdown after the shadow child stopped is still recorded, and a lost-write record that cannot be written keeps the close from sealing, as does a seal confirmation still running at close (`seal_confirm_pending`). Status names every seal decision and its reason. Readiness still counts only finished clean full passes. Swap readiness criterion 1 now also needs the newest clean full pass to have finished under 24 hours ago (`reconcile.last_clean_full_pass_at`); the readiness policy and its hash are unchanged.
