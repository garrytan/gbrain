Rust engine shadow mode: a brain used only through short serve sessions (for example MCP stdio sessions of 10 to 20 seconds) now reaches a valid coverage watermark and keeps it from one session to the next. A full reconcile pass is checked for 5 seconds after a serving process starts instead of a minute; a session that closes during a pass no longer records a failed pass, and the next session finishes it. A serving process that closes cleanly seals the follower, and the next session trusts the seal only after the seal's own file checks pass and the Postgres primary's write counters show nothing written since it; otherwise a full pass runs as before. PGLite never carries a seal over (`pglite_no_db_continuity`), so every PGLite session needs its own full pass. The seal is removed before any later event and when it is taken over, a write during shutdown after the shadow child stopped is still recorded, and a lost-write record that cannot be written keeps the close from sealing. Status names every seal decision and its reason. Readiness still counts only finished clean full passes. Swap readiness criterion 1 now also needs the newest clean full pass to have finished under 24 hours ago (`reconcile.last_clean_full_pass_at`); the readiness policy and its hash are unchanged.
