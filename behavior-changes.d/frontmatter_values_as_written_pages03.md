Frontmatter values are now kept exactly as written. A date stays the text you wrote (born: 1990-05-01 no longer becomes 1990-05-01T00:00:00.000Z), a timestamp keeps its offset (2024-03-01T10:00:00+02:00 is no longer converted to UTC), and a number is read as a number only when it prints back the same, so zip: 02134, version: 1.10 and n: 1.0 stay as written instead of 2134, 1.1 and 1. get, get_page include_content, export and the files gbrain writes back show those values as written, and an edit of the page body no longer rewrites them in your Markdown file. Pages stored by an earlier release hold the old values until their next write or the next sync of their file: sync reads every Markdown file once more after the upgrade, and the first write of each page puts its file's values back, so a Git repository shows that change once per page whose file had such values. Dates in frontmatter are still read as dates for effective dates, valid time, timelines and the life chronicle. A frontmatter id or code that only looks like a number (for example 001) is now written to files without quotes.
