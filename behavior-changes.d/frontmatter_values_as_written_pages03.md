Frontmatter values are now kept exactly as written. A date stays the text you wrote (born: 1990-05-01 no longer becomes 1990-05-01T00:00:00.000Z), a timestamp keeps its offset (2024-03-01T10:00:00+02:00 is no longer converted to UTC), and a number is read as a number only when it prints back the same, so zip: 02134, version: 1.10 and n: 1.0 stay as written instead of 2134, 1.1 and 1. What API and MCP callers see: a value such as 1.0, 0.80 or 10.50 now comes back as the string "1.0", "0.80" or "10.50", not the number 1, 0.8 or 10.5. A caller that needs a number converts it (Number(value) in JavaScript, float(value) in Python); values such as 3, 0.5 or 42 still come back as numbers. get, get_page include_content, export and the files gbrain writes back show values as written, and an edit of the page body no longer rewrites them in your Markdown file. When gbrain writes a file, it quotes a value that another YAML reader would otherwise read as a number or date, so zip: 02134 is written as zip: '02134' and every reader gets the same text. A valid_from or valid_until written as midnight UTC in any YAML timestamp form (2024-03-01T00:00:00Z, 2024-03-01 00:00:00 +00:00 and the like) counts as that date. Pages stored by an earlier release hold the old values until their next write or the next sync of their file: sync reads every Markdown file once more after the upgrade, and the first write of each page puts its file's values back, so a Git repository shows that change once per page whose file had such values. That re-read makes no paid calls: pages whose meaning did not change are not embedded, scanned or judged again, and a page whose atom scan was partial or held stays that way. Until its first write, an older page still takes edits: changing one nested value keeps the written text of the values beside it, and a page with an id like 007, a title like 1.10 or a value like .inf is renamed or edited without a refusal. Dates in frontmatter are still read as dates for effective dates, valid time, timelines and the life chronicle.
