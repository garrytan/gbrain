Shadow mode, the sampled comparison of the Rust engine against your brain, no longer lets a cleanup worker from a replaced evidence epoch delete the new epoch's lost-window file. That file (write-owed.window-lost-<session>.json) is what keeps an older gbrain sharing the same folder from reading the epoch as measured after a crash lost a window of samples. Before, an older gbrain could then read the write comparison as measured and pass swap criterion 5 although samples were lost. This build's own status always read it as not measured. Two read-error cases now stop and retry instead of miscounting: an unreadable session record no longer puts the wrong process on the lost-window file, and an unreadable client journal no longer makes the settle pass count its samples twice (6 for 3 owed). The settle pass also no longer counts a session twice when its child writes its last samples and exits while the pass runs. Nothing you run changes, and no count, reason or status text is added or renamed.
