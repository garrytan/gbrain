A page that opens with a frontmatter block gbrain does not read, and that block names its readers, is no longer stored as a page every member can read. gbrain reads frontmatter only when the opening --- is in the first column, so a fence with a space, tab or no-break space before it (or written as ----, as +++, or never closed), including a block in flow style such as {title: Example, readable_by: [alice-example]}, used to give the page no readers at all. put_page, edit_page and capture now refuse it with invalid_frontmatter (reason ambiguous_protected_key) and write nothing, large uploads and large local captures refuse it the same way, and git sync and gbrain import hold such a file while the rest of the source still syncs. The check treats readable_by in any spelling as naming readers, so a misspelled key under an unread fence is caught as well. To fix a page, start both --- fences in the first column and write readable_by: [alice-example] on its own line, then check who can read it with gbrain access check --token NAME --as MEMBER. A page that opens with an indented fence and names no readers saves as before, and a block with its fence in the first column is read exactly as before. Pages already stored this way are not rewritten and gbrain doctor does not count them; a later edit of such a page is refused until its fence is fixed.
