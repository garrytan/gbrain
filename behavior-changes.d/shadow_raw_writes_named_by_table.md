Shadow mode, the sampled comparison of the Rust engine against your brain, no longer marks its coverage watermark invalid when a Postgres gbrain serve starts. Each start adds a pool listener, which runs no statement, but the shadow counted it as a write it could not describe and set the follower's watermark invalid. A member that is not listed anywhere still invalidates. The swap report also names the writes it does not compare by the table they write. Raw SQL statements and typed members outside the write map were counted under the single keys raw_sql and unmapped; they are now counted under the first table they write (for example timeline_entries, takes, wanted_links, sources or persistence_effects), or no_row: and the member's name for a member or raw statement that only sets transaction settings or takes locks. Criterion 5 prints three new lines (side tables, process bookkeeping, no row written), a line that says these counts are named, not verified, and a second named loss. None of these writes is compared, and none counts toward the comparable count or the write bar: the totals and the rule criterion 5 passes on do not change. Nothing you run changes.
