gbrain git commit-push --untrack in a managed canonical worktree now admits a file by its path under a storage.db_only folder that gbrain.yml declares and .gitignore ignores, whatever its extension. Before, every file was matched by its page slug, so .json, .yml and other files whose slug sync flattens refused untrack_not_db_only even though their folder was declared and ignored. A Markdown page still needs its slug under a declared folder. A code-extension file (sync's code list, .json and .yml included) is checked against the brain, because on a source whose sync strategy is code or auto it is a page with a flattened slug that a database-only folder does not cover: it is admitted when the strategy does not import code or no live page comes from it, refused when it is a page, and refused when the brain cannot be read within 10 seconds (retry when it is free). A tracked symlink out of the folder, a file reached through a symlinked folder and a sibling folder that only shares the name as a prefix now refuse. Each refusal's fix names what is missing for that file. The managed sync note about pages kept from the working tree now says that pages under a declared storage.db_only folder are database-only by declaration and need nothing, instead of telling every such page to be deleted or committed.
