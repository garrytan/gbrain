gbrain publish now decides whether a block below other text is frontmatter with the YAML parser sync uses, instead of a key-line pattern. Before, wrapped frontmatter whose keys the pattern missed (an indented key block, a key holding a colon such as time 10:30:, a [a, b]: key, a block opened by a tag or anchor on its own line, empty-quoted, -: and ?: keys) was published with its values. A block between two unindented --- lines in the first five non-blank lines, or after an --- line that never closes up to the first blank line, is refused with invalid_frontmatter when it parses as a mapping or as a list holding one, or when it cannot be parsed and holds a colon followed by a space or the line end. An early horizontal rule followed by a list of Label: value items, or by a sentence YAML reads as a key and value (We met at 10:30 and agreed: ship it.), is now refused too, so reword those lines or move the rule. gbrain publish, in HTML and --markdown mode, also refuses with invalid_params, and writes nothing, when --out names the page itself through the same path, a symlink, a hard link or a case variant; before, the published copy replaced the page. Republish any page you shared this way before this release.
