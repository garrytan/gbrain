kind: breaking
exception: data-loss
---
A gbrain put that names no source no longer writes a second copy of a page that lives in another source. Before, once the default source held one page, gbrain put people/alice-example --force for a page that lived only in your git source wrote a new copy into default. An unscoped get then showed that copy, while the page in the git source and its file kept the old text. Now that put is refused. The same check covers each page of gbrain put-pages (a refused page is reported in the receipt; the other pages are still written) and new pages begun or committed through begin_page_upload and commit_page_upload. The error names the source that holds the page and the command to run instead, for example gbrain put people/alice-example --source-id vault --force. Scripts that relied on the old behavior must now pass --source-id. A put that names or implies its source works as before: --source-id, --source, GBRAIN_SOURCE, a .gbrain-source file, or running the put from inside a source's checkout (a registered local_path), which writes to that source. commit_page_upload takes no source of its own, so a deliberate separate copy by upload names the source again with the global --source flag on the commit; running the commit from inside a source's checkout does not count as naming a source, because the commit writes to the source fixed when the upload began. When an unsourced put goes to default while your only other git source is federated, gbrain now prints the routing notice it already printed for other commands, and --quiet silences it.
