gbrain repair ghost-pages now soft-deletes a page only when a commit deleted its file, because only then does Git still hold what the file held. Three kinds of page it used to remove are now listed apart and kept. ghost_never_committed: no commit ever held the file, or sync last imported it from uncommitted working-tree bytes that the deleting commit never held, so the page holds the only copy; write the file from the page with gbrain repair file-drift --source <id> --slug <slug> --prefer database, then commit and sync. ghost_worktree_only: the file is gone from the working tree but HEAD still holds it; restore it with git checkout HEAD -- <path> and sync, or commit the deletion, sync and preview again. ghost_history_unknown: Git cannot say which commit deleted the file (a shallow clone, a folder that is not a Git checkout, or a failed history read); write the file from the page, fetch the full history and preview again, or, outside Git, delete the page by hand if that is intended. gbrain repair file-drift --prefer file skips these pages with the same codes. An approval saved before upgrading is refused at apply for these pages, with the same code.
