A gbrain binary older than the brain's schema (the database's schema version is above its newest migration because a newer gbrain on another host or install migrated it) now refuses schema setup with `client_behind` and changes nothing: `gbrain init` and `init --migrate-only`, the schema step of `gbrain upgrade`, and `gbrain apply-migrations` (before any orchestrator runs, and before the schema pass of `--force-schema` or `--force-all`; `--list` and `--dry-run` still work). Before, it replayed its own older schema, which reinstalled superseded function bodies (the writer-fence guards among them) over the newer ones, and reported success. Reads and ordinary commands on the older binary are unchanged; the fix is `gbrain upgrade` on that host. A new doctor check, `schema_function_bodies`, fails when a function of this gbrain's schema has another body installed (what an older replay leaves behind) and names each one: upgrade every gbrain that shares the database, then run `gbrain init --migrate-only`. PGLite and Postgres alike, with or without a git repo.
