OpenClaw: when someone other than the owner writes on a session the owner also uses (OpenClaw's default session.dmScope main puts every DM on the agent's main session), the skill-resolver plugin now sends a block that withdraws the owner's operator rule, pins, session brief and suggestions. OpenClaw keeps a session's system prompt fixed and sends later changes as updates, so before this an owner block from an earlier turn stayed in force for the next person's turn. Groups and the owner's own heartbeat, cron and relay turns are unchanged. New: gbrain setup openclaw --owner-skill <name> keeps a skill to the owner's sessions by name, whatever copy OpenClaw loads, and --no-owner-skill <name> removes it. The plugin also stops logging a skill_resolver_worker_crash at every gateway start. To get this, rerun the gbrain setup openclaw command you installed with (keep its --workspace, --name and --agent flags) and restart the gateway once; gbrain doctor warns skill_resolver_plugin_outdated until you do. Others still share the owner's transcript on a shared session, so give each DM its own session (session.dmScope per-channel-peer) when other people message the agent.
