`--room <list>` now works on every gbrain operation command (`gbrain query "plan" --room alice-example,group:team-a`). The command prints what it always printed; the room only adds marks. With --json every item carries room_access and the document carries _meta.room, and a list answer becomes { results, _meta } only when --room is given. Without --json, stderr adds a [gbrain room: ...] summary. The local CLI marks the brain owner's view (gbrain access owner set) or the member --as names; with no owner every item is unknown (unbound). A trailing --room with no value marks every item unknown (invalid) with the degraded stamp and exits 0. A running gbrain serve that owns a PGLite brain marks delegated answers, and a thin client sends the room as _meta.room; an owner or host that predates room marks leaves every item unknown (not_supported). With a room declared, think answers are now marked at the strictest class of everything their synthesis retrieved (unknown when built partly from takes or with no recorded evidence), and put_page and remember mark the page or fact they wrote without a degraded stamp, where before they answered op_not_covered. Calls with no room are unchanged. Guide: docs/guides/rooms.md.
