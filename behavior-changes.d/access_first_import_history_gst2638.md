A folder-rule edit (gbrain access rule add, rm, revert or import) on a git-backed source that has no folder-rule revision yet now refuses before writing anything, with access_policy_history_unreadable, when its checkout is shallow or a partial clone missing the Git objects of its folder-rule history; it used to commit the file and leave the whole source reading as nobody. When you hit it, run git -C <source root> fetch --unshallow (for a partial clone, git -C <source root> log --first-parent -p HEAD -- .gbrain/access.yml, which fetches every version), then rerun the same gbrain access rule command; nothing was written, so the source keeps its current reads meanwhile. A first edit on a source with no folder-rule history no longer reads the whole source as nobody while it applies. An edit whose result state is invalid now exits 1 instead of 0. Unchanged: a plain gbrain sync of a shallow checkout whose commits already hold folder-rule history still fails closed as before, reading the whole source as nobody because the history cannot be replayed; recover the same way, git -C <source root> fetch --unshallow, then gbrain sync --source <id> --no-pull.
