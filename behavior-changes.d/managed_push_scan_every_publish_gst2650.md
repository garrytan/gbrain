Every push gbrain makes is now scanned for secrets with no opt-out: `commitAndPush` no longer has an unscanned mode, so a push handed over from a busy publish lock is scanned too. Only the commits the remote lacks are read, and a missing remote-tracking branch is fetched first instead of scanning the whole history. In a managed root below the repository's top level, a commit changing that root's own `.gbrain-scan-allow` is held like one at the top level, and its path globs match paths relative to that root. A strict (canonical: git) source's commit whose files a Git clean filter changed is scanned instead of trusted, and so is one made before this release that is still unpushed; either is still pushed when the scan finds nothing. Git replace refs no longer change what a page-write commit holds. A false positive in an unpushed commit holds the push with `publish_secret_found` naming the file, line and rule, never the value: add its fingerprint to `.gbrain-scan-allow`, then run `gbrain sources writer retry-effects <source> --parked-pushes`, or the push fix `gbrain doctor` names.
