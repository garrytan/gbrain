On a source whose pages are canonical in Git (`canonical: git`), a fact the Google loops extraction (or any writer that keeps a fallback entity, writeSingleFact) finds for an entity with no page that an exact page rule names is now refused `git_home_required` (reason `facts_lane`) before anything is stored, with a fix that creates the entity's page; before, it was stored in the database only, with no file in Git, or refused with a message naming memory/unattributed. When the access rules cannot be read the write refuses `access_policy_pending` (retry), and that refusal's message now names the entity, for `remember` too. The loops job still records the loop and logs the refusal code with the entity's page; nothing is stored for that fact. Facts stored the old way are not changed: `gbrain repair facts-home` lists them as `folder_restricted`. Sources that are not strict and brains with no Git repository are unchanged.
