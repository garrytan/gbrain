`gbrain repair ghost-pages` on a managed brain now retires a code or image page (a JSON, YAML or image file indexed as a page) at its recorded file instead of at `<slug>.md` (#7967): when that file is restored after the request was prepared, publication refuses and the page is kept (outcome `file_restored`), and the door commits the removal of the recorded file, so on a git-canonical source HEAD stops holding the file of a page the database deleted.
