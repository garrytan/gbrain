New: gbrain dedupe --preview lists groups of person and company pages that are likely the same person or company, with the evidence (the type of each shared key, never its value) and a class: clean, likely, weak, thin or conflict. A group is clean only when its pages share an account or registry id (a LinkedIn profile, a GitHub login or an id field the schema pack declares) and exactly the same name; a shared email, phone, X handle or company domain alone makes it likely. When two pages from different sources share no account or registry id and their LinkedIn profiles, GitHub logins or declared ids differ, the pair is a conflict for review, never a likely or weak match; correct the wrong id on one page if they are one person. Two such pages inside one source are listed as likely, with the differing id named in the evidence. Each shared email, phone, X handle or domain also shows how many other pages carry it, with the same name and with other names. --json prints a versioned contract, and --kind and --source narrow the list. gbrain doctor gains an entity_duplicates check that counts the groups and warns when there are any. Both only read: nothing is merged, linked or changed. A schema pack can now declare identity_keys on a page type, naming the frontmatter fields that hold one id per person or company.
