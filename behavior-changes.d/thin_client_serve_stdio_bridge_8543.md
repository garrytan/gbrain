On a thin client (gbrain init --mcp-only), plain `gbrain serve` no longer refuses: it is now a stdio MCP server that relays every call to the brain host with the stored OAuth client's grant, opens no local database and adds no access. A harness entry that runs `gbrain serve` on a thin client now connects to the remote brain instead of exiting with requires_local_engine. `gbrain serve --http`, `--access` and the other host flags still refuse there. `gbrain doctor` on a read or read+write client now reports the missing admin scope as expected (ok) instead of a warning that suggested re-registering with admin.
