On a brain with no embedding provider (the default keyless install), search and query now add the pages that hold only some of the question's words when the first page of results comes back shorter than the limit. Search runs the same request once more with that looser keyword match and appends only the new pages; every row returned before keeps its place and score. The added rows pass the same read policy, redirect, superseded-page, evidence and injection checks as any other row, carry keyword_fill: true, and --explain-target says they matched only some of the words. Brains with embeddings search exactly as before.
