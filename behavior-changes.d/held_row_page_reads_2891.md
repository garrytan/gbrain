A world fence row restating a private fact that waits for the operator's accept (a remote put_page or remember restatement) is now left out of page, chunk, search and edit reads for remote callers who cannot read that private fact: get_page (as_of and known_as_of included), get_versions bodies and diffs, fetch, search, query, search_exact, get_chunks, the entity card and the edit_page diff. Such a caller's put_page keeps the held row it could not read, restored exactly as stored. The owner's callers, the local CLI and a member reading their own member page see the page as before. A world copy of the claim saved about another entity no longer lets a remote remember skip that hold. A held row also stays private when the page is synced or rewritten, until the operator accepts it with gbrain trust confirm tp<N>. If the lookup of held rows fails, the page read fails rather than return the page, and search drops every fence row. The page file in the brain repository still holds the world cell, and restatements that were never held stay world.
