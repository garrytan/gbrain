Ordinary commands (remember, recall, config get and every command except apply-migrations, post-upgrade, upgrade, doctor, init and setup) no longer print a "wedged" migrations_pending notice, with a request to ask the user for a forced retry, for an upgrade migration that stopped three or more runs in a row once a newer migration has completed since. apply-migrations already treats such a wedge as history; since v0.60.725.0 the notice did not, so a brain with three old partial rows for v0.53.0 printed it on every call. A wedge with no newer migration past it still gets the notice. The v0.53.0 shared-skills migration's source conflicts stay visible where an operator looks: gbrain doctor (as a warning, when connected), gbrain apply-migrations --dry-run and --yes, and post-upgrade name each source in conflict with a code and its next step, read from the migration's read-only preview, and none of them advises --force-retry. A new code, shared_skills_unmanifested, marks a source whose skills/ folder holds skills with no skillpack.json declaring them: declare the ones to share in a skillpack.json at the source's root, or keep the source out of shared-skills adoption with gbrain sources shared-skills <id> off. Doctor stops warning once the preview finds no source in conflict. A named run of a wedged v0.53.0 still refuses, now with the read-only preview as its fix instead of a forced retry.
