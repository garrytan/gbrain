A credential bound to the brain owner (access.owner_member) and speaking for itself now reads over remote MCP what the local CLI reads: get_page and fetch give it the private and held rows of a page's Facts fence, graph hops give it the stored edge context, and when the credential has no takes holders list of its own every read that filters takes by holder reads every holder (among them get_page and fetch, takes_list, takes_search, takes_scorecard, takes_calibration, search, query, recall, delta, think and synthesize). A credential with a list still reads only the holders it names, and synthesize now reads world takes only for a non-owner with no list. Every other remote caller reads exactly as before. With a room declared, the owner's credential reads world takes and gated hop text, as before this PR, until GST-3066 adds room marks to those operations; its get_page still returns the Facts rows, and a whole-body read or `view: 'markdown'` whose body carries private or held rows is marked not readable for the room (room_access reason private_label). The mark is per page. It does not cover held rows inside read-view windows (lines, bytes, section, grep) or in the segmented markdown view of an owner credential with a holders list, which stay as on master until GST-3066. The local CLI's `--room` marks change the same way: a page whose body carries private rows, held rows or takes is now marked private_label. Known limit: editing or deleting a private Facts row through a remote put_page does not stick yet (the old row is restored); use the local CLI for that.
