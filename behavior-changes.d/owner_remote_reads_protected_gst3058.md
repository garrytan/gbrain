A credential bound to the brain owner, making a direct remote MCP call for itself with no room declared, now reads what the local CLI reads: get_page and fetch give it the private and held rows of a page's Facts fence, graph hops give it the stored edge context, and when the credential has no takes holders list of its own every read that filters takes by holder reads every holder (among them get_page and fetch, takes_list, takes_search, takes_scorecard, takes_calibration, search, query, recall, delta, think and synthesize). A credential with a list still reads only the holders it names, and synthesize now reads world takes only for a non-owner with no list. Every other context reads exactly as before: other credentials, stdio, on-behalf-of audiences, attested actors, agent jobs and group chats (a declared room). Known limit: agent jobs and group chats read as before this PR until GST-3066. An agent job now reads its client's stored takes holders list, else world takes as before. With a room declared, a get_page whole-body read or `view: 'markdown'` whose returned body carries rows a world-only read strips (private rows, held rows, takes) is marked not readable for the room (room_access reason private_label); the mark is per page, and it does not cover held rows inside read-view windows (lines, bytes, section, grep) or in a segmented page's markdown view, which an owner reads as on master. The local CLI's `--room` marks a page whose body carries private rows, held rows or takes private_label the same way. Known limit: editing or deleting a private Facts row through a remote put_page does not stick yet (the old row is restored); use the local CLI for that.
