On a source with `canonical: git`, a page committed with a legacy file mode (100664) no longer gets a mode-only commit when a write leaves its bytes unchanged, and with `core.fileMode=false` a write of it commits the page as 100644 (before, Git refused the rebuilt tree and the write failed `git_unavailable`). A write replayed after its commit landed and refused `git_index_conflict` because someone staged the page meanwhile now says HEAD already holds its bytes, instead of that it committed nothing. The index refresh after a door commit removes the index copies (`index.gbrain-<pid>-*` in the git directory) a killed gbrain process left behind, and on Windows retries a briefly refused rename of the index before it reports that the commit landed but the index was not updated.
