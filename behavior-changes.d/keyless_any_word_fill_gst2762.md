On a brain with no embedding provider (the default keyless install), search and query now add pages that hold only some of the question's words when the first page of results comes back shorter than the limit. Every row returned before keeps its place, text and score, and the added pages follow them. The added rows pass the same read policy, redirect, superseded-page, evidence and injection checks as any other row, carry keyword_fill: true, and --explain-target says they matched only some of the words. When adding them would change another row, or a check that is on was skipped for them, they are left out; a row from a source on decide.egress.deny_sources is treated like any other row from that source, which today means it is returned and counted as judged. Brains with embeddings search exactly as before, and there is no setting to change.
