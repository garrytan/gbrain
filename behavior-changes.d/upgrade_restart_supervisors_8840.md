Self-upgrade restarts no longer leave a process dead or refuse because of another brain. An autopilot that nothing relaunches (the ephemeral-container start script runs it once at container boot, or it was started by hand) now starts itself again after a self-upgrade swap instead of exiting for good; under launchd, systemd, this brain's cron line or a declared autopilot_launcher it still exits for that supervisor. On macOS, gbrain upgrade reads each process's GBRAIN_HOME (else HOME) with ps -E, so another brain's serve on the same host no longer makes every restart refuse. A serve that gbrain's own serve service does not run now gets a refusal naming the exact command: systemctl --user restart <unit> for a systemd unit of your own (found from the serve's cgroup, any name), else the command line serve was started with. New key: gbrain config set self_upgrade.serve_launcher external lets every upgrade run that unit's restart command, or stop serve and wait up to 6 minutes for your own supervisor to start the new build; leave it unset and upgrades never restart that serve themselves.
