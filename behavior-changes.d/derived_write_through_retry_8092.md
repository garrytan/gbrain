The dream cycle's atom and concept write-through (#8092) waits for a busy checkout commit lock without freezing the worker (up to 30 s, as before). After a refused commit, a rewrite of an existing atom or concept file and the removal of a retired atom's file are now retried on the next run like new files, instead of staying behind the database until the page changes again; the summary reads "N file(s) rolled back; the next run writes them again". The rollback runs under the commit lock and takes its files out of the pending write-through ledger, so a later hand edit at one of those paths is never swept into a gbrain commit; when the lock stays busy the files are left for that writer's commit.
