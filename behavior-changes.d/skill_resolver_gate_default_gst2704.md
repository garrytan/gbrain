The skill resolver now stays quiet when no skill fits. Before, it showed a skills block on almost every message, including ones that need no skill, because some skill always shared a word with the message. It now leaves the block out when its best match is weak (skills.resolver.top_gate, default 0.6), and a skill you name in the message is still suggested. On a 351-skill public test catalog this cut blocks on no-skill requests from 100% to 11.5% and kept the right skill in the block for 174 of 228 requests that needed one, against 176 before. To tune it, run gbrain config set skills.resolver.top_gate <number>; set it to 0 to get the old behavior back. OpenClaw and Pi pick up the setting on the next gbrain setup <harness> --skill-loading resolve.
