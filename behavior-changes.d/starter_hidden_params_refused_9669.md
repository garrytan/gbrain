A remote MCP caller on the starter surface can no longer pass a parameter that its tool list leaves out in a direct tool call. Before, the server accepted any of them, so a read-only client pinned to starter could pass `include_deleted: true` to `get_page` or `list_pages` and read soft-deleted pages, and `page_not_found` told it to. Now such a call is refused with `param_not_on_surface` and nothing runs; its fix is `request_tools {"surface":"full"}` where the connection may widen itself (the owner's stdio session, an OAuth client the operator has not pinned), and otherwise asks the user. A short list of hidden parameters that gbrain's own clients and fixes send stays usable on starter (page windows on `get_page`, the shared-skill reads, the thin client's source binding, the connection check's `recall`, `remember` and `submit_agent` arguments, a delegating client's `submit_agent` `queue`, `model` and `allowed_slug_prefixes`, `list_pages` paging with `offset`), each with its reason in `STARTER_CALLABLE_PARAMS`. The tools an agent job runs (`submit_agent`) follow the same rule. Structured fixes never name a parameter the caller's surface refuses (`page_not_found` on starter offers a search); plain-text suggestions may still name one. The local CLI and full-surface callers are unchanged.
