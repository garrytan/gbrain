`gbrain extract-conversation-facts` now keeps a name tag on a fact about a person or company that has no page, instead of storing the fact with no entity (the 0.60.162.0 rule, which still applies to every other writer). The tag is the full name in slug form without a folder (Alice Example becomes alice-example); a single word such as a first name or a topic keeps no tag. No page is created, lists of pages never show a tag, and only new extractions get one. A page written later at that file name (people/alice-example) reads the tag's facts, and `gbrain facts relink --conversation --unbacked` (preview with --dry-run) moves them onto the page the name resolves to. Forgetting or purging a fact on a tag now applies to that claim across the whole source (a forget refuses with claim_linked while the same claim is active on another person's or company's fact), and a claim forgotten or purged for anyone never comes back on a tag; facts already stored on a bare slug with no page are treated the same way. Two people with the same full name in one source share a tag until a page or alias separates them (docs/guides/facts-relink.md). Turn tags off with `gbrain config set facts.unbacked_entity_keys false`.
