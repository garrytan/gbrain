A page whose database row keeps its timeline inside the body (an import before v0.46.25.0 left a bare dated ## Timeline section there with an empty timeline) no longer counts as differing from its file when the file holds the same text and only the split differs, which is how today's parser reads such a file when it has no timeline sentinel. Writes to such a page (remember, put_page, timeline entries, maintenance writes) are no longer refused source_changed (file_database_drift), and sync imports the next edit of its file instead of holding it file_drift. A file_drift hold an earlier release wrote is re-checked only when someone asks (gbrain sources retry-held, or the release below), never by a plain sync. A hold on a file unchanged since its import (database side) is never imported over by sync on its own: gbrain repair file-drift --source <id> --held lists the ones whose page and file now agree as release_hold, and gbrain repair file-drift --source <id> --slug <slug> --prefer file previews their release; the release, like gbrain sources retry-held, now re-checks such a hold and imports only when the file holds the page, and holds it again otherwise; a pending write waiting for its Git publish and a page under storage.db_only keep their database copy. A file over the 24 MiB in-memory sync limit whose page also changed in the database is held file_drift instead of streamed over the database copy. Any line that differs still refuses as before.
