Every remote MCP credential now reads and steers only the background jobs it submitted, admin scope included. get_job, wait_job, list_jobs (both pages), get_job_progress, watch_job, cancel_job, pause_job, resume_job, retry_job, replay_job and send_job_message answer a remote caller only for jobs its own credential queued, for the same person or audience its call declares (x-qm-actor, X-Gbrain-On-Behalf-Of); any other job, including jobs the local operator queued, reads exactly like a missing id (not_found), and job insight never names another caller's parent, child, slot holder or lock holder and never counts its spend or tokens (queue positions and pending-child totals still count every job). Before, any remote credential with the admin scope could list and read every job on the brain, with other clients' agent prompts, data and results, and cancel, pause or message them. Three callers keep the whole-queue view: the local CLI (gbrain jobs list), a local stdio MCP server with no per-token auth, and a remote admin credential bound to the brain owner (config access.owner_member) speaking for itself. A brain with no owner set has no owner-bound credential, so there every remote credential, even one that only you use, now sees only its own jobs. If a remote client of yours needs the whole queue, name the owner and bind its credential: gbrain access member add <id>, gbrain access owner set <id>, then gbrain auth rescope --client <client_id> --member <id> (or --token <name> for a legacy token); gbrain access check --token <name> shows the result. Jobs queued remotely from now on also record the declared person or audience, so two people behind one shared credential never see each other's jobs. watch_job refuses a call that declares an audience (actor_not_attested, reason audience_not_supported) until watches are kept per audience; call wait_job instead.
