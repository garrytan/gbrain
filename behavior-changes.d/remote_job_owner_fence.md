kind: breaking

Every remote MCP credential, admin scope included, now reads and steers only the background jobs it submitted, for the same person or audience its call declares (x-qm-actor, X-Gbrain-On-Behalf-Of). get_job, wait_job, list_jobs (both pages), get_job_progress, watch_job, cancel_job, pause_job, resume_job, retry_job, replay_job and send_job_message treat any other job, including the local operator's, like a missing id (not_found; cancel_job answers both with "Cannot cancel"). Fenced responses never name another caller's parent, child, slot or lock holder, and leave their tokens and spend out. Before, any admin-scoped remote credential could read every job's prompts, data and results, and cancel, pause or message them. Three callers keep the whole-queue view: the local CLI, a local stdio MCP server with no per-token auth, and a remote admin credential bound to the brain owner (config access.owner_member) that declares no person or audience. On a brain with no owner set, every remote credential now sees only its own jobs; to give one the whole queue, run gbrain access member add <id>, gbrain access owner set <id>, then gbrain auth rescope --client <client_id> --member <id> (or --token <name>). Wakeshift watch calls refuse a call that declares an audience (actor_not_attested, reason audience_not_supported) until watches are kept per audience: call wait_job instead. An open job watch whose credential can no longer read the job ends at delivery without a wake.
