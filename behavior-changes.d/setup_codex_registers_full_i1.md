`gbrain setup codex` now registers `serve --surface full` by default, so a new Codex connection lists every tool gbrain serves instead of the starter set (`serve --surface starter --advertise verbs`). Codex does not reload its tool list, so the tools `request_tools` unlocked on starter never reached it. The wider surface grants nothing a starter session could not already reach on stdio by calling `request_tools {"surface":"full"}`: read-only connections, credential scopes, publish gates, page readers and the session's source still apply. On a brain that sets `mcp.allow_session_widen false`, starter was a real ceiling for Codex and full lifts it; pin starter if that matters to you. The Codex receipt now records `surface_origin` (`explicit` when you passed `--surface`, `default` when setup picked it). Pin the old registration with `gbrain setup codex --surface starter --advertise verbs`; `--advertise` is new and keeps the listing you pass. `gbrain config set mcp.default_surface_codex starter` turns the Codex default back for every later setup run, and `gbrain config unset mcp.default_surface_codex` restores the shipped default; `mcp.default_surface_claude_code` and `mcp.default_surface_hermes` do the same for those harnesses. Claude Code, Hermes, opencode and other hosts keep registering starter.
