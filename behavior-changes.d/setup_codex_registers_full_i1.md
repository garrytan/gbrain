`gbrain setup codex` now registers `serve --surface full` by default, so a new Codex connection lists every tool gbrain serves instead of the starter set (`serve --surface starter --advertise verbs`). Codex does not reload its tool list, so the tools `request_tools` unlocked on starter never reached it. The wider surface grants nothing a starter session could not already reach on stdio by calling `request_tools {"surface":"full"}`: read-only connections, credential scopes, publish gates, page readers and the session's source still apply. When `mcp.allow_session_widen` is off (`gbrain config set mcp.allow_session_widen false`, read from the brain database first and then the config file, with the values `gbrain serve` reads as off), setup keeps starter as the Codex default, since full would lift that ceiling; if setup cannot read the brain database (a running gbrain server holds it), a new Codex entry gets starter, an existing one stays as it is, and setup prints a note; `mcp.default_surface_codex full` or `--surface full` still picks full. The Codex receipt now records `surface_origin` (`explicit` when you passed `--surface`, `default` when setup picked it). Pin the old registration with `gbrain setup codex --surface starter --advertise verbs`; `--advertise` is new and keeps the listing you pass. `gbrain config set mcp.default_surface_codex starter` turns the Codex default back for every later setup run, and `gbrain config unset mcp.default_surface_codex` restores the shipped default; `mcp.default_surface_claude_code` and `mcp.default_surface_hermes` do the same for those harnesses. Claude Code, Hermes, opencode and other hosts keep registering starter.
