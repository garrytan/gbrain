# Upgrade to v0.56.2.0: preserve memory and review blocked work

Preserve the agent's identity, capture preferences, provider choices and source
grants. This patch adds no schema migration and authorizes no live repair,
ownership change, paid backfill or service installation.

## Upgrade without mixing consumers

1. On a managed deployment, gracefully stop and drain the owner and older
   workers on every host. Retain the original installation and a verified full
   database backup. Git alone is not a full database backup.
2. Use the installation's supported upgrade path, retaining independent
   opt-outs where applicable:

   ```bash
   GBRAIN_NO_AUTOPILOT_INSTALL=1 GBRAIN_NO_REEMBED=1 gbrain upgrade --no-autopilot-install
   ```

   If an existing migration phase failed, inspect that failure before using
   `gbrain apply-migrations --yes --no-autopilot-install`. Do not delete its
   ledger, force a retry blindly, enable capture or add credentials.
3. Restart compatible owners/workers and verify the installed version, scoped
   page readback and writer state:

   ```bash
   gbrain --version
   gbrain sources writer status --json
   gbrain backup check --json
   ```

   A source claim is not activation. Existing leases and the native worktree
   lock do not exclude every already-running legacy writer. Never disable
   protections or activate persistence just to bypass a refused sync.

## Review embedding identity before changing models

The retired provider integration is no longer available. Do not assign a new
model label to existing vectors or rerun `init` to convert them: re-init checks
chunks, facts, query cache and takes, including companion-only stores. Without
an explicit model, retain keyword/read-only access and inspect
`gbrain migrate embeddings --status --json`. Keep a verified full backup,
preview an explicit supported target with `--dry-run`, and obtain approval
before migrating. Equal vector widths do not imply compatible models; an
approved model change invalidates incompatible companion vectors without
deleting the underlying memory text. Follow the
[embedding migration guide](../../docs/guides/embedding-migration.md).

## Review retained sync and Git work

Resume a pending sync with its original source, full/working-tree/filter
options, and processing choices. `--no-embed`, `--no-extract` and
`--no-schema-pack` remain attached to new accepted work. A changed choice does
not silently reinterpret an unfinished request. Required provider-free
canonical projections still run; already committed historical effects are
not retroactively cancelled.

Cancellation stops new admission; it does not revoke requests already accepted
durably. A pending receipt keeps its original ID, and committed work is banked
before reporting partial progress. Resume with the same options rather than
submitting replacement requests.

Old imports or checkpoints without durable processing choices, and old
deletions without a provable physical origin, refuse under their original
request IDs. Inspect the failure and current files first. Only after explicit
approval, an idle filesystem source can rediscover with its original selection
options and the operator's chosen processing flags, for example:

```bash
gbrain sync --source source-example --no-pull --no-embed --no-extract --no-schema-pack --retry-failed
```

Replace the example source and retain any original selection flags. Company
sources must retain their approved manifest and required schema; do not use
`--no-schema-pack` to bypass that approval. Queued or running work must settle
before replacement. Never edit frozen requests, terminal receipts or source
bookmarks to manufacture success.

Old Git effects resolve their target at execution without rewriting retained
data. Ambiguous targets and changed file bytes still refuse. A local commit is
not a successful remote push; inspect the effect's recorded state before
approving its retry. Do not force-push, include unrelated staging or rename a
source tree automatically.

## Verify a backup without replacing the original

Follow [the full backup and fresh-root restore guide](../../docs/guides/in-agent-setup.md#6-back-up-the-complete-local-database).
Archive entries with unsafe or conflicting names are rejected, not renamed.
Windows backup work requires permitted built-in Windows PowerShell and a local
filesystem supporting enforceable Windows ACLs. Private-path enforcement
failure is a refusal, not permission to continue with public staging.

Restore only into an absent disposable root, reopen it in a fresh process and
check remembered pages and required paths before relying on it. Review the
reconnect inventory for unchanged legacy absolute origins and detached external
sources. Keep restored scheduling and connectors inactive until separately
approved. The archive is not encrypted and may contain secrets; never attach
it to a public issue.

This patch preserves compatible existing vectors but does not recreate vectors
or pages already lost. The reported macOS reindex hang remains unresolved;
Linux pressure evidence does not authorize checkpoint/reconnect workarounds,
WAL repair, a live-store experiment or an automatic downgrade.
