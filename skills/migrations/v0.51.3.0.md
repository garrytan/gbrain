# v0.51.3.0: converge two-brain Claude hook ownership

This release changes local Claude harness ownership only. It adds no database
migration and does not authorize broader grants, paid enrichment, deletion, or
a different capture policy. Preserve each brain's existing endpoint, source,
host list, project list and capture choice.

1. **Inventory every brain home before changing hooks.** For each installation,
   select its normal environment and record the current receipt without copying
   tokens into notes or chat:

   ```bash
   gbrain --version
   gbrain bootstrap harness --status --json
   ```

   Record whether Claude hooks are user-scoped or list one or more project
   paths, whether capture is disabled, and which other harnesses are installed.
   Do not proceed if the receipt is unreadable or its target paths are unclear.

2. **Upgrade every affected brain binary first.** Use the installation's normal
   upgrade method, restart its service normally, then confirm the new binary and
   service health:

   ```bash
   gbrain upgrade
   gbrain --version
   gbrain doctor
   ```

   Do not delete a live PGLite lock or start a second process against the same
   embedded database. Two homes require separate running services and protected
   database credentials.

3. **Converge project-scoped homes before adding user scope.** Re-run each
   project's original harness command with the same host, project, source,
   endpoint and capture options. Include every prior repeatable `--project`
   argument and add `--yes`. Example only:

   ```bash
   gbrain bootstrap harness --harness claude-code \
     --project /absolute/company-project --no-capture --yes
   ```

   Never replace a project-scoped receipt with bare `gbrain bootstrap harness
   --yes`. A second home claiming an owned project must refuse before minting a
   token or changing settings. Do not use `--force` to bypass that refusal.

4. **Converge a user-scoped home last.** Re-run its original command with the
   same hosts and options, but no `--project` arguments. If an existing
   user-scope install prevents a project home from converging, stop and plan a
   brief rewiring window: remove only that recorded user-scope harness through
   its owning brain, converge project homes, then reinstall the same user-scope
   policy. Do not hand-edit markers or copy tokens between homes.

5. **Verify ownership and routing under every home.** For each installation:

   ```bash
   gbrain bootstrap harness --status --json
   gbrain doctor
   ```

   Confirm every target is healthy, each project appears under only one brain,
   and the service URL and source match the prior receipt. Start a fresh Claude
   session inside one representative project per brain and verify that its brain
   tools reach the intended source. Keep capture disabled wherever it was
   disabled before the upgrade.

If a confirmed legacy install cannot migrate, keep its settings and receipt
intact and file a sanitized issue with the installed version, target scope and
error text. Never include bearer tokens, database URLs or private project paths.
