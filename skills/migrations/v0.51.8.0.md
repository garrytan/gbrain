# v0.51.8.0: company ingestion, source-aware schemas, and origin-aware extraction

The upgrade orchestrator applies migration 162. If it did not complete, run
`gbrain apply-migrations --yes` on the intended brain host, then `gbrain doctor`.
Do not initialize another brain or change the operator's chosen search mode.

Existing source files, page types, and grants do not need rewriting. Do not
activate the company schema, connect a repository, or run `unify-types` merely
because the optional company features are installed.

When the operator requests link extraction, retain explicit brain/source routing.
The database extraction path now replaces origin-attributed derived links
atomically and preserves manual links. If it reports missing legacy origin
metadata, stop and show the operator that diagnostic. Do not delete all links or
invent provenance to force the extraction through.

Typed queries now refuse when the selected schema cannot be read. Diagnose the
actual selected engine/schema instead of switching to the host's vocabulary.
