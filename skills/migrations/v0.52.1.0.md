# Upgrade to v0.52.1.0: source identity and deliberate writer recovery

Preserve existing identity, grants, source routing, capture choices and provider
settings. This release does not require activating a new writer topology.

## Memory-only upgrade

```bash
GBRAIN_NO_AUTOPILOT_INSTALL=1 GBRAIN_NO_REEMBED=1 gbrain upgrade --no-autopilot-install
```

The autopilot option propagates through package hooks and migration orchestration
and skips service-unit rewrites. `GBRAIN_NO_REEMBED=1` separately skips potentially
paid reindexing; other migrations still run. For a source clone linked with Bun,
follow the [installation upgrade steps](../../INSTALL_FOR_AGENTS.md#upgrade).
Existing service deployments retain their coordinated host/client upgrade
procedure and must not infer a topology change from this release.

If upgrading from before v0.51.7.0, also read its
[projection-readiness guidance](v0.51.7.0.md). Pending projections are not proof
that source content is missing. Use the existing designated writer and approved
keyless recovery paths; retain `--no-autopilot-install` for manual migration
orchestration on a memory-only installation. Do not enable paid embeddings just
to make a readiness warning disappear.

## Search and fetch clients

Pass each search result's `id` unchanged to `fetch`. It is an opaque address for
that source and page in the selected brain, not a slug or an access grant. Legacy
slugs work only when unambiguous among currently readable live pages. On
`ambiguous_id`, search again; do not choose an arbitrary source. On a missing-page
response, check current access and page state rather than retrying another source.
Read the [wire protocol](../../docs/protocol/DEEP_RESEARCH_IDS_v1.md) for aliases,
escaping and compatibility.

## Writer administration

Ordinary diagnosis, startup and maintenance must not claim a checkout, activate
managed mode or transfer ownership. Begin with read-only inspection on the
selected brain host:

```bash
gbrain sources writer status --brain host --json
```

For a separately approved topology change, update automation to supply the exact
`--admin-intent` and the unchanged `--expected-state` from reviewed status.
Activation also retains its all-host quiescence precondition. A changed state
requires renewed inspection and review, not an automatic fingerprint refresh.
A terminal or generic `--yes` is not a substitute, and remote credentials remain
ineligible. Use the full [operator procedure](../../docs/architecture/topologies.md)
for deliberate noninteractive administration.

## Verify the enabled capabilities

- Search for a known phrase and fetch its returned ID; check the expected source
  and content. Duplicate slugs should not change which page you receive.
- Read a saved fact and its provenance after a process restart. This proves local
  persistence, not native-harness activation or a new-conversation test.
- Inspect writer status before and after routine repair. Owner identities and
  epochs should not change solely because of diagnosis.
- Keep optional provider and daemon work opt-in. Disabled primary embeddings do
  not need destructive reinitialization to make diagnostics pass.

The reported macOS PGLite reindex hang remains unproven; the retained synthetic
fixture is a diagnostic and recovery regression, not evidence that every aged
store is repaired. On failure, retain sanitized diagnostics and use the existing
[database access repair loop](../../docs/ENGINES.md#engine-detection-and-access-repair)
without deleting ownership markers or bypassing the designated writer.

**Say to your agent:** "Upgrade the enabled memory capabilities, preserve my
grants and writer topology, and verify a known search result and saved fact."
