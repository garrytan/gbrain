# Upgrade to v0.54.1.0: inspect first, repair deliberately

Preserve the agent's identity, capture choices, provider choices and source
grants. This release adds recovery capabilities; it does not authorize their
execution. Never disable managed persistence or delete ownership/lock files to
make an operation pass.

## Upgrade the installation

1. For a managed brain, identify and gracefully stop/drain its owner and older
   workers on every host using the deployment's normal shutdown procedure.
   Keep a verified full database backup and the original installation. A Git
   remote alone is not a full backup. Do not mix old consumers with the new
   durable intent types.
2. Upgrade through the installation's supported path. Preserve independent
   opt-outs where applicable:

   ```bash
   GBRAIN_NO_AUTOPILOT_INSTALL=1 GBRAIN_NO_REEMBED=1 gbrain upgrade --no-autopilot-install
   ```

   Do not add credentials, enable capture, install services or start a paid
   backfill as an upgrade side effect. If a migration reports a failed phase,
   inspect it; a partial result is not completion. Forced `--dry-run` previews
   never apply repairs. Historical false-complete migration entries need an
   explicit reviewed `--force-retry`, not blanket ledger deletion.
3. Restart the upgraded owners/workers and verify `gbrain --version`, scoped
   page readback and `gbrain sources writer status --json`. Review the source
   topology and `unsupported_maintenance` entries before scheduling work.
   A claim alone is not completed onboarding. Follow
   [writer administration](../../docs/architecture/topologies.md) for deliberate
   claim/activation or self-transfer; never manufacture fresh expected-state
   values automatically just to overcome a refusal.

## Restore only the affected derived work

Use the actual brain/source and original receipt IDs, not example placeholders.
For stalled Git-backed managed sync, fix and commit the source input, inspect the failed
run, then approve `gbrain sync --source source-example --no-pull --retry-failed`
with the same full/working-tree/filter options. Do not use `--skip-failed` on
managed cursors or treat a successful full run as repairing a separate failed
incremental run.

For managed Google/GitHub sync, repair the reported storage or source problem,
then explicitly run `gbrain sync --source source-example --retry-failed` with the
same connector options. This preserves the API bookmark and original failed
receipt while authorizing a linked replacement. Pending work is resumed, not
replaced; a newly failed replacement needs another deliberate retry after its
cause is repaired. Cancelled receipts remain cancelled.

Preview missing fact vectors before deciding whether to pay for repair:

```bash
gbrain embed --stale --facts --source source-example --dry-run --json
```

After the operator approves the source, count and budget, the corresponding
bounded execution is:

```bash
gbrain embed --stale --facts --source source-example --yes --max-cost-usd 1 --max-facts 100 --json
```

The repair reports actual/estimated cost and remaining work; it does not enable
embeddings or switch models. A lost resident acknowledgment requires waiting
and another preview, not an automatic paid retry. Failed page embedding effects
have a separate `sources writer retry-effects <source> --request-id <uuid>
--dry-run --json` preview. Execution reconciles valid vectors for free or permits
one additional bounded worker-attempt cycle; provider sub-batches are not the
same as worker attempts.

For atom recovery on PGLite, gracefully stop its owner and supervisor, run the
reviewed `jobs submit extract-atoms-drain ... --follow` command, and restart the
owner. The explicit retry payload names the failed receipt. Inspect its job ID
instead of resubmitting a failed job, which is a new extraction approval. Do not infer live-owner
dream/jobs delegation from the fact-extraction/backfill IPC routes.

Receipt compaction preserves acceptance identity but can discard full retry
payloads. Expired atom retries return `recovery_required`; failed fact-batch
replays return `facts_payload_expired`. Inspect the original receipt and current
pages before deciding on recovery or separately approving new extraction. An
expired payload is not work that never ran, and must not trigger automatic
repeat model spending.

## Client and backup checks

Inside the intended OpenClaw installation, inspect and back up its existing
configuration. If its selected slot is the legacy `gbrain-context`, migrate
that selection to `gbrain-context-engine`, preserving unrelated settings and
the installed plugin ID. On hosts without per-call workspace context, supply
the intended absolute `plugins.entries.gbrain-context-engine.config.workspaceDir`;
never guess from the gateway's working directory. Restart that harness and
verify a new conversation retrieves the intended source. Do not mark activation
complete from a manifest alone. See [OpenClaw](../../docs/mcp/OPENCLAW.md).

Run `gbrain backup check --json` on the trusted host to inspect current remote
evidence, then perform a disposable full restore drill before relying on a
backup. Stale, offline or unverified evidence is not a healthy backup. This
release does not claim to fix the separate Windows PGLite dump failure or the
unreproduced aged-store macOS reindex hang. Do not blindly downgrade a datastore
containing new accepted requests; retain its journals and use compatible forward
repair or a verified restore.
