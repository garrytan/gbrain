# v0.51.7.0: search and projection readiness

Preserve the operator's brain, source grants, provider choices and capture settings.
This release fixes search and recovery; it does not authorize paid enrichment.

1. Run `gbrain apply-migrations --yes` if upgrade reported a schema failure.
   Migrations 160 and 161 create current-projection statistics and a pending-work
   lookup index. Schema maintenance needs an authorized database role. Do not
   broaden runtime grants or disable row security to make it pass.
2. Run `gbrain doctor`. A pending projection is not proof that source content is
   missing. Restart the upgraded resident `gbrain serve` to let its existing
   worker drain queued Markdown and code rebuilds.
3. For code metadata that still needs repair, run
   `gbrain reindex-code --force --no-embed --source <source-id>` on the brain host.
   The CLI uses the current datastore owner when required. Do not bypass the
   managed writer or roll the brain back to legacy writers.
4. Repeat a source-scoped search and inspect readiness. `projection_pending`,
   `projection_status_unknown` and `vector_candidates_incomplete` all mean the
   results are not evidence of complete retrieval. They can accompany hits.
5. If vectors remain missing after text recovery, explain that distinction and
   obtain any required provider-spend approval before `gbrain embed --stale`.
   Diagnostics and keyless rebuilds must not opt the operator into embedding.

If statistics refresh fails after a batch, ask the authorized database owner to
run `ANALYZE pages(text_projection_revision, knowledge_revision)`. Do not force a
global index plan or increase query timeouts to conceal the failure.
