# Upgrade to v0.60.269.0: a plain managed sync retries recorded failures; `--retry-failed` is a deprecated alias

On a managed source, a plain `gbrain sync` now retries the failure the previous run recorded. Before, only
`gbrain sync --retry-failed` did. `--retry-failed` stays accepted for two releases: it does the same as a plain sync
and prints one `[gbrain notice sync_retry_failed_deprecated]`. On a google or github connector source it still
re-approves failed item receipts. This upgrade has no schema migration and rewrites no rows.

1. **Finish the upgrade.** `gbrain upgrade` runs it. To be sure, on the brain host:
   ```bash
   gbrain apply-migrations --yes --no-autopilot-install
   ```

2. **Drop `--retry-failed` from managed-source schedules.** Look for it in the user's crontab, launchd or systemd
   units, and agent routines:
   ```bash
   crontab -l 2>/dev/null | grep -n -- '--retry-failed'
   ```
   On a managed source, remove the flag; the plain command does the same. Ask the user before you edit a schedule
   they own. Doctor's recipe stays `gbrain sync --all --no-pull --hard-deadline 13m`. Keep the flag on a google or
   github connector source if the user relies on it to re-approve failed items.

3. **Two failures need the user, and no sync retries them.** Preview:
   ```bash
   gbrain repair managed-sync-orphans --source <id>
   ```
   - `slug_mode_refused`: the checkpoint was refused `slug_root_mode_mismatch` while the source keeps the other slug
     mode pin. Retiring the cursor keeps the pin.
   - `checkpoint_moved` (#6834): the source's checkpoint moved outside this run.

   Relay the preview to the user. Apply only with their agreement: `--apply --expect <hash>`, using the hash from the
   preview.

4. **Legacy pages are adopted, not forked.** A file whose page an older gbrain imported under a different slug
   spelling now imports into that page. When several pages match, the file is held as `legacy_slug_conflict`.
   `gbrain sync status --source <id> --json` lists the hold with the pages. The user keeps one and removes the
   others, then syncs. Twin pages that older syncs already created are not merged.

Verify:
```bash
gbrain sync --no-pull --source <id> && gbrain sync status --source <id> --json   # state synced, or a named hold
```
