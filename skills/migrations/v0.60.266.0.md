# Upgrade to v0.60.266.0: retired sync config keys move to environment variables

Five `sync.*` config keys are no longer read: `sync.bulk_max_txn_ms`, `sync.hold_cap`,
`sync.hold_escalate_count`, `sync.hold_escalate_pct` and `sync.parser_regression`. Each one is now an environment
variable of the process that syncs. A value stored on the brain before the upgrade stays in the config table but is
not applied, so a brain that tuned one of them runs with the default until the variable is set. No schema migration,
and the upgrade rewrites no rows.

1. **Finish the upgrade.** `gbrain upgrade` runs it. To be sure, on the brain host:
   ```bash
   gbrain apply-migrations --yes --no-autopilot-install
   ```

2. **Find values that stopped applying.**
   ```bash
   gbrain doctor --only sync_config_keys --json
   ```
   `ok` means nothing to do. `warn` lists each stored retired key with the value in effect now and the variable that
   replaces it:

   | Retired key | Environment variable | Default |
   |---|---|---|
   | `sync.bulk_max_txn_ms` | `GBRAIN_SYNC_BULK_MAX_TXN_MS` | 15000 |
   | `sync.hold_cap` | `GBRAIN_SYNC_HOLD_CAP` | 500 |
   | `sync.hold_escalate_count` | `GBRAIN_SYNC_HOLD_ESCALATE_COUNT` | 50 |
   | `sync.hold_escalate_pct` | `GBRAIN_SYNC_HOLD_ESCALATE_PCT` | 5 |
   | `sync.parser_regression` | `GBRAIN_SYNC_PARSER_REGRESSION` | stop |

   `gbrain config get <key>` prints the value in effect for one key and, on stderr, where it comes from.

3. **Ask the user before carrying a value over.** Whether to keep a tuned value is the user's call. If they want to,
   set the variable where the sync runs: the environment of `gbrain serve` when it runs the catch-up for the CLI,
   the cron line (`GBRAIN_SYNC_HOLD_CAP=200 gbrain sync --all --no-pull --hard-deadline 13m`), or the shell. Then
   remove the stored key so doctor stops reporting it:
   ```bash
   gbrain config unset sync.hold_cap
   ```
   `gbrain config set` of a retired key now warns, names the variable and writes nothing (exit 0).

4. **Rollback keys keep working.** `sync.job_drain`, `sync.foreground_priority`, `sync.federated_v2`,
   `sync.waive_batch` and `sync.bulk` are the ways back that earlier notices named. They stay readable and honored
   until at least 2027-01-14; `config set` writes them with a note saying so. They are not tunables, so do not
   suggest them for tuning. `sync.foreground_priority` is now accepted without `--force`.

5. **Older sync clients.** A serve or PGLite owner on this release accepts `explicitProcessing` from a sync CLI below
   0.60.255.0 until 2026-11-14, ignores it and prints one `[gbrain notice]` naming it. Upgrade every machine that runs
   `gbrain sync` against this brain. The PGLite owner lane now accepts `--lanes N` and `--no-lanes` (it ignores them:
   PGLite publishes without lanes) instead of refusing them.

Verify:
```bash
gbrain doctor --only sync_config_keys --json   # ok, or only the keys the user chose to keep stored
```
