# Upgrade to v0.60.30.0: fix wave 6

Fix wave 6 closes two privacy leaks (private ontology values shown to remote
callers, forgotten facts kept in hot memory), stores investor, partner and
attendance links from the person to the page, links facts saved without an
entity, makes the contradiction judge stricter about time and names, and keeps
the vector half of hybrid search on large Postgres brains. Migrations v187 and
v188 run during `gbrain upgrade`. Never apply a relink or a repair on the
user's behalf without asking.

## What the user will notice

- Remote agents no longer see ontology values saved as private.
- A forgotten fact disappears from the hot-memory block right away.
- "Who invested in X?" and "Who attended <meeting>?" answer from the person
  side. A person only mentioned in meeting notes is a mention, not an
  attendee.
- `remember` without an entity may file the fact on the one person or company
  it names; the response says `entity_inferred`, or warns `NO_ENTITY` with a
  hint.
- A CLI write on a PGLite brain held by another CLI call waits up to 30
  seconds for the lock instead of failing with `owner_unavailable`.
- The next `gbrain eval suspected-contradictions` re-judges every pair once
  (judge prompt v3) and prints its cost estimate first.
- `gbrain doctor` may report `unlinked_facts`, `vector_plan` or
  `self_capture`.

## Step 1: restart everything that runs gbrain

Tell the user, then, with their agreement: stop autopilot and workers, stop
each resident `gbrain serve`, run `gbrain upgrade` on each host, confirm
`gbrain --version` prints `0.60.30.0` through each launcher's binary path,
and restart them.

## Step 2: re-derive relationship and attendance links

The link extractor version moved, so the next `gbrain extract --stale` (or the
autopilot cycle) re-derives body links on its own. Frontmatter links need one
explicit run per source. Ask the user first, then for each source id from
`gbrain sources list`:

```bash
gbrain extract links --source db --include-frontmatter --source-id <id>
```

Each page's own derived links are replaced in one transaction. Manual links
and links created by other pages are untouched. If the user wants a reviewed,
preview-bound repair of historical attendance instead, follow
`docs/guides/attendance-evidence.md` ("Preview-bound historical repair").

Code or routines that walked meeting -> person `attended` edges must now walk
incoming edges (person -> meeting).

## Step 3: link facts that have no entity

Run `gbrain doctor` and read `unlinked_facts`. If it reports a backlog, show
the user the preview:

```bash
gbrain facts relink --dry-run
```

Only after they agree, apply it (the model tier is capped by `--max-usd`,
default $1.00):

```bash
gbrain facts relink
```

If the user does not want automatic entity inference on new facts:
`gbrain config set facts.entity_inference off`. That does not undo earlier
links.

## Step 4: contradiction re-judge

Before the next `gbrain eval suspected-contradictions`, tell the user the
judge cache was invalidated and the run will re-judge every pair. Show the
printed cost estimate and wait for agreement.

## Step 5: verify

```bash
gbrain doctor
gbrain stats
```

If vector search regresses on a Postgres brain, the rollback for this release
is `gbrain config set search.vector_legacy_guard true` on the brain host,
then a restart of serve and autopilot. Report it as an issue.
