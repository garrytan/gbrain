# v0.52.2.0: exact-page reconciliation and derived atom scan state

Upgrade resident owners and maintenance workers before using the new repair
commands. Preserve all existing ownership, source roots, activation state, and
checkpoints. Never delete owner markers, disable guards, or run writer claim,
transfer, or activate as a shortcut for a content disagreement.

Reconciliation requires the existing trusted CLI registration's original and
current grants to permit `put_page` for the exact source and slug. Whole-source
audit additionally requires no slug-prefix restriction. Receipt lookup needs its
own `get_write_request` grant; replaying the original apply artifact and UUID is
the alternative without changing permissions.

1. Let `gbrain upgrade` apply schema migration 163. If schema maintenance failed,
   run `gbrain apply-migrations --yes` using the existing authorized maintenance
   role. The migration adds derived processing state and conservatively copies
   matching legacy markers; it does not rewrite canonical page content.
2. Restart upgraded resident writers and maintenance workers so older processes
   cannot keep writing legacy scan markers. Do not change providers or authorize
   paid enrichment as part of this migration.
3. On the canonical host, use `gbrain sources reconcile <source> --brain <brain>
   --audit --limit 25 --json` for bounded, read-only verification. Continue with
   the returned `next_after` cursor. A sample is not proof that the whole source
   is clean. A missing or invalid owner requires operator diagnosis, not automatic
   registration or activation.
4. For each affected page, run an exact preview using `sources reconcile <source>
   <slug> --brain <brain> --preview`. Save an actionable artifact only to a new
   private path outside canonical repositories with `--out`. Relay conflicts and
   the final resolved result to the operator before applying. Never choose file
   wins, database wins, or timestamp wins on the operator's behalf.
5. Apply only an operator-reviewed ready artifact with an explicit request UUID.
   Keep that UUID after a lost response or pending result. Changed preconditions
   require a new preview; a terminal conflict requires a new request UUID. The
   command retains both originals privately and leaves topology unchanged.
6. Submit the originally blocked memory intent as a separate new request after
   repair commits, then independently read back the fact, visibility, and
   provenance. A committed repair receipt alone does not prove that memory was
   inserted.

Private retained originals outlive temporary recovery records and receipt
compaction. Inspect them using `sources reconcile <source> <slug> --brain <brain>
--backups --json`. Remove an exact terminal backup only after explicit operator
approval with `--remove-backup <reference>`; nonterminal/recovering backups cannot
be removed. Forgetting active memory does not erase backup history.

See `docs/guides/concurrent-writes.md` for the complete command and decision-file
examples. Unsupported managed atom extraction now refuses before model calls;
this migration does not add a general managed dream/maintenance publication lane.

If rollback is necessary, stop new repair submissions and drain or recover every
accepted request using a compatible upgraded owner before reverting the binary.
Never downgrade a live reconciliation queue, remove the additive table or private
backups, or restore an old preimage over newer edits. Inspect the receipt state
instead of changing ownership or disabling writer guards.
