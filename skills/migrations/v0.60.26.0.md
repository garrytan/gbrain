# Upgrade to v0.60.26.0: System One decision support (on with a TypeSafe key for what measurably helps)

This release adds System One: typed decisions from TypeSafe's Jev, or from a
chat model the user already configured, at nine points in search, `think`,
the hook user-prompt path, dream and the fact sweep.

**Without a TypeSafe key, every slot is off.** Nothing is sent to TypeSafe,
and search, `think`, dream and fact writes behave exactly as before.

**With a TypeSafe key installed** (`TYPESAFE_API_KEY` or
`JEV_TYPESAFE_API_KEY`, in the shell or `~/.gbrain/.env`), upgrading turns on
the two slots with a measured win, as a documented default with nothing
written to config:

- **Dream triage** (`triage`): each dream cycle sends transcript windows
  (conversation text, including private conversations) to TypeSafe to decide
  what is worth synthesizing. In the maintainer's end-to-end run it caught
  every buried decision (10/10 vs 3/10) and raised dream spend by 73%
  ($1.50 to $2.60), because it also synthesizes some routine chats.
- **Contradiction proposals** (`conflict`): the sweep after `extract_facts`
  sends fact text (facts are private by default) to TypeSafe and writes
  supersede proposals the user reviews. It never changes a fact by itself.
  It starts at the newest fact, so it never sweeps history silently.

For those two slots the key counts as the user's opt-in for that data. The
other seven slots stay off.

Three schema migrations run automatically: `decision_receipts`,
`decide_calibrations` and `decide_proposals`, with the spend ledger, an
internal state table and the sweep retry table riding along. They create empty tables, backfill nothing, hold no
long transaction and start no background service. No config key changes
value.

Never turn a slot on, set `decide.egress.private allow`, raise
`decide.budget.daily_usd` or set a `force_on` key on the user's behalf without
asking. Every step below that changes the brain needs the user's agreement
first. Opting out is the user's call too, so tell them how and let them
decide.

1. **Upgrade and confirm the schema.** Run `gbrain upgrade`, then
   `gbrain doctor`. Without a key, `decide_health` reports
   `System One is off (every decide slot is off; nothing is sent).` With a
   key it reports `triage=on (default: Jev key present), conflict=on
   (default: Jev key present)` and the opt-out command. If schema
   work did not complete, run
   `gbrain apply-migrations --yes --no-autopilot-install` on the brain host.

2. **Tell the user what System One is, in one paragraph, and stop there unless
   they want it.** Each slot is off (today's behavior) or on (GBrain acts on
   the decision). Code owns every threshold, and every slot falls back to
   today's behavior on timeout, rate limit, provider error, budget or model
   drift. The operator guide is
   [`docs/guides/system-one.md`](../../docs/guides/system-one.md); key setup is
   [`docs/ai-providers/typesafe.md`](../../docs/ai-providers/typesafe.md).
   **If a TypeSafe key is present, also tell the user** that dream triage and
   contradiction proposals are now on by default, what each sends to
   TypeSafe (transcript windows; fact text), that dream spend rose about 73%
   in the measured run, and how to opt out:
   `gbrain decide disable triage`, `gbrain decide disable conflict`, or
   `gbrain decide disable --all`. Do not opt out for them.

3. **If the user wants to try it, run the quickstart.** Ask the user to put
   `TYPESAFE_API_KEY` (or `JEV_TYPESAFE_API_KEY`) in their shell or
   `~/.gbrain/.env`; never ask for the key in chat. Then:

   ```bash
   gbrain decide probe                                  # sends a fixed sentence, nothing from the brain
   gbrain decide probe --query "<a question the brain can answer>"   # show the user the egress line, then add --yes
   gbrain decide status                                 # triage and conflict: on (default: Jev key present)
   gbrain decide enable --recommended                   # already on by default: says so and writes nothing
   ```

   `enable --recommended` turns on only slots with a recorded eval win and a
   passing reference calibration for the pinned model, the same set the key
   turns on by default. It only writes config when an explicit setting
   turned a default off; then show the summary and confirm with the user
   before `--yes`. When none qualifies it prints
   `no slot has a recorded win for jev-1.13.0; see docs/eval/system-one/`,
   exits non-zero and changes nothing. That is expected; relay it.

4. **Relay refusals as written.** A refused `enable` prints a reason code, a
   fix command and a `docs/guides/system-one.md#<reason>` anchor. Read that
   row before running the fix. Slots that send private content (know-to-ask,
   dream triage, claim support, the contradiction sweep) need
   `decide.egress.private allow` on Jev, or an `llm:` route; ask the user
   which.

5. **Upgrades never move an enabled slot.** `enable` pins the resolved model
   id, and a new binary never switches an enabled slot to a newer reference
   calibration by itself. When `gbrain decide status` shows
   `newer reference available`, show the user the threshold change before
   running `gbrain decide calibrations adopt <id>`. An enabled slot that shows
   `on (inactive: <reason>)` is running with today's behavior; relay the
   printed fix. A slot that is on only by the key-aware default uses the
   reference calibration shipped with the binary; to pin it, ask the user
   before running `gbrain config set decide.slots.<slot>.calibration ref:<id>`
   (the id `gbrain decide status` prints).

6. **Kill switch.** `gbrain decide disable --all` turns every slot off and
   restores reranker settings that `gbrain decide enable rerank` changed.
