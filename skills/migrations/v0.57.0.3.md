# Upgrade to v0.57.0.3: honest drift accounting for database-only pages

Preserve existing identity, grants, source routing, capture choices and provider
settings. This release changes only what the read-only reconcile audit reports;
it does not require activating a new writer topology and makes no schema change.

## Memory-only upgrade

```bash
GBRAIN_NO_AUTOPILOT_INSTALL=1 GBRAIN_NO_REEMBED=1 gbrain upgrade --no-autopilot-install
```

The autopilot option propagates through package hooks and migration orchestration
and skips service-unit rewrites. `GBRAIN_NO_REEMBED=1` separately skips potentially
paid reindexing; other migrations still run. For a source clone linked with Bun,
follow the [installation upgrade steps](../../INSTALL_FOR_AGENTS.md#upgrade).

## What changes for reconcile audits

- A whole-source audit (`gbrain sources reconcile <source> --brain <brain>
  --audit`) now counts pages without a canonical Markdown file separately under
  `database_only`, instead of reporting each one as `source_changed` drift.
- Findings for those pages no longer suggest an exact-page reconcile preview —
  there is no recorded file origin to preview against.
- The `drifted` count now only covers file-backed pages. If an earlier audit
  inflated `drifted` with database-only pages, re-running the audit gives an
  honest count; no repair of the pages themselves is needed.
- `database_only` findings are informational: no canonical file exists, so
  reconcile is not applicable. Pages with real missing files or byte drift
  still report `source_changed` as before.

## If rollback is necessary

Reverting the binary restores the previous audit behavior. No migration,
ownership change, or queued repair depends on this release; nothing needs to be
drained or reverted first.
