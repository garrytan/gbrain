This release has no schema migration and rewrites nothing on upgrade. Walk these steps on the brain host and relay
anything that needs the user.

1. **Finish the upgrade.** `gbrain upgrade` runs it. To be sure:
   ```bash
   gbrain apply-migrations --yes --no-autopilot-install
   ```
   A Postgres brain that was wedged on v0.11.0 only because it has no `sync.repo_path` clears on this run; the
   ledger gets a `retry` row with reason `phase_f_no_repo_path`. Doctor `minions_migration` then names the
   autopilot install command for the brain; ask the user before installing it.

2. **Settle renames sync kept aside.** List the open pairs and their remedies:
   ```bash
   gbrain doctor --only rename_identity_downgrades --json
   gbrain repair rename-identity --source <id>
   ```
   For each pair, preview the remedy the report names (`gbrain repair rename-identity --source <id> --slug <new-slug>`,
   plus `--from <old-slug>` when two pairs share a new slug) and show the user what moves. Only after the user
   agrees, run the apply command the preview prints (`--apply --expect <hash> --yes`; destructive). If the user says
   the files are different documents, preview and apply `--close` instead. On a managed source only `--close` is
   available this release (`managed_remedy_unavailable`); `gbrain restore <old-slug> --source-id <id> --force` stays
   the alternative wherever doctor names it.

3. **Bootstrap exit 14.** `gbrain bootstrap harness` (and `--status`) now exits 14 (`bootstrap_cleanup_pending`)
   while earlier shared-skills enrollments or carried token ids still await cleanup. Treat 14 as "wired, cleanup
   pending", not as a failure: follow `fix.next` in the `--json` result (re-run the same command, or relay the
   owner's revoke or restore step), then re-run.

   the writer lock now lives under `GBRAIN_COORDINATION_HOME`, else `~/.gbrain/persistence`. In a container, ask the
   user to set `GBRAIN_COORDINATION_HOME` to a mounted directory outside the checkout so the lock survives
   recreation. Check the path and the rule that chose it:
   ```bash
   gbrain sources writer status --json   # onboarding.sources[].coordination_lock
   gbrain doctor --only coordination_lock_location --json
   ```
   A recorded lock always wins; never edit or delete a reservation.
