# Upgrade to v0.59.10.0: preserve memory during maintenance

This release adds schema v166 fact-vector provenance and changes migration,
withdrawal, export and Gmail attachment metadata handling. It does not authorize
paid repair, archive restoration, attachment downloads or new background services.

1. **Prepare a maintenance window.** Stop all old CLI, resident, sync and worker
   processes for this brain. Take and verify an engine-appropriate full backup.
   Markdown export does not include the full database and is not a backup
   substitute. Mixed old/new writers are not a supported upgrade procedure.

2. **Upgrade and apply the schema.** Run
   `gbrain upgrade --no-autopilot-install`, then confirm
   `gbrain --version` reports v0.59.10.0 or newer. If the binary upgraded but its
   schema work did not complete, use
   `gbrain apply-migrations --yes --no-autopilot-install` after the backup and
   quiescence checks. The new fact identity fields do not infer an old vector's
   model from the current configuration. Unknown legacy identity remains unknown;
   installing the schema does not call an embedding provider.

3. **Inspect before authorizing repair.** Run
   `gbrain migrate embeddings --status`. Preview an explicitly chosen model and
   dimension with `--dry-run`. Any live migration requires an operator-approved
   finite `--max-cost-usd` total; `--yes` does not waive the cap. Interrupted
   requests retain their debits. Read
   [embedding migration](../../docs/guides/embedding-migration.md) for retained
   vector refusals, pending projections and safe retry instructions. Never
   automatically restore an archived source, reset a cursor or force a revision.

4. **Use fresh export destinations.** Export now refuses collisions and occupied
   planned output paths rather than overwriting files. An interrupted destination
   remains visibly incomplete; retry into a fresh destination. Existing exports
   remain historical snapshots and are not retroactively edited by a withdrawal.

5. **Keep Gmail repair opt-in.** Ordinary sync reports attachment inspection for
   that sweep, not historical completeness. Preview
   `gbrain google attachments backfill --source <id>` for an existing managed
   Gmail source. Add `--yes` only when the operator approves the bounded
   metadata-only batch. No attachment content is downloaded or indexed, and
   unavailable or incomplete inspection remains explicit.

6. **Verify the intended outcome.** Check `gbrain --version`, the migration status,
   and representative authorized searches after any approved repair. Genuine
   misses and private-only matches remain clean misses. MCP timeout/source-binding
   diagnostics do not establish a fix for the unresolved Windows/Hermes report.
   Restart only upgraded writers after the maintenance checks succeed.

If a step fails, preserve the backup and diagnostic output and follow the linked
recovery guide. Do not run a destructive reset, restore over intervening writes,
or expand a spending authorization to make the status turn green.
