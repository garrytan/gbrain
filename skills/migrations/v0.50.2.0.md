# v0.50.2.0: verify saved writes and resume unfinished maintenance

Keep the agent's identity, unrelated instructions, capture consent, and existing
grants unchanged. These steps do not authorize paid enrichment or deletion of
historical data. Run host-only maintenance on the brain host, not a thin client.

1. **Check the starting version.** Run `gbrain --version`. If the installation
   predates v0.50.0.0, follow [that coordinated cutover](v0.50.0.0.md) before this
   upgrade. Do not start old workers against a newer authorization schema.

2. **Upgrade and verify the host.** On an already-compatible v0.50 host, run
   `gbrain upgrade`, restart its services through their normal service manager,
   then run `gbrain --version` and `gbrain doctor`. This release adds no schema
   migration. If doctor reports a partial earlier migration, inspect the exact
   failure and use the existing migration recovery procedure; do not run a
   destructive cleanup or authorize queued jobs in bulk.

3. **Restart old PGLite holders safely.** Stop and restart the owning service
   normally so the new lock records structured arguments. Live legacy locks
   without provable identity intentionally refuse automatic PID-reuse reaping.
   Never delete a live lock or run two processes against the same embedded
   database to bypass that refusal.

4. **Repair affected hosted launchers without expanding access.** If the recorded
   launcher still exports a write source or passes `--brain host` for a hosted
   connection, rerun the original `gbrain connect ... --install` workflow with
   the existing private handoff, harness, and installation root. Keep credentials
   local and private. Do not mint a broader grant or replace the agent's unrelated
   instructions. Verify through the absolute recorded launcher: an unqualified
   read may use the grant's readable sources; an explicit source and every write
   remain subject to host authorization. `gbrain call` is intentionally host-only.

5. **Recover affected code sources with an explicit full walk.** Identify the
   source whose Bash parsing or Windows subdirectory sync failed and back up its
   files. Replace the example source ID before running:

   ```bash
   gbrain sync --source code-example --full --no-embed
   gbrain doctor
   ```

   The code chunker version advances to 7, but an incremental run after new
   commits can still skip historical files. Check representative Bash functions
   and changed files after the full walk. `--no-embed` avoids authorizing paid
   embedding here; review the remaining embedding work with the operator before
   running it. Do not re-embed the whole brain merely to update a page signature.

6. **Preserve facts that cannot yet be attached to a canonical page.** New
   unresolved references keep their fact/provenance with a NULL entity target.
   The legacy fence migration reports `skipped_no_page` rather than creating
   stubs. Historical orphan facts, prior stubs, and fence drift are not repaired
   automatically. Keep a restorable database backup as well as source backups;
   Markdown alone cannot recover DB-only facts. Do not delete them or invent
   entity pages merely to clear a diagnostic.

7. **Interpret write and maintenance results accurately.** `storage_busy` on
   worktree acquisition means the write was not applied and was not queued. Read
   the latest page before retrying the complete revision. A saved page can
   separately report embedding failure or supersession; do not overwrite a newer
   page to retry enrichment. There is no durable acceptance queue, caller revision
   precondition, or crash-atomic file/database commit in this release.

   A job with `require_writes: true` must save a page. Prose-only and rejected
   imports fail that requirement; use optional-write behavior only for genuinely
   optional work. Global maintenance and synthesis cooldowns now leave explicitly
   incomplete or budget-deferred work due for retry. Inspect
   `gbrain jobs stats --json` and the relevant job results before restoring
   unattended schedules.

8. **Verify OAuth scopes without broadening them.** A generic client following
   the default challenge starts with `read`, even if its registration permits
   more. Saving requires an explicit authorized `write` request and operator
   approval. Preserve existing authorized sessions; do not purge tokens or
   re-register every client. Discovery no longer advertises `agent`, and explicit
   DCR requests for it remain rejected. SDK/HTTP tests are not evidence of a new
   live ChatGPT or Claude session; verify the intended harness separately.

Report failures with sanitized diagnostics, the installed version, source ID,
and failing step. Keep credentials, private page contents, and private handoffs
out of public issues.
