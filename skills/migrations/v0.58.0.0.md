# Upgrade to v0.58.0.0: explicit attendance and optional question-first recall

Preserve the agent's identity, source grants, capture preferences, provider
choices and existing service opt-outs. This release adds no schema migration
and authorizes no live repair, automatic backfill or paid enrichment.

## Upgrade and verify without changing defaults

1. On a managed deployment, stop and drain older owners and workers before
   replacing them. Retain the original installation and a verified full
   database backup. A Markdown export is not a full backup.
2. Use the supported upgrade path while retaining independent opt-outs:

   ```bash
   GBRAIN_NO_AUTOPILOT_INSTALL=1 GBRAIN_NO_REEMBED=1 gbrain upgrade --no-autopilot-install
   ```

   If an earlier migration failed, inspect that failure before using
   `gbrain apply-migrations --yes --no-autopilot-install`. Do not delete its
   ledger, rerun initialization or enable capture to bypass a refusal.
3. Restart compatible owners/workers and verify the installed version and
   a permitted page read through the existing connection:

   ```bash
   gbrain --version
   gbrain sources writer status --json
   ```

   The version should be `0.58.0.0` or a later approved release. Retain the
   existing brain and source selection; do not switch them just to make a
   check pass. A writer claim is not permission to activate it.

## Keep question-first recall opt-in

Omitted `budget_policy` retains the existing facts-first behavior. Only use
`query_first` for a question where matching page evidence should take priority
over stored facts:

```bash
gbrain recall --query 'What did the planning meeting decide?' \
  --budget-tokens 512 --budget-policy query_first --json
```

The memory verb accepts the same choice as `budget_policy: "query_first"`.
Use `facts_first` for fact-focused consumers. Review returned evidence rather
than treating a small synthetic packing win as a general answer-quality claim.
No query-expansion change or native-harness activation is part of this upgrade.

## Inspect attendance rules before extracting

Read [the evidence and operator guide](../../docs/guides/attendance-evidence.md).
Where the active schema does not override attendance, explicit attendee lists
must resolve to live person pages; ordinary mentions, code examples and hidden
comments are not attendance evidence. Removing supported evidence retracts only
the origin's owned claims. Unresolved references preserve the graph for retry.

Pack-owned directions remain unchanged. In particular, the shipped base and
company packs retain their outgoing attendance mappings and do not gain
incoming attendance lookup. Do not disable or rewrite a pack to force a match.
Restore a missing pack before retrying refused extraction. Normal remote page
writes keep their existing deferred-maintenance behavior.

## Historical repair requires a separate decision

Do not run repair automatically from this migration guide. The trusted-local
`gbrain extract links --source db --repair-attendance --source-id notes --json`
surface can preview a bounded window only after the operator chooses a live
source. Keep the preview private and inspect proposed additions, removals and
skips. MCP and thin clients cannot perform this operation.

Before applying, quiesce older extraction writers, verify a full database backup
and its recovery procedure, and obtain approval for the exact saved preview's
digest. Follow the operator guide's private-directory, confirmation and
checkpoint requirements. `--backup-verified` acknowledges the operator's
verification; it does not create or verify a backup.

Each origin commits separately and briefly locks link writers database-wide.
Changed inputs refuse the preview, and approvals and commit proofs have bounded
lifetimes. Resume only with the exact approved command and private checkpoint;
when the guide requires a fresh preview, obtain fresh approval too. Reverting
the binary does not undo a completed repair.

If verification fails, preserve the refusal and inspect it before retrying.
Report a sanitized description at https://github.com/garrytan/gbrain/issues;
never attach credentials, private previews, checkpoint contents or backups.
