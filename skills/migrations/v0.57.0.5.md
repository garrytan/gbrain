# v0.57.0.5

## fix(timeline): accept a slug-prefixed colon as a Source delimiter (#5282)

`findTimelineSourceDelimiter` — shared by the FS extractor
(`extractTimelineFromContent` Format 1) and the DB parser
(`parseTimelineEntries`) — now falls back to a `Source: Summary` colon
split when no em/en/hyphen delimiter exists. The fallback only fires when
the token before the colon is slug-shaped (lowercase, no spaces:
`manual`, `alice-agent`, `acme/wiki`), and the dash pass always wins, so
canonical write-through rows are unchanged and sentence-shaped
`Note: …` rests keep their `markdown` source default.

- No schema change. No operator action required.
