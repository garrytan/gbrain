# v0.36.2.0 migration history

This release made a now-retired hosted provider the default retrieval stack:
1280-dimensional text embeddings and a cross-encoder reranker. The provider
retired on **2026-09-04** and its switch command has been removed. This is
historical context, not an executable playbook. Original identifiers and
attribution are preserved at Git revision
`6040075c6cb95be5881cc2e1b76ef7d71f4e5d29` (retained on 2026-09-23).

Existing brains had an opt-in, TTY-only prompt. Enter meant stay on the current
provider; non-TTY upgrades only printed information. An accepted switch could
combine a pending chunker upgrade with one re-embed pass to avoid charging twice.
Codex outside-voice review caught that double-charge case before implementation.
The text-vector schema transition and HNSW rebuild were atomic. The prior
embedding model was OpenAI at 1536 dimensions; the retired model's 1280 width
was one of its supported Matryoshka reductions, not a Voyage width.

The release also enabled reranking in `balanced` mode, retained the existing
`conservative`/`tokenmax` choices, and added a check comparing configured
dimensions with the actual `content_chunks.embedding` column.

Do not replay the retired switching, undo or self-hosting instructions. Use
the [explicit-consent migration playbook](v0.46.3.0.md) to inspect a brain,
choose a supported target and approve the work. Upgrading does not convert
stored vectors or authorize a paid backfill.
