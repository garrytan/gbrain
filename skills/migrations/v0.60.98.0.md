# Upgrade to v0.60.98.0: a malformed facts or takes fence never blocks a sync

A page whose facts or takes table cannot be imported without dropping or
guessing rows is now **held** by managed sync (code `invalid_fence`): the rest
of the source syncs, the checkpoint advances, and the hold names the fence,
section, rows and reason. A source such a fence blocked before this release
recovers by itself.

1. **Finish the upgrade.** `gbrain upgrade` runs it; no schema migration is
   added. Restart every `gbrain serve`, autopilot and worker.

2. **Unblock a source a fence blocked.** `gbrain post-upgrade` prints a
   `fence_holds:` line naming each such source. The next scheduled or manual
   sync recovers it automatically; to do it now run:
   ```bash
   gbrain sync --source <id> --no-pull
   ```
   The blocked request is converted in place (`converted_from_failed`): the
   file is held and everything else imports. No `--retry-failed`.

3. **Tell the user what is held, then fix it.**
   ```bash
   gbrain sources status <id>              # each fence hold: fence, section, rows, reason
   gbrain get --source <id> -- <slug>      # read the page
   ```
   Edit only the named fence in the file (the user's file: say what you will
   change), commit, then `gbrain sync --source <id> --no-pull`. Do not run
   `gbrain repair frontmatter` for a fence hold; it does not touch fences. To
   add rows without hand-editing a table, use `remember` (facts) or
   `takes_add` (takes). A `prepare_time` hold was refused against stored rows
   (for example a takes row number a stored take already uses): fix it as its
   `fence.reason` says; after a database-side fix run
   `gbrain sources retry-held <id>`.

4. **Know the behavior changes.**
   - Coordinated writes (`put_page` on a managed brain, managed import) refuse
     a malformed fence with code `invalid_fence` and a `reason`; the wire
     `error` stays `invalid_params` (`take_row_collision` for a stored-row
     collision). Correct the named fence and resubmit with a new request_id.
   - Legacy (unmanaged) sync still imports such a page with its bad rows
     skipped and never holds it.
   - Teams that want fail-closed blocking keep `gbrain config set sync.holds fail`;
     a fence refusal then blocks with the typed text. Company-brain sources
     always fail closed: fix the fence in the repository and commit.

5. **Verify:**
   ```bash
   gbrain doctor --only git_held_files --json
   gbrain sources status --json
   ```
   `git_held_files` lists each source's fence holds with the status read and
   the sync command; it clears when the files are fixed.
