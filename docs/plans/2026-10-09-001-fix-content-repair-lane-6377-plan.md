# Content-repair lane (#6377): sync holds clear themselves, a frontier model decides the cases that need judgment

Thread: GBRA-72. Issue: #6377. Builds on #5988 (holds), #6188 (fence repair tiers, gates, caps, maintenance phase), #6340/#6347 (`sync status` / `sync unblock`, the class / safe_actions / needs_human triple). One PR to `garrytan/gbrain`, version stamped at the merge slot (master + 1 PATCH; no migration expected). Paired gbrain-evals PR for the model-tier eval. ## 0. Why now

Holding instead of failing (#5988, #6188, #6347) was the first half. The second half is still a person: every content hold ends with "gbrain will not guess this repair" and a `fix` that sends an operator to edit a file. On Garry's brain on 2026-10-09 five holds (`invalid_fence` ×2, `frontmatter_slug_conflict` ×3) sat 16 hours until an external agent fixed them by hand; the week before, the same brain needed 198 frontmatter repairs, 471 glued-fence repairs and 146 fence-adoption retries from an external agent writing ad-hoc scripts against gbrain's error messages. Four of the five holds were mechanical. The fifth (a duplicate person page) is the case where gbrain's deterministic proposal (delete the `slug:` line) would have made the brain worse: it would have minted a second page for the same person.

Goal: the end user never sees a content hold unless gbrain itself, after trying, says `needs_human` with a one-paragraph reason written for a person and the exact command that applies what it proposes.

## 2. Design

One lane, two tiers, one contract. Every repair goes preview → hash-bound apply → receipt, and the maintenance cycle applies the current plan unattended under the caps, exactly as `fence_repair` does today. The model **chooses**; every byte written comes from a deterministic rule and passes the gates.

### Lane A: fence structure repairs become deterministic (Tier 1), with the model for the judgment residue

A1. **`merge_fences`** (new Tier 1 fix class; clears `repeated_marker`). When one section holds N > 1 fences of the same kind and each is balanced (begin and end marker) with a header that maps to the canonical columns: the later fences' rows are appended to the primary fence in document order; a row whose cells (every column except the row number) equal a kept row's cells after cell trimming is dropped as an exact duplicate; an appended row whose number collides with a kept row is renumbered above the page's highest number (stored rows consulted as the `renumber` rule does; `superseded by #N` references follow); the later fences' markers, tables and a duplicated section heading immediately above them (`## Facts` twice) are removed; blank lines collapse to one. Anything else (an unbalanced repeat, a header that does not map, a repeat whose region holds non-table text) stays `repeated_marker` manual. Near-duplicates (same claim, different confidence or date) are **not** deduped: both rows stay and the contradiction machinery owns that case.

   **Validator (Codex #3).** The gates pair `primaryFence` before and after, positionally, so a merge is invisible to them. `validate.ts` gains a merge mapping: when the before section holds several fences of a kind and the after holds one and the fixes include `merge_fences`, the before rows are the concatenation of every fence's rows in document order, each mapped to an after row by occurrence or marked `duplicate_of: <occurrence>`; gates (b) claims, (c) numbers, (d) visibility and (f) cells run through that mapping; gate (e) accepts exactly the rows marked duplicate and only when the kept row's cells are byte-equal after trimming. Gate (c) already skips a number that is not page-unique (`validate.ts:126`), so a renumbered colliding row passes it and every unique number keeps its claim. The receipt carries occurrence identities (`merged: {fences: N, rows: [{occurrence, from_fence, kept_as | duplicate_of}]}`), never cell text. T1 mutates a claim in the *second* fence and proves gate (b) rejects it.

A2. **Closing an unclosed fence ahead of trailing text** (clears `unclosed_trailing_content`; Codex #2 reshaped it). The fence has no end marker, its rows are one contiguous block, and lines follow the last row. Closing after the last row makes those lines visible to whatever reads through the privacy boundary. Two cases:
  - **No exposure**: the page is `private` (effective visibility: `effectiveVisibility`, the same read the fence ctx already makes). Remote readers never see a private page's body and local readers see everything, so nothing new is disclosed; the end marker is inserted after the last row deterministically (`close_fence`, as today when nothing trails) and the receipt records `trailing_lines: N`. Gate (g) is unchanged: on a private page the boundary hides nothing from anyone, and the gate exemption is keyed to that fact, not to the fix class.
  - **Exposure** (a `world` page): nothing unattended. The model tier (A3) classifies the tail; a `prose` verdict makes the close **previewable** (the preview prints the exact lines that would become visible and the hash binds them), and only an explicit `gbrain repair content --apply --expect <hash>` applies it. Unattended runs (cycle, `sync unblock`) record `needs_human` with the rendered paragraph: "gbrain can close the takes fence in the timeline after row N; lines L1–L2 would then be visible to readers of this page. Approve with: gbrain repair content --source <id> --only <path> --apply --expect <hash>". So the one judgment that discloses text is the user's, hash-bound, as Codex asked; everything else clears itself.
  - A tail that mentions a fence marker stays `marker_near_miss` manual as today.

A3. **Model tier for the tail** (new Tier 3 request kind `tail`, same gateway call, caps, ledger and memo as rows). The model sees the fence's begin line, header, every row and the trailing lines to the section end (never the rest of the page) and answers one JSON object `{"tail": "prose" | "rows" | "unsure"}`. `rows` (the tail holds table rows written without pipes) and `unsure` render `unclosed_ambiguous_tail` (new reason, manual, with the exact edit); `prose` on a world page yields the previewable close above; on a private page the model is never called (A2 closes deterministically). The memo key is the fence region's sha256 + model + prompt version, so an unchanged tail never costs twice and a transient `llm_unavailable` does not consume it. The `rows_through_line` realignment idea from the first draft is cut (Codex #1): once a fence is closed, the existing row rules and the row prompt handle its rows on the next normalization round.

### Lane B: `frontmatter_slug_conflict` gets a judgment tier; merging is recommended, not executed

B1. **New repair kind `slug-conflicts`** (`src/core/repair/slug-conflicts.ts`; `REPAIR_KINDS` + `registry.ts` with `preview_bound: true`, `spends: 'llm'`, `checks: []` so doctor's first-match lookup keeps `git_held_files` on `frontmatter` (Codex #12), **not** `explicit_only`, so `--all`, `doctor --remediate` and the cycle phase run it). Candidates: every `frontmatter_slug_conflict` hold of the sources in scope (plus `--only <path>`). Identity is resolved, not textual (Codex #8): the frontmatter slug is normalized the way the screen does, resolved through `slug_aliases` (`readPageSnapshot(..., {resolveAlias: true})`) to a page id in the same source; a slug that resolves to the held file's own page is `slugExempt` and never a candidate; the held file may have no page yet (`page_id: null`, a new file) and that is a normal candidate.

B2. **Deterministic tier** (no model, confidence `high`): `remove_slug` when the named slug resolves to **no page** and names no other file in the checkout (a stray `slug:` from a template or a renamed file; nothing to merge into), or when the named page has a different `type` **and** shares no title token with the held file (the two COMPENDIUM cases). The edit is the one line, applied through the frontmatter repair's existing publication path (`prepareRepairPublication` / `submitManagedFileRepair`: exact bytes bound to the sha256 the preview read, import, hold clear and Git target effect in one coordinated write; legacy sources back up, write, import, clear the hold and print the commit step). Everything else is `ambiguous` → B3.

B3. **Model tier** (`tier: 'llm'`). The model sees: both files' frontmatter, headings and first 60 lines of body plus any line that mentions the other's slug anywhere in either body (Codex #7: evidence beyond the first 60 lines), both slugs and paths, the hold's reason, and the allowed answers. It returns one JSON object: `{"action":"remove_slug"}`, `{"action":"merge_into","canonical":"<one of the two slugs>"}` or `{"action":"needs_human"}`, plus an optional `why` sentence that goes into the run's output only, never into hold metadata (Codex #11). Same provider path as the fence tier, same failure classes, same `thinkingOffControl` and output ceiling. Memo key: sha256 of both participants' content + both ids + model + prompt version + rules version. Model: `models.content_repair` (explicit always runs) else `models.fence_repair` else the content-repair measured list (section 4), else the fence list. **Caps and ledger (Codex #9):** the kind reserves against the existing `FENCE_REPAIR_LEDGER` identity (one `fences.repair.max_usd_per_day` for the whole lane, today's prior spend counted) and the same per-page cap; `repair content` passes the fences run's remaining allowance into the slug-conflicts run. `fences.repair.llm=false` turns the model tier off for both kinds; `--no-llm` per run.

B4. **Outcomes.** `remove_slug` (deterministic, or the model's answer) applies as in B2. `merge_into` is **not executed in this PR**: it becomes `needs_human` with the rendered paragraph "This file and page `<canonical>` describe the same `<type>`; gbrain recommends merging the unique sections of `<path>` into `<canonical>` and deleting `<path>`, then committing; the hold clears on the next sync. gbrain does not merge pages by itself yet." and the recommendation stored as codes and slugs on the hold (`meta.content_repair: {action:'merge_into', canonical, model, at}`). `needs_human` from the model renders the generic paragraph ("gbrain could not decide whether `<path>` and `<canonical>` are the same page; decide which keeps the slug …"). Codex #4–#7 show that a general lossless merge needs coordinated two-page intents (both ids, revisions, incarnation, owner epoch, file hashes), withdrawal and metadata preservation rules, revision-bound deletion and database-aware recovery that the phantom path has only for its narrow shape. That is a feature of its own, filed in TODOS.md with those requirements; the acceptance criterion for the duplicate case ("merge_into … or needs_human with that recommendation, not a slug deletion") is met by the recommendation.

B5. **Receipt, trailer and hold state (Codex #6, #11).** Every content repair commit (fence and slug-conflict) carries the Git trailer `gbrain-repair: <hold_code> <tier> <confidence>` through the commit note in `effect-model.ts` (`fenceRepairCommit` gains a trailer line the Git effect prints after a blank line; legacy commit steps print the same `-m` pair). The durable receipt is the write's outcome: the existing `fence_repair` receipt gains `merged`/`trailing_lines`; the slug-conflict write carries a `content_repair` receipt (action, tier, confidence, model, cost, before/after sha256), validated by a parser like `parseFenceRepairReceipt` so nothing forged reaches a commit message. Receipts distinguish `published` from the Git effect's own state (`committed: effect | commit_step | not_in_git`) as the fence receipt does today; no promise about reverting beyond "git revert of the single file commit restores the bytes; the hold then re-screens". Hold state: `meta.content_repair` is written with `recordContentHoldRepair` (conditional on the hold's `upstream_version`, like `recordFenceHoldRepair`), carries reason codes, slugs, `at` and `next_attempt_after` only, and `writeGitHold` keeps it when a re-screen rewrites a hold with the same `upstream_version` and code; a changed file drops it. `sync status` renders `needs_human: true` and the paragraph from those codes (`human_reason` templates in `sync-fault-class.ts`), never model prose. A hold the lane could not decide is retried on `next_attempt_after` (24 h for `llm_unavailable`/`budget_exhausted`, never for `needs_human` until the file changes).

### Lane C: the lane runs by itself

C1. **Cycle phase `content_repair`** (`src/core/cycle/content-repair.ts`, after `fence_repair` in the phase table): one bounded run of `slug-conflicts` through `repairRunner` (apply on a real run, preview on dry run), deadline min(120 s, a third of the job's remaining time), gated on `fences.repair.enabled`; reports counts by action and reason, spend and the oldest unresolved hold's age; never fails the cycle. `holdRepairSteps` says "the next maintenance run repairs the fence and slug-conflict holds it can by itself" when the lane is active. Every unresolved hold stays listed with its state (`needs_human`, `paid`, `owner`, `apply`): nothing hides budget-blocked or owner-unavailable work (Codex #12).

C2. **`sync unblock --apply`** performs `repair`: for `invalid_fence` holds it runs the `fences` kind on those paths, for `frontmatter_slug_conflict` the `slug-conflicts` kind, each a bounded apply under the caps, then schedules the re-screen and prints the sync. `UnblockOutcome.applied` gains `action: 'repair'` with per-path structured outcomes (`repaired | held | needs_human | skipped`, reason code, `llm_usd`, receipt ref, exact next action); `--no-llm` keeps to the free tiers; `--no-repair` restores the old refuse-only behaviour. The runbook sentence "unblock writes no page" changes to "unblock writes only hash-bound repairs and prints each receipt" (BEHAVIOR_CHANGES row). `invalid_frontmatter` and `rename_held` still route to `repair frontmatter` (interpretive YAML fixes stay consent-gated; TODOS entry with the weekly counts from the issue).

C3. **`gbrain repair content`** runs `fences` then `slug-conflicts` for the same `--source`/`--only` selection, printing each kind's own preview hash (no combined hash scheme); `--apply` without `--expect` applies both current plans (both kinds are `preview_bound` without `explicit_only`, as `fences` is today), `--apply --expect <fences-hash>[,<slug-hash>]` applies exactly those sets, `--max-usd` is the lane's allowance for the run (remaining allowance flows from the first kind to the second). Both component plans are built before the first mutation (Codex #10). `gitHoldFix` names this command for both codes.

C4. **Reason table and surfaces.** New reasons in `reasons.ts`: `unclosed_ambiguous_tail` (manual, exact edit), `tail_exposure_approval` (paid: false, actor `user`, the hash-bound approval above). Error registry rows with agent-operator envelopes for `unclosed_ambiguous_tail`, `tail_exposure_approval`, `content_repair_needs_human`, `merge_recommended`; `bun run build:error-codes`. `holdRescreenDue` is unchanged for slug conflicts (already unconditional, `sync-holds.ts:343`); `FENCE_RULES_VERSION` bumps so older fence holds re-screen under the widened rules.

### What this plan does not do

- No LLM-composed text, no model-executed merge: the model chooses among coded actions; every byte written comes from a deterministic rule and passes the gates.
- No page merge executor (B4; follow-up with Codex's requirements in TODOS.md).
- No YAML frontmatter interpretation unattended (the 198 weekly frontmatter repairs): TODOS.md.
- No change to what `put_page`/`capture` accept on write beyond the Tier 1 `merge_fences` rule, which `fences.normalize` already governs (lossless, gated).

## 6. Risks and the answer to each

- Disclosing hidden text → only private pages close unattended; world pages need the user's hash-bound approval of the exact lines (T2b proves remote reads stay clean until then).
- A wrong `remove_slug` mints a duplicate page → the deterministic tier removes a slug only when there is nothing to merge into (no page, or a different type with no title overlap); the model tier's hard-failure eval covers the rest; `merge_into` never deletes anything in this PR.
- Dedup drops a real row → byte equality after trimming only, recorded per occurrence; the validator mapping protects every kept row.
- Spend → one shared day cap (default $1), memo, per-page cap; `fences.repair.llm=false` is the kill switch; `--no-llm` per run.
- Racing a sync → both kinds use `repairBusy` admission re-reads and the coordinated file-repair intent's hash binding, as fences does today.
- Two threads editing `write-refusals.md` (GBRA-57) → coordinate before the docs lane; merge master before the gate.
