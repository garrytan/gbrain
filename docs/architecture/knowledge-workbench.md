# 知识工作台与模型服务

更新：2026-10-12，统一产品版本 1.4.59。请求上下文、连接恢复及验收边界见下文，工作台附件继续随用户消息保存。

## 模块边界

Desktop 与浏览器共用 `admin/src/workbench`，包含会话列表、消息、模型选择、知识辅助和输入区。`src/product/workbench` 独立承载会话生命周期、文件存储和受认证的 Admin API。`shared/workbench.ts` 定义跨端契约。原导入功能移到 `knowledge-import`，不再承担对话工作台职责。

模型调用复用 Core Gateway，知识检索复用 Admin 既有检索流程，再按命中的 Source 精确读取页面。工作台不复制 Gateway、向量引擎、OCR 或数据库业务逻辑，不依赖外部 MCP 客户端。

会话按当前数据库标识隔离，保存于配置目录下 `workbench/<数据库标识哈希>`。会话档案保存于独立目录；开启自动记忆后，新用户回合通过下述记忆任务进入 Facts 和派生知识页，原始资料不改写。消息先落盘再生成，支持取消、显式重试、修改已发送问题并从该处重答、删除、重命名和服务重启后的中断提示。知识库助手只有一个。助手设置里可以改名称、头像、默认模型、描述、温度、系统提示词，以及新对话是否默认检索当前知识库。上下文按该助手单独设置：默认最多带上 24 条完整消息，并按所选模型的上下文长度估算，到达约 80% 后把更早的完整轮次压缩成摘要；模型没填上下文长度时按 32000 token 估算，明确标记容量未知。摘要模型可以单独指定，留空则用当前对话模型。会话不再有 200 轮上限，完整记录仍留在会话里。长消息分段完整送入摘要；摘要失败、空响应或超长响应时本轮报错，不推进摘要边界，也不使用截断摘录继续回答，原记录和上一次成功摘要保留供重试。回答通过 Gateway 的文本增量写回会话，页面轮询显示已生成的部分。单次输出按模型思考能力、已知输出上限和当前窗口动态预留；普通模型基准 4096、思考模型基准 32k，均受窗口约束。遇到长度上限自动续写，最多 8 段；仍未写完时界面提示可以发送「继续」。知识库辅助未检索到资料时，回答上直接标明这是一般知识。回答标题使用模型的界面名称。

发送完成与列表刷新分开处理；自动清理使用 `emptyOnly=true`，后端仅允许删除没有消息且未生成的会话。发送响应丢失时保留并重新读取已接收的会话。流式备用模型切换通过可选 `onTextReset` 清除失败片段，工作台只重置当前续写段，保留已完成段落并更新模型名称。不支持重置的流式调用方在已经输出文字后不会继续拼接备用模型；未使用流式回调的调用方保持原有行为。

## 老用户兼容

### 1.4.53 请求上下文子系统

`context-runtime.ts` 承载每次请求整形、实际 usage 校准、工具结果预算、结构裁剪和分批历史压缩；`context.ts` 保留会话规划和完整记录的摘要边界，`tools.ts` 适配既有知识工具及下文的原生记忆业务工具。模型窗口来自当前端点保存的模型元数据，未知时明确采用保守估算；回复上限同时遵守 Gateway 既有模型/端点输出限制。系统提示、摘要、工具 Schema、消息、资料和多模态成本均参与请求核算。

每批工具在执行前按 toolCallId 分配不可变份额，四路以内并发仅对显式幂等只读工具开启；默认调用和非幂等工具保持顺序，崩溃回放也保持原顺序。工具结果按结构缩短文本，保留 source_id、slug、引用和 nextOffset；空间不足返回明确的缩短标记，不把搜索标记为失败。每次模型请求前先裁剪旧工具结果和冗长工具说明，再压缩完整的更早轮次，保留最新问题和最后一组工具调用/结果。预附加知识节选也按剩余空间让额，系统指令和材料边界保留。生成中的摘要只调整请求视图；已保存的工具记录仍留在会话，完整知识原文继续由既有接口读取。轮次开始的持久摘要沿用会话存储，重载或切换更大模型后不会重新展开已压缩前缀。摘要失败或被截断不推进持久摘要边界，空最终回答不标成功。

Core Gateway 仅增加可选的请求整形返回值、只读工具并发和上下文传递。工作台 Ollama 带工具请求复用 `/api/chat`，携带本次窗口、原生工具定义和具名工具结果；同轮保持固定窗口，避免每个工具步骤变更 num_ctx 导致模型反复装载。未声明上下文的既有工具调用仍使用原协议；其他端点不发送 Ollama 参数。Qwen3.5 及之后不添加 `/no_think`；服务端无法关闭思考时仍保留预算、裁剪和压缩保护，不能保证所有服务都能关闭思考。

本轮借鉴 Cherry Studio 提交 `36dd9771b785bd343a03acc35e0ce88371b72162` 的 [请求预算](https://github.com/CherryHQ/cherry-studio/blob/36dd9771b785bd343a03acc35e0ce88371b72162/src/main/ai/contextBuild/resolveInputRoom.ts)、[工具结构裁剪](https://github.com/CherryHQ/cherry-studio/blob/36dd9771b785bd343a03acc35e0ce88371b72162/packages/aiCore/src/core/context/truncator.ts) 和 [请求整形与压缩分工](https://github.com/CherryHQ/cherry-studio/blob/36dd9771b785bd343a03acc35e0ce88371b72162/src/main/ai/runtime/aiSdk/params/features/contextBuild.ts)，按 PMBrain 接口独立实现，没有复制 AGPL 源码或引入 Cherry 的数据层。与 Cherry 的差异：不新增文件离线存储/VFS 工具，知识原文继续由既有精确 Source/slug/offset 接口读取；不开放文件或写入工具。真实模型验收与可重复协议测试分别记录在现有台账，不能把脚本端点当作真实模型质量证据。

读取模型服务时同时合并旧自定义模型清单，保留密钥、模型 ID、已选用途和维度。旧配置里已经单独保存的向量地址，在用户修改该平台 API 地址之前继续用于向量调用；修改地址后对话和向量改用这一份。选中的旧用途保持 `custom-openai` 路由；其他模型按服务别名路由。获取模型列表只展示候选，不自动并入已添加模型。启用开关和模型增删会立即保存。云端密钥在添加密钥弹窗确认后保存，API 地址在添加端点确认后保存；本地服务不填写密钥。添加自定义提供商在同一个窗口填写名称、密钥和一份 OpenAI 兼容地址，点「添加」后才保存，并接着打开选择模型。知识库模型配置切换后自动保存，更换已有向量模型仍要确认。增删未使用的模型、删除未使用的自定义服务商只写配置，不重启本机服务。删除自定义服务商如果带走了地址或密钥，运行中的服务会重新读取配置。内置平台不能删除。模型行显示名称，自定义名称下方显示 API 模型 ID；只有多个模型共用的分组，或用户单独写过的分组，才显示分组标题。密钥、地址和当前普通模型、OCR 模型保存后，由运行中的服务重新读取配置。更换向量模型、切换数据库或升级迁移仍会重启服务。保存使用配置版本检查和原有备份机制，避免覆盖并发设置。

当前使用中的向量接口地址不能直接改成另一个服务；需要通过原有模型用途切换和维度确认流程。此次升级不执行向量重建、Schema 变更或知识迁移。模型价格及能力标签仍为可维护元数据，不承诺计费、自动联网或工具执行。原高级分层及阶段路由通过既有配置 API 保留。

### 1.4.54 模型请求生命周期与历史证据

输出预留同时受模型声明、当前窗口四分之一及实际输出能力约束。历史规划、预检索和循环内请求复用同一预留值，输入预算由扣除该预留后的空间乘压缩阈值得出，不再同时使用固定 4096 与动态预留。小窗口保留必要证据，大窗口仍可给思考模型预留 32k；无法容纳当前问题时明确报告本地预算限制。

参考 [LibreChat agents 的压缩与历史管理](https://github.com/LibreChat-AI/agents/blob/97b2db3a329c105c39a250fd39534701b6c9ddb1/docs/summarization-behavior.md)、[ai-retry 的流式重试边界](https://github.com/zirkelc/ai-retry/tree/8de8706bdc2eb79dc83e653c3a10fc22b26ee797) 和 [AI SDK 超时机制](https://ai-sdk.dev/docs/reference/ai-sdk-core/stream-text)。独立适配现有 Gateway 和 GBrain 检索，不复制第三方代码或更换数据层。

`src/core/ai/chat-request-runtime.ts` 提供可选请求策略。Workbench 在回答、摘要与工具循环中启用，其他调用方保持原超时。首个有效响应、连续无进展、单次请求和整轮会话分别计时；空 SSE 心跳不算进展。缓存 Provider 的 fetch 通过异步作用域获得当前请求信号，Bun 的隐式传输超时仅在此策略启用时关闭。OpenAI SSE 缺少结束标记、Ollama 缺少 done 不会被当作完整回答。

云端默认首响应 180 秒、无进展 90 秒、单次 600 秒、整轮 15 分钟；Ollama/llama-server 分别为 600 秒、180 秒、1200 秒、30 分钟。可通过 `PMBRAIN_ASSISTANT_FIRST_RESPONSE_TIMEOUT_MS`、`PMBRAIN_ASSISTANT_IDLE_TIMEOUT_MS`、`PMBRAIN_ASSISTANT_REQUEST_TIMEOUT_MS` 和 `PMBRAIN_ASSISTANT_TURN_TIMEOUT_MS` 单独配置，单位毫秒，最小 1000。计时涵盖重试和退避。网络断开、5xx、首响应或无进展超时最多恢复一次；认证、真实上下文超限、解析错误、总期限及用户停止不自动重试。SDK 内部重试关闭，避免重试叠加。

恢复只重发当前模型请求，已完成工具结果保留，不重放检索，也不消耗正常工具轮次。失败响应的增量通过 onTextReset 替换；不支持替换的调用方在发出文字后不重试。等待、思考、生成、工具选择和恢复阶段可观察；完整/失败请求保存尝试、耗时、Token 及输出上限。失败请求未返回用量时记为未知。用户停止、服务重启中断、超时、连接失败、本地预算和服务上下文拒绝分别持久保存，刷新可重载。

模型上下文采用完整历史的投影，先缩短已消费工具结果，给最新未消费证据保留空间；持久正文不随请求裁剪。跨轮引用按精确 Source/slug 合并，并在投影中重编号；历史观察与助手正文分开，原存储不改写。工具循环预留最后一轮直接回答，将该轮的原生工具历史转换成只读证据投影，避免持续查资料直到轮数耗尽。拒绝原生工具的端点改用受限 JSON，仍复用同一工具执行器及输入校验；schema 被拒则移除，协议能力按端点和模型在当前进程缓存。

摘要中的引用使用完整会话的精确 Source/slug 映射，近期消息全部被折叠时也保留来源卡片。压缩前只重编号请求投影，旧正文、旧角标和原卡片不改写。请求目录只列当前正文、摘要和节选实际引用的来源，避免把全部历史来源标题塞进上下文。

整句预检索未命中时，提示模型用人物、项目或主题关键词调用既有 knowledge_search；完成校验要求至少执行一次关键词检索，再判断是否缺少资料。多词查询均为空时，要求再用单独的人物名、项目名或一个主题词核对；被校验拒绝的提前结论不会拼进最终回答。该校验仍受正常轮数和最终回答额度约束，不修改 GBrain 的检索算法。模型通过精确的 source_id、slug 字段读取资料，不把带斜杠的展示路径当作工具参数。

`src/core/ai/tool-text.ts` 根据 [DeepSeek 官方 DSML 编码定义](https://huggingface.co/deepseek-ai/DeepSeek-V3.2/blob/main/encoding/encoding_dsv32.py) 独立解析 calls/tool_calls/function_calls、具名 invoke 及 string 参数，兼容单/双分隔符；先转换成统一调用，再由原工具执行器验证权限和 Source。无效或截断协议不当作成功回答；流式输出隐藏思考和协议标记。Core 通过可选回调启用，其他业务原有协议不改。该请求恢复适配没有引入自动模型探测或文件 VFS；原生受控写入工具见 1.4.59 章节。

工作台及启用策略的原生 Ollama 同时识别完整思考块和缺少开头标签的结束标记。已输出片段需要重新分离时，通过替换回调重置当前段；选择工具时的文字不拼进最终结论，普通正文的空白保留。默认 CLI 的无工具思考回退契约继续保留。

## 原生对话记忆（1.4.59）

用户确认实施后，内置助手通过 Core、Operations 与 Product Task Runtime 接入，MCP 仍供外部 AI 使用。助手设置复用全局 off / salient / all 与临时 TTL；新对话选择未归档的实际 Source，旧会话继续使用 default。关闭配置保持关闭，历史消息不自动回填。完整消息、实际工具输入/结果、编辑和重试分支留在会话文件；原生自动任务只处理新回合的用户陈述。

回合先保存并捕获配置与内容版本，回答结束后提交持久任务。任务身份覆盖数据库目录、Source、会话、消息及版本，记录每块完成状态和事实 ID。失败独立于回答，任务中心按原任务继续；退出后继续未完成部分。执行租约、最新消息、实际 Source、开关和可见性在写入与提交时复核；较旧执行者不能覆盖新回执。Windows 回执采用短哈希路径与 Core 原子写入。

Core 提炼增加可选 transient 分类和明确纠正的已知事实 ID。临时状态按捕获时间和配置 TTL 过期，过去事件、长期偏好与决定不统一过期；缺少分类报错。短中文、事实与问句混用、长消息、第三方引用和一次性操作分别过滤。原生 writer 使用已有数据库写入，避免对原始 Markdown 追加 Facts fence；同源同实体同类型、同可见性及同持久性去重，纠正保留旧事实历史。现有配置模型可生成新事实向量，不启用未配置服务。

自动召回复用 GBrain 实体定位及当前 Source 的有效 Facts，采用关键词与实体匹配，共用回答证据预算；没有新增独立 Facts 语义向量索引。派生快照不作为当前事实检索，避免遗忘或过期后从旧快照重新出现。记忆卡片按原始消息版本查看出处；删除会话保留已沉淀知识，出处缺失显示真实错误。

派生记忆页通过 Core 导入和链接协调关联已有知识。只有已配置的 synthesize 才进一步处理新产物；输入仅为公开稳定事实，私有和临时内容不进入正式知识语料，不默认打开深度整理。原生工具按当前明确请求开放 remember、forget、已读取且版本一致的同源页面追加及快速维护任务。追加加锁并保留原正文；停止在提交前复核。没有整页替换、删除、批量修改、任意 Shell 或通用编码工具。

验收记录见统一变更台账和 2026-10-12 实施方案；源数据和正式配置不参与 QA。源码与安装发布验收分别记录。

## 版本与验证

唯一产品版本来源是 `desktop/package.json`。根 package、VERSION、内嵌 Admin 和发布清单同步同一版本，使用 `bun run version:sync` 和 `bun run check:version-sync` 检查；保留构建所需字段，不另发浏览器版本。

定向测试覆盖老配置继承、分接口路由、缺少密钥、鉴权错误、本地模型分类、Ollama 部分详情失败、多轮真实 HTTP 请求、Source 引用隔离、取消/重试及重启持久化。1.4.54 使用隔离资料实际验证 MiMo、DeepSeek 各四轮，检索峰值均为四路并发，正文读取、摘要和重载通过。真实 Qwen3.6 前三轮通过，第四轮在执行中断和服务恢复后重试通过，不能描述成四轮无中断连续运行；另一次真实请求同时执行三路搜索，核对预算、工期、负责人和三项引用。原脚本只匹配“八月”导致实际“8 月”回答验收失败，修正同义形式后复核原始响应通过，没有因此修改产品代码。所有测试资料均未变。HTTP 脚本另外验证四类端点的断线恢复、校验后的 JSON 协议以及 DSML。模型凭证仅用于实际请求，不输出或写回；正式知识库和原始资料不参与测试。当前源码页面、Windows 六条核心用户旅程、基础 runtime 与发布门禁证据写入统一台账，原生安装包及 GitHub exact-SHA CI 待用户提交打包后验收。
