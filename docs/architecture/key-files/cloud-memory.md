# Key files: HydraDB cloud memory

[Subsystem index](../KEY_FILES.md). Current behavior and invariants.

- `src/core/hydradb.ts`, `src/core/search/hydra-primary.ts`, `hydra-filters.ts` — opt-in HydraDB client and primary relevance ranking. Both public hybrid entry points and keyless recall consult the cloud backend before local embedding capability. Search metadata names `backend: hydradb`; operations preserve that order instead of running local fanout, fact-ranking additions or escalation. Source and live read policy remain local authorization checks; schema-expanded type aliases, date/slug filters and offsets do not switch backends. Unknown cloud pages have unknown trust, cannot pass a trust floor or proactive suppression, and never acquire a local fetch id. Explicit keyword enumeration, image embeddings and structural symbol walks retain their local contracts.
- `src/core/hydradb-mirror.ts`, `hydradb-transfer.ts` — serialized write-through and cursor catch-up. PostgreSQL uses a reserved transaction advisory lock across processes (also pinned through transaction-mode PgBouncer), with keepalive and transfer cancellation on lock connection failure. Source archive transitions are reconciled independently of page timestamps; restored sources are replayed, and failed transitions retain their state for retry. Disconnect removes only this brain's shared-vault reference. Page identity includes source, slug and microsecond update time; old cursors replay once. The shared hydraProjection excludes private, embed-skipped and quarantined pages before full-body projection and title redaction; the benchmark upload uses the same projection. Per-item queue acceptance and asynchronous indexing must succeed before the cursor advances; delete failures retain the deletion cursor. The background drainer tracks pending key checks and bounds shutdown waits. The optional live smoke only creates and deletes synthetic databases.

- `src/core/hydradb-response.ts`, `src/core/search/hydra-evidence.ts`, `src/mcp/hydra-output.ts` — normalize legacy/unified HydraDB evidence, admit supporting chunks, and use the SDK Markdown formatter. Canonical Markdown is delivered only when every referenced source is admitted and the output has no truncation; filtered responses reconstruct permitted evidence. Explicit or configured page, section and window requests deliver authoritative held-page text with unchanged match-span coordinates; permitted cloud context is formatted at the presentation boundary. Stdio MCP also carries structured results; HTTP preserves its JSON block for existing clients.
