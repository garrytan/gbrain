## Skill resolver

The engine-free skill resolver behind `gbrain skills index` and
`gbrain skills resolve`. Guide: [docs/guides/skill-resolver.md](../../guides/skill-resolver.md).
Contract schemas: `docs/schemas/skill-resolver.v1.*.json`. Every module under
`src/core/skills/resolver/` is a leaf: no engine, operations table, provider or
`skill-catalog.ts` import, static or dynamic (`test/skill-resolver-module-graph.test.ts`).

- `src/core/skills/resolver/index.ts` — the library entry (`gbrain/skill-resolver` export, and the entry of the Node bundle `gbrain-skill-resolver.mjs`). Re-exports build, status, remove, resolve, `openCatalog`, `buildSkillIndexOffThread`, `ResolverError`, `resolverHome`; `resetSkillSession` deletes one session's state; `gcSkillSessions` runs one bounded async GC pass; `RESOLVER_FEATURES` names what an adapter may rely on.
- `src/core/skills/resolver/resolve.ts` — one turn: `normalizeTurnInput` (the turn-input schema, unknown fields refused, message capped at 8 KB), catalog loading through a `TurnSource` (`openCatalogIndex`: receipt and ranker identity, index size; then per turn the gbrain version and, for `dir` and `claude_plugins` catalogs, the sliced stat freshness check: at most `STAT_CHECK_SLICE` entries per turn, a full sweep at most once per `STAT_CHECK_INTERVAL_MS`, cursor in `stat-check`; `stale.stamp` is written without fsync, only when absent and only for a catalog with `rebuild_argv`, never an adapter-owned stdin one), ack and no_match, explicit mentions first, merged-catalog interleave, the `min_match_strength` floor before the cut to k, `top_gate` (default `TOP_GATE_DEFAULT` 0.6 when the turn sets none, 0 off; over the skills the block would deliver, after exclude, `min_match_strength`, session dedupe and pacing: the best score over `maxIdf(n)` of its catalog, highest across catalogs, below the threshold empties the block as `weak_top_match`; an explicit mention bypasses it), `previous_user_message` as the no-match fallback, the session rules (k 5/3/1 at 50%/80% of the budget, strong-match pacing, no-repeat, one re-suggestion after 10 turns, a named skill past a spent budget, `budget_exhausted` kept on ack and no-match turns), the block and its `block_reason`, `explain`, `failOpen`, `deadlineMs`. Returns `commit()`; session state changes only through it. Pinned by `test/skill-resolver.test.ts` and `test/skill-resolver-contract.test.ts`.
- `src/core/skills/resolver/rank.ts` — the A5 BM25F ranker over an `IndexReader` (scores summed in the prototype's order, ranked by score over summed idf, ties by name then id), `maxIdf(n)` (the BM25 idf of a term in one of `n` skills, the `top_gate` divisor), the multilingual acknowledgement list, `mentionsSkill` (a `/name` counts only as a leading slash command) and `reasonText`. `test/skill-resolver-reproduction.test.ts` pins top-5 equality with the Step 1 prototype.
- `src/core/skills/resolver/tokenize.ts` — `splitWords` (shared with `scoreSkillMatch` in `skill-catalog.ts`) and `lexTerms`, the frozen Step 1 term rule (stopwords, light stemming); CJK runs become overlapping bigrams. Vectors: `test/fixtures/skill-resolver/tokenizer-vectors.json`.
- `src/core/skills/resolver/index-format.ts` — `index.bin` (magic `GBSKIDX1`, JSON header, field-length averages, per-skill lengths, sorted term dictionary, flat postings with per-field tf, per-skill meta), byte-identical for identical records; `VARIANT_PARAMS` (D and T constants), `fieldText`, `summaryOf` (the description cut at 120 characters), `IndexReader` (lazy postings and meta reads).
- `src/core/skills/resolver/build.ts` — `buildSkillIndex` under the catalog lease (variant choice: T at a 25% trigger-or-routing share, kept down to 20%; publication only while the lease is held and the catalog directory is still the one the build started on, compared by device and inode and held open through the build, so a catalog removed, or removed and made again under the same name, fails `skill_index_removed` and is left alone; receipt written last), `catalogStatus` (content tier: re-reads the source and re-hashes the index), the model picker's `picker.json` (`prompt_version`, ids and descriptions cut to `PICKER_DESCRIPTION_CHARS`) written beside the index, `removeSkillIndex` (rename then delete, so a concurrent build fails `skill_index_removed`), `listCatalogs`, `sessionStatus`, `dirFingerprintSlice`, `catalogHash`.
- `src/core/skills/resolver/sources.ts` — the four sources: `--dir` (symlinks out of the root followed only to a skill folder or a `SKILL.md` file, indexed under the link's path, others skipped as `symlink_outside_root`, breadth-first, dot-entries and `node_modules` never read, a per-directory `listingKey` so a harness writing its own dot-files leaves the index fresh, first id wins, plugin namespace from `.claude-plugin/plugin.json`, stat fingerprint), `--bundled` (dynamic import of `src/core/skills/bundled.ts`, never the operations table), `--from-json` (`JSON_INPUT_CAP_BYTES` 64 MB, 10,000 entries, bodies trimmed to 4 KB, a snapshot over `JSON_SOURCE_CAP_BYTES` kept trimmed; an adapter list or OpenClaw's `skills list --json` as is, name as id; with `--dir`, `mergeSkillFolders` takes bodies, paths and triggers by name) and `--claude-plugins` (`readClaudePluginSources`: enabled user-scope plugins from `installed_plugins.json` and `settings.json`, as `<plugin>:<skill>`); `applyRouting`; bounds (`MAX_SKILLS`, `MAX_DIRS_VISITED`, `MAX_DEPTH`).
- `src/core/skills/resolver/frontmatter.ts` — bounded SKILL.md reader (64 KB file, 4 KB body): name, description, `when_to_use`, triggers, `disable-model-invocation`, `eligible`, `deprecated`, `replaced_by` (a deprecated skill is indexed with `dep` in its meta; `resolve.ts` admits it only when the turn names it) and `audience` (`ownerOnly`: any non-empty value of an `audience` key in any letter case (`restricted`), or an `audience:` line, quoted or not, in front matter that does not parse or anywhere in a file whose front matter is never closed, marks the skill owner-only, indexed with `aud` in its meta; a leading byte order mark is dropped first).
- `src/core/skills/resolver/routing.ts` — one RESOLVER-style routing file's table and compact-list rows, skipping the generated skills block.
- `src/core/skills/resolver/session.ts` — session state (`sessions/<sha256(scope, harness, id)>.json`: ids and counters only), `commitSession` under a short lease, file and id caps, 7-day GC with a per-run work bound; every commit (sync or async) then starts an async GC pass after it settles, at most once per `GC_INTERVAL_MS` (10 min) per home by the mtime of `logs/session-gc.stamp`, so new sessions keep deduping past `MAX_SESSION_FILES`. A pass may take a `GcBound` (`files`, `until`): the hook lane passes `LANE_GC_FILES` (64) and its deadline less `GC_RESERVE_MS` and awaits `sessionGcSettled()` before exit; the stamp is written only when a pass finishes, so a pass its deadline cut retries on the next turn.
- `src/core/skills/resolver/handle.ts` — `openCatalog(catalogs, opts)`, the warm handle for long-lived hosts: keeps each catalog's receipt and open `IndexReader` and the settings, re-stats `receipt.json`, `index.bin` and `config.json` once per turn and reloads only what changed; turns run `resolve.ts` `runTurn`, so output, `pending`, `commit()` and errors equal `resolveSkills` apart from `meta.timing_ms` (`test/skill-resolver-runtime.test.ts`).
- `src/core/skills/resolver/build-thread.ts` — `buildSkillIndexOffThread`: `buildSkillIndex` in a `node:worker_threads` Worker whose entry is the module's own URL (in the Node bundle, the bundle), run by a top-level guard keyed on `BUILD_THREAD_MARKER` in `workerData`; no worker file ships; a `ResolverError` comes back with its code, message, fix and context. The hook lane never reaches it (`test/skill-resolver-module-graph.test.ts`).
- `src/core/skills/resolver/block.ts` — the `<relevant_skills>` block: header, one JSON-quoted line per suggestion (id, name, path for codex, openclaw, pi and cursor, summary unless names-only), one load line per harness or `--load-hint`, cut at whole lines to 400 tokens by `estimateTokens`.
- `src/core/skills/resolver/lock.ts` — ownership leases (O_EXCL create, random token, expiry; reclaimed only after expiry; release and renewal check the token).
- `src/core/skills/resolver/config.ts` — `skills.resolver.session_token_budget` (0 or 100-50,000, default 8,000) and `auto_rebuild` / `GBRAIN_SKILLS_NO_AUTOREBUILD=1`, read straight from `config.json`; the lane's turn settings `top_k` (1-8, default 5), `min_match`, `top_gate` (0-`TOP_GATE_MAX`, 0 off, unset the resolver's default), `pinned` (sent to resolve as exclude) and `per_harness.<harness>.{top_k,min_match,top_gate}` (falling back to the global keys) through `laneTurnSettings` and the validators `validateTopK`, `validateMinMatch`, `validateTopGate` and `validatePinned`; `per_harness.<claude-code|codex>.dirs` (at most `SKILL_DIRS_MAX` absolute paths, no `..`) through `configuredSkillDirs`, read by setup; `per_harness.<claude-code|codex>.session_start` (plain text, at most `SESSION_START_TOKEN_CAP` tokens, no control characters but newlines and tabs; `validateSessionStart`, read by the lane through `laneSessionStart`); `readResolverSection` returns the `skills.resolver` object (`{}` when absent or unreadable), which `readResolverSettings` and `checkResolvable` read; `configuredTopGate` reads and validates only the `top_gate` keys for `gbrain skills resolve` (a bad value anywhere in the section is `skill_resolver_config_invalid`); the model picker's keys (`router`, `router_model`, `router_timeout_ms`, `router_max_usd_per_day`, `router_base_url`, `router_api_key_env`, `router_usd_per_mtok`, `router_extra_body` (a JSON object of at most `ROUTER_EXTRA_BODY_MAX_BYTES`, compat: models only, never `model`, `messages`, `stream`, `n` or the token limits), `router_prompt_version`) through `routerSettings`, which never throws: a bad value leaves the picker off for the turn and is reported as `router.fallback.code` `config_invalid`.
- `src/core/skills/resolver/router.ts` + `router-http.ts` — the model picker (`skills.resolver.router`, off by default), started only by callers that pass `ResolveOptions.router` (the CLI and the Claude Code and Codex hook lanes): `pickSkills` sends the catalog's ids and descriptions (every skill up to `PICKER_FULL_CATALOG_MAX`, 150, else the top `PICKER_SHORTLIST`, 40) and keeps only catalog ids from the JSON reply (at most `PICKER_PICKS`, 3); `PICKER_PROMPT_VERSION` names the request shape a model can be trained on (a test pins its hash, so a change to `pickerPrompt` or its limits bumps it), and a `router_prompt_version` other than it is `config_invalid` with no call; `ROUTER_DEFAULT_MODELS` picks the first model whose provider has a key; the per-UTC-day spend ledger `skill-index/router-spend.json` is charged at the largest possible cost under its lease before each call and settled after; every way it can fall back has a code in `ROUTER_FALLBACK_CODES`, documented in the guide; `routerTimeoutMs` caps a Claude Code turn's wait at `ROUTER_TIMEOUT_MS_CLAUDE_CODE_MAX` (2,000 ms, in `config.ts`) whatever `router_timeout_ms` says; an HTTP 4xx (`PickerHttpError`) answered by the provider itself (`firstParty`: not `compat:` and no `ANTHROPIC_BASE_URL`, `OPENAI_BASE_URL` or `GOOGLE_GENERATIVE_AI_BASE_URL` override) is settled at 0, while one through a proxy or a `compat:` endpoint stays charged; `resolve.ts` makes no call when the turn offers the picker no skill, and the word matcher answers with no fallback code. `router-http.ts` makes the call over plain HTTPS (Anthropic, OpenAI, Google, or an OpenAI-compatible `compat:` endpoint at `router_base_url`, with `router_extra_body` added under the fields the picker owns), no SDK or gateway, redirects refused. Pinned by `test/skill-resolver-router.test.ts`.
- `src/core/skills/resolver/vectors.ts` + `embed-http.ts` — skill vectors (GST-3568): `embedCatalog` writes `<catalog>/vectors.bin` ("GSV1", a JSON header naming the model, width, catalog hash and `VECTOR_TEXT_ID`, then unit float32 rows) at build when the brain's `embedding_model` (voyage, openai or google) has a key, the catalog is Claude Code, Codex or harness-less in user scope and the model has a cosine floor in `VECTOR_FLOOR`; otherwise the receipt's `vectors` is `{skipped: <EMBED_SKIP_CODES>}` and the index still publishes. A zero or non-finite reply vector is `bad_reply`, a build that timed out or failed with requests running publishes no vectors, and `too_many_skills` counts the file's header against `VECTOR_FILE_CAP_BYTES` (checked before any request when the width is configured, else after the first reply). `resolve.ts` embeds the message (`embedQuery`, at most `VECTOR_WAIT_MS` with the picker off, and never within `VECTOR_DEADLINE_RESERVE_MS` of the caller's deadline), fuses the word list with the skills at or above the floor by RRF (`RRF_K` 60, the search constant), gates no-skill on the floor instead of `top_gate`, and on any failure returns the word matcher's output with `vectors.fallback.code`; `hook-lane.ts` extends the Claude Code and Codex deadline by `VECTOR_WAIT_MS` when a turn's catalog has vectors and the picker is off. `embed-http.ts` reads the embedder from `config.json` and calls the provider over plain HTTPS, no SDK or gateway (the resolver must not import `src/core/ai/`). Pinned by `test/skill-resolver-vectors.test.ts` and the lane's skill-vectors tests.

## Moved skills

- `skills/moved-skills.json` + `src/core/skillpack/moved.ts` + `src/cli/moved-registry-seam.ts` + `scripts/{check-moved-skills,announce-moved-skills}.ts` — the registry of bundled skills whose home moves to another catalog (`moved`), the skill folders gbrain keeps (`kept`; `conventions/` and `migrations/` are neither) and the `destination` (`name`, `install` with `{skill}` replaced by the skill, https `url`), null until it is announced. The file is a static JSON import, so a compiled binary carries it; `parseMovedRegistry` validates it (names, duplicates, overlap, destination fields) and a file that does not validate counts as nothing moved at run time, never failing a command (`test/moved-skills.test.ts` loads the committed one). `isMovedSkill` reads only the list; `movedSkillNotice`/`movedSkillNotices` return the one notice text, or nothing while the destination is null, so with it null every surface behaves as before. Surfaces, each through this module: `skillpack scaffold <name>|--all|--harness` and `skillpack reference <name>|--harness` still use the copy compiled into gbrain and print the notice on stderr; `skillpack status` adds a `moved` notice per skill and `counts.moved` (absent while none moved) and a `moved` list per harness bridge, stubs included (`collectBridgesStatus`); `skillpack pin|unpin` print it; `--update-untouched` skips a moved skill with reason `moved` and the notice as a note (`classifySkill`); `gbrain bundled-skill <name>` serves a still-bundled moved skill with the notice on stderr and answers a moved name no longer bundled with the notice (exit 0, `--json` field `moved`) instead of `skill_not_found`; `checkResolvable` grades a moved skill the skills dir lacks (see its entry). `GBRAIN_TEST_SKILLS_MOVED_REGISTRY` (tests only; read in `moved-registry-seam.ts`, outside src/core, by the skillpack dispatcher and `bundled-skill`) replaces the registry for one process; `setMovedRegistryForTests` does it in process. `check:moved-skills` (in verify) refuses, once the destination is set, a folder under `skills/` neither list names, and prints `GBRAIN_CHECK_SKIPPED` while it is null. `announce-moved-skills.ts --remove-after <date> --owner <who>` writes `deprecations.d/skill_moved_<skill>.md` per moved skill (dashes in the name become underscores) (surface `bundled-skill`), `behavior-changes.d/skills_moved_<date>.md` (`kind: action`) and `changelog.d/skills-moved-<date>.md` with its marker; it refuses while the destination is null, a date under 14 days away, or a file that already exists. Tests: `test/moved-skills.test.ts`, `test/moved-skills-cli.test.ts`. Doc: "Moved skills" in `docs/guides/skillpacks-as-scaffolding.md`.
