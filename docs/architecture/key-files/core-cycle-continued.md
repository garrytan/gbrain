- `src/core/cycle/synthesize-postprocess.ts` — Managed synthesis quote repair and provenance stamping publish together through a deterministic maintenance request bound to the source incarnation, transcript hash, child output, and original committed page revision. `loadCommittedSynthesisOutputs` finds each child's committed output by canonicalizing the retained `brain_put_page` input (`parseWriteRequestId` for the request id, `journaledPageSlug` for the slug) before matching request id, source, incarnation, committed put_page, slug and revision (#6616); slug discovery (`collectChildPutPageSlugs`) and postprocessing share that set. The immutable committed receipt is the completion checkpoint: later runs skip finalized output rather than repairing user edits. Pending work replays its retained intent under the original revision and existing authority/file guards; missing provenance fails closed. A publish still `write_pending` after the job's shared maintenance wait is deferred, never written or finalized: `withPublishPending` turns the phase result into `warn` with `publish_pending` and `SYNTH_PUBLISH_DEFERRED` ("publish deferred (writer busy); finishes next cycle, no action needed"), `synthesize.ts` leaves `dream.synthesize.last_completion_ts` unstamped, and the next ordinary cycle resumes the same deterministic request id. Runs the same claim verification as the unmanaged path (`groundSource` + `resolveVerifyPrior` + `verifyDreamPage` from `synthesize-verify.ts`, scoped by the ref's `first_write_at`, else the child write epochs passed as `sinceByTranscript`) and stamps the dream provenance fields only on dream-owned pages (`isDreamOwnedPage`); the published page reconciles its automatic links like an ordinary put_page (`page-prepare.ts` treats `managed_maintenance_page` intents as auto-linked); the unmanaged path retains its fail-open behavior. - `src/core/cycle/synthesize-postprocess-deferral.ts` — #6757: config row `dream.synthesize.postprocess_pending`, keyed by source and bound to its incarnation: each pending output (child request id, journaled and input slug, revision, job key, transcript path, content hash, seat, first write) and the source's consecutive deferred passes with the last read and its elapsed time. `isPostprocessReadTimeout` unwinds a cancelled cycle first, then accepts only SQLSTATE 57014 with the statement-timeout message (a user cancel is not deferred). `recordPostprocessPass` drops settled outputs, adds deferred and carried ones and resets the count on a pass that deferred nothing; `repeatedPostprocessDeferrals` lists sources at three or more for doctor `persistence_request_indexes`. The replay runs no child job and verifies a replayed output's quotes against the transcript as it is now, even when it grew after synthesis; a quote not found there goes to `unverified_claims` like any failed quote.
- `src/core/cycle/dream-write-deferral.ts` — W3 (#7587): config row `dream.write_deferral.pending`, keyed `<phase>:<source>`. A purge or consolidate write accepted but still pending after its publish wait (`maintenancePublishWaitMs`) is recorded with its request id (`deferDreamWrite`); the next pass's `reconcileDreamWriteDeferrals` reads each receipt before anything is submitted: committed clears it, a terminal failure is reported with its real code and not resubmitted that pass, still pending holds the source (nothing new submitted) and counts a replay. At `DREAM_WRITE_DEFERRAL_MAX_REPLAYS` (3) doctor's `dream_write_deferred` (`src/commands/doctor/checks/dream-write-deferred.ts`) warns with the receipt and `gbrain write-request -- <id>`. `dream.write_deferral.enabled=false` restores the failing phase. Audit rows go to `src/core/heal-audit.ts` (config `heal.audit`, 200 rows, 30 days) in the same transaction. Tests: `test/dream-write-deferral-w3.test.ts` (PGLite, Postgres, repo and repo-less).
- `src/core/embedding-restamp.ts` — W3 (#5527 class): `restampCurrentSpaceSignatures` runs at the start of the cycle embed phase (never on upgrade, skipped in dry runs) and sets `pages.embedding_signature` on up to 500 pages per run whose every chunk already holds a current-model vector (`currentSpaceChunkPredicate`), with no provider call. Each stamp takes `lockPageKeys` and re-checks the selected revision and signature, the sealed text projection, the active column and every chunk, so a concurrent edit or re-embed makes it match nothing (`rejected`). Three failed runs in a row escalate to doctor `embedding_restamp_stalled` (`src/commands/doctor/checks/embedding-restamp.ts`); `embed.restamp.enabled=false` turns it off. Tests: `test/embedding-restamp-w3.test.ts`.
- `src/core/cycle/bookkeeping-gc.ts` — the `bookkeeping_gc` phase, split out of `purge` with the same functions and retentions (op and brainstorm checkpoints, batch-retry audit files, volunteer events, decision receipts, applied captures, retrieval feedback); it never touches a page, so unattended upkeep runs it.
- `src/core/learning/derive.ts` — the `learning_derive` phase (brain-global, free, after `schema-suggest` and before `purge`; the cycle mints one `run_id` per run). It writes pointer rows to `learning_items` (`learning/schema.ts`, migration v334): an extractor's fact (`fact_added`), a Facts fence row the owner typed (`fence:reconcile`, `you_wrote`, informational, never counted), a pending claim-conflict proposal created in the window (`conflict_found`), a page `gbrain enrich` filled (`page_filled`, pointing at the preimage `page_versions` row) and an open `commitment_owed_to_me` loop (`promise_found`). `learning/duplicates.ts` adds `duplicate_to_confirm`: the top five person groups of the `gbrain dedupe --preview` scan (read-only, keyless; conflicts left out), ranked by the best owner-contact score among their members (preview order when the owner's page does not resolve), each pointing at its anchor page (lowest member page id, `target_table 'pages'`); nothing is linked, merged, confirmed or rejected. On a keyless brain whose owner resolves, the pass also stores the count of thin pages the owner has recent contact with in config `learning.keyless_thin_contacts` (cleared otherwise). Each kind is one `INSERT … SELECT` with `ON CONFLICT DO NOTHING` over `UNIQUE (kind, target_table, target_id)`, capped at 500 per kind; the window starts at config `learning.derive.watermark` minus an hour (at most 7 days back), and a capped pass keeps the old watermark. Rows hold ids only, never text; a pending or expired pointer whose target is gone is deleted (decided ones stay for stats). The claim-conflict backlog stays one count. A brain behind the migration or an engine without raw SQL skips with a reason; errors warn and never fail the cycle. Repo-less brains work the same. `learning/kinds.ts` holds the kind lists and shared SQL.
- `src/core/learning/read.ts`, `src/core/learning/stats.ts`, `src/core/ops/learned.ts` — the `learned` read op (scope read). It renders each pointer from its live target under the caller's own filters (world-only facts and the private-page policy for remote callers, the source scope from `sourceScopeOpts`, deleted and withdrawn targets dropped, fact text through `quoteFacts`), lists unseen pending items of the last 7 days by default (`since` lists all), stamps `shown_at` and `member_id` only for a caller that reads the whole ledger and is not a `--as` preview, and returns 15 by default (`limit` up to 100), every one printed. A `duplicate_to_confirm` row shows only while the recomputed preview still holds a group anchored at its page and the caller can read every member (in its own sources when remote); it carries the `gbrain dedupe confirm` (confirmable groups only) and `gbrain dedupe reject` commands. With no chat model, owner and local callers get a `thin_contacts` line from the stored keyless count (at most 7 days old), with the commands that turn filling on and its cost. Remote callers need a resolved source scope (`permission_denied`). `stats` groups ledger rows by night (the local day ending 06:00 in `brain.timezone`; the newest 20,000 rows, `truncated` past that) and reports the share of nights at the bar; non-owner remote callers count only items they can read (`scope: readable`), and the claim-conflict backlog line is for local and owner callers. Refuses `engine_capability_missing` without raw SQL and `migrations_pending` without the table. Tests: `test/learning-ledger.test.ts` (repo-less PGLite and Postgres, remote tokens).
