# Apple connector (key files cluster)

[Subsystem index](../KEY_FILES.md). User guide and permission table:
`docs/guides/apple-connect.md`. Read only the entries relevant to your change.
Current behavior and load-bearing invariants; history belongs in Git and CHANGELOG.

- `src/core/apple/types.ts` — pure shapes for the `apple` source kind: `AppleSourceConfig` (account label, services, windows, calendar ids, contacts dir, mailboxes, managed dir), the normalized `AppleCalendarEvent` / `AppleContact` / `AppleMailMessage`, the `AppleReaders` seam (`calendar`, `contacts`, `mail`, `probe`) and `AppleSourceState` (the `.apple-source.json` cursor). No I/O.
- `src/core/apple/source-config.ts` — parses `sources.config` keys prefixed `a_`. A present-but-unrecognized `a_services` parses to NO services, never to all of them (Mail and Contacts are private, a typo must not widen scope). `appleTuningConfig` is the writer of the non-default keys for `sources add`.
- `src/core/apple/source-add-config.ts` — the one builder of the config blob `sources add --kind apple` writes, shared by `sources-ops.ts` (unmanaged insert) and `persistence/managed-sources.ts` (managed lifecycle) so the two cannot diverge. Writes `a_services` explicitly, `a_managed` when the dir is the default clone location, and no credential field because none exists.
- `src/core/apple/apple-source.ts` — `runAppleSync(engine, sourceId, cfg, opts, injection?)`: the sweep entry through `withConnectorSync`. Sweep order contacts, calendar, mail; each enabled service is independent and a disabled service is never read, hashed or deleted from. A reader failure is source-level (logged with its fix, recorded in `last_probe`, never an item hold); only a single item's render/import failure feeds the item holds. Managed runs pin `{kind:'apple', account}` through `assertAccount` and always commit the (hash-keyed) cursor with `saveState`, so a denied service neither loses its recorded `last_probe` nor stalls the others; freshness stamps only when some service synced cleanly, and a deferred save still publishes `last_probe` and invalidated Mail-loop recovery state through `publishHolds`' `extra`. Before any enabled-service reader or page admission, a managed run with Mail loop tracking commits a cursor-preserving `publishHolds` observation invalidation (`fresh:false`); a refused publication stops before reading. The working state retains its prior coverage, so a successful observation can complete normally, including a genuinely empty listing. An interrupted observation instead leaves durable `coverage_gap`/`reread` bookkeeping requiring nonempty whole-window recovery; no post-abort authority is used. `injection.readers` is the test seam.
- `src/core/apple/{render,sweep,sweep-shared,state}.ts` — page rendering (calendar `meeting`, contacts `person`, mail `email`, bodies in fenced quotes), the per-service sweeps with hash-diffing, `--full` reconciliation with the 200-removal guard, and the 0600 cursor file whose corrupt copy is quarantined to `.corrupt`.
- `src/core/apple/readers/` + `scripts/apple/` — the macOS-only readers: package-local helpers (EventKit and Contacts via Swift, Mail via JXA; text embedded by `embedded-scripts.ts`, written to a private 0700 temp dir per run so a compiled binary needs no `/$bunfs` path) spawned by argv with a timeout, an output cap, a scrubbed environment and an abort signal. Every entry point gates on darwin and returns a coded `AppleReaderError`; `fixFor` carries the user-facing fix strings.
- `src/core/apple/loop-evidence.ts` — adapts classified Mail evidence to the shared detector without Gmail labels. Rendering persists one compact evidence item per message in `apple_loop_messages`; validation requires exact coverage of the page's `apple_message_ids`. Missing/unclassified legacy evidence refuses evaluation until a reader repairs it. The recent-thread cursor cache is diagnostic only.
- `src/core/apple/mail-holds.ts` — the Mail side of the shared connector item holds. Two hold kinds in the one `item_holds` state: `mail:<thread>` (a page that failed to render/import; `ref` remembers the messages it was built from) and `mail-message:<id>` (ONE message the reader proved unreadable; key = stable id, `meta.upstream_at` = received date, `ref` = thread). Only `unavailableMessages` (proven) count; `deferredThreads`, `incomplete`, reader/helper errors and budget stops never do and keep pinning the cursor. `planMailHolds` excludes held messages from the read and lists the due recovery units (one message, or one thread's remembered list; retry-held, due reconsideration, `--full`, failing thread imports), and flags a due record no list can rebuild (`walk`, only when the mail window can reach its oldest known message: `walkReaches`); `readMailHolds` counts proven failures and re-reads the units by id and date through the optional `AppleReaders.mailMessages` (outside the cursor's listing, so the cursor is never touched; a failed targeted read is a source error): each call asks only for what is unresolved (oldest first, whole units packed to the helper's observed capacity, at most `APPLE_MAIL_RECOVERY_MAX / APPLE_MAIL_TARGET_MAX` = 4 calls a run, a call that resolves nothing ends the reads), the evidence accumulates across runs in `state.mail_recovery` (mail-recovery.ts), units rotate by its persisted turn (never a failure count), and a unit not completely resolved feeds nothing; `parseThreadLocator`/`mergeThreadRef` keep the locator (`{m:[[id,date]..]}` up to 100, else `{w:n,o:oldest}`) as a union that grows with the thread; `settleReadMessages` clears a record only when its thread's page landed; `MailHoldRun.blockedThreads` keeps those threads live and Mail loop coverage incomplete. The sweep rebuilds a thread with an import record only when every remembered message is accounted for, and recovers `{w:n}` threads through a whole-window recovery walk (`mail.walk.recover`/`landed`, `beginMailWalk(..., recover)`) that settles the hold only when it completes. `mailHoldGroup` gives the circuit breaker separate message and thread groups and exempts a record that was already held when the run began (it is only re-attempted). `ItemHoldsRun` (entry in [core-persistence-continued.md](core-persistence-continued.md)) takes the optional `groupOf(key, heldAtStart)` for connectors that mix item kinds (default: one group, unchanged; `null` exempts a held re-attempt from the breaker's counts, and a judged group in outage still suppresses it), and `ConnectorItemUnreadableError` classifies as item-scoped, transient `item_unreadable`.
- `src/core/apple/mail-recovery.ts` — bounded persistent staging of Mail hold recovery (`AppleSourceState.mail_recovery`, part of the one cursor state and so of the one canonical checkpoint write): messages read by id and gone-upstream ids accumulate across runs because a slow Mail.app hands the helper only a few bodies per call. Hard bounds across ALL holds (`STAGE_MAX_MESSAGES` 100, `STAGE_MAX_BYTES` 2.5 MiB, `STAGE_TTL_MS` 14 days); a thread is admitted by reserving its whole target list (`admit`), overflow refuses (`stage`) and never evicts; `reconcileRecovery` drops what no hold names (run start and again after the holds merge, so a cleared hold takes its mail text with it); `normalizeMailRecovery` drops a malformed or over-bound value whole. Mail text is never logged or sent to a model.
- `src/core/apple/mail-routing.ts` — pure Mail account routing from the public Mail dictionary fields `id`, `server name`, `account type` and `enabled` only. Four documented Gmail receiving hosts route to the Google connector; a malformed, Google-like-undocumented, unreadable or unsupported enabled account fails closed for the whole Mail read. The eligible-account fingerprint includes id + normalized host + type (so provider changes under the same id reset the scope). Google/disabled accounts are never passed to the Mail item reader. `readMailRouting` in `readers/mail.ts` asks the helper for metadata only; `mail.js --routing` re-checks the account set and each eligible account before reading. Per-account mailboxes replace application-level unified Inbox/Sent; the helper's within-run dedupe key is account id + mailbox id + message id.
- `src/core/apple/mail-walk.ts` — binds resume cursors to purpose, source read scope, owner digest and routing fingerprint. `mail.walk` freezes `since` and accumulates seen ids; only a completed full enumeration authorizes reconciliation. A new full/identity/routing walk never inherits an incompatible suffix.
- `src/core/apple/loops.ts` + `loops-status.ts` + `loops-enqueue.ts` — re-evaluate complete durable page evidence each sweep, including quiet grace-held threads and extraction candidates. `pending_threads` preserves unreadable/failed/missing recovery obligations; cache/page absence never means upstream gone. `coverage_gap` requires nonempty whole-window recovery. Any coverage gap invalidates `complete_at`, persists `reread`, and makes Apple coverage partial on `open_loops`. Identity changes reconcile obsolete open deterministic rows before the shared apply step can label a direction change as a reply. Only a current suppression-filtered open verdict restores an `apple_owner_changed` row, including after grace; manual done/drop/mute and genuine reply closures remain untouched. Direction comes only from `a_mail_owner_addresses`. Enqueue and execution re-read current registered-source consent independently of page markers; paid extraction also requires the global switch and refuses unsupported Gmail label exclusions. Durable pages and queue outcomes recover global/provider/spend/depth deferrals on later sweeps; only extracted revisions settle, not arbitrary completed jobs. Apple jobs carry their connector origin; the judge receives current owner aliases in trusted system context. Google queue/prompt behavior is unchanged.
- `src/core/apple/permission-guide.ts` — the System Settings pane and app to name for a denied service. Shared by `gbrain apple` and the `apple_permissions` doctor check so both say the same thing.
- `src/commands/apple.ts` + `apple-output.ts` + `src/cli/commands/apple.ts` — `gbrain apple setup|status|services`, a pre-connect command with the `gbrain google` envelope and exit contract (0 done, 1 failed, 2 waiting on the user). `runApple(args, deps)` returns the exit code and takes `readers`, `platform`, `engine`, `sync` as injected deps. It reads Apple only through `readers.probe`; the sync (inside `setup`) is the only data read. Mail requires `--confirm-mail` or `--yes` before any probe. Explicit source id takes precedence; ambiguous account labels refuse. Effective existing scope is resolved before Mail confirmation, all explicit selector differences refuse before probes, retry commands preserve quoted selectors and consent flags, and a config change during probes refuses sync.
- `src/commands/sources-apple-flags.ts` + `sources-apple-add.ts` + `sources-set-services.ts` — `sources add --kind apple` flag validation (shared by the legacy parser and `sources-lifecycle-args.ts`), the legacy add path, and `sources set-services --add|--remove` (never deletes pages; asks `--yes` on a managed brain when the cursor identity changes). A non-macOS host gets a warning on add, not a refusal.
- `src/commands/doctor/checks/apple-permissions.ts` — the `apple_permissions` check (a `WAVE_CHECKS` entry, `operator` resolution, host-only): zero helper runs, reads the `last_probe` a sync stored in the cursor state, warns for an enabled service that was `permission_denied` / `automation_denied`. `connector_held_items`, the checkpoint migration, the held-items store and the connector status readers include the `apple` kind through `CONNECTOR_SOURCE_KINDS` and their `IN (...)` lists.

Identity: `apple` is a `ConnectorKind` in `persistence/connector-identity.ts` (entry in [core-persistence-continued.md](core-persistence-continued.md)) with its own `CONNECTOR_LEAF_RULES`: account, services, windows, `calendarIds`, `mailMailboxes`, `contactsDir` and dir are identity; `services`, `calendarIds` and `mailMailboxes` canonicalize as sorted de-duplicated sets, so reordering them never re-keys the checkpoint. Apple pages publish with mode 0600 like Google's; the `IN ('google','github','apple')` connector-kind lists and `CONNECTOR_SOURCE_KINDS` cover it.
