- `src/core/backup/rust-restore-safety.ts` + `src/core/rust-engine/restore-types.ts` + `rust/crates/gbrain-store/src/restore.rs` (+ `jobs/restore.rs`, napi `families/restore.rs`) — the restore-side safety of a Rust brain (PR 21b-rust; PGLite runs the same job as 66 SQL statements, a Rust store takes no raw SQL). `restoreCensus(purgeRequestIds)` is one read: unfinished write requests, claims, live effects, recovery records, jobs, the live authority the archive holds (local writers, OAuth clients; any of it is the blocker `archived_authority`), every source (archived too), the config rows a restore may change, the purge request ids the ledgers lack, any record of a kind no classified list names (a new key tag, `jobs`/`persistence` sub-tag or `~` family other than the keyed lookups `~k` fails closed), and the named `blockers` (`pending_requests`, `recovery_required`, `purge_replay`, `archived_authority`, `shared_skill_state`, `unclassified_state`). `restoreQuarantine(plan)` is one write transaction that repeats the safety census (`restore_refused`), then detaches external sources (config replaced, `local_path` cleared), rebases managed sources and their page `source_path` origins one to one, switches automation settings off, cancels unfinished jobs (it revokes nothing; live authority refuses first), gives the store a fresh brain id (the format record is rewritten in the same transaction with `rotated_from`, `FORMAT` follows by atomic rename, and an open repairs a `FORMAT` that still names the rotated-from id; the report carries `previous_brain_id` and `brain_id`), keeping what it replaced in the inert config row `restore.<id>.detached_execution`; a second call with one restore id is `invalid_state`. It changes nothing and refuses on a transaction-bound handle (`invalid_state`: the new id and `FORMAT` are published together, which an outer rollback could not undo), on a handle opened read-only (`read_only_transaction`, asked of the key-value layer's `is_read_only` before the lock, any `FORMAT` repair or a write transaction), when the rebased origins would give two live pages one origin (`origin_claimed`) and when `plan.settings` does not list every held safety setting exactly once (`invalid_argument`); Windows drive and UNC origins, and an absolute origin not under its source's old root, stay unchanged and are counted in the source's preserved-origins line of `reconnect`. Nothing is revoked here (a follow-up adds revocation): a live OAuth client or local writer refuses as `archived_authority` with its ids, activated shared-skill publication, a shared-skill member, batch or policy, or `mcp.publish_skills` on refuses as `shared_skill_state`, an archived access-token (`jobs 0x2b`), OAuth token (`0x2c`) or OAuth code (`0x2d`) record is refused by name, and an unknown kind refuses. The take purge ledger (`F 0x10`) counts as a purge ledger, restores run one at a time (a process-wide lock held through the id rotation and the `FORMAT` write; with it held, a `FORMAT` that still names an earlier rotation's id is brought up to the committed id before another rotation commits, and a failed write refuses with nothing changed), and a cancelled job with a payload that is not an object keeps it under `__restore_original_data`. TypeScript: `buildQuarantinePlan`, `restoreRefusalFor` (the registered `restore_step_unsupported` reasons, each with what was not published and the fix), `checkStoreIdentity` (the archive's `store.engine_format_version` is never the container's `format_version`) and `restoreAddonSupportsSafety`. Not BrainEngine members; the CLI that calls them is PR 21b-ts.
