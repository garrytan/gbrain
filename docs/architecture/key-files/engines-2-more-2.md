- `src/core/engine-sql/trust-fence.ts` + `rust/crates/gbrain-store/src/trust/held_rows.rs` — the fence guard's read of a page's facts-fence rows with their trust tier (`listFenceFactRows`, from `trust/fence-guard.ts` `guardFenceRows`): live numbered rows the incoming fence does not state as they are, that are more trusted than the writer (`gbrain.write_trust_tier`, read by the statement; `WRITER_RANK_SQL`), held narrower by a widening proposal, or opened by `gbrain repair open-facts`, locked `FOR UPDATE OF f`. The incoming fence is bound once as `v.incoming`. `src/core/engine-sql/facts.ts` `listFenceRetireCandidates` is the fence projection's read of the rows it would retire (before-state as `FACT_PREIMAGE_SQL`, from `generations/adapters/fact-rows.ts`). The Rust store answers both from its write trust context, with each row's stored tier and the held arm read from its `trust_proposals` family (rust/docs/store/facts.md). `listHeldRows` is the held-row read of `trust/fence-guard.ts` `heldRows` as a typed member on every engine: of one page's `takes` or `timeline_entries` rows among the given ids, those more trusted than the writer (a named tier, else `gbrain.write_trust_tier`) or, with `pending`, under a pending `forget` contest (`OPEN_CONTEST_SQL`), `{ id, trust_tier }` by id, locked `FOR UPDATE OF x`. Callers pass the page id: projection (`canonical-projections.ts`), the timeline orphan prune (`timeline-extract.ts`) and takes reconcile (`cycle/extract-takes.ts`). The Rust store serves `timeline_entries` from its stamped tier and the `trust_proposals` family; its TypeScript member and the store refuse `takes`, whose records keep no tier. Test: `test/engine-parity/trust-fence.test.ts`.
- `src/core/engine-sql/takes-reads.ts` (extract section) + `rust/crates/gbrain-store/src/takes/extract.rs` — the reads and the prune delete of `gbrain extract takes` as typed members on every engine: `readLivePageIdBySlug` (`getPageIdForSlug`), `readPageTierRef` / `readPageTierRows` (the page tier `reconcileTier` and `upsertProjectedTakes` read), `pageHasFrontmatterKey` (the checkout's quarantine check), `listTakeIdsLeavingFence` (`unheldTakes`, `removed` or `replaced` form), `listTakePreimages` (`takePreimages`, `TAKE_PREIMAGE_SQL`), `deleteTakesByIds` and `findTakeId`. The batch guard `guardTakeRows` reads through `listGuardedTakeRows` (`engine-sql/trust-fence.ts`, `trust/held_rows.rs`) and the coverage report through `listCoveredSources` (`engine-sql/belief.ts`; the Rust store records no belief events and answers `[]`). The Postgres text is byte-identical to the raw statements they replace. On Rust the whole re-extract still stops on the typed `raw_sql` refusal inside `publishFenceGeneration`. Tests: `test/engine-parity/extract-takes-reads.test.ts`, `test/engine-parity/extract-takes.test.ts`, `test/extract-takes-sql-pin.test.ts`, `rust/crates/gbrain-store/tests/takes_extract.rs`.
- `src/core/engine-sql/synopsis-tier.ts` + `src/core/rust-engine/store-members/synopsis-tier.ts` + `rust/crates/gbrain-store/src/synopsis_tier.rs` — the synopsis tier's configuration read, one typed member on every engine. `readSynopsisTierSources(skipFrontmatter)` returns the live sources whose own mode is per_chunk_synopsis (by id in byte order, `COLLATE "C"`) and whether a live markdown page's trusted frontmatter picks the tier; `readSynopsisTierConfig` (`src/core/synopsis-sweep.ts`) calls it. The Rust store reads each source's mode from `source_cr_mode.rs` (rust/docs/store/synopsis-tier.md).
- `src/core/engine-sql/source-cr-mode.ts` + `src/core/rust-engine/store-members/source-cr-mode.ts` + `rust/crates/gbrain-store/src/source_cr_mode.rs` — a source's own contextual-retrieval mode, written by `gbrain sources set-cr-mode` through `setSourceContextualMode(sourceId, mode)` on every engine: one statement sets the mode or clears it to NULL and answers whether the source exists (the command exits 4 when it does not). The Rust store keeps the mode under `M source_cr_mode/<source id>` beside the source record, stamped with the source's incarnation, and `getSource`, `listSynopsisSourceIds` and `readSynopsisTierSources` read it back (rust/docs/store/source-cr-mode.md).
- `src/core/engine-sql/persistence-admission.ts` + `src/core/rust-engine/store-members/persistence-admission.ts` + `rust/crates/gbrain-store/src/persistence/worktree_admission.rs` — the managed-worktree admission reads as engine members: `readWorktreeAdmission` (the worktree row under a share lock, then its active refresh, locked when the refresh barrier is on, and whether the source binding holds; Postgres sends both statements before it waits), `completeSyncedRefresh` (completes a `syncing` refresh whose member sources reached its target head), `hasDeferralRoom` (no live consumer on the worktree's owner host lacks a capability), `readRefreshTiming` (a refresh's running time and the median of its worktree's last 10 completed refreshes) and `countHeldBehindImport` (the deferred writes not yet released that wait on a source's import or refresh). `persistence/journal.ts` admission and `persistence/refresh-retry-hint.ts` call them; each text is the statement they sent through `executeRaw`, written as static strings and pinned to the refresh schema constants by `test/persistence-admission-sql.test.ts`. The Rust store keeps refresh rows under `d 0x10` and the worktree and binding rows the writer claim stores under `d 0x09`, so admission reads `bound` from them (rust/docs/store/persistence.md). The members are classified `managed_persistence`, which the Rust engine holds back (`store-capabilities.ts` `HELD_FOR_CALLERS` names the bound-write sites that still run raw SQL: `compareFileTarget`, `guardOwnership`, publication recovery and `withTopologyLocks`), so a write to a bound worktree refuses `engine_capability_missing` at admission and writes no request row; an unbound write and an unbound grouped admission are served. Pinned by `test/engine-parity/persistence.test.ts`.
- `src/core/engine-sql/remote-links.ts` + `src/core/rust-engine/store-members/remote-links.ts` + `rust/crates/gbrain-store/src/remote_links.rs` — the remote `links` effect's statements as engine members: `setEffectTransactionLimits` (synchronous commit, 1s lock wait, 5s statement limit), `readOwnedLinks` and `deleteOwnedLinks` (the edges one producer owns from a page), `readLinkTargetPages` (which live targets the writer reads and the privacy part shows) and `rearmLinksEffects` (a finished batch's re-arm, `persistence/effect-journal.ts`). `persistence/effect-links.ts` keeps the decisions. The writer's read policy is gathered once (`persistence/page-visibility.ts` `writerReadPolicy`) and rendered here; the Rust member serves the no-caller and single-identity renderings and refuses others by name. An OAuth client writer is not served on Rust yet (`readWriterSlugFence` refuses `oauth_client`). Pinned by `test/engine-parity/remote-links.test.ts` (rust/docs/store/remote-links.md).
- `src/core/engine-sql/facts-backstop.ts` + `src/core/rust-engine/store-members/facts-backstop.ts` + `rust/crates/gbrain-store/src/jobs/facts_extraction.rs` — the facts backstop effect's two extraction reads: `hasPendingFactsExtraction(pageId, jobStates)` (a queued or running facts-backstop effect or a facts-absorb job of the page in those states) and `hasCompletedFactsExtraction(pageId)` (a completed facts-absorb job of the page that was not skipped). `persistence/effect-facts.ts` calls them and otherwise uses existing members (`readWriterSlugFence`, `readWriteRequestById`, `requireSynchronousCommit`, `lockEffectClaimRow`), so it sends no raw SQL (rust/docs/store/jobs.md, "Facts extraction reads").
- `src/core/engine-sql/facts-conversation.ts` — the statements of conversation fact publication and relink as 30 typed engine members in place of `executeRaw`, each taking `raw: EngineRawRead` first. `facts/conversation-publication.ts` reads and writes a page's conversation facts through them (newest fact id, active and window counts, held slots, the five-step clear that `clearConversationPageFacts` runs, outcome-row delete, purge-tombstone ordinals, source-window moves and stamps, the write journal reads), `relink-publish.ts`, `conversation-relink.ts`, `conversation-relink-carry.ts`, `conversation-entity-hints.ts`, `conversation-memo.ts`, `conversation-incremental.ts` and `relink.ts` read relinked, unbacked and unlinked rows, hint pages, the memo outcome row and the page lock. It exports `RELINKED_DERIVED_ROW` and `LABEL_RETIRED_MARKER`; the caller modules re-export them. Both engines delegate each member; the Rust engine refuses them by name with `engine_capability_missing` (capability `facts`). Tests: `test/facts-conversation-sites-sql-pin.test.ts` (statement text and binds against the pre-change text in `test/helpers/facts-conversation-base-sql.ts`) and `test/engine-parity/facts-conversation-sites.test.ts` (21 parity cases).
