# Situation-aware recall

[Subsystem index](../KEY_FILES.md).

- `src/core/memory-cues/` — opt-in derived situation-cue storage and generation. Settings default to no enrolled sources and disabled generation/read/push. Retrieval and push thresholds have separate bindings to the encoder and construction-pipeline version. The `situation-v5` pipeline uses at most 8,192 UTF-8 bytes of original safe text per window, up to 640 bytes of overlap, three source chunks and four grounding spans; speaker/turn mapping and serial execution are preserved. `evidence.ts` formats complete source windows as deterministic numbered, nonoverlapping excerpts of at most 640 UTF-16 units, targeting 512 units and capped at 64 excerpts. Live output has exactly four nullable slots: `scene`, `association_1`, `association_2`, `association_3`. Scene family/relation are derived; each association chooses one discriminator from valid horizon pairs or explicitly enabled bridge pairs. Shared slot and pair constants drive the prompt and decoder, and all-null is the only empty response. Extra/duplicate keys, missing/malformed slots and unknown/forbidden discriminators fail closed. Live generation selects one evidence reference per cue, with reuse allowed across cues; trusted decoding trims only excerpt-edge whitespace and carries the selected UTF-16 source offset through validation and publication. Grounding verifies the exact source slice at that occurrence and converts to chunk code-point offsets; injected providers without offsets retain the original first-match behavior. Schema, relation, sensitive-profile and grounding limits remain enforced. The same formatter supplies wire content, exact input reservations and worst-case preview bounds, including JSON escaping and excerpt IDs. Older pipeline builds and calibrations fail closed and require explicitly budgeted regeneration plus independent recalibration; structured generation is source-grounded and cue text is never canonical fact/evidence. Provider output accepts bare JSON or one whole-response JSON fence; malformed payloads, extra prose, duplicate fields, unsupported reference shapes and failed schema/quote grounding remain rejected. Injected providers retain the quote-based contract. Builds use existing protected Minion jobs and durable owner budgets; retries and incremental scheduling retain the original allowance. Per-window publication compares source incarnation, canonical revision, chunk snapshot and model; stale rows are unreadable before physical cleanup. Recall uses bounded indexed vector work and batch final revalidation. The public `gbrain/memory-cues` export supports the external evaluation consumer without deep imports.
- `src/core/ops/memory-cues.ts` — trusted-local `memory_cues` administration (`gbrain memory-cues <action>`): status, configuration preview/apply, build preview/submission, cancellation and resume. Explicit source IDs, capped limits and a positive spending cap are validated; mutating actions require apply and honor dry run. Agent-facing callers are rejected before database access, including stdio and subagents. Capture settings are untouched.
- `src/core/search/memory-cues.ts` — optional bounded cue arm for production hybrid search. One vote per source-qualified host; a separate ranker-only document view prevents generated cues from entering answer evidence. Shadow mode observes without admitting. Metadata names execution/degradation and numerical cue similarity without replacing source cosine or fact-existence evidence. Final revalidation removes invalidated hosts after asynchronous ranking.
- `src/commands/doctor/checks/memory-cues.ts` — local read-only readiness/coverage check. Silent on a default-off installation; reports missing independent calibration, unsupported/missing schema, empty/stale/pending windows and blocked/exhausted builds. It does not start jobs or repair state. Remote doctor does not receive the local build ledger.

See [operator guide](../../guides/situation-recall.md). The external Cat36 retrieval experiment and category-by-category release comparison are in `garrytan/gbrain-evals`; deterministic feature tests do not establish semantic-quality gains.
