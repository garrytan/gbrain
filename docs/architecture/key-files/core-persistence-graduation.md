# Key files: Core Persistence (engine graduation)

[Subsystem index](../KEY_FILES.md) · [Core Persistence](core-persistence.md). Read only the entries relevant to your change.
Current behavior and load-bearing invariants; history belongs in Git and CHANGELOG.
Verified engine graduation, PGLite to Postgres ([operator guide](../../guides/move-to-postgres.md)).

- `src/core/persistence/engine-graduation.types.ts` — the shared contract every graduation module codes against: manifest, source-row and target-row states with their allowed transitions (`assertTransition` throws on an illegal one), inventory classes and loss kinds, target identity (host, port, database, user; never the password), batch and table receipts, plan, verify result, receipt, intent marker, tombstone, blockers, `GRADUATION_ERROR_CODES`, and the CLI-to-orchestrator surface (`GraduationCommandOptions`, `GraduationStatusDoc`, `GraduationPathState`, `GraduationProgressSink`, `GraduationRollbackResult`). Changes are additive.
- `src/core/persistence/graduation-inventory.ts` — `GRADUATION_INVENTORY`: every public relation on either engine mapped to exactly one class (carry, rebind, rebuild, discard, schema-owned) with an engine-presence flag, a loss kind and the permitted column transforms. `assertRelationSet` refuses `graduation_unclassified_table` (reason `newer_schema` when the database is ahead of this binary, `missing_inventory_row` otherwise); `copyOrder` and `fkClosure` derive the FK topological order from `pg_constraint` at run time (self-FKs allowed, cycles throw). Test: `test/graduation-inventory.test.ts` fails when a migration adds a relation without a row.
- `src/core/persistence/graduation-digest.ts` — canonical engine-independent digests: every value read as text under fixed session settings (`TimeZone=UTC`, `DateStyle=ISO`, `extra_float_digits=3`, hex bytea), primary-key keyset batches ordered `COLLATE "C"`, sha256 computed client-side per batch and rolled into a per-table root independent of batch size; identifiers are always quoted from the catalog. Test: `test/graduation-digest.test.ts`.
- `src/core/persistence/graduation-verify.ts` — `verifyGraduation`, the cutover gate: relation set, column contract, counts and digests (source side transformed by the inventory's transforms), sequence positions, an anti-join per FK, trigger state (`gbrain_graduation_fence` present until cutover), derived side tables, the target doctor, and `replayProbe` (resubmits a carried request through `admitWriteInTransaction` inside a rolled-back transaction; `not_available` with a reason when no caller input exists). Test: `test/graduation-verify.test.ts`.
- `src/core/persistence/graduation-errors.ts` — one builder per graduation code (`sourceWriterHeldError` … `engineGraduatedError`) so the orchestrator, CLI, serve and doctor render each refusal one way: `why`, a filled `fix` with real argv (none only for `report`), a read-only verify (`gbrain migrate --status --json`, the `--plan` form, or doctor), `GRADUATION_DOCS` anchors, and the command helpers `planArgv`/`runArgv`/`resumeArgv`/`rollbackArgv`/`discardArgv`/`statusArgv`, which echo the user's `--to` spelling and name the URL only through `--url-env`. Test: `test/graduation-errors.test.ts` (table-driven over every code; each emitted argv names a real command with accepted flags and parses to its graduation mode).
- `src/core/persistence/graduation-serve-guard.ts` — file reads only (marker, tombstone, config, manifest summary; never a lock attempt): `serveGraduationStartRefusal` (a serve launched while another live run owns the host brain exits 75 with `graduation_in_progress`, called from `connectCliOnlyEngine` in `src/cli.ts`), `graduationStatusReason` (a tombstoned path is status-only `engine_graduated`), `exitOnEngineIdentityChange` (status-only and degraded reconnect gates exit 75 for relaunch when the config names another engine, a tombstone appears or a run starts; a serve started with no config keeps recovering in place), `graduationHandoffRequested` (the resident stdio serve's 2 s marker poll in `installStdioLifecycle`), and `readGraduationManifestSummary` (the redacted view of the 0600 manifest). Test: `test/graduation-serve-guard.serial.test.ts` (includes a real `gbrain serve` child exiting 75 and `engine status --json`).
- `src/core/persistence/engine-graduation.ts` — the orchestrator behind `gbrain migrate --to postgres`: `planGraduation` (zero mutations: probe-only source open, one read-only target session, refuses while a run is recorded non-terminal), `runGraduation` (needs `yes` plus `expectPlanHash`; a changed plan throws `preview_changed`), `resumeGraduation`, `rollbackGraduation`, `reconcileGraduation` and `graduationStatus` (files plus a read-only target-row read; split brain opens both datastores for counts). The kernel lock is held from step 1 to the routing flip: intent marker before the lock, autopilot pause marker, source open (waits up to 30 s for a resident serve's hand-off, else `graduation_source_writer_held`), in-process source doctor, route cross-check, drain and freeze, target fence, per-table copy with manifest checkpoints, deferred index build on the DDL route, verify (doctor child under `GBRAIN_GRADUATION_RUN`), then fence both and grant authority (source row `cutover`, lock-retaining close, move-aside, `O_EXCL` tombstone, one target transaction that sets `persistence_brain.enabled` and drops the fence) and flip routing (config, mounts). Every state change follows the transition tables and is mirrored into the 0600 manifest (`<GBRAIN_HOME>/.gbrain/graduation-manifest.json`, the only file holding target URLs) and the marker; each step announces its `graduationBoundary`. Resume continues from the recorded state with recorded identities; a resume after a lock gap recomputes source digests and re-drains and re-copies changed tables with their FK closure. Rollback before cutover abandons the target (fence kept); after cutover it fences first, takes the kernel lock, compares (`graduation-losses.ts`) and returns the target to authority on any refusal; `rollback_approved` onward only rolls forward. A rollback after cutover refuses with `not_found` when the retained copy is no longer at `<path>.graduated-<run_id>` or the manifest records `sourceDiscardedAt`, checked before the fence and again under the kernel lock, so it never opens an empty brain at the old path; `graduationStatus` reports `sourceDiscardedAt`. `--resume --yes` moves a stray datastore at the old path to `<path>.stray-<run_id>`. All refusals come from `graduation-errors.ts`. Tests: `test/graduation-state.test.ts`, `test/graduation-rollback.test.ts`, `test/e2e/graduation-*.test.ts`.
- `src/core/persistence/graduation-custody.ts` — filesystem custody and the open-path checks: the sibling intent marker (atomic replace, 0600, fsync), the `O_CREAT|O_EXCL` tombstone at the old data dir path, `inspectGraduationPath` (`none`, `in_progress`, `interrupted`, `graduated`, `split_brain`; marker liveness from pid, boot id, pid namespace and process start time), `assertPgliteGraduationOpenable` (called by `PGLiteEngine` before `acquireLock`, so a tombstone refuses `engine_graduated` and a live run `graduation_in_progress` without touching the path, and again after the lock, refusing `graduation_interrupted` past cutover), `assertGraduationConnectAllowed` (every CLI connect: a non-authoritative target or a cut-over source refuses unless the session is the run's) and `assertGraduationAdmission` (writer admission). `moveAsideHeld` renames under the already-held kernel lock as a sanctioned filesystem publication (a managed brain's datastore is a managed root). `discardingPath` names where `--discard-source` renames the retained copy before removing it. Test: `test/graduation-custody.test.ts`.
- `src/core/persistence/graduation-schema.ts` + `src/core/schema-migrations/v201-persistence-graduation.ts` — the `persistence_graduation` singleton (each engine's own custody row; schema-owned, never copied) and `gbrain_graduation_fence()`. `installGraduationFence` puts a statement-level `ENABLE ALWAYS` trigger on every table that refuses writes unless `gbrain.graduation_run` equals the row's run id; `dropGraduationFence`, `setTargetState`/`setSourceState` (transition-table driven) and `withGraduationRun`.
- `src/core/persistence/graduation-losses.ts` — rollback write detection: per carried table, the target digest against the verified receipt (`persistence_brain.enabled` through its transform), requests after the cutover sequence, and the security tables plus `fact_withdrawals` against the retained PGLite copy by identity and content (`last_used_at` ignored, expired OAuth tokens may disappear). Missing or changed security rows and new withdrawals are final.
- `src/core/persistence/graduation-discard.ts` — `gbrain migrate --discard-source`: `planDiscardSource` (zero mutations) lists what the recorded run left on this computer (the retained copy, the tombstone and the intent marker, with sizes) and binds them with the run id in a `plan_hash`; it refuses unless the manifest is `graduated` (`graduation_interrupted`/`graduation_in_progress` for an unfinished run or a pending rollback, `not_found` with no run or a rolled-back one), only that run's files sit at those paths (`local_conflict`), and, when anything is left, the target confirms in a read-only session that its row is this run's `authoritative` one (`graduation_in_progress` when a rollback fenced it, `database_error` when unreachable or unconfirmed). `discardSource` needs `yes` and the matching hash (`confirmation_required`, `preview_changed`), takes the source's kernel lock (`lock_busy`), re-plans under it, records `sourceDiscardedAt` in the manifest, renames the copy to `discardingPath` before removing it (so `graduatedPath` holds the whole copy or nothing), then removes the tombstone and marker; the manifest stays. Test: `test/graduation-discard.test.ts`.
- `src/commands/migrate-graduation.ts` — the `gbrain migrate` graduation CLI, routed before connect from `routeEngineFreeSubcommands` in `src/cli.ts` when `routesToGraduation` holds (run-scoped verbs and `--plan` always; a bare `--to postgres|supabase` on a durable PGLite config unless `migrate.graduation` is false or the host is Windows). Without `--yes --expect` it plans and returns the `confirmation_required` payload (effects egress and destructive, what moves and what stays, `plan_hash`, the `--plan` preview; no stdin prompt); `--plan`/`--dry-run` prints the plan; the run reports the receipt, retained copy, target doctor, `gbrain mcp expose` and the MCP restart note. `--discard-source` mirrors the same UX over `graduation-discard.ts`: bare, the exit-3 `confirmation_required` payload (effect destructive, the plan, `--dry-run` preview); `--dry-run`/`--plan`, the plan; `--yes --expect <plan_hash>`, the delete; it takes no `--to`, `--url`, `--url-env` or `--force`. Exit codes 0/1/2/3, 11 for a progressing drain stop (1 when a blocker needs a person), 75 for `graduation_in_progress`, 130 after SIGINT (stops at the next batch boundary). `--json` prints one document; progress goes to stderr per table and batch. Test: `test/migrate-graduation-cli.serial.test.ts`.
- `src/commands/doctor/checks/engine-graduation.ts` — `graduationStateCheck`, emitted from the filesystem lane of `local-audits.ts`: `graduation_interrupted` fails when a manifest or marker is non-terminal with no live owner (fix `gbrain migrate --resume`, rollback named) or a stray brain sits at the old path, is `ok` while a live run owns it, exempts the run named by `GBRAIN_GRADUATION_RUN`, and emits nothing on a brain that never graduated. The retained `.graduated-*` copy is reported by `pglite_leftovers` (`src/core/pglite-leftovers-check.ts`), silent while a manifest is non-terminal; for the recorded `graduated` run's copy its fix is `gbrain migrate --discard-source` (consent empty: the command itself asks), any other retained copy keeps the manual delete.
