- `src/core/persistence/content-author-schema.ts` + migration v341 (GST-4056) — who wrote a page's live text. `pages.content_author` is the channel of the write that produced the current text (`cli:transcripts-ingest`, `connector:<kind>`, `mcp:<operation>` for every remote write, NULL when the writer declared none) and `pages.content_author_hash` the content hash it wrote. putPage and the segmented flip declare it from the write's own channel (`import-file.ts` `content_author`, defaulting to `ingested_via`); a write of identical text keeps the stored author. The `pages_content_author` BEFORE UPDATE trigger clears both columns when a statement changes `content_hash` without declaring an author, so an older binary or a raw rewrite never leaves a stale author. Tag changes, contextual re-embedding and other metadata writes keep it. Readers (`transcripts/importer-provenance.ts` `importerWroteLiveTextSql`, `identity/speaker-owner.ts`) trust a page only through `contentAuthoredBySql`: author in the importer set and author hash equal to the live hash; `ingested_via` stays the first-ingest record and is never a trust signal. The migration backfill stamps legacy importer and connector pages the earlier rule trusted unless a committed remote request (compacted or not) or an archived version by a remote principal is on record for the page. Repo-less and repo-backed brains behave the same. Tests: `test/importer-trust-spoof-gst4056.test.ts`.
