- `src/core/persistence/content-author-schema.ts` + migrations v342 (DDL) and v343 (backfill) (GST-4056) — who wrote a page's live text. `pages.content_author` is the channel of the write that produced the current text (`cli:transcripts-ingest`, `connector:<kind>`, `mcp:<operation>` for every remote write, `legacy:<channel>` for a page the backfill vouches for only through its first-ingest stamp, NULL when the writer declared none) and `pages.content_author_hash` the content hash it wrote. A write declares its author by setting `content_author` with a NULL `content_author_hash` (the trigger stamps the hash), so a repeated declaration still counts; putPage and the segmented flip declare it from the write's own channel (`import-file.ts` `content_author`, defaulting to `ingested_via`), except that a segmented flip that changes no manifest row, type, title or text frontmatter (`BodyFlipInput.bodyUnchanged`) keeps the verified author, or none, and a projection-only re-chunk or the oversized-page backfill carries the verified author of the revision it read (`verifiedContentAuthor(exec, pageId, revision)`; the backfill's unmanaged rewrite also pins that revision). An exact copy sets `content_author_hash` to `EXACT_AUTHOR_MARK` (putPage option `exactContentAuthor`): `migrate-engine` and the v343 backfill set the author exactly, none when it is NULL, whatever the text and the stored author. An unchanged re-import never claims a page: the author is stamped only by a write of the writer's own text. The `pages_content_author` BEFORE UPDATE trigger compares the text (type, title, body, timeline, body generation, frontmatter minus hash-ephemeral keys and tags), not the hash: an unchanged text keeps a verified author and advances its hash (tag changes, re-embedding, metadata writes, a re-import that changes only tags) and keeps none on a page with none, whatever the write declares, a changed text takes the declared author, and a changed text with no declared author clears both columns, so an older binary, a raw rewrite or a hash-keeping fence mirror never leaves a stale author. Readers trust a page only through `contentAuthoredBySql` (author in the set and author hash equal to the live hash); `importerWroteLiveTextSql(page, via, {legacy})` admits `legacy:` authors for speaker markers, and accept-fences never offers a `legacy:` page but keeps an acceptance recorded for its exact `content_hash` (GST-4026) while that text stays; `ingested_via` stays the first-ingest record and is never a trust signal. The v343 backfill takes the author from a live local importer request, a `connector_v2_import` job, or a first ingest with no later write, stamps `legacy:` where only the first-ingest stamp vouches, and skips any page with a committed remote request that changed text, matched by page id or by source and slug (compacted or not; a recorded no-op does not count; a link change counts as text, since a managed `add_link` edits the links fence), or a version a remote principal wrote or replaced; a compacted local request other than `put_page` or a connector job gives no author; it reads only the request fields its rule needs and only pages an importer or connector could have written; its update re-checks the hash, revision and empty author on the locked row, so a concurrent write is never stamped. `migrate-engine` copies the author only when it matches the copied body's hash.
