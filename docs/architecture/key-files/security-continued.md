- `src/core/outside-content.ts` — GBRA-221: `neutralizeOutsideText(text)`, the one neutralizer for text a third party wrote before it lands in a page body (Gmail/Calendar/Contacts renders in `google-render.ts`, GitHub `renderItemPage`/`renderRepoCard`, chat transcripts in `transcripts/render.ts`, `book-mirror` chapter output). It escapes every `gbrain<ws>:<ws><name>` marker token to `gbrain\:<name>` (case-insensitive), `[Source:` to `[Source\:`, and backslash-prefixes each timeline sentinel, bare `## Timeline`/`## History` heading, dated timeline row or heading, transcript message anchor and date heading, using the parsers' own predicates. - `src/core/facts/private-fact-pages.ts` + `src/commands/auth-private-facts.ts` + `src/commands/auth-client-rows.ts` — the per-credential private-facts axis (`PrivateFactsGrant` `none` | `granted_sources` in `access_tokens.private_facts` and `oauth_clients.private_facts`, migration v319 `principal_private_facts`, default `none`, never in the legacy permissions mirror; set only by the local `gbrain auth rescope --token|--client --private-facts`, refused for a credential with scope sources in `src/core/access/attest-sources.ts`). - `src/core/access/owner-only.ts` — owner-only sources: a source of a kind in `OWNER_ONLY_KINDS` (`imessage`) or with `owner_only: true` in `sources.config` is read only by the local CLI and by a credential bound to the brain owner speaking for itself (`CallerAccess.owner`). Decided at read time by `gbrain_owner_only_lineage` (v320; v322 adds the `owner_only_marks` a delete leaves, below). `ownerOnlyPageSql`, `ownerOnlyFactSql`, `ownerOnlyTakeSql` and `ownerOnlyTimelineSql` match a row in an owner-only source, a synthesized concept with a `concept-provenance` input there, a row whose `derivation_inputs` (followed transitively, with no depth limit and cycle-safe) reach a page, fact, take or timeline row there, or a marked row; each is guarded by the zero-argument `gbrain_owner_only_lineage()`, so a brain with no owner-only source and no mark never calls the row test. From v328 each read passes `gbrain_owner_only_read_mode()` (the `mode` form), which reads lineage closed for a login whose reads of the lineage tables or the marks are not complete; a page or fact whose source row the login cannot read counts as owner-only. Below v320, or when the schema version is unknown, the closed form (`ANY_OWNER_ONLY_SQL`, or the `OWNER_ONLY_HELD` flag on `owner_only_marks`) treats every row as owner-only on a brain that holds or has held owner-only data. `src/core/search/private-visibility.ts` appends them to the mandatory member-access part of the page and fact policies (no grant, hatch or lineage switch relaxes them), and `src/core/persistence/page-visibility.ts` refuses a remote write into an owner-only source from any credential but the owner's (`page_not_found`). `ownerOnlySourcesPresent` and `sourceIsOwnerOnly` fail closed. Tests: `test/imessage-owner-only.test.ts` (every caller class under each relaxation), `test/owner-only-read-side.test.ts`, `test/e2e/owner-only-marks-scoped-login.test.ts`, `test/e2e/imessage-source-postgres.test.ts`.
- `src/core/access/owner-only-marks.ts` + `src/core/engine-sql/owner-only-marks.ts` + `src/core/schema-migrations/v322-owner-only-marks.ts` — GST-3032: owner-only lineage outlives its origin. A `BEFORE DELETE` trigger on `sources`, `pages`, `facts`, `takes` and `timeline_entries` records the deleted row and every row derived from it in `owner_only_marks`, which `gbrain_owner_only_lineage` reads; nothing derived is deleted. The triggers run as the deleting role (no SECURITY DEFINER, #7659): a role whose reads row-level security limits gets `owner_only_lineage_unreadable` deleting a row it sees as owner-only, and its delete of a row it sees as open sets the `('*', 'row_security')` mark. The guard reads `OWNER_ONLY_HELD`, a one-way comment on `owner_only_marks` set by the first owner-only source or mark, so a brain that never held owner-only data never reads the marks; the table has row-level security and no policy, a login that cannot read every mark reads lineage closed, and its deletes on a held brain are refused with `owner_only_marks_unwritable`. `ensureOwnerOnlyMarkTriggersAtRun` creates each trigger every migration run where the role owns the table and names the rest on stderr; while one is missing on a brain holding owner-only data, the `('*', 'unguarded')` mark makes lineage read closed until the owner deletes it. `BrainEngine.ownerOnlyMarkTriggers` is the shared state read; doctor `owner_only_marks_triggers` (`src/commands/doctor/checks/owner-only-marks-triggers.ts`) names a missing or disabled trigger with its owner fix, each login that still needs the marks grant (with the GRANT and CREATE POLICY statements), and the row-security mark. Operator docs: [ENGINES.md](../../ENGINES.md#owner-only-delete-triggers). Tests: `test/owner-only-removal-lineage.test.ts`, `test/engine-parity/owner-only-marks.test.ts`, `test/e2e/owner-only-marks-scoped-login.test.ts`.
