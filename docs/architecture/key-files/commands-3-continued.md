- `src/commands/extract-timeline-db.ts` — the `extract timeline --source db` walk (`extractTimelineFromDB`), also used by `runExtractCore` for a timeline-only pass on a managed brain. Managed brains (every fresh `gbrain init` brain) publish each page that needs a change as one database-only maintenance request (`managed_maintenance_timeline_extract`, owner-checked by `maintenancePreflight`, request id bound to the page revision; `prepareTimelineExtract` is dispatched from `prepareMaintenanceMutation`): under the page lock it retracts rows the current text no longer produces and inserts the canonical tuples with no stored row (`unrecordedCanonicalTimeline`); a page with nothing to change admits no request, and a page edited meanwhile is skipped. The retraction's `page_versions` scan runs before the publication transaction, one version body per statement (`versionTimelineScan`, #9362); inside the transaction it only checks that each version it read is still the page's with the same body, and a row whose versions changed in between stays until the next run. Unmanaged brains batch raw inserts. A refused write prints `refused: <code>; nothing written; existing timeline rows are untouched`, the summary counts written versus refused (a request still pending counts as not confirmed) with `gbrain extract --stale` and the `write-refusals.md#extract-timeline-refused` anchor, and the CLI exits 1 (the `extract` job throws). Pinned by `test/extract-timeline-db-managed.test.ts`, `test/e2e/extract-timeline-db-postgres.test.ts`, `test/fresh-init-db-extract.serial.test.ts`.

- `src/commands/extract-stale-options.ts` — `gbrain extract --stale` source-option validation, run by `extract-stale-delegate.ts` before every `--stale` invocation connects (so before direct and owner dispatch alike): `--source` is the fs|db read mode, never a source id; `--source db` is accepted, `--source fs` and any other `--source <x>` refuse `invalid_params` (exit 2) with a fix naming `--source-id <x>`. `assertStaleSourceModeUnambiguous` refuses `--source db` as ambiguous when a registered source is named `db` (direct path in `runExtract`; owner path in `writer_extract_stale`, which also takes `catch_up`). Tests: `test/extraction-nudge-6803.test.ts`.

- `src/commands/friction.ts` + `src/core/friction.ts` — `gbrain friction {log,render,list,summary,diff}` reporter. Append-only JSONL under `$GBRAIN_HOME/.gbrain/friction/<run-id>.jsonl`. Schema is a flat extension of `StructuredAgentError`; every claw-test run opens with a `phase-marker`/`start` meta record carrying `agent` + `scenario` + `harness_schema` (agent-name resolution depends on it). Render groups by severity → phase, defaults to `--redact` for md output (strips `$HOME`/`$CWD` to placeholders so reports paste safely in PRs). `diff --base <run-or-agent> --compare <run-or-agent>` is the cross-agent instrument: exact run-id wins, else agent name resolves to that agent's latest run; identity is `(kind, phase, normalized 80-char message prefix — digit runs collapsed so durations/counts don't split identities)` over `kind ∈ {friction, delight}` as MULTISETS (per-severity counts + totals are the compared attributes: `count_changed` = volume, `severity_changed` = distribution shape via exact integer proportion test, so a delight→friction flip or a 2×error+1×nit → 1×error+2×nit redistribution always surfaces; markers/interrupted feed the compatibility banner, which warns on scenario/version mismatch); output labels sections "unique to <run>" — an instrument, never a blame-attributor. Run-id resolves from `--run-id` > `$GBRAIN_FRICTION_RUN_ID` > `standalone.jsonl`. Skills the claw-test exercises carry a `_friction-protocol.md` callout so agents know when to log friction.

- `src/commands/doctor/checks/outside-content-fences.ts` — `outside_content_fences` (GBRA-221, BRAIN, registered before `fence_integrity`). Lists facts (`row_num` set, active; world-visible counted apart), active takes and `links_fence` links indexed from a fence on an imported page whose body is outside-authored text (Google `email`/`meeting` pages, every GitHub-source page, pages with `transcript_import` frontmatter). Reads the derived rows, never a page body, so segmented pages are covered. Before GBRA-221 a sender could plant such rows and a re-render carries a stored fence forward; gbrain writers also add rows on purpose, so it only lists pages (location and counts, never a cell value) with an `ask_user` review fix (`gbrain get`) and removes nothing. Pages accepted by `gbrain transcripts accept-fences` are left out and counted as `accepted_transcripts` in the details, and when the listed pages include imported transcripts the fix is that command's preview.
- `src/commands/transcripts-accept-fences.ts` + `src/core/transcripts/fence-acceptance.ts` — `gbrain transcripts accept-fences [--source-id S] [--json] [--yes --expect <plan_hash>]` (#9427): the one-pass owner review of `outside_content_fences` for imported transcripts. `listOutsideFencePages` is the check's page list (location, counts and a fingerprint of each page's fence fact, take and link ids; never a value); only `type: conversation` pages with `transcript_import` frontmatter whose live text the importer wrote (`importerWroteLiveTextSql` in `importer-provenance.ts`, the page's content author: `persistence/content-author-schema.ts`, never a `legacy:` one) qualify. Without `--yes` it previews with a `plan_hash`; `--yes --expect` re-plans, refuses `preview_changed` on a different hash, and records `{page_id, source_id, slug, fingerprint, accepted_at}` in the config row `transcripts.fence_acceptance`. A new, removed or changed row or a later non-importer write leaves `isAccepted` false, so the page is listed again; embedding-only row updates do not. An acceptance also records the page's `content_hash` (GST-4026); maintenance that changes no text keeps the page's content author, so it stays accepted. Nothing in a page or its rows changes, so repo-less and repo-backed brains behave the same. Tests: `test/transcripts-accept-fences-9427.test.ts`.
