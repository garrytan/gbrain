- `src/core/rust-engine/owner-ipc/` — the owner protocol of the Rust engine (ENGINES.md "The Rust engine shell"; design in `docs/designs/RUST_ENGINE.md`). One process owns a brain: `election.ts` `electOwner` takes the kernel lock `<database_path>.gbrain-owner.lock`, makes the store directory mode 0700 (created `0o700` and `chmod`ed, whatever the socket path length) and the owner serves its engine on `<database_path>/.gbrain-owner.sock` (`server.ts`: 32 calls at once, the rest in a FIFO queue of at most 1,024 calls, at most 256 MiB of call frames held at once (queued and running), at most 256 connections, each over a bound refused `owner_busy` with reason `queue_full`, `inflight_bytes` or `connections`; a refused connection gets one `refused` frame and is half-closed, a refused peer that never closes its side is cut off after 1 second (`OWNER_IPC_REFUSED_DRAIN_MS`), and past 64 refusals in flight the next is dropped with no frame; a cancel frame ends a call, `deadline_at` and `read_deadline_at` bound it; where the kernel gives a peer's uid (`cli-socket/peer-cred.ts`) a connection from another OS user gets a `refused` frame `owner_ipc_peer_refused` reason `peer_uid` and nothing runs); every other process becomes a client (`client.ts` `installOwnerClient`, never opens the store, capabilities mirror the owner's hello; before it connects it refuses a socket file another user owns, `socket_owner`, or one with group or other permission bits outside a private 0700 directory of this user, `socket_mode`, and after it connects an owner of another uid, `peer_uid`; for a remote caller, `callerIsRemote`: a handler call marked by `src/core/remote-caller.ts` (an MCP request, a subagent brain tool or a SkillOpt tool), a job whose submission authority is not the application, or a remote verified writer, it sends only the reads of `routes.ts` `OWNER_IPC_REMOTE_READS` and refuses any other member `engine_capability_missing` with nothing sent) or, after 5 seconds, throws `owner_unavailable` with reason `not_sent`. `routes.ts` classifies each member: `local` (`kind`, `capabilities`, `connect`, `disconnect`, `reconnect`, `registerBeforeDisconnect`), `refuse` (`transaction`, `transactionDirect`, `withReservedConnection`, `holdSchemaMigrationLock`, `keywordBoundedRead`; against a Rust owner all but `holdSchemaMigrationLock` first meet the capability check below and refuse with the owner's own reason, `transactions` or `raw_sql`; `holdSchemaMigrationLock` and a call whose arguments hold a function other than a search metadata hook refuse `engine_capability_missing` with `via=owner_ipc`) or `forward` (everything else; a member the owner's hello lacks, and the store does not serve, refuses at the client as the owner's own engine does). `whole-op.ts` and `owner-ops.ts` can forward `importFromContent`, `importFromFile`, `importImageFile` and `importManagedFiles` as one request that runs, transaction included, in the owner (paths are made absolute, and a remote caller or a function option refuses), but no entry point calls the sender yet: a client's journaled write (`put_page`, `remember`, so `gbrain bootstrap verify`'s roundtrip and the Apple Contacts person-fact sync) stops at write admission, which opens a transaction, on `engine_capability_missing` reason `transactions`. `protocol.ts` and `codec.ts` frame the calls (an owner reply over 128 MiB ends `response_too_large`; a call's `access` field carries the caller's access record, which the owner runs it under; `deadline_at` ends a queued call `timeout` reason `not_started` and a running one `outcome_unknown`; `timer.ts` `setDeadlineTimer` re-arms past the 2^31-1 ms setTimeout limit on both sides, so a far deadline waits instead of firing at once; frame rules refuse `owner_ipc_protocol`: a hello of another version (the owner sends its hello, then closes; the client's connect rejects `version_mismatch`, which the election does not retry), a call before the hello (`hello_missing`), an id still open on the connection (`duplicate_id`, the first call keeps its cancel and close abort), arguments that are not a list (`args_not_array`), and an answer the client cannot decode (`result_undecodable`, that call only); the socket directory and lock path resolve symlinks, so every alias of one brain names one owner). When the owner exits, a call in flight ends `owner_unavailable` with reason `outcome_unknown`; a RustEngine client (`installOwnerClient`'s `rejoin`, `RustEngine._takeOver`, which shares the open's single flight) runs the election again on its next call and becomes the owner, opening its store, or a client of the new owner, so the call works with no restart; a whole operation that finds this process became the owner ends `not_sent` and its retry runs in process. A client installed without `rejoin` answers later calls `not_sent`. Pinned by `test/rust-owner-ipc.test.ts` (child processes from `test/helpers/owner-ipc-child.ts`), `test/rust-owner-ipc-frames.test.ts`, `test/rust-owner-ipc-limits.test.ts`, `test/rust-owner-ipc-peer.test.ts` and `test/rust-owner-ipc-remote.test.ts`. `whole-op.ts` also carries two whole operations that are not imports: `snapshotStore` and `snapshotStatus`, run by `src/core/rust-engine/store-snapshot.ts` on the owner. A snapshot copies the brain at one committed generation (`rust/docs/store/snapshot.md`), one at a time per store; a caller that is gone, a free-space reserve of max(2 GiB, 5 %) and a 2-hour age budget each cancel it, and the call settles, and `snapshotStatus(opId)` says terminal, only after the Rust call has returned with the read released and the target removed. Only the trusted local caller may run it, in process as well as before it is forwarded (a remote caller is refused `engine_capability_missing`). A copy that does not run or finish ends `rust_snapshot_stopped` with reason `busy`, `cancelled`, `disk_pressure` or `age_budget`; a copy asked for while the engine is disconnecting (`RustEngine.disconnecting`) is refused with reason `cancelled` before the Rust call starts, and a disconnect stops a copy already running and waits for the Rust call before the store closes. The shadow drill (`src/shadow/drill.ts`) is the one entry point that calls them; `gbrain backup` does not yet. `verifyStoreDir` in `store.ts` checks a copy without opening it. Pinned by `test/rust-engine-store-snapshot.test.ts`.

It changes nothing and refuses on a transaction-bound handle (`invalid_state`: the new id and `FORMAT` are published together, which an outer rollback could not undo), on a handle opened read-only (`read_only_transaction`, asked of the key-value layer's `is_read_only` before the lock, any `FORMAT` repair or a write transaction), when the rebased origins would give two live pages one origin (`origin_claimed`) and when `plan.settings` does not list every held safety setting exactly once (`invalid_argument`); Windows drive and UNC origins, and an absolute origin not under its source's old root, stay unchanged and are counted in the source's preserved-origins line of `reconnect`. Nothing is revoked here (a follow-up adds revocation): a live OAuth client or local writer refuses as `archived_authority` with its ids, activated shared-skill publication, a shared-skill member, batch or policy, or `mcp.publish_skills` on refuses as `shared_skill_state`, an archived access-token (`jobs 0x2b`), OAuth token (`0x2c`) or OAuth code (`0x2d`) record is refused by name, and an unknown kind refuses. The take purge ledger (`F 0x10`) counts as a purge ledger, restores run one at a time (a process-wide lock held through the id rotation and the `FORMAT` write; with it held, a `FORMAT` that still names an earlier rotation's id is brought up to the committed id before another rotation commits, and a failed write refuses with nothing changed), and a cancelled job with a payload that is not an object keeps it under `__restore_original_data`. TypeScript: `buildQuarantinePlan`, `restoreRefusalFor` (the registered `restore_step_unsupported` reasons, each with what was not published and the fix), `checkStoreIdentity` (the archive's `store.engine_format_version` is never the container's `format_version`) and `restoreAddonSupportsSafety`. Not BrainEngine members; the CLI that calls them is PR 21b-ts.

- `src/core/rust-engine/addon-loader.ts` — the Rust engine addon loader (ENGINES.md "The Rust engine shell"). `loadRustEngineAddon(overrides?)` returns `{ ok: true, addon }` or `{ ok: false, code, reason, message }` for the two refusals and rethrows anything else; `loadRustAddon` is the throwing form. It never reaches the network, takes no lock and writes nothing; a refusal leaves every file as it was. Only the Rust engine's open path may import the loader, lazily, so PGLite and Postgres brains never load the addon or create `<gbrain home>/engines/`; it loads with `process.dlopen` from a computed path (a literal `require` of a `.node` would be bundled into compiled executables). The addon itself (`rust/crates/gbrain-napi/src/binding.rs`) refuses a typed array whose buffer the runtime (`napi_is_arraybuffer`) does not call a plain `ArrayBuffer`, so hiding `SharedArrayBuffer` or swapping a prototype changes nothing. Pinned by `test/rust-engine-addon-loader.test.ts` and `rust/smoke/smoke.test.ts`.

- `src/shadow/` + `src/commands/engine-shadow.ts` — Rust engine shadow mode: sampled reads compared in the background, plus a seeded Rust store that follows the brain's writes, and the writer evidence the swap check needs (ENGINES.md "Rust engine shadow mode"). `shadow/status-document.ts` `shadowStatusDocument` builds the one status object `gbrain engine shadow status --json` prints and the engine swap reads (`readConfiguredShadowStatus`: null when the brain has no `state.json`, which the swap reports as `no_shadow`). `shadow/state.ts` (`shadowStateFor(config)`) reads `configDir()/shadow/<brain>/state.json` (brain key `<engine>-<12 hex>` from `brainIdentity`) and returns null when shadow mode is off, the file is missing or unreadable, or `GBRAIN_SHADOW_CHILD=1`; a failed write keeps them staged and retries, and a stage bound counts lines of every kind. At disconnect `drain` waits up to 2 s for the pipe to flush, and `closeOwed` closes the record (`closed`; `child_exited` is written when the child dies) so the child books any sample it never read as `pipe_unflushed` (capability_missing `pipe_unflushed_nonqualifying` for one that was not a page or link write). `shadow/write-compare.ts` keeps the other half: `WriteTally.note` takes the credit a verdict settles and saves it in the same locked rename (`settled[session]` and its page-and-link part `settled_qualifying[session]`, carried into a new epoch together with `lost_applied` and `applied`), a client or retired child writes `no_epoch`/`epoch_retired` lost lines that name the session (numbered per writer: a batch retried after a partial or unflushed append writes the same numbers, and the owner takes each once, in the tally's `line_seq`), `readWriteSnapshot` reads tally, then unfolded lost lines, then owed files, then the tally's identity again so status can only over-block, and `WriteTally.obligations` (at start, each save and every 10 s) books a gone session's `owed - settled` once as `receipt_orphaned`, split by `owed_qualifying` less `settled_qualifying` (the rest is capability_missing `receipt_orphaned_nonqualifying`; `LOST_NONQUALIFYING` folds those lines), and removes its file only after a tally read back from disk covers it; the child removes its own file at the end of its input under the same rule. Legacy `write-sent.*` receipts, lost lines with no session (`legacy_lines`) and `sent_count n=`/`no_epoch n=` faults from older writers are still read as no evidence. The supervisor stops when `state.json` turns off. `shadow/child.ts` (`runShadowChild`) loads the addon offline (`shadow/addon.ts` `loadRustEngineAddonOffline`, the cache-only loader: `not_installed` when no addon is cached or overridden, never a network call), opens the Rust engine, replays each read, classifies it (`shadow/classify.ts`: `match`, `order_diff`, `diff`, `stale`, `inconclusive`, `collation_order`, `privacy_diverged`, `capability_missing`, `error`, `timeout`, `addon_unavailable`) and appends content-free rows to the local ledger (`shadow/ledger.ts`); a privacy divergence pauses comparison and tells the parent to stop mirroring. `shadow/report.ts` (`buildProvisionalReport`) totals the per-child summary files (`summaries/`), not the ledger rows, into a report whose verdict is always `NOT READY`; `gbrain engine shadow report` writes `reports/provisional.{json,md}` only after the shadow directory exists. `commands/engine-shadow.ts` (`runEngineShadow`) is `gbrain engine shadow start|status|stop|report|seed|reconcile|drill|bench`; `start` previews a plan and its `plan_hash`, needs `--yes --expect <hash>` (a missing or stale hash refuses `preview_changed`), and refuses without writing when the real addon loader refuses. `start` also reads the brain's storage mode once, best-effort (`shadow/managed-gate.ts` `readManagedStorage`; a brain that cannot be opened or read is `managed: null` with a reason code), prints a line for a managed brain, which cannot swap, and records `storage: { managed, checked_at, reason? }` in `state.json`; `status --json` and the report carry it as `storage` with a `note`.
