- `src/core/snapshot-schema-inputs.ts` — the inputs of the PGLite snapshot schema hash (`computeSnapshotSchemaHash` in `pglite-engine.ts` hashes each file's raw bytes). Computed, not hand-kept: the static import closure (`import`, `export ... from`; type-only imports skipped) of `SNAPSHOT_SCHEMA_ROOTS` (`pglite-schema.ts`, `schema-migrations/registry.generated.ts`, `migrate.ts`, `engine-sql/bootstrap.ts`) plus `SNAPSHOT_SCHEMA_LEAVES`; every literal dynamic `import()` inside the closure must be classified as a leaf or in `SNAPSHOT_DYNAMIC_IMPORTS_NOT_HASHED`. - `src/core/sql-trace.ts` — env-gated wire-level SQL trace for benchmarks. `traceSqlOptions(options, pool)` returns the postgres.js options untouched unless `GBRAIN_SQL_TRACE=<file.jsonl>` is set; then it supplies a tracing socket and sets `application_name` to `gbrain:<GBRAIN_SQL_TRACE_LABEL or command>:<pid>:<pool>`. All four pool construction sites use it (`db.ts` module singleton, `PostgresEngine` instance pool, `ConnectionManager` read and direct pools), so `executeRaw`, `tx.unsafe`, the engine-sql adapter and tagged templates are all seen. Each Sync, simple Query or describe Flush and its reply is one JSONL record (statement text without parameter values, start, duration, process, pool, client connection, backend pid, SQLSTATE on error); a `connect` record covers TCP plus the startup handshake. TLS connections are recorded once as `tls_untraced`. Records are buffered and flushed every second and at exit. Consumed by `scripts/bench/managed-sync-catchup.ts` ([record](../../eval/managed-sync-catchup.md)); pinned by `test/sql-trace.test.ts` and `test/e2e/sql-trace-postgres.test.ts`.

- `src/core/worker-pool.ts` — (must-abort tags: `BUDGET_EXHAUSTED` and `SPEND_GROUP_REFUSED`, a job's spend-group refusal) Canonical sliding-pool + bounded-semaphore primitive (used by the `src/commands/embed.ts` sliding-pool sites and `src/commands/eval-cross-modal.ts`'s `runWithLimit` semaphore). Two exports: `runSlidingPool<T>({items, workers, onItem, signal?, onError?, failureLabel?, onProgress?})` + `runWithLimit<TIn, TOut>({items, limit, fn, signal?})`. Atomicity invariant: `const idx = nextIdx++` is one synchronous JS statement (no `await` between read and write — guaranteed by the single-threaded event loop), documented in the module header AND enforced by `scripts/check-worker-pool-atomicity.sh` (wired into `bun run verify`), which rejects importing `worker_threads` in any consuming file and inserting `await` between the `nextIdx` read and write. `MUST_ABORT_ERROR_TAGS` set is seeded with `BUDGET_EXHAUSTED` from `src/core/budget/budget-tracker.ts`; tagged errors (matched via `err.tag === 'BUDGET_EXHAUSTED'` to avoid cross-module import) bypass `onError` and hard-abort the pool via `AbortController.abort()` to in-flight `onItem`, then the pool JOINS every worker (each finishes its current item) before rethrowing — the budget cap is a structural ceiling under concurrency and no worker is left running detached past the caller's catch. `failures[]` shape is `{idx, label, error}` records (NOT full items; callers supply `failureLabel(item) => string`) for bounded memory under huge brains. Pinned by `test/worker-pool.test.ts` + `test/scripts/check-worker-pool-atomicity.test.ts`. Drives every `--workers N` bulk command.

- `src/core/rust-engine/addon-loader.ts` — the Rust engine addon loader (ENGINES.md "The Rust engine shell"). `loadRustEngineAddon(overrides?)` returns `{ ok: true, addon }` or `{ ok: false, code, reason, message }` for the two refusals and rethrows anything else; `loadRustAddon` is the throwing form. - `rust/crates/gbrain-store/src/facts/reconcile.rs` — the Rust store's `page_facts_reconcile` watermark (`F 0x0D page_id` → reconciled and attempted revision, outcome, times) and its four members. `listFactsReconcileBacklog`: the due live pages (no watermark, or one behind `knowledge_revision`) that hold the fence marker the TypeScript member sends or own a fence row, in (source, slug) byte order, and the count of other due segmented pages. `settleFactsReconcile`: one live page's outcome at the revision the reconcile read (or the current one); `complete` moves the reconciled revision, other outcomes keep it. `selectFactsReconcileDrain`: settles the source's fenceless due pages as complete (page-id order, at most the settle limit), then answers the due retryable slugs, never-attempted first. A hard page delete removes the row through `remove_page_rows`, which `cascade::remove_page_rows` calls. `lockReconcileRevision`: whether the live page is still at the revision the reconcile read, read inside the caller's store transaction, whose single writer is the lock, so the extract_facts commit step runs whole on Rust. Pinned by its unit tests and `test/engine-parity/facts-purge.test.ts`.
- `rust/crates/gbrain-store/src/facts/generations.rs` — the Rust store's derived generation ledger (`F 0x0E generation_id` → the `derived_generations` row with its `derived_generation_items` inline) and `listUnwithdrawnFacts`: the expired, fenceless facts the newest facts-fence generation of a page retired, with withdrawal (`withdrawalCoversFactSql` at the current fingerprint), active-duplicate and page columns, in (source, slug) byte order. No member writes the ledger on Rust; the fence writer (`generations/fence.ts`, `generations/publish.ts`) and the managed activation journal (`generations/managed.ts`) write it with raw SQL and refuse, so a writer needs the source-delete cascade first. Pinned by its unit test and `test/engine-parity/facts-repair.test.ts` (the `recordFenceRetirement` fixture).
