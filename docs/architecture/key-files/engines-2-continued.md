- `src/core/schema-client-behind.ts` — #7776: `assertSchemaNotAhead(query)` runs on the schema-setup connection before both engines' schema replay: a `config.version` above `LATEST_SCHEMA_VERSION` refuses `client_behind` (fix `gbrain upgrade`, `host_admin`) before the bootstrap and replay, so an older binary never reinstalls its superseded function bodies over a newer schema. Pinned by `test/init-schema-client-behind.test.ts` and its Postgres e2e twin.

- `src/core/snapshot-schema-inputs.ts` — the inputs of the PGLite snapshot schema hash (`computeSnapshotSchemaHash` in `pglite-engine.ts` hashes each file's raw bytes). - `src/core/sql-trace.ts` — env-gated wire-level SQL trace for benchmarks. `traceSqlOptions(options, pool)` returns the postgres.js options untouched unless `GBRAIN_SQL_TRACE=<file.jsonl>` is set; then it supplies a tracing socket and sets `application_name` to `gbrain:<GBRAIN_SQL_TRACE_LABEL or command>:<pid>:<pool>`. All four pool construction sites use it (`db.ts` module singleton, `PostgresEngine` instance pool, `ConnectionManager` read and direct pools), so `executeRaw`, `tx.unsafe`, the engine-sql adapter and tagged templates are all seen. Each Sync, simple Query or describe Flush and its reply is one JSONL record (statement text without parameter values, start, duration, process, pool, client connection, backend pid, SQLSTATE on error); a `connect` record covers TCP plus the startup handshake. TLS connections are recorded once as `tls_untraced`. Records are buffered and flushed every second and at exit. Consumed by `scripts/bench/managed-sync-catchup.ts` ([record](../../eval/managed-sync-catchup.md)); pinned by `test/sql-trace.test.ts` and `test/e2e/sql-trace-postgres.test.ts`.

- `src/core/worker-pool.ts` — (must-abort tags: `BUDGET_EXHAUSTED` and `SPEND_GROUP_REFUSED`, a job's spend-group refusal) Canonical sliding-pool + bounded-semaphore primitive (used by the `src/commands/embed.ts` sliding-pool sites and `src/commands/eval-cross-modal.ts`'s `runWithLimit` semaphore). Atomicity invariant: `const idx = nextIdx++` is one synchronous JS statement (no `await` between read and write — guaranteed by the single-threaded event loop), documented in the module header AND enforced by `scripts/check-worker-pool-atomicity.sh` (wired into `bun run verify`), which rejects importing `worker_threads` in any consuming file and inserting `await` between the `nextIdx` read and write. `MUST_ABORT_ERROR_TAGS` set is seeded with `BUDGET_EXHAUSTED` from `src/core/budget/budget-tracker.ts`; tagged errors (matched via `err.tag === 'BUDGET_EXHAUSTED'` to avoid cross-module import) bypass `onError` and hard-abort the pool via `AbortController.abort()` to in-flight `onItem`, then the pool JOINS every worker (each finishes its current item) before rethrowing — the budget cap is a structural ceiling under concurrency and no worker is left running detached past the caller's catch. `failures[]` shape is `{idx, label, error}` records (NOT full items; callers supply `failureLabel(item) => string`) for bounded memory under huge brains. Pinned by `test/worker-pool.test.ts` + `test/scripts/check-worker-pool-atomicity.test.ts`. Drives every `--workers N` bulk command.

A served member that cannot match PGLite for an input refuses it typed: a `source_path` write, a `resolveSlugs` with no exact match, a `getChunks` over several sources. `listPages` with `listColumnsOnly` keeps PGLite's list projection, `content_hash` and `emotional_weight` present and undefined as rowToPage sets them. `common.ts` `throwIfAborted` stops an aborted write before it starts. `searchKeyword` ranks with BM25 and is not parity with PGLite's ranking (design D5). `transaction`, `transactionDirect`, `lockPageKeys` and the belief ledger stay refused. Page trust: the store stamps each page write's `trust_tier` and `write_origin` inside the store write (a page write outside one refuses), `createVersion` copies them into the snapshot (`store-codec.ts` `toCreatedVersion` lets the store's values replace the defaults), `readPageTrustRows` computes `flagged` from the write-gate receipts (it also labels the page rows of `gbrain delta`, the turn context and the retrieval reflex through `eligibility/activation.ts` `pageActivationVerdicts`), and the retrieval coverage reads (`link-temporal.ts` `coverageScope`) send `minTrust` and `suppressFlagged` to the store. `initSchema` (`store-members/init-schema.ts`) writes the `embedding_model` and `embedding_dimensions` config rows PGLite's schema seeds, when absent. `store-members/catalog.ts` is not a store member: it answers Postgres-catalog probes (`answersFromCatalog`, `catalogTableExists` via `TABLE_CAPABILITY`) from the engine's capability list on an engine without `raw_sql`, and `catalogSkipCheck` builds the doctor row for a Postgres-internals check that does not apply (status `ok`, `details.outcome: 'skipped'` with a `reason`); PGLite and Postgres keep their SQL. Pinned by `test/rust-engine-store.test.ts` (needs the built addon), `test/rust-engine-shell.test.ts` and the opt-in Rust arm of `test/engine-parity/` (`rust-arm.ts`, `GBRAIN_TEST_RUST_ARM=1`, expected differences in `test/rust-expected-divergence/` (one `<family>.tsv` per family), each with a named normaliser; `test/rust-arm-harness.test.ts` pins the arm's own check).
- `src/core/rust-engine/addon-loader.ts` — the Rust engine addon loader (ENGINES.md "The Rust engine shell"). `loadRustEngineAddon(overrides?)` returns `{ ok: true, addon }` or `{ ok: false, code, reason, message }` for the two refusals and rethrows anything else; `loadRustAddon` is the throwing form. Order: `GBRAIN_RUST_ENGINE_ADDON` (an absolute path to a `bun run rust:build` file; skips only the release checksum pin, `engine_abi` and target are still checked); then the addon at `<gbrain home>/engines/rust/<engine_build>/<target>.node` named by the cached `manifest-<version>.json` of the running version, loaded only when its SHA-256 equals the manifest's. It never reaches the network, takes no lock and writes nothing; a refusal leaves every file as it was. Only the Rust engine's open path may import the loader, lazily, so PGLite and Postgres brains never load the addon or create `<gbrain home>/engines/`; it loads with `process.dlopen` from a computed path (a literal `require` of a `.node` would be bundled into compiled executables). Reasons (`addon-errors.ts`, listed in `error-registry.ts`): `rust_engine_addon_missing` is `unsupported_target`, `not_installed` or `override_not_found`; `rust_engine_addon_mismatch` is `digest`, `engine_abi`, `engine_build`, `target` or `load_failed`; both are raised before the brain is touched. `addon-manifest.ts` parses the manifest and holds `RUST_ENGINE_ABI` and `RELEASE_ADDON_TARGETS` (`linux-x64-glibc`, `darwin-arm64`); `addon-target.ts` names this platform's target. The addon itself (`rust/crates/gbrain-napi/src/binding.rs`) refuses a typed array whose buffer the runtime (`napi_is_arraybuffer`) does not call a plain `ArrayBuffer`, so hiding `SharedArrayBuffer` or swapping a prototype changes nothing. Pinned by `test/rust-engine-addon-loader.test.ts` and `rust/smoke/smoke.test.ts`.

Both engines send the two lists unscoped through their own executor (Postgres through `preparationRead`), and the claim read through the transaction's own executor, so its row lock holds until the claim stamp commits. The Rust engine serves it in `src/core/rust-engine/store-members/effect-scans.ts` from `gbrain-store` `persistence/effect_scans.rs`: a Rust brain has no persistence worktrees, so each list is empty; the claim read answers the next claimable effect with the Postgres queue rules (`persistence/effect_worker.rs`); and the arguments the Postgres casts refuse (a host id that is not a uuid, a cursor that is not a bigint, a fractional or negative limit) get the Postgres refusal. Pinned by `test/engine-parity/effect-scans.test.ts`.
- `src/core/engine-sql/persistence-owner-scans.ts` — the write owner's housekeeping scans as typed engine members. `listOverdueHeldWrites(hostId, maxWaitMs, hold)` lists up to 100 deferred writes on this host's worktrees whose refresh or import hold is past the wait limit, and `lockOverdueHold(hold)` rechecks one such hold under the protocol lock and row-locks it for the transaction (`persistence/refresh-barrier.ts` `expireDeferredWrites` calls both). `listOwnerRecoveryHeads(hostId, excluded, { direct })` is the consumer's recovery scan (`persistence/consumer.ts` `readOwnerRecoveryHeads`): the oldest recovering write of each worktree the host owns, at most 16; on Postgres `direct` takes the direct lane, as the consumer's statements do (`consumerOnDirectLane`). `listResumableRefreshes(hostId, budgetMs)` and `listSourceLastCommits(sourceIds)` are the refresh resume's reads (`persistence/worktree-refresh.ts` `resumeWorktreeRefreshes`): the interrupted refreshes of worktrees the host owns, at most 16 with a syncing row last and each marked `stale`, and the last commit of each named source in id order. The module also holds the SQL fragments of those holds (`overdueDeferredFrom`, `overdueImportFrom`, `holdOverdue`), which the owner's idle probe (`overdueDeferredWorkSql`) reuses, so the text is the one the callers always sent, byte for byte. Both engines send it unscoped through their own executor; the hold check runs on the transaction's connection. The Rust engine serves them in `src/core/rust-engine/store-members/owner-scans.ts` from `gbrain-store` `persistence/owner_scans.rs`: a Rust brain has no persistence worktrees, so every list is empty and no hold stands, and an id that is not a uuid gets the Postgres uuid refusal. Pinned by `test/engine-parity/owner-recovery-scans.test.ts`.
- `src/core/engine-sql/persistence-effect-worker.ts` — the effect worker's claim and settle statements as typed engine members: `stampEffectClaim`, `renewEffectClaim`, `advanceEffectRow`, `completeEffectRow`, `retryEffectRow`, `retryBusyEffectRow`, `requeueEffectRow`, `parkEffectRow` and `failEffectRow` (`persistence/effect-journal.ts` calls them; each settle matches only the claim it names), `readMirrorGateRows` (the withdrawal-mirror gate), `hasRearmableTargets` (the re-arm probe after a mirror commits; `REARMABLE_SQL` is shared with `rearmWithheldTargets`) and `lockEffectGuard` (`persistence/effect-recovery.ts` `guardEffectSource`: the brain-row share lock and, for a worktree effect, the worktree owner read). Each text is the one its caller always sent; both engines delegate here (Postgres sends a direct renewal through `executeRawDirect`). The Rust engine serves them in `src/core/rust-engine/store-members/effect-worker.ts` from `gbrain-store` `persistence/effect_worker.rs` (`lockEffectGuard` resolves null there: single writer, no worktrees). Pinned by `test/engine-parity/persistence.test.ts` and the statement golden in `test/persistence-journal-statements.test.ts`.
- `src/core/engine-sql/persistence-idle-probe.ts` — the consumer's idle probe as the typed member `probeIdleWork` (`persistence/consumer.ts` `hasWork` calls it on its reserved idle lane, the direct lane, or the engine): one statement answers whether any worker of the host has work and where the resident projection window stands. The statement is the one the consumer always built, with each value bound where it is read (renderFragment numbers the placeholders); it is pinned equal to the consumer's value for value, and both engines send the same text and values, in `test/persistence-journal-statements.test.ts` (golden `sql-text-extra/persistence-idle-probe.json`). The Rust engine serves it from `gbrain-store` `persistence/idle_probe.rs` (no worktree terms: a Rust brain has no worktrees). Behavior pinned by `test/engine-parity/persistence.test.ts`.
