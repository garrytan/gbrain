- `src/core/rust-engine/owner-ipc/` — the owner protocol of the Rust engine (ENGINES.md "The Rust engine shell"; design in `docs/designs/RUST_ENGINE.md`). One process owns a brain: `election.ts` `electOwner` takes the kernel lock `<database_path>.gbrain-owner.lock`, makes the store directory mode 0700 (created `0o700` and `chmod`ed, whatever the socket path length) and the owner serves its engine on `<database_path>/.gbrain-owner.sock` (`server.ts`: 32 calls at once, the rest in a FIFO queue of at most 1,024 calls, at most 256 MiB of call frames held at once (queued and running), at most 256 connections, each over a bound refused `owner_busy` with reason `queue_full`, `inflight_bytes` or `connections`; a refused connection gets one `refused` frame and is half-closed, a refused peer that never closes its side is cut off after 1 second (`OWNER_IPC_REFUSED_DRAIN_MS`), and past 64 refusals in flight the next is dropped with no frame; a cancel frame ends a call, `deadline_at` and `read_deadline_at` bound it; where the kernel gives a peer's uid (`cli-socket/peer-cred.ts`) a connection from another OS user gets a `refused` frame `owner_ipc_peer_refused` reason `peer_uid` and nothing runs); every other process becomes a client (`client.ts` `installOwnerClient`, never opens the store, capabilities mirror the owner's hello; before it connects it refuses a socket file another user owns, `socket_owner`, or one with group or other permission bits outside a private 0700 directory of this user, `socket_mode`, and after it connects an owner of another uid, `peer_uid`; for a remote caller, `callerIsRemote`: a handler call marked by `src/core/remote-caller.ts` (an MCP request, a subagent brain tool or a SkillOpt tool), a job whose submission authority is not the application, or a remote verified writer, it sends only the reads of `routes.ts` `OWNER_IPC_REMOTE_READS` and refuses any other member `engine_capability_missing` with nothing sent) or, after 5 seconds, throws `owner_unavailable` with reason `not_sent`. `routes.ts` classifies each member: `local` (`kind`, `capabilities`, `connect`, `disconnect`, `reconnect`, `registerBeforeDisconnect`), `refuse` (`transaction`, `transactionDirect`, `withReservedConnection`, `holdSchemaMigrationLock`, `keywordBoundedRead`; against a Rust owner all but `holdSchemaMigrationLock` first meet the capability check below and refuse with the owner's own reason, `transactions` or `raw_sql`; `holdSchemaMigrationLock` and a call whose arguments hold a function other than a search metadata hook refuse `engine_capability_missing` with `via=owner_ipc`) or `forward` (everything else; a member the owner's hello lacks, and the store does not serve, refuses at the client as the owner's own engine does). `whole-op.ts` and `owner-ops.ts` can forward `importFromContent`, `importFromFile`, `importImageFile` and `importManagedFiles` as one request that runs, transaction included, in the owner (paths are made absolute, and a remote caller or a function option refuses), but no entry point calls the sender yet: a client's journaled write (`put_page`, `remember`, so `gbrain bootstrap verify`'s roundtrip and the Apple Contacts person-fact sync) stops at write admission, which opens a transaction, on `engine_capability_missing` reason `transactions`. `protocol.ts` and `codec.ts` frame the calls (an owner reply over 128 MiB ends `response_too_large`; a call's `access` field carries the caller's access record, which the owner runs it under; `deadline_at` ends a queued call `timeout` reason `not_started` and a running one `outcome_unknown`; `timer.ts` `setDeadlineTimer` re-arms past the 2^31-1 ms setTimeout limit on both sides, so a far deadline waits instead of firing at once; frame rules refuse `owner_ipc_protocol`: a hello of another version (the owner sends its hello, then closes; the client's connect rejects `version_mismatch`, which the election does not retry), a call before the hello (`hello_missing`), an id still open on the connection (`duplicate_id`, the first call keeps its cancel and close abort), arguments that are not a list (`args_not_array`), and an answer the client cannot decode (`result_undecodable`, that call only); the socket directory and lock path resolve symlinks, so every alias of one brain names one owner). When the owner exits, a call in flight ends `owner_unavailable` with reason `outcome_unknown`; a RustEngine client (`installOwnerClient`'s `rejoin`, `RustEngine._takeOver`, which shares the open's single flight) runs the election again on its next call and becomes the owner, opening its store, or a client of the new owner, so the call works with no restart; a whole operation that finds this process became the owner ends `not_sent` and its retry runs in process. A client installed without `rejoin` answers later calls `not_sent`. Pinned by `test/rust-owner-ipc.test.ts` (child processes from `test/helpers/owner-ipc-child.ts`), `test/rust-owner-ipc-frames.test.ts`, `test/rust-owner-ipc-limits.test.ts`, `test/rust-owner-ipc-peer.test.ts` and `test/rust-owner-ipc-remote.test.ts`.

- `src/core/rust-engine/addon-loader.ts` — the Rust engine addon loader (ENGINES.md "The Rust engine shell"). `loadRustEngineAddon(overrides?)` returns `{ ok: true, addon }` or `{ ok: false, code, reason, message }` for the two refusals and rethrows anything else; `loadRustAddon` is the throwing form. Only the Rust engine's open path may import the loader, lazily, so PGLite and Postgres brains never load the addon or create `<gbrain home>/engines/`; it loads with `process.dlopen` from a computed path (a literal `require` of a `.node` would be bundled into compiled executables). `engine-factory.ts` calls it and, only when it is on, dynamically imports `shadow/attach.ts`, which wraps the engine (`shadow/wrapper.ts`) so a sampled read or search (`shadow/reads.ts`) is answered by the primary first and then offered to a bounded fail-open `MirrorQueue` (`shadow/mirror.ts`: sheds on overflow, never awaits the transport) as a capture function the queue runs synchronously when it has room, before the caller sees the result; the arguments are encoded (`shadow/codec.ts`, functions and signals dropped) before the primary call and the result inside the capture, so later changes by the caller cannot cause a false diff; a sampled read encodes its arguments even when the queue then sheds it, and only an accepted read also encodes its result; calls inside a transaction are skipped. `shadow/supervisor.ts` (`ShadowSupervisor`) spawns `gbrain engine shadow __child <dir>` lazily through `src/core/spawn.ts`, unref'd, with stderr to `child.log`, restarts it with doubling backoff, disables mirroring after 5 exits in 10 minutes (`restart_budget_spent`), kills a child silent for 60 s, refuses lines past an 8 MiB stdin buffer, and stops when `state.json` turns off. `shadow/child.ts` (`runShadowChild`) loads the addon offline (`shadow/addon.ts` `loadRustEngineAddonOffline`, the cache-only loader: `not_installed` when no addon is cached or overridden, never a network call), opens the Rust engine, replays each read, classifies it (`shadow/classify.ts`: `match`, `order_diff`, `diff`, `privacy_diverged`, `capability_missing`, `error`, `timeout`, `addon_unavailable`) and appends content-free rows to the local ledger (`shadow/ledger.ts`); a privacy divergence pauses comparison and tells the parent to stop mirroring. `shadow/report.ts` (`buildProvisionalReport`) totals the per-child summary files (`summaries/`), not the ledger rows, into a report whose verdict is always `NOT READY`; `gbrain engine shadow report` writes `reports/provisional.{json,md}` only after the shadow directory exists. `commands/engine-shadow.ts` (`runEngineShadow`) is `gbrain engine shadow start|status|stop|report|seed|reconcile`; `start` previews a plan and its `plan_hash`, needs `--yes --expect <hash>` (a missing or stale hash refuses `preview_changed`), and refuses without writing when the real addon loader refuses. `start` also reads the brain's storage mode once, best-effort (`shadow/managed-gate.ts` `readManagedStorage`; a brain that cannot be opened or read is `managed: null` with a reason code), prints a line for a managed brain, which cannot swap, and records `storage: { managed, checked_at, reason? }` in `state.json`; `status --json` and the report carry it as `storage` with a `note`. Shadow mode never refuses over storage; only the swap does. `commands/doctor/checks/rust-engine-addon.ts` (`rust_engine_addon`) reports the offline addon load only when shadow mode is on. Its only writes to the brain database are the swap-eligibility writer evidence; nothing is written to brain content, the config table or the brain repo. `shadow/writer-observations.ts` notes one `engine_writer_observations` row per writing process (host id, connection name, command kind, version, first and last write), after the write committed and at most every 10 minutes, only while `state.json` says shadow mode is on. `shadow/writer-hooks.ts` is Postgres-only: `start --yes` installs the statement-level `gbrain_writer_note` trigger on every brain table in one transaction (`writer-hooks.json` is written first) and `stop` removes it; the trigger records each writing connection in `engine_writer_sessions` and every failure or skipped refresh in `engine_writer_coverage_gaps`, never fails a write and waits at most 50 ms on its own tables. `shadow/eligibility.ts` (`buildEligibilityStatus`) fills the status document's `eligibility` fields (`writer_hosts_7d` and `unknown_writer_paths` only when the caller passes the open brain, `team_brain`, `preview_target`; a failed read leaves the writer fields out and adds `eligibility_evidence` with the error code), and `shadow/writer-coverage.ts` adds the file-side evidence (reconcile misses, repairs under an invalid watermark, a lost note, torn records); `gbrain engine shadow status` never opens the database. Pinned by `test/rust-engine-shadow.test.ts`, `test/rust-engine-shadow.serial.test.ts`, `test/shadow-writer-eligibility.test.ts` and `test/e2e/shadow-writer-hooks.test.ts`. Swap-readiness evidence: `shadow/evidence-epoch.ts` keeps `evidence/epoch.json` (seed id, addon SHA-256, comparator and adapter versions, capability-set hash, readiness-policy hash; a changed input opens a new epoch, an unrelated release does not) and the child's content-free `rust_internal_error` fault recorder; ledger rows, usage lines and faults carry the epoch id. `shadow/exactness.ts` is the one table of comparisons that must match exactly (every `exact` read, `findByTitleFuzzy`, and the `ts_rank` keyword and title searches); a mismatch there is `stale` only when the child's follower held older committed, unapplied work, else `inconclusive`. `shadow/usage.ts` and the `UsageMeter` in `mirror.ts` count every call per operation class (offered, sampled out, shed, in a transaction, unmirrorable) into `usage/<day>.jsonl`. `shadow/evidence.ts` `buildEvidenceStatus` (spread into `shadowStatusDocument`) folds the current epoch's ledger, usage files and whole fault history into `reads`, `search.trigram_exact_disagreements`, `search.keyword_title` and `child` (absent, never zero, when evidence is missing; no privacy or vector-recall fields yet) and prints the epoch start, the earliest READY date and the 100-per-class engineering default. Epoch opening is serialized across processes by `evidence/epoch.lock`; the epoch names the addon the child loaded, so a child that is only a client of another process's owner (whose addon digest the owner handshake does not carry) opens none and its rows count for nothing, until it takes over. `SHADOW_ADAPTER_VERSION` (pinned to a digest of the adapter source by a test) is an epoch input. Serving processes append each operation class's first use per epoch at once (`usage/`), and the follower's probe, fingerprint totals, allocator result, lag histograms and reconcile passes are tagged with the evidence epoch and reported only for the current one. An unparsable or malformed fault line makes the child fields absent. `follower.json` names its seed in `seed_id`; the status `epoch_id` and `epoch_started_at` come from the manifest. The manifest also records `build` (stamped gbrain commit, version, addon target) once when the epoch opens; it is never an epoch input, and an epoch from before the field has none (unknown). A text-ordered read (`getTags`, `listPages` with `sort: 'slug'`) whose rows are the primary's re-sorted in C byte order is `collation_order`: explained and counted as successful coverage, with its own count per class in `evidence.collation_order`; never an unexplained divergence.
