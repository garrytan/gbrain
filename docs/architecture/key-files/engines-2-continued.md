- `src/core/sql-trace.ts` — env-gated wire-level SQL trace for benchmarks. `traceSqlOptions(options, pool)` returns the postgres.js options untouched unless `GBRAIN_SQL_TRACE=<file.jsonl>` is set; then it supplies a tracing socket and sets `application_name` to `gbrain:<GBRAIN_SQL_TRACE_LABEL or command>:<pid>:<pool>`. All four pool construction sites use it (`db.ts` module singleton, `PostgresEngine` instance pool, `ConnectionManager` read and direct pools), so `executeRaw`, `tx.unsafe`, the engine-sql adapter and tagged templates are all seen. Each Sync, simple Query or describe Flush and its reply is one JSONL record (statement text without parameter values, start, duration, process, pool, client connection, backend pid, SQLSTATE on error); a `connect` record covers TCP plus the startup handshake. TLS connections are recorded once as `tls_untraced`. Records are buffered and flushed every second and at exit. Consumed by `scripts/bench/managed-sync-catchup.ts` ([record](../../eval/managed-sync-catchup.md)); pinned by `test/sql-trace.test.ts` and `test/e2e/sql-trace-postgres.test.ts`.

The access token is never persisted, logged, or written to receipts/config.

- `src/core/worker-pool.ts` — (must-abort tags: `BUDGET_EXHAUSTED` and `SPEND_GROUP_REFUSED`, a job's spend-group refusal) Canonical sliding-pool + bounded-semaphore primitive (used by the `src/commands/embed.ts` sliding-pool sites and `src/commands/eval-cross-modal.ts`'s `runWithLimit` semaphore). Two exports: `runSlidingPool<T>({items, workers, onItem, signal?, onError?, failureLabel?, onProgress?})` + `runWithLimit<TIn, TOut>({items, limit, fn, signal?})`. Atomicity invariant: `const idx = nextIdx++` is one synchronous JS statement (no `await` between read and write — guaranteed by the single-threaded event loop), documented in the module header AND enforced by `scripts/check-worker-pool-atomicity.sh` (wired into `bun run verify`), which rejects importing `worker_threads` in any consuming file and inserting `await` between the `nextIdx` read and write. `MUST_ABORT_ERROR_TAGS` set is seeded with `BUDGET_EXHAUSTED` from `src/core/budget/budget-tracker.ts`; tagged errors (matched via `err.tag === 'BUDGET_EXHAUSTED'` to avoid cross-module import) bypass `onError` and hard-abort the pool via `AbortController.abort()` to in-flight `onItem`, then the pool JOINS every worker (each finishes its current item) before rethrowing — the budget cap is a structural ceiling under concurrency and no worker is left running detached past the caller's catch. `failures[]` shape is `{idx, label, error}` records (NOT full items; callers supply `failureLabel(item) => string`) for bounded memory under huge brains. Pinned by `test/worker-pool.test.ts` + `test/scripts/check-worker-pool-atomicity.test.ts`. Drives every `--workers N` bulk command.

- `src/core/rust-engine/addon-loader.ts` — the Rust engine addon loader (ENGINES.md "The Rust engine shell"). `loadRustEngineAddon(overrides?)` returns `{ ok: true, addon }` or `{ ok: false, code, reason, message }` for the two refusals and rethrows anything else; `loadRustAddon` is the throwing form. - `src/core/engine-sql/chat-usage.ts` — the chat usage ledger (`chat_usage_log`) statements behind two typed members on every engine. `logChatUsage(row)` appends one row (`created_at` given or the database clock); the gateway sink `makeEngineChatUsageSink` (`src/core/ai/chat-usage.ts`) writes every record through it. `readChatUsage(days)` returns `{ rows, logged_since }`: the sums per `(model, phase)` over the window in summed-cost order (null cost last), then model and phase in byte order (`COLLATE "C"`, null phase first), with `cost_usd` null when no call in the group is priced, and the ledger's first `created_at` as text; `get_usage` (`src/core/ops/usage.ts`) reads only through it, so a refusal passes through and a missing table still reports `table_present: false`. The Rust store keeps the rows under telemetry sub-tag `0x0B` (`rust/docs/store/telemetry.md`). Pinned by `test/engine-parity/telemetry.test.ts` and `test/chat-usage-typed-members.test.ts`.
- `src/core/engine-sql/field-usage.ts` — the page sample read of `gbrain schema detect --fields`, one typed member on every engine. `readFieldUsageSamples({ sourceId?, maxTypes, samplePerType })` returns the live page types of the source (or the brain) with their counts, most pages first and ties in byte order (`COLLATE "C"`), and per type the frontmatter and compiled_truth of the oldest live pages (`ORDER BY pages.id`, no id returned). It runs unscoped, as `executeRaw` did. `runFieldUsage` (`src/core/schema-pack/field-usage.ts`) reads only through it. Two behaviours are kept and filed in TODOS.md: archived-source pages count, and a segmented page samples a null body, read as empty. The Rust store answers it from the page rows (`rust/docs/store/field-usage.md`). Pinned by `test/engine-parity/field-usage.test.ts` and `test/schema-field-usage-typed-members.test.ts`.
- `src/core/engine-sql/persistence-declaration.ts` — the persistence protocol declaration as one engine member, `declarePersistence(opts?)`: protocol 2 for the current transaction, plus synchronous commit and the lock, statement and optional idle-in-transaction timeouts when `opts.durable` is given, and the brain id read under the brain row's share lock (null when the row is missing). The text is the one `persistence/protocol.ts` has always sent, byte for byte, so `isPersistenceDeclaration` still matches it and a transaction can still send it before BEGIN's answer; both engines send it through their own `executeRaw`, so a spy or a transaction engine sees it as before. `declarePersistenceProtocol` and `declareDurablePersistence` call the member. The Rust engine serves it in `src/core/rust-engine/store-members/transactions.ts`: it keeps `gbrain.persistence_protocol` = '2' on the transaction (read back by `readTransactionSettings`), ignores the timeouts (the store commits durably through its one writer) and answers the id `readPersistenceBrainId` answers. Pinned by `test/engine-parity/persistence-declaration.test.ts` (which also admits a write through `admitWrite` on every arm) and `test/persistence-pipeline-first.test.ts`.
- `src/core/engine-sql/trust-tier-reads.ts` + `rust/crates/gbrain-store/src/trust/tier_reads.rs` — the typed reads of stamped trust tiers that core memory (`listCorePageRows`), the eligibility scan (`listTrustScanRows`, `countUnscannedTrustRows`), belief history (`readBeliefHistoryRows`, `listVisibleBeliefLifetimes`), `get_versions` (`listVersionTrustTiers`, `listVersionReasonWriters`) and valid time (`listValidTimeIdentities`, `pickValidTimeEdition`) used to run through `executeRaw`. Ordered text reads use `COLLATE "C"`. The Rust store serves the core list (page policy through `facts/privacy.rs`, floor and suppression through `TrustPolicy`), the pages and facts scan, both version reads and both valid-time reads (`trust/valid_time.rs`, over the `V` version records); its TypeScript members (`store-members/trust-tier-reads.ts`) refuse a caller page policy that widens the no-caller one, the takes and timeline scan tables and non-integer cursors, limits and ids. The valid-time pick also refuses a date that is not `YYYY-MM-DD` and a history PGLite would have pruned (TODOS `rust-version-prune`); it reads a null change reason (TODOS `rust-version-change-reason`). The belief members refuse before any store call, naming the missing belief ledger (TODOS `rust-belief-ledger`). No new key prefix. Pinned by `test/engine-parity/trust-tier-reads.test.ts` on every arm and by `rust/crates/gbrain-store/tests/trust_tier_reads.rs` and `tests/valid_time.rs`.
