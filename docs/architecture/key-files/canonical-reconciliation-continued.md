# Canonical reconciliation (continued)

Current behavior and load-bearing invariants; history belongs in Git and CHANGELOG.

- `src/core/persistence/rows-behind.ts` — #8071: `scanRowsBehind(engine, sourceId, { deadlineAt })` finds live Markdown pages of a managed source whose row holds an older version of its file than `sources.last_commit`, with no hold. It reads the checkpoint tree from Git (`readHeadTree(root, commit)`), compares each page in id batches of 256 with the committed blob (`compareInlineExportFile`, or `compareSegmentedExportBlob` for a page stored in segments) and confirms a difference with `prepareRepairPublication`; direction comes from the page's sync import record (`behind` when its revision is the recorded one, `unproven` without a record, `database_moved` skipped). Paths sync would not import (`loadSyncEligibility` from `sync-discovery.ts`) are skipped `not_eligible`. A blob over `SYNC_READ_BOUND` is never read and reported with `file_too_large`. Blobs are read and compared in chunks of at most `ROWS_BEHIND_BATCH_BYTES` (64 MiB) and dropped after the comparison, and the deadline is checked before each tree read and each chunk, so one batch of large files neither holds every blob in memory nor runs past the budget. Owner host only; a repo-less brain is `not_applicable`.
- `src/commands/doctor/checks/rows-behind.ts` — doctor `sync_rows_behind_checkpoint` (BRAIN, after `sync_overwritten_db_edits`): per source counts and first slugs from `scanRowsBehind`; `warn` on `behind` rows with the read-only `gbrain repair rows-behind --source <id> --json` preview as the fix; `unknown` (info) when the `GBRAIN_DOCTOR_ROWS_BEHIND_TIMEOUT_MS` budget (default 10 s) stopped a scan or a checkout is unreadable; not applicable (ok) off the owner host and on repo-less brains.
- `src/core/repair/rows-behind.ts` — `gbrain repair rows-behind --source <id>`: explicit-only, preview-bound (`--apply --expect <hash>`, `--include-ambiguous` adds rows with no import record). `reimport` submits the committed bytes through `submitManagedFileRepair`; `hold:<code>` writes the hold sync would have written (`writeGitHold`). Refused off the owner host (`not_owner_host`). Never runs on upgrade. Tests: `test/rows-behind-checkpoint-8071.test.ts` (PGLite and Postgres via `test/e2e/rows-behind-checkpoint-8071-postgres.test.ts`).
