- `src/commands/doctor/checks/write-gate-holds-stranded.ts` — `write_gate_holds_stranded` (BRAIN, after `trust_release_unpreviewed_fields`, read-only). A held write (`write_gate_holds`) follows its page: a bound hold carries `page_id`, an unbound one is matched by slug or through the same source's rename record, so a rename does not lift it. The check ignores every held row that a live page matches under the readers' own rule (`holdAppliesToPageSql`, with `holdReachCte` resolving the rename chain), so it never warns about a bound hold whose page exists, or an unbound hold the rename record leads to a live page. Held rows in the selected sources (`doctorSourceIds`; an explicit empty scope reads nothing) that no live page matches are counted once each, in the first class that fits: `page_deleted` (a page the hold applies to is soft-deleted) and `no_page` (no page at all, for example a write held before its page exists); both are `ok` with `severity: info`, because nothing leaks through them. There is no rename warning any more: the check warns only when the count is unknown. The one structured next action is the read-only `gbrain trust review`. Bounded: held rows are read in `(source_id, id)` keyset batches of 500 on the `(status, source_id, id)` index (id, kind, source and slug only), the 5000-row budget counts held rows before any slug, page or rename filtering, an extra-row probe tells a full read from a cut one, and the scan stops at `ctx.entryDeadlineAt` (else 10 s). A scan that stops early is `warn` with `details.health: unknown` and `reason: bound` (`bound: row_limit | deadline`), never ok. Before any read, one preflight asks which of `write_gate_holds`, `slug_aliases`, `slug_rename_history` and `pages` have row security active for the running role (the table has it on and the role is not the owner, a superuser or BYPASSRLS; policies are never judged, so it fails closed); any such relation is `warn`, `health: unknown`, `reason: row_level_security`, `details.hidden_tables`, because a hidden table reads as zero rows, never an error. The pages of a batch are resolved first (bound and candidate pages by primary key, the slugs the hold's own slug leads to by the `(source_id, slug)` key through a correlated lateral lookup, so `pages` is never scanned) and each is judged by the readers' rule. Per-source counts are built in a Map, so a source id such as `constructor` keeps its own entry. An unreadable or missing rename table, and any other read failure, is unknown through `checkError`. A raw-SQL refusal from an engine without raw SQL (`engine_capability_missing`, the Rust engine) is a named unknown (`reason: engine_capability_missing`); the scan helper catches nothing and the entry classifies what it throws, so the capability-refusal guard has nothing to baseline. A schema without `write_gate_holds` is `ok` (`pre_trust`). Test: `test/doctor-write-gate-holds-stranded.test.ts` (PGLite, and Postgres with `DATABASE_URL`).
