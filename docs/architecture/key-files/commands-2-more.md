Current behavior and load-bearing invariants; history belongs in Git and CHANGELOG.

- `src/commands/doctor/missing-brain.ts` — doctor's pre-connect refusal for the selected brain (the host, or the enabled mount named by its exact id) when its PGLite datastore is missing, or (host brain) when its Rust store directory is missing or holds neither `FORMAT` nor `records.redb`; the lock-time second look is PGLite's only, since a Rust connect takes the owner lock. `src/cli/commands/doctor.ts` (`doctorWillConnect`) calls `missingBrainRefusal()` before every doctor path that opens the engine (all but `--fast` and filesystem-only `--only`, which never connect and still run). A datastore is missing when a connect would create it: the folder is absent or cannot be stat'ed (a path that vanishes mid-check counts as missing), or is a directory without PGLite's `PG_VERSION` marker (an unmounted drive's empty mount point). The folder is `database_path` for any `engine: pglite` config, whatever `database_url` holds; a path that is a plain file (a graduated brain's tombstone) is left to the engine. A `mounts.json` that does not load is not a missing brain: no refusal; the registry reports that file's own error first. The host case consults serve's `probeStatus` (`src/mcp/status-mode.ts`) so doctor and serve agree on `missing_brain`; any other probe state (graduated, repair failed, no config) is left to doctor's own diagnostics. The refusal is the `brain_missing` envelope (reason `missing_brain`, `ask_user: true`, verify `gbrain doctor --only connection --json`) with a non-zero exit. A health check never creates the brain it checks; a mount's recovery text never suggests `gbrain init` (it rewrites the host config). A host probe of `lock_held` still gets the folder test (a leftover `.gbrain-lock` with unreadable metadata reads as held). The test runs twice: before any connect, and again under the held lock, since the folder can move during the wait for the datastore's kernel lock. `guardMissingBrainAtLock` installs a create guard (`installPgliteCreateGuard`, `src/core/pglite-create-guard.ts`) for the datastore read at start (a later `database_path` edit or a symlink that stops resolving changes nothing); `acquireLock` runs it once it holds the lock, before it creates the folder or any metadata, and a throw releases the lock. `doctor.ts` renders the refusal (its filesystem-only fallback never swallows it) and removes the guard when the run ends, or when a connect abandoned at the budget settles. Under `--alert` the refusal is the alert contract: exit 17, a `--json` document that keeps the envelope and adds `alert` (level `act`, one `brain_missing` item), and the text form `[ACT] connection (brain_missing)`. Without `--alert` the exit stays 1. A Rust brain must refuse the same way. Tests: `test/doctor-missing-brain.test.ts`, `test/doctor-missing-brain-after-lock.test.ts` (guard seam and waiter, no timing), and `test/doctor-missing-brain-vanish.serial.test.ts` (failed stat, unloadable `mounts.json`).
- `src/commands/doctor/checks/write-gate-holds-stranded.ts` — `write_gate_holds_stranded` (BRAIN, after `trust_release_unpreviewed_fields`, read-only). A held write (`write_gate_holds`) follows its page: a bound hold carries `page_id`, an unbound one is matched by slug or through the same source's rename record, so a rename does not lift it. The check ignores every held row that a live page matches under the readers' own rule (`holdAppliesToPageSql`, with `holdReachCte` resolving the rename chain), so it never warns about a bound hold whose page exists, or an unbound hold the rename record leads to a live page. Held rows in the selected sources (`doctorSourceIds`; an explicit empty scope reads nothing) that no live page matches are counted once each, in the first class that fits: `page_deleted` (a page the hold applies to is soft-deleted) and `no_page` (no page at all, for example a write held before its page exists); both are `ok` with `severity: info`, because nothing leaks through them. When something is listed, `awaiting_sweep` counts the listed holds a purge noted for the maintenance sweep (`write-gate-recheck.ts`), and the message says they are noted for a recheck by the next `bookkeeping_gc` run (omitted when the role cannot read the notes table in full). There is no rename warning any more: the check warns only when the count is unknown. The one structured next action is the read-only `gbrain trust review`. Bounded: held rows are read in `(source_id, id)` keyset batches of 500 on the `(status, source_id, id)` index (id, kind, source and slug only), the 5000-row budget counts held rows before any slug, page or rename filtering, an extra-row probe tells a full read from a cut one, and the scan stops at `ctx.entryDeadlineAt` (else 10 s). A scan that stops early is `warn` with `details.health: unknown` and `reason: bound` (`bound: row_limit | deadline`), never ok. Before any read, one preflight asks which of `write_gate_holds`, `slug_aliases`, `slug_rename_history` and `pages` have row security active for the running role (the table has it on and the role is not the owner, a superuser or BYPASSRLS; policies are never judged, so it fails closed); any such relation is `warn`, `health: unknown`, `reason: row_level_security`, `details.hidden_tables`, because a hidden table reads as zero rows, never an error. The pages of a batch are resolved first (bound and candidate pages by primary key, the slugs the hold's own slug leads to by the `(source_id, slug)` key through a correlated lateral lookup, so `pages` is never scanned) and each is judged by the readers' rule. Per-source counts are built in a Map, so a source id such as `constructor` keeps its own entry. An unreadable or missing rename table, and any other read failure, is unknown through `checkError`. A raw-SQL refusal from an engine without raw SQL (`engine_capability_missing`, the Rust engine) is a named unknown (`reason: engine_capability_missing`); the scan helper catches nothing and the entry classifies what it throws, so the capability-refusal guard has nothing to baseline. A schema without `write_gate_holds` is `ok` (`pre_trust`). Test: `test/doctor-write-gate-holds-stranded.test.ts` (PGLite, and Postgres with `DATABASE_URL`).
- `src/commands/doctor/checks/legacy-slug-spellings.ts` — `legacy_slug_spellings`: warn with the count of pages stored under an older spelling of their name per source (`countSlugSpellings`, bounded) and the read-only `gbrain repair slug-spelling --source <id>` preview as the fix (applying it needs the preview's hash and consent). On a managed brain the finding says a person has to decide how to rename them, `details.needs_human` is set, and the fix is a user action with no command. With none left the check is ok; a scan that stopped at its 100000-candidate limit without finding one warns (count unknown), never ok, and so does a role that row-level security applies to on `pages` (`rowSecurityTables`; its count can come back short). Tests: `test/repair-slug-spelling.test.ts`, `test/repair-slug-spelling-postgres.test.ts`.
