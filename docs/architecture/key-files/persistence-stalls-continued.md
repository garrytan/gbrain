# Managed sync and persistence stalls (continued)

Current behavior and load-bearing invariants; history belongs in Git and CHANGELOG.

- `src/core/persistence/transient-retry.ts` — the retry budget for a managed write's transient interruptions: a statement the database ended with 57014 (`statement_cancel`), a stale cached plan (0A000, `stale_plan`) or a publication `boundPublication` cancelled at the ceiling (`publication_ceiling`, read from its signal by `publicationDeadlinePassed`). `chargeTransientInterruption` counts it in `persistence_requests.transient_interruptions` (v261, never `preparation_attempts`) and sets `next_attempt_at` to 1 s, 2 s, 4 s, 8 s, then 15 s (under the drain's 30 s no-progress window); `BACKOFF_ELAPSED` keeps every claim (`claimableWriteSql`, lane heads, group followers) off the row until then, so no claim is held while it waits, and `readHeadBlockers` names it `transient_backoff`. Past `persistence.max_transient_retries` (default 5, 0 to 20, a preparation-budget key) coordinator.ts ends the request `write_interrupted`; the charge commits with the claim's release. Off with `preparation_deadlines`. Tests: `test/pathological/lp-b-transient-retry-budget.test.ts`, `test/pathological/lp-c-publication-ceiling-retry.test.ts` (`_setPublicationTimingForTest`), `test/persistence-write-interrupted.test.ts`.
- `src/core/persistence/sync-discovery.ts` (#6349 staged catch-up) — when an incremental delta (not `--full`, not company) exceeds the cursor bound (100,000 entries, 16 MiB; `_setCursorBoundForTest` lowers it), `stagedSyncTarget` gallops forward over `git rev-list --first-parent last..HEAD`, verifying every candidate's delta from the last synced commit against the bound (a net delta is not monotone, so no binary search), and discovery reruns pinned at the furthest fitting commit with no working-tree entries, recording `stagedHead`; the cursor carries it and `SyncResult.staged { target, head, stages }` reports it. One commit alone above the bound refuses `request_too_large` naming the commit. `commands/sync/perform.ts` loops a drain stage by stage to HEAD (the drain's one extra HEAD-moved pass is skipped for a staged result). Tests: `test/sync-staged-catchup.test.ts`.
