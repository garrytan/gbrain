- `src/core/engine-sql/source-cr-mode.ts` + `src/core/rust-engine/store-members/source-cr-mode.ts` + `rust/crates/gbrain-store/src/source_cr_mode.rs` — a source's own contextual-retrieval mode, written by `gbrain sources set-cr-mode` through `setSourceContextualMode(sourceId, mode)` on every engine: one statement sets the mode or clears it to NULL and answers whether the source exists (the command exits 4 when it does not). The Rust store keeps the mode under `M source_cr_mode/<source id>` beside the source record, stamped with the source's incarnation, and `getSource`, `listSynopsisSourceIds` and `readSynopsisTierSources` read it back (rust/docs/store/source-cr-mode.md).
- `src/core/engine-sql/persistence-admission.ts` + `src/core/rust-engine/store-members/persistence-admission.ts` + `rust/crates/gbrain-store/src/persistence/worktree_admission.rs` — the managed-worktree admission reads as engine members: `readWorktreeAdmission` (the worktree row under a share lock, then its active refresh, locked when the refresh barrier is on, and whether the source binding holds; Postgres sends both statements before it waits), `completeSyncedRefresh` (completes a `syncing` refresh whose member sources reached its target head), `hasDeferralRoom` (no live consumer on the worktree's owner host lacks a capability), `readRefreshTiming` (a refresh's running time and the median of its worktree's last 10 completed refreshes) and `countHeldBehindImport` (the deferred writes not yet released that wait on a source's import or refresh). `persistence/journal.ts` admission and `persistence/refresh-retry-hint.ts` call them; each text is the statement they sent through `executeRaw`, written as static strings and pinned to the refresh schema constants by `test/persistence-admission-sql.test.ts`. The Rust store keeps refresh rows under `d 0x10` and the worktree and binding rows the writer claim stores under `d 0x09`, so admission reads `bound` from them (rust/docs/store/persistence.md). The members are classified `managed_persistence`, which the Rust engine holds back (`store-capabilities.ts` `HELD_FOR_CALLERS` names the bound-write sites that still run raw SQL: `compareFileTarget`, `guardOwnership`, publication recovery and `withTopologyLocks`), so a write to a bound worktree refuses `engine_capability_missing` at admission and writes no request row; an unbound write and an unbound grouped admission are served. A remote write that would queue a mention-links effect (a stdio or token writer not trusted to link inline: `put_page`, `capture`, `edit_page`, `append_page`) refuses `raw_sql` at admission the same way, since the links effect and a finished batch's re-arm still run raw SQL (`rust-engine/errors.ts` `requireRawSqlPublication`). Pinned by `test/engine-parity/persistence.test.ts`.
