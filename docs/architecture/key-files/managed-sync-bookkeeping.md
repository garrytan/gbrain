# Key files: Managed sync bookkeeping

[Subsystem index](../KEY_FILES.md). Read only the entries relevant to your change.
Current behavior and load-bearing invariants; history belongs in Git and CHANGELOG.

What a managed sync records about itself besides pages: the durable failure row and its local-ledger mirror, the orphan
classifier and repair, the doctor check over them, `gbrain sync status`'s failure view, the write diagnostic of a blocked
run, and the supersession of a checkpoint whose cursor another run replaced. The cursor, manifest and drain themselves are in
[Core Persistence](core-persistence.md) and [Managed sync and persistence stalls](persistence-stalls.md); `sync-status.ts` and
`sync-fault-class.ts` stay in [Core Services (2/3)](core-services-2.md).

- `src/core/persistence/sync-failures.ts` — durable managed cursor/receipt diagnostics are the authority; JSONL is a compatibility mirror keyed by cursor and source/path. Failure observations deduplicate terminal receipts, retaining structured codes and attempts; success clears only its matching cursor. A failure records the cursor-selecting `syncOptions` and `processingOptions` of its run (falling back to its cursor's when read), and every local hint (the thrown failure line, the blocked report, the terminal write diagnostic and local doctor) renders the exact retry through `managedSyncRetryCommand` → `checkpointRetryCommand`; a failure recorded before options were kept says so instead of guessing. `sync --retry-failed` counts only failures of the cursor key its own options select (`managedSyncCursorKey`) and lists the others with the action that settles each (`managed-retry-actions.ts`). #6712 PR 3 (L7): `--retry-failed` is a deprecated alias of the plain sync, which retries a recorded failure by itself; a failure records the `gbrain_version` that recorded it, so an unchanged content refusal the same version recorded replays without a new request until the file or the version changes. Local CLI shows request/run/pinned target details, while remote doctor returns source-scoped aggregates without paths, raw messages or receipt IDs. Missing durable state warns rather than certifying health. Failed receipts cannot be acknowledged, auto-skipped or rewritten; explicit idle ordinary-source retry creates fresh admission, while approved company manifests remain pinned. Tests: `test/persistence-sync-failures.serial.test.ts`, `test/e2e/managed-sync-failures.test.ts`. #6402: an observation moves `updated_at`; a new target commit restarts `first_seen`/`attempts`; an `invalid_params` resume refusal is not recorded. #6288: after a managed sync succeeds, `clearSettledManagedSyncFailures` removes the source's rows under other cursor keys (a `--full` run's) whose cursor is done or gone and whose file the imported commit settles; `gbrain sync --source ID --acknowledge-managed REQUEST_ID_OR_PATH` (host CLI) removes only such rows, refusing others `managed_failure_unsettled` (`sync-managed-stale-failures.test.ts`). Wave 16 (#6513 comments): a failure recorded from a receipt carries `write_error_detail`, the receipt's `publicFailureDetail` projection (origin, sqlstate, raiser, table, the closed `reason`; never message text), `readManagedSyncFailures` re-reads it from the pending receipt's `error_detail`, and `formatManagedSyncFailure` appends ` raiser= table= reason=` (`publicationDetailText`, identifiers only), so the ledger mirror, doctor and the blocked report name the refusing trigger; `sync status --json` surfaces it as `last_error.write_error_detail` with `last_error.detail` = the reason (`sync-status.ts`).

- `src/core/persistence/managed-sync-orphans.ts` + `src/core/repair/managed-sync-orphans.ts` — `gbrain repair managed-sync-orphans --source <id>` (#5459), explicit-only and preview-bound (approved set, `preview_changed` on drift). `classifyManagedSyncOrphans` (read-only; doctor `sync_failures` names the repair when it finds any) takes the source's managed-sync bookkeeping and classes each row `no_cursor` (a failure row with no cursor to resume), `principal_unadoptable` (an unfinished cursor recorded by a principal that is no longer an active local writer, by join on the recorded principal), `superseded` (a pre-options cursor a later run replaced), `incarnation_retired` (#6518: an unfinished cursor or a failure row recorded under a source incarnation the source no longer has, joined on the source id alone, archived sources excluded, a live pending request still retaining it) or `mirror_only` (#6518: a local ledger row with a `managed_cursor_key` and no durable failure row under that key; `mirrorOnlyManagedFailures`, which throws on a failed durable read rather than naming every mirror), and keeps `pending_request_live` and `resumable` rows untouched. `retireManagedSyncOrphan` retires one row atomically: an `incarnation_retired` cursor needs the source still active under another incarnation at apply time and skips the live-writer veto (no retired key is resumable); a `mirror_row` deletes nothing durable and prunes the ledger row only when the durable read, repeated at apply, still finds none. `pruneMirrorOnlyManagedFailures` is the successful-sync path (`clearSettledManagedSyncFailures`). Doctor `sync_failures` classifies whenever the brain is reachable, so the diagnostic is reachable with no current-incarnation failure visible, and reports a failed classification as unknown. `sources set-strategy` points at it when an unfinished run blocks a strategy change. Pinned by `test/repair-managed-sync-orphans.test.ts` and `test/managed-sync-orphans-incarnation-6518.test.ts` (both engines); `test/repair-explicit-only.test.ts` pins its place last in `REPAIR_KINDS`. #6712 PR 3 (L7): `slug_mode_refused` is an unfinished cursor whose every page committed and whose checkpoint was refused `slug_root_mode_mismatch` while the source still pins the other mode (`slugModeRefusedSql`, bound to the run and request at apply); no sync rediscovers it, so retiring it is how a person keeps the pin, and its slice record is cleared like `checkpoint_moved`'s.

- `src/core/persistence/sync-cursor-key.ts` — #6712 PR 1: one managed cursor per source. `managedCursorKey` is a digest of the source incarnation and, for a company approval only, the company; writer principal, authority and options no longer select a cursor. `resolveManagedCursor` is the one boundary that picks a run's key and folds older keys in crash-safely under the drain lease: the canonical unfinished cursor wins, else the newest older-key unfinished cursor is adopted and finished in place under its own key; every other older cursor has its queued requests cancelled and is retired through `retireManagedSyncOrphan` (reason `superseded_by_adoption`, fenced by `assertDrainLease`). A cursor with a running, recovering or publishing request or a recovery row is retained and the pass waits for that request (`writer_pending`) before it drains anything. A company brain's finished old-key cursors are kept. - `src/core/persistence/sync-lease.ts` — #6712 PR 1: the drain lease, one managed drainer per source. `withDrainLease` takes the source's sync lock (`syncLockId`) with a 2-minute TTL renewed every 20 s, so a dead holder's lease lapses inside one cron tick; it is reentrant for the holder (nested passes and the in-process lanes reuse it). The holder record (`managed-sync-lease` checkpoint: kind, id, version, start) plus the lock row give `readDrainHolder` (host, pid, heartbeat, `progress`: commits, last commit, last cursor save). A non-job holder also writes a beacon row in the `gbrain-drain-lease` minion queue (application authority, `max_stalled` 0, renewed with the lease, deleted on release) so an older binary's `liveSyncJob` backs off; downgrades are quiescent (stop serve and crons first). `assertDrainLease` is the fence inside every transaction that admits work, settles or holds an entry, folds a cursor in or swaps the cursor. Following callers (the CLI, a CLI run delegated to a serve) wait for a live holder within their budget (`followStopAt`) and take over when it releases; out of budget, or after losing the lease, they return `leaseHeldResult` (`resumable`, `sync_drain_lease_held`, `next.retry_after_ms` 60 s, `safe_to_loop`); a holder with no progress for `HOLDER_STALL_MS` (5 min) returns `leaseStalledResult` (`blocked`, `drain_stalled`, cause `no_progress`, `stall.lease_holder`). Jobs and the cycle get `SyncLockBusyError` and skip. #7596: `drainLeaseLive` is `isLockHolderLive`'s rule at the drain TTL (`readDrainLease` returns it with the holder, and `liveSyncJob` counts only a live holder); a killed holder's lock row outlives it until a takeover, so status reads it as not live. Pinned by `test/persistence-sync-lease.test.ts`.

- Pass round phase lines and honest stalls (GBRA-133 PR 3a, #7243; `src/core/persistence/sync-pass-run.ts`, `sync-pass-status.ts`, `sync-drain.ts`) — each pass round emits `managed_sync.round_level` (paths, target, read time) after its level read and `managed_sync.round_admit` (imports, deletes, in flight) before its import walk, and a `managed_sync.round_batch` (`batch` of `batches`, starting at candidate `base`, #7866) before each import batch; an announcing drain prints the level and admit lines (`[sync] pass round N: …`).
