Current behavior and load-bearing invariants; history belongs in Git and CHANGELOG.

- `src/core/engine-sql/trust-tier-reads.ts` + `rust/crates/gbrain-store/src/trust/tier_reads.rs` — the typed reads of stamped trust tiers that core memory (`listCorePageRows`), the eligibility scan (`listTrustScanRows`, `countUnscannedTrustRows`), belief history (`readBeliefHistoryRows`, `listVisibleBeliefLifetimes`), `get_versions` (`listVersionTrustTiers`, `listVersionReasonWriters`) and valid time (`listValidTimeIdentities`, `pickValidTimeEdition`, `listAmendmentsNotApplied`, `readPageVersionEdition`, `readCursorEdition`) and the purge check `get_page` and `fetch` make (`pageAwaitsRederive`, `needs_rederive`) used to run through `executeRaw`. Ordered text reads use `COLLATE "C"`. The Rust store serves the core list (page policy through `facts/privacy.rs`, floor and suppression through `TrustPolicy`), the pages and facts scan, both version reads and the valid-time reads (`trust/valid_time.rs`, over the `V` version records, and the amendment list over the `amends` links and their relationship starts, `link_queries/link_temporal.rs`); its TypeScript members (`store-members/trust-tier-reads.ts`) refuse a caller page policy that widens the no-caller one, the takes and timeline scan tables and non-integer cursors, limits and ids. The valid-time pick also refuses a date that is not `YYYY-MM-DD`; its `reason`, `introduced_because`, `successor_pruned` and `gap_at` read the store's version change reasons and prune marks as PGLite does. `pageAwaitsRederive` answers false on Rust: the store keeps no `needs_rederive` queue. The belief members refuse before any store call, naming the missing belief ledger (TODOS `rust-belief-ledger`). No new key prefix. Pinned by `test/engine-parity/trust-tier-reads.test.ts` on every arm and by `rust/crates/gbrain-store/tests/trust_tier_reads.rs` and `tests/valid_time.rs`.
- `rust/crates/gbrain-store/src/timeline/receipt.rs` — the Rust store's timeline write receipt, the counterpart of PGLite's `gbrain_stamp_write_attribution` trigger on `timeline_entries`. `TimelineRecord.receipt` holds the seven attribution columns (`write_*`, `last_write_*`, `last_written_at`; `serde(default)`, left out of the stored record when empty, so older records decode unchanged). `stamp(old, new)` runs in both timeline writers (`insert_entry`, `put_entry`): an insert under a principal takes the actor from the write context's `WriteAttribution` (`write_trust.rs`: `gbrain.write_request`, `gbrain.write_principal_kind`, `gbrain.write_principal_id`) in `write_*` and `last_*` plus the transaction time; an update keeps `write_*` and moves `last_*` only when the row's content changed; a stamp outside a store write, or under a `gbrain.write_request` that is not a UUID, refuses `invalid_argument`. The engine routes the three attribution settings to the store with the six trust settings (`src/core/rust-engine/store-members/transactions.ts`), and `store-codec.ts` `toTimelineEntry` revives `last_written_at`. Pinned by the receipt unit tests in the file and `test/engine-parity/timeline.test.ts` ("timeline write receipts").
- `rust/crates/gbrain-store/src/timeline/tier.rs` — the Rust store's timeline trust stamp, the counterpart of PGLite's `trust_tier_stamp` trigger on `timeline_entries`. `TimelineRecord.trust` holds `trust_tier` and `write_origin` (`serde(default)`, left out of the stored record while `unknown` with no origin, so older records decode unchanged). `stamp(old, new)` runs `trust::stamp` with `TrustTable::TimelineEntries` in both timeline writers: an insert takes the write's declared tier and origin; an update starts from the stored tier and origin and lowers them only when `summary`, `detail` or `date` changed. `getTimeline` returns both columns and serves an eligibility `floor` and `suppressFlagged` through `TrustPolicy::admits`; `Store::read_row_trust_rows` (`cli_reads/import.rs`) serves `readRowTrustRows` for `timeline_entries`, which `stampRowTrust` (`src/core/eligibility/stamp.ts`) reads on every engine. Pinned by the tier unit tests in the file, `test/engine-parity/timeline.test.ts` and `test/engine-parity/cli-reads-import.test.ts`.
- `beginSnapshotRead` (`src/core/engine-sql/transaction-settings.ts`) — starts a read transaction as one snapshot, `SET TRANSACTION ISOLATION LEVEL REPEATABLE READ`, with `READ ONLY` when asked. The valid-time read, the fuzzy `get_page` fallback and `gbrain export` call it first in their transaction. The Rust member (`store-members/trust-tier-reads.ts`, capability `transactions`) sets no isolation level: a store transaction holds the store's one writer from its start, so its reads already see one state. Its `READ ONLY` calls the store's `set_transaction_read_only`, and every later write in the transaction refuses as on Postgres: code `25006`, `cannot execute <member> in a read-only transaction` (`store-errors.ts`), nothing written. Pinned by `test/engine-parity/transaction-settings.test.ts` on every arm.
- `src/core/engine-sql/version-reasons.ts` + `rust/crates/gbrain-store/src/pages.rs` — the change reason a page write gives its archived versions, as two typed members on every engine. `readLatestVersionId(pageId)` reads the page's newest version id before the write; `stampVersionChangeReason({ pageId, afterVersionId, reason })` sets `page_versions.change_reason` on each version the write added after that id and answers the count. `withChangeReason` (`src/core/persistence/change-reason.ts`) and the adopted-edit reason in `src/core/persistence/file-repair.ts` use them, so a Rust brain keeps the reason: `getVersions` reads it as `replaced_because` and `pickValidTimeEdition` as `reason` / `introduced_because`. The Rust `createVersion` serves a plain `reason` option and `historyGap`, and refuses a Git-sourced reason (`reasonSource`). The bulk reason rewrites of a fact purge and `repair/purged-change-reasons.ts` stay raw SQL, which Rust refuses. Pinned by `test/engine-parity/versions-raw.test.ts` and `test/engine-parity/trust-tier-reads.test.ts` on every arm and by `tests/pages.rs`.
- `src/core/page-state/versions.ts` + `rust/crates/gbrain-store/src/version_prune.rs` — the version prune every snapshot runs. A large inline page keeps its newest `LARGE_PAGE_VERSIONS_KEPT` large versions; a segmented page keeps `versions.segmented_max_per_page` versions and none pinning more closed manifest bytes than `versions.segmented_max_pinned_bytes` (or the page's body bytes), then sweeps the page's segments. Each prune marks `successor_pruned` on the newest kept version before a pruned one and stamps `pages.version_history_gap_at`, which `createVersion({ historyGap })` also stamps. The Rust store runs it inside the snapshot's write (`createVersion`, a journal page write, `updateSlug`); the holding-page prune runs only through a fact append's raw SQL, which Rust refuses. Pinned by `test/engine-parity/trust-tier-reads.test.ts` on every arm and by `tests/valid_time.rs` and `tests/page_body.rs`.
