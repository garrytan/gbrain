- `src/core/engine-sql/persistence-embedding-noop-settle.ts` — the no-op embedding settle pass's statements as typed members (`persistence/embedding-noop-settle.ts` calls them): `probeNoopEmbeddingSettle` (the due probe), `lockNoopEmbeddingWindow` (the newest effect id, then the locked window), `readNoopEmbeddingCandidates` (the completion test for one write column, model and signature, with the effect refresh fence written out) and `settleNoopEmbeddingRows` (the claim and completion in one update). The texts are the ones the pass always sent; the candidate read binds each value where it is read. `test/persistence-journal-statements.test.ts` pins the candidate read equal to the pass's own builder value for value and both engines to the same text (golden `sql-text-extra/persistence-embedding-noop-settle.json`). The Rust engine serves them from `gbrain-store` `persistence/noop_settle.rs` (the `embedding` column only). Behavior pinned by `test/engine-parity/persistence.test.ts`.
- `src/core/rust-engine/store-members/private-provenance.ts` + `rust/crates/gbrain-store/src/facts/privacy.rs` — the `excludePrivate` policy the Rust store applies. `storePrivacyPolicy` (fact reads) and `storePagePolicy` (page reads) send `{ honorAliases, entityPrivacy }` when the policy text PGLite would render now equals the no-caller rendering. A page family that passes `{ callerReaders: true }` also serves a caller whose text equals the rendering for a record of only its reader identity and private-readable grant, and then sends `identity` and `privateReadableSources`. `page_hidden` reads them: a page whose `readable_by` names one of the principals passes (`access_readers`, the twin of `gbrain_access_readers`), and a page of a granted source that is not a pinned question passes the privacy part. Any other caller refuses with `engine_capability_missing`. The page families that opt in: aliases (`resolveAliases`, `aliasCanonicalRefs`), alias fan-out (`findPagesByTitles`), salience, `findAnomalies`, the chunk-page reads, the code chunk reads and frozen hits, keyword search, the chronicle reads, `getTimeline`, the links reads, the link-temporal reads and retrieval coverage, the page-ops scope reads and `readIdentitySiblingCandidates`. Every fact family opts in too (the fact lists, the relevance pool, `listSimilarActiveFacts`, `countWorldFacts` and the ontology reads): the entity gate reads the identity and grant, and the provenance gate reads the identity only on the caller's own member page (`memberPage`, the CASE of `privateProvenanceFilterUnderPolicy`; `privateFactFilterForCaller` has none). Pinned by the caller cases in `test/engine-parity/{facts,facts-trust,facts-purge,facts-cycle,timeline}.test.ts` (fixture `fact-callers.ts`) and the Option C refusals in `test/rust-engine-store.test.ts`. `storeFloorPolicy` serves the remote provenance floor of `findActiveSingleFact` (`remoteProvenanceFloorSql`): when its rendering equals the no-caller one it sends `provenanceOnly`, and the store judges only the provenance page with the empty identity; any other floor refuses. A fact read also serves a caller with a member identity on a brain that never named readers (`judgeWidenedFactCaller`, under the restricted rendering), which the page families do not.
- `src/core/rust-engine/store-members/fact-visibility.ts` + `rust/crates/gbrain-store/src/facts/widen.rs` — a fact list read's `visibility` list as the Rust store reads it. A list without `private` that `factVisibilitySql` widens for the caller's own member page (`memberFactAdmitSql`) or private-facts grant (`grantedPrivateFactSql`) goes as the list plus a `widen` record (`member`, `memberPagePolicy`, `privateFactSources`), sent only when the caller's text equals the rendering for a record of its reader identity and grants; the store admits the same private rows per row (`facts/widen.rs`). `findTrajectory` and the fact relevance pool (`store-members/facts-trust.ts` `poolArgs`) send the same record with `worldOnly` (`world_admits`). Any other widening caller refuses with `engine_capability_missing`. Pinned by `test/engine-parity/fact-visibility-widening.test.ts`, `fact-trajectory-widening.test.ts` and `fact-pool-widening.test.ts`.
- `src/core/rust-engine/store-members/label-line.ts` — `labelsOf` reads the label line of `countLabelFacts` (`(^|\n)\*\*(labels)[[:space:]]*:\*\*`) into the literal labels its alternation spells (ASCII letters, spaces, `[sz]` classes and `?`), lower case, or null for any other pattern. The Rust store (`facts/repair.rs` `has_label_line`) matches them at each line start with ASCII case folding and the musl `[[:space:]]` set PGLite reads, so it evaluates no regular expression. Pinned by `test/rust-engine-store.test.ts` and `test/engine-parity/facts-repair.test.ts`.
- `src/core/engine-sql/trust-tier-reads.ts` + `rust/crates/gbrain-store/src/trust/tier_reads.rs` — the typed reads of stamped trust tiers that core memory (`listCorePageRows`), the eligibility scan (`listTrustScanRows`, `countUnscannedTrustRows`), belief history (`readBeliefHistoryRows`, `listVisibleBeliefLifetimes`), `get_versions` (`listVersionTrustTiers`, `listVersionReasonWriters`) and valid time (`listValidTimeIdentities`, `pickValidTimeEdition`, `listAmendmentsNotApplied`, `readPageVersionEdition`, `readCursorEdition`) and the purge check `get_page` and `fetch` make (`pageAwaitsRederive`, `needs_rederive`) used to run through `executeRaw`. Ordered text reads use `COLLATE "C"`. The Rust store serves the core list (page policy through `facts/privacy.rs`, floor and suppression through `TrustPolicy`), the pages and facts scan, both version reads and the valid-time reads (`trust/valid_time.rs`, over the `V` version records, and the amendment list over the `amends` links and their relationship starts, `link_queries/link_temporal.rs`); its TypeScript members (`store-members/trust-tier-reads.ts`) refuse a caller page policy that widens the no-caller one, the takes and timeline scan tables and non-integer cursors, limits and ids. The valid-time pick also refuses a date that is not `YYYY-MM-DD` and a history PGLite would have pruned (TODOS `rust-version-prune`); it reads a null change reason (TODOS `rust-version-change-reason`). `pageAwaitsRederive` answers false on Rust: the store keeps no `needs_rederive` queue. The belief members refuse before any store call, naming the missing belief ledger (TODOS `rust-belief-ledger`). No new key prefix. Pinned by `test/engine-parity/trust-tier-reads.test.ts` on every arm and by `rust/crates/gbrain-store/tests/trust_tier_reads.rs` and `tests/valid_time.rs`.
- `beginSnapshotRead` (`src/core/engine-sql/transaction-settings.ts`) — starts a read transaction as one snapshot, `SET TRANSACTION ISOLATION LEVEL REPEATABLE READ`, with `READ ONLY` when asked. The valid-time read, the fuzzy `get_page` fallback and `gbrain export` call it first in their transaction. The Rust member (`store-members/trust-tier-reads.ts`, capability `transactions`) sets nothing: a store transaction holds the store's one writer from its start, so its reads already see one state. It does not enforce `READ ONLY`, so a write in that transaction lands on Rust where Postgres refuses it. Pinned by `test/engine-parity/transaction-settings.test.ts` on every arm.
- `rust/crates/gbrain-store/src/timeline/receipt.rs` — the Rust store's timeline write receipt, the counterpart of PGLite's `gbrain_stamp_write_attribution` trigger on `timeline_entries`. `TimelineRecord.receipt` holds the seven attribution columns (`write_*`, `last_write_*`, `last_written_at`; `serde(default)`, left out of the stored record when empty, so older records decode unchanged). `stamp(old, new)` runs in both timeline writers (`insert_entry`, `put_entry`): an insert under a principal takes the actor from the write context's `WriteAttribution` (`write_trust.rs`: `gbrain.write_request`, `gbrain.write_principal_kind`, `gbrain.write_principal_id`) in `write_*` and `last_*` plus the transaction time; an update keeps `write_*` and moves `last_*` only when the row's content changed; a stamp outside a store write, or under a `gbrain.write_request` that is not a UUID, refuses `invalid_argument`. The engine routes the three attribution settings to the store with the six trust settings (`src/core/rust-engine/store-members/transactions.ts`), and `store-codec.ts` `toTimelineEntry` revives `last_written_at`. Pinned by the receipt unit tests in the file and `test/engine-parity/timeline.test.ts` ("timeline write receipts").
- `rust/crates/gbrain-store/src/timeline/tier.rs` — the Rust store's timeline trust stamp, the counterpart of PGLite's `trust_tier_stamp` trigger on `timeline_entries`. `TimelineRecord.trust` holds `trust_tier` and `write_origin` (`serde(default)`, left out of the stored record while `unknown` with no origin, so older records decode unchanged). `stamp(old, new)` runs `trust::stamp` with `TrustTable::TimelineEntries` in both timeline writers: an insert takes the write's declared tier and origin; an update starts from the stored tier and origin and lowers them only when `summary`, `detail` or `date` changed. `getTimeline` returns both columns and serves an eligibility `floor` and `suppressFlagged` through `TrustPolicy::admits`; `Store::read_row_trust_rows` (`cli_reads/import.rs`) serves `readRowTrustRows` for `timeline_entries`, `facts` and `takes`, which `stampRowTrust` (`src/core/eligibility/stamp.ts`) reads on every engine. Pinned by the tier unit tests in the file, `test/engine-parity/timeline.test.ts` and `test/engine-parity/cli-reads-import.test.ts`.
- `rust/crates/gbrain-store/src/persistence/effects.rs` — the Rust store's `persistence_effects` rows (`d 0x05 <journal id> 0x00 <kind>`, with a `d 0x06` id-order index for a later claim scan). `insertPublicationEffects` stores every kind `queued` in queue order, leaves out a gated kind while `auto_link` or `mcp.remote_auto_links` is off and keeps a kind already stored; `insertWithdrawalEffects` stores a managed forget's `withdrawal-mirror`, `git` and `embedding` kinds the same way, for a known source only, and refuses a request the journal does not hold. `completeWriteRow` and `readAdmissionRate` count the effect bytes. The effect worker claims and settles them through `persistence/effect_worker.rs`. `readRequestEffects` reads a request's effect states for the write receipt. Contract: `rust/docs/store/persistence.md` "Publication effects"; tests `rust/crates/gbrain-store/tests/publication_effects.rs` and `withdrawal_effects.rs`.
- `rust/crates/gbrain-store/src/trust/row_trust.rs` — the trust columns of a take or timeline row. `RowTrust` holds `trust_tier` and `write_origin` (`serde(default)`, omitted while `unknown` with no origin; `TimelineTrust` is the same type). `stamp_row(table, old, supplied, content_changed)` runs `trust::stamp` under the open write's context: an insert takes the declared tier and origin, an update starts from the stored ones and lowers them only on a content change. The takes writers store through `takes::store_take`, which compares `claim`, `kind` and `holder`; `trust::proposals::contested_ref` gives a fact or take its pending supersede proposal for `readRowTrustRows`. Pinned by `rust/crates/gbrain-store/tests/cli_reads_import.rs` and the fact and take cases of `test/engine-parity/cli-reads-import.test.ts`.
