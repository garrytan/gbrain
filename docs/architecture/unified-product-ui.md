# 统一桌面产品界面

## 已授权目标（2026-09-27）

桌面是主要入口。打开即显示知识工作台；模型、知识库、数据库、MCP、桌面行为、更新与修复都由同一个设置导航承载，不再跳转独立管理台。浏览器复用相同前端，原生能力只在桌面出现。

## 部署与职责

- 前端：React + TypeScript 共用 `admin/src` 产品入口，Electron renderer 编译同一入口；一套导航、主题和设置容器。
- 桌面主进程：保留现有 Sidecar、数据库准备、模型配置、系统设置、文件选择与更新控制器。
- 后端：保留现有 Bun Sidecar / Admin API / Core，数据库仍为现有 PGLite 或 Postgres，不迁移、不复制业务实现。
- 桌面请求：受信本地 renderer → preload 窄桥 → 主进程校验相对 API 路径 → Sidecar 已有会话认证 → 原 API。Cookie 与引导令牌不进入前端。
- 浏览器请求：继续同源 HttpOnly Cookie；不暴露桌面 IPC，也不允许远程网页调用本机管理能力。
- 本地 renderer 始终存在；服务启动、重启、恢复不再将窗口导航到管理台地址。未完成配置或启动失败在同一界面提示并打开对应设置。
- 设置迁移：已有配置表单及控制器先作为同一 DOM 内的设置模块复用，保持保存、维度变更确认、备份恢复等行为；消除独立侧栏与独立窗口。后续逐块改写 React 表单时不改 IPC 与底层能力。

## 验收

1. 桌面启动和 Sidecar ready 均不替换当前文档；首页为知识工作台。
2. 菜单、托盘和页面中的设置入口路由到同一界面。
3. 模型配置、数据库配置、系统设置仍调用原处理器；不注入演示状态。
4. API 传输支持 JSON、文本与文件上传，并保留 HTTP 错误状态和响应内容。
5. 不放宽既有窗口信任边界；拒绝外部 URL、路径穿越、认证头注入。
6. 必要定向测试、前端和桌面构建通过；本轮不执行安装包打包和提交。

## 当前验证与边界

- Desktop 定向测试 72 项、Admin 定向测试 17 项通过；双端类型检查及构建通过。
- 以最新桌面构建资源和隔离的原生 API 测试适配器进行页面验收，1440×900、1100×800 无页面水平溢出；未连接真实数据库，不能等同安装版原生 IPC 全链路验收。
- 已验证快捷填入、切换设置后保留草稿、新建对话清空当前草稿、设置分类和外观入口。
- 供应商卡片与多轮聊天尚未实现：当前保留可工作的模型配置表单、知识助手操作及最近五条记录。其他内容页保留既有实现，只统一外层导航。
- 手机浏览器保留旧入口；浏览器本机特权设置不展示，桌面使用既有权限桥接。
- 已生成 Admin 内嵌资源和发布清单；用户后续提交 GitHub、检查该提交的 CI，再执行 Windows 安装包构建。已安装旧版不会因源码修改自动更新。
