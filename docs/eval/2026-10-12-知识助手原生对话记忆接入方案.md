# 知识助手原生对话记忆接入方案

日期：2026-10-12。状态：用户已明确回复“实施吧”，底层接入已授权；1.4.59 实施及验收结果见文末。

## 目标与基线

知识助手正常对话时保存会话，在后台把用户直接表达的事实、决定、偏好、经验和承诺沉淀为知识；后续对话按主题自动使用相关记忆。内置助手直接调用 Core、Operations、Product Task Runtime，MCP 继续服务外部 AI。

本次只读核对 PMBrain `0c559646`，产品版本 1.4.58；本地 GBrain 固定提交 `5b5891069413b28b2fe3a50675116d67d5a1e145`，版本 0.60.102.0。在线指南另作机制核对，不把在线 master 的新增行为写成本地已经拥有。

## 接入方式

### 1. 会话保存与记忆提炼分开

- 继续使用当前数据库隔离的 WorkbenchStore。保存原始用户消息、实际回答、工具参数、实际工具返回结构、执行状态与时间；界面节选和请求压缩不改变档案。
- 编辑和重试增加版本记录，保留出处。当前会话仍展示有效分支；被替换分支不再作为后续自动提炼输入。
- 用户明确删除会话时沿用删除语义，不能暗中留一份不可见永久档案。已提炼记忆保留出处状态，遗忘通过已有记忆业务处理，避免无提示地级联删除正式知识。
- 新增消息先保存，再登记后台任务；进程退出或提交队列失败时，下次启动从未处理回合恢复。回答生成和记忆任务分别显示结果，后台提炼失败不把已成功回答标为失败。

### 2. 一次配置，逐轮增量处理

- 使用现有长期记忆模式和有效期配置，内置助手与外部客户端共享同一开关语义。off 停止自动提炼，salient 只保留重要长期信息，all 处理直接事实；老用户的关闭配置不被升级强行改成开启。
- 在助手设置中一次选择实际存在、未归档的记忆 Source；新会话绑定数据库身份和 Source。没有显式选择时只允许使用经验证存在的 default，不根据搜索命中的页面推断写入 Source，也不发明 `hook:writeback` Source。
- 开启后从新回合开始沉淀，历史聊天不自动批量回填。关闭期间的回合记录捕获状态，重新开启不会补写关闭期间的内容；配置读取失败或文件/数据库不一致时保留待处理状态。
- 使用已有 Product Task Runtime / Minion 持久队列，添加对话记忆任务。身份包含数据库、Source、conversationId、messageId、内容版本；完成回执和生成出的事实 ID 可读回。失败保留原生错误，不静默切换模型或改业务流程。
- 闲置后合并本会话尚未处理的回合，减少任务和模型调用；恢复只继续未完成部分。用户正在聊天时后台任务沿用数据库优先级和资源保护。

### 3. 复用 GBrain 提炼、写入与去重

- 原始会话全部保存，Facts 只提炼用户直接陈述或明确确认的内容。助手推测、工具输出、引用和粘贴的第三方材料不自动变成用户事实；正常问句和确认语可以得到零条记忆。
- 复用现有提炼模型路由、过滤、实体解析、Facts writer、去重及 supersession。保持 fact/event/preference/commitment/belief/idea 的既有语义；纠正意见更新当前记忆，保留历史和出处。
- 对短中文事实、混合事实与问句、合法长消息单独验证，不能让现有长度门槛把所有短偏好都丢掉，也不能让分块把第三方粘贴当成用户原话。
- 出处包含 PMBrain 知识助手、数据库/Source、会话与消息版本、原始时间；写入会话身份穿过 writer，不能只保存一段无法追溯的来源文字。
- 原批量提炼缺少临时/长期区别。本轮只为原生自动记忆补充可选的临时分类及 TTL 传递，明确的临时状态采用现有有效期；已经发生的事件、长期决定不因 kind=event 就统一过期。旧调用方未启用新选项时保持原行为。
- 写入前重新检查自动记忆开关。无向量时仍应保证同一回合重试和完全相同事实的确定性去重；语义去重能力不足如实报告，不启用未经配置的向量服务。
- 只通过既有受控 Facts 写入和派生产物流程增量更新，不直接替换 Wiki 正文，不修改原始资料，不批量扫描、清空或重建真实知识数据。

### 4. 下一轮自动使用

- 会话开始、摘要压缩后和主题变化时，复用 GBrain 的实体解析、context pack 与 recall 机制，并与当前知识检索共同参与请求预算。
- 选择与当前问题、当前实体和有效会话主题相关的 Facts；过滤已过期、已遗忘、被替代和无权限的记忆。不能无条件把最近记忆或整个历史塞给模型。
- 读取绑定的 Source；其他 Source 的同名实体不得自动合并。跨 Source 引用保留真实 Source/slug，并按已有显式授权与实体回退规则解析。
- 新会话能使用上次已沉淀的知识。关闭自动写入不删除旧记忆；是否使用知识仍遵守助手已有知识辅助设置。
- 回答中的对话记忆可打开出处，区分原始资料引用与对话记忆。提示内容作为资料进入模型上下文，不作为新的系统指令。
- 常态只做小范围召回；复杂跨页综合继续由现有执行能力按需要调用，不每轮启动一次完整 Dream。

### 5. Dream 整理和 Agent 执行

- 对新对话的受控提炼产物按既有自动化配置调度 Dream，复用周期锁、必要阶段和原阶段顺序，完成与已有项目、人物及概念的关联。
- 普通回合不全库重扫，不自动打开此前关闭的深度整理或付费任务；稳定知识的正式 Wiki 整合继续遵守既有证据、输出目录和产品准入条件。
- 内置助手接入已有 remember、recall、forget/纠正及任务入口。明确要求修改知识时使用现有内部业务能力；执行绑定明确目标和内容，高风险操作进入审批。后台自动记忆使用既有配置授权，不每轮弹出保存确认。
- 工具只公开经过核对的业务能力和参数，执行结果、持久化状态、原生失败和停止都能读回；不通过 MCP 调用自身，不复制另一套业务执行器。

## 三层改动边界

| 层 | 实施范围 |
|---|---|
| UPSTREAM CORE | 复用事实提炼/写入/遗忘、Source 实体解析、召回与预算；核对 GBrain 记忆去重/上下文依赖闭包。必要的可选 TTL、出处、确定性去重适配先得到本方案确认，保持旧调用契约 |
| PMBrain ADAPTER | 原生对话回合接入、版本与处理回执、Source 绑定、持久任务、启动恢复、内部业务工具适配、对话产物进入原 Dream |
| PRODUCT | 助手设置展示现有记忆模式和目标 Source；对话中展示沉淀/召回结果及出处；失败、保存重载与任务中心反馈。只适配电脑端 |

优先不新增数据库表或调整现有 Schema；利用会话文件和已有持久任务记录保存处理水位与回执。若实现中证明现有结构无法保证事务或来源正确性，需要先明确新增迁移范围，不能悄悄扩大设计。

## 验收脚本的产品口径

先写以下行为用例并证明缺口，再编码。所有资料在隔离测试库和临时目录中创建，数据库相关场景同时运行 PGLite 和 Postgres。

1. 说“以后给我的方案先写结论，再写依据”，完成对话后不用点保存就能读到 preference；新开对话提出相关任务，助手自动使用该偏好并可查看原句。
2. 保存一个项目决定，换会话仍能召回。随后明确纠正，当前回答使用新版本，旧事实作为历史保留；再明确遗忘，后续不再自动召回。
3. 普通问句、确认语、助手推测、工具结果和第三方粘贴不自动写成用户事实；短中文陈述、混合问句和长合法陈述不遗漏应保存的内容。
4. 临时行程到期后不再召回，历史记录仍在；长期偏好、已经发生的事件和长期决定不会被错误过期。
5. 重试回答、编辑消息、刷新、重启和后台中断不重复保存同一回合；旧分支不被再次提炼，回执可追溯。模型失败保持待处理和实际报错。
6. 关闭记忆后停止提炼，重新开启不会补写关闭期间的消息。写入中的关闭、配置漂移和数据库切换都不能越权落库。
7. 两个 Source 同名人物/项目不混写；换数据库不带入另一库的会话或记忆。未配置向量时可完成保存与关键词/实体召回，并明确语义去重边界。
8. 同一主题的新记忆能与既有知识建立可解析关联；Dream 只处理本次受控范围，必要阶段、停止与失败能读回；原始资料、已有 Wiki 非目标正文和向量不变。
9. 用当前源码页面验证配置保存和刷新重载、自动沉淀状态、跨会话使用、出处、失败和恢复；使用实际已配置模型做隔离端到端，不把脚本 HTTP 端点当模型提炼质量证据。
