Here is a macOS Bash script that does that. It uses `mdls` for the date, falls back to the file’s modification time, sorts by timestamp, and prints proposed changes by default. It does not rename anything unless you pass `--apply`.

Save it as `rename_photos.sh`:

```bash
#!/bin/bash
set -euo pipefail

PHOTO_DIR="${1:-$HOME/Pictures/Italy Trip}"
MODE="${2:---dry-run}"

if [[ ! -d "$PHOTO_DIR" ]]; then
  echo "Folder not found: $PHOTO_DIR" >&2
  exit 1
fi

if [[ "$MODE" != "--dry-run" && "$MODE" != "--apply" ]]; then
  echo "Usage: $0 [folder] [--dry-run|--apply]" >&2
  exit 1
fi

tmp="$(mktemp)"
trap 'rm -f "$tmp"' EXIT

find "$PHOTO_DIR" -maxdepth 1 -type f \
  \( -iname '*.jpg' -o -iname '*.jpeg' -o -iname '*.heic' -o -iname '*.png' \) \
  -print0 |
while IFS= read -r -d '' file; do
  exif_date="$(mdls -raw -name kMDItemContentCreationDate "$file" 2>/dev/null || true)"

  if [[ "$exif_date" == "(null)" || -z "$exif_date" ]]; then
    sort_date="$(stat -f '%Sm' -t '%Y-%m-%d %H:%M:%S' "$file")"
  else
    sort_date="${exif_date%% +*}"
  fi

  date_part="${sort_date:0:10}"
  time_part="${sort_date:11:8}"
  printf '%s\t%s\t%s\n' "$date_part $time_part" "$file" "${file##*.}" >> "$tmp"
done

sort -t $'\t' -k1,1 "$tmp" |
awk -F '\t' -v dir="$PHOTO_DIR" -v mode="$MODE" '
{
  timestamp = $1
  oldpath = $2
  ext = tolower($3)
  date = substr(timestamp, 1, 10)

  if (date != previous_date) {
    count = 1
    previous_date = date
  }

  printf "%s\t%d\t%s\t%s\n", date, count, oldpath, ext
  count++
}' |
while IFS=$'\t' read -r date count oldpath ext; do
  newname=$(printf '%s_%03d.%s' "$date" "$count" "$ext")
  newpath="$PHOTO_DIR/$newname"

  printf '%s -> %s\n' "$(basename "$oldpath")" "$newname"

  if [[ "$MODE" == "--apply" ]]; then
    if [[ -e "$newpath" && "$oldpath" != "$newpath" ]]; then
      echo "Refusing to overwrite existing file: $newpath" >&2
      exit 1
    fi
    mv "$oldpath" "$newpath"
  fi
done
```

Before I try it, can you explain why the script uses a temporary file and why it uses `sort` and `awk` instead of doing everything in one loop?

[assistant]
The temporary file separates metadata collection from ordering and renaming.

During the first pass, each file produces one tab-separated record containing:

```text
timestamp    full-path    extension
```

For example:

```text
2024-07-14 16:32:11    /Users/sam/Pictures/Italy Trip/IMG_4382.JPG    JPG
2024-07-14 18:04:02    /Users/sam/Pictures/Italy Trip/DSC_0197.jpg    jpg
2024-07-15 09:11:45    /Users/sam/Pictures/Italy Trip/IMG_4410.HEIC    HEIC
```

A shell glob or `find` does not guarantee chronological order. `sort` gives us a predictable order before numbering. Then `awk` maintains a counter and resets it whenever the date changes:

```text
2024-07-14 -> 001, 002, 003
2024-07-15 -> 001, 002
```

Doing metadata lookup, sorting, counter management, and renaming in one loop would either number files in arbitrary directory order or require keeping all records in shell arrays. The temporary file also makes the stages easier to inspect and debug. It is created in the system temporary directory and removed automatically by the `trap`, including when the script exits normally.

One important correction: the earlier script’s tab-separated format is fragile if a filename contains a tab or newline, which is unusual but possible. Also, the timestamp parsing assumes the metadata format is consistent. For ordinary camera filenames and macOS metadata, it is generally adequate, but I can provide a more defensive version.

```bash
import os
import sys
from collections import defaultdict

records_path, plan_path, photo_dir = sys.argv[1:]

with open(records_path, "rb") as f:

    if not fields[i]:

    stamp = fields[i].decode("utf-8", "surrogateescape")
    source = fields[i + 1].decode("utf-8", "surrogateescape")
    path = fields[i + 2].decode("utf-8", "surrogateescape")

# Timestamp first, original basename second, full path third for deterministic order.
records.sort(key=lambda r: (r[0], r[1], r[2]))

used = set(os.listdir(photo_dir))

plan_rows = []
```
