```bash
git diff --no-index -- /tmp/package-lock.ours.json /tmp/package-lock.regenerated.json > /tmp/ours-to-regenerated.diff || true
git diff --no-index -- /tmp/package-lock.theirs.json /tmp/package-lock.regenerated.json > /tmp/theirs-to-regenerated.diff || true
less /tmp/ours-to-regenerated.diff
```

Look for these categories:

1. The root dependency adds `yaml`.
2. `node_modules/yaml` and its transitive dependencies are added.
3. Integrity or metadata fields are normalized consistently.
4. npm changes lockfile formatting or metadata because the original was generated by another npm release.

Be cautious if unrelated packages change versions, disappear, or gain platform-specific optional dependencies without an explanation. You can list package versions from the regenerated lockfile and compare them with each stage using a small script:

```bash
node - <<'NODE'
const fs = require('fs');
for (const file of ['/tmp/package-lock.ours.json','/tmp/package-lock.theirs.json','/tmp/package-lock.regenerated.json']) {
  const lock = JSON.parse(fs.readFileSync(file));
  const entries = Object.entries(lock.packages || {})
    .filter(([path]) => path.startsWith('node_modules/'))
    .map(([path, data]) => `${path.slice(13)}@${data.version}`)
    .sort();
  console.log(`\n${file}\n${entries.join('\n')}`);
}
NODE
```

If the extra changes are only generated metadata and the dependency graph is correct, they can be acceptable; if not, stop and investigate before staging.
