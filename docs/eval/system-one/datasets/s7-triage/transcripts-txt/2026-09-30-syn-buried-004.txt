I need a regex to strip trailing whitespace from log lines. By trailing whitespace I mean spaces and tabs at the end of each line, before the newline. I want to preserve indentation and whitespace inside the line.

[assistant]

A common regex is:

```regex
[ \t]+$
```

Replace each match with an empty string, using multiline mode so `$` is evaluated at the end of every line rather than only at the end of the whole input.

For example, in a PCRE-style tool:

```text
find:  file not found··
warning: retrying··→
  connected successfully··
```

Here `·` represents a space and `→` represents a tab. The replacement result is:

```text
find:  file not found
warning: retrying
  connected successfully
```

The two spaces at the beginning of the third line remain untouched.

[user]
Will `[ \t]+$` also remove the carriage return in Windows CRLF files? I need the line endings preserved exactly.

[assistant]

Usually, no, provided the regex engine treats `$` as matching before a line-feed and the character class does not include `\r`. In a CRLF file, the match generally consumes the spaces or tabs before `\r\n`, leaving the line ending unchanged.

For portability, use an explicit lookahead:

```regex
[ \t]+(?=\r?$)
```

Enable multiline mode. This says: match one or more spaces or tabs only when followed by an optional carriage return and the end of the line. The `\r` is asserted, not consumed, so CRLF remains CRLF.

If your tool has a separate “dot matches newline” setting, that setting is irrelevant here. The important setting is multiline mode, often written as `m`.

I’m using Python. What is the safest implementation if I want to process a complete string and preserve both LF and CRLF endings?

[assistant]

Use `re.sub` with a lookahead and `re.MULTILINE`:

```python
import re

TRAILING_HORIZONTAL_WS = re.compile(r"[ \t]+(?=\r?$)", re.MULTILINE)

def strip_trailing_horizontal_whitespace(text: str) -> str:
    return TRAILING_HORIZONTAL_WS.sub("", text)
```

Example:

```python
sample = (
    "alpha  \n"
    "beta\t\t\r\n"
    "  gamma \t \n"
    "\n"
    " \t \r\n"
    "delta\r\n"
)

cleaned = strip_trailing_horizontal_whitespace(sample)

print(repr(cleaned))
```

Output:

```text
'alpha\nbeta\r\n  gamma\n\n\r\ndelta\r\n'
```

The pattern removes only ASCII spaces and tabs. It preserves the `\n` or `\r\n` terminator, preserves indentation, and does not alter empty lines. Avoid using `\s+$` here: in multiline mode, `\s` can match line breaks and may collapse or remove line-ending characters.

Could you show a small command-line program that reads raw bytes, changes only spaces and tabs immediately before LF, and preserves CRLF? I want to avoid universal-newline translation.

[assistant]

Yes. If the requirement is specifically “remove spaces and tabs immediately before each LF,” byte processing is direct and avoids text-mode newline conversion:

```python
#!/usr/bin/env python3
import argparse
import re
import sys

TRAILING_WS_BEFORE_LF = re.compile(rb"[ \t]+(?=\r?\n)")

def main() -> int:
    parser = argparse.ArgumentParser(
        description="Strip spaces/tabs immediately before LF without changing line endings."
    )
    parser.add_argument("input", help="input file, or - for stdin")
    parser.add_argument("output", help="output file, or - for stdout")
    args = parser.parse_args()

    if args.input == "-":
        data = sys.stdin.buffer.read()
    else:
        with open(args.input, "rb") as source:
            data = source.read()

    cleaned = TRAILING_WS_BEFORE_LF.sub(b"", data)

    if args.output == "-":
        sys.stdout.buffer.write(cleaned)
    else:
        with open(args.output, "wb") as destination:
            destination.write(cleaned)

    return 0

if __name__ == "__main__":
    raise SystemExit(main())
```

The key expression is:

```python
rb"[ \t]+(?=\r?\n)"
```

It matches spaces or tabs only when the next bytes are either `\n` or `\r\n`. It does not match spaces at end-of-file unless they precede an LF. It also leaves lone `\r` endings unchanged.

Example:

```text
python3 strip_log_ws.py app.log app.clean.log
```

For a pipeline:

```text
cat app.log | python3 strip_log_ws.py - - > app.clean.log
```

Using `sys.stdin.buffer`, `sys.stdout.buffer`, and binary file modes prevents newline translation.

That is expected for the version that defines trailing whitespace as whitespace immediately before LF. A final unterminated line has no LF, so the regex deliberately does not touch it.

If you want to remove spaces and tabs at the end of either a terminated line or the complete input, use an alternation:

```python
TRAILING_WS = re.compile(rb"[ \t]+(?=\r?\n)|[ \t]+\Z")
```

The second branch, `[ \t]+\Z`, matches spaces or tabs only at the absolute end of the byte string. It will not remove spaces inside the final line.

A compact program change is:

```python
TRAILING_WS = re.compile(rb"[ \t]+(?=\r?\n)|[ \t]+\Z")

cleaned = TRAILING_WS.sub(b"", data)
```

For this input, shown with escaped bytes:

```text
b"first  \nsecond\t\r\nthird   "
```

the result is:

```text
b"first\nsecond\r\nthird"
```

The line endings remain one LF and one CRLF. If you do not want to alter an unterminated final line, retain the original `rb"[ \t]+(?=\r?\n)"` pattern.

One concern: our logs can contain non-ASCII whitespace, but the policy says only ASCII spaces and tabs count as removable. Can you explain why the explicit class is preferable, and show a negative test?

[assistant]

Use `[ \t]` (or `rb"[ \t]"` for bytes) because it states the policy exactly: remove U+0020 space and U+0009 tab, and nothing else. A shorthand such as `\s` has broader semantics. In Python text regexes, it can match Unicode whitespace such as non-breaking space, and in byte regexes its behavior can also vary with flags and the chosen pattern. It can additionally match line terminators, which is especially risky when used with repetition near line boundaries.

For the byte-oriented implementation:

```python
import re

TRAILING_WS = re.compile(rb"[ \t]+(?=\r?\n)|[ \t]+\Z")

def clean(data: bytes) -> bytes:
    return TRAILING_WS.sub(b"", data)

source = (
    b"name\xC2\xA0\n"       # UTF-8 non-breaking space before LF
    b"count\xE3\x80\x80\n"  # UTF-8 ideographic space before LF
    b"ok \t\r\n"
    b"final \t"
)

expected = (
    b"name\xC2\xA0\n"
    b"count\xE3\x80\x80\n"
    b"ok\r\n"
    b"final"
)

actual = clean(source)

assert actual == expected, (
    "Non-ASCII whitespace was changed or ASCII cleanup failed:\n"
    f"expected: {expected!r}\n"
    f"actual:   {actual!r}"
)
```

The first two lines retain their UTF-8 whitespace bytes. The third line loses its ASCII space and tab, and the final unterminated line loses its ASCII trailing space and tab.

```python
TRAILING_WS = re.compile(rb"[ \t]+(?=\r\n|\n|\r)|[ \t]+\Z")
```

```text
b'lf\ncrlf\r\ncr\rfinal'
```

This preserves every line-ending byte sequence and removes only ASCII spaces and tabs immediately before a recognized terminator, plus at absolute end of input. Decide explicitly whether lone CR is valid in your logs before enabling that branch.
