Can we verify the offsets with a command-line tool? Please give an example that handles both dates and prints UTC, Central Europe, and India.

[assistant]
You can use Python’s standard `zoneinfo` module, which reads the system time-zone database. This example treats the Pacific input as a local time in `America/Los_Angeles` and converts it to the other zones:

```python
from datetime import datetime
from zoneinfo import ZoneInfo

dates = [
    datetime(2025, 10, 26, 9, 0, tzinfo=ZoneInfo("America/Los_Angeles")),
    datetime(2025, 11, 2, 9, 0, tzinfo=ZoneInfo("America/Los_Angeles")),
]

zones = [
    ("UTC", "UTC"),
    ("Central Europe", "Europe/Berlin"),
    ("India", "Asia/Kolkata"),
]

for dt in dates:
    print(dt.strftime("%Y-%m-%d %H:%M %Z %z"))
    for label, name in zones:
        converted = dt.astimezone(ZoneInfo(name))
        print(f"  {label}: {converted.strftime('%Y-%m-%d %H:%M %Z %z')}")
    print()
```

Expected output is approximately:

```text
2025-10-26 09:00 PDT -0700
  UTC: 2025-10-26 16:00 UTC +0000
  Central Europe: 2025-10-26 17:00 CET +0100
  India: 2025-10-26 21:30 IST +0530

2025-11-02 09:00 PST -0800
  UTC: 2025-11-02 17:00 UTC +0000
  Central Europe: 2025-11-02 18:00 CET +0100
  India: 2025-11-02 22:30 IST +0530
```

The exact abbreviation shown for Central Europe can vary by the selected IANA zone, but `Europe/Berlin` should show CET on both dates after its October transition.

[assistant]
Yes, 1:30 AM is ambiguous on November 2, 2025 in `America/Los_Angeles`, because the hour from 1:00 AM through 1:59 AM occurs twice.

The two possibilities are:

```text
First occurrence:
2025-11-02 01:30 PDT, UTC−7
2025-11-02 08:30 UTC
2025-11-02 09:30 CET
2025-11-02 14:00 IST

Second occurrence:
2025-11-02 01:30 PST, UTC−8
2025-11-02 09:30 UTC
2025-11-02 10:30 CET
2025-11-02 15:00 IST
```

A calendar application needs to choose which occurrence is intended. The first is the daylight-time occurrence, before the clocks move back; the second is the standard-time occurrence, after the change.

In Python, the `fold` attribute distinguishes them:

```python
from datetime import datetime
from zoneinfo import ZoneInfo

zone = ZoneInfo("America/Los_Angeles")
first = datetime(2025, 11, 2, 1, 30, tzinfo=zone, fold=0)
second = datetime(2025, 11, 2, 1, 30, tzinfo=zone, fold=1)

print(first.isoformat(), first.astimezone(ZoneInfo("UTC")))
print(second.isoformat(), second.astimezone(ZoneInfo("UTC")))
```

For ordinary daytime times such as 9:00 AM, there is no ambiguity because the repeated hour has already ended.
