```python
text = (

    "NOTICE keep  internal spaces  \r\n"
    "\r\n"
    "    \r\n"

print("Input:")
print(repr(text))
print("\nOutput:")
print(repr(cleaned))
print("\nLine endings and content:")

for number, line in enumerate(cleaned.splitlines(keepends=True), start=1):
    ending = ""
    if line.endswith("\r\n"):
        content, ending = line[:-2], "\\r\\n"
    elif line.endswith("\n"):
        content, ending = line[:-1], "\\n"
    elif line.endswith("\r"):
        content, ending = line[:-1], "\\r"
    else:
        content = line
    print(f"{number}: content={content!r}, ending={ending!r}")
```

The important part is `(?=\r?$)`: it asserts that the spaces or tabs are immediately followed by an optional carriage return and the line end. The replacement therefore cannot consume `\r` or `\n`.

How should I handle a file that might have LF, CRLF, or old-style CR line endings? I’d like one Python function, and I want whitespace-only lines to remain unchanged.

[assistant]
Use an explicit line-ending alternation and require a non-whitespace character before the trailing spaces or tabs. This preserves line endings and leaves whitespace-only lines alone:

```python
import re

_TRAILING = re.compile(r"(?<=\S)[ \t]*(?=\r\n|\r|\n|$)")

def strip_trailing_space(text: str) -> str:
    return _TRAILING.sub("", text)

sample = (
    "LF line   \n"
    "CRLF line\t\t\r\n"
    "CR line     \r"
    "    \n"
    "\t\t\r\n"
    "mixed  \r"
    "final line   "
)

result = strip_trailing_space(sample)

print("Input: ")
print(repr(sample))
print("Output:")
print(repr(result))
```

The lookbehind `(?<=\S)` requires the character immediately before the matched spaces or tabs to be non-whitespace. Consequently, a whitespace-only line is not changed. The lookahead recognizes LF, CRLF, CR, or end-of-string, and the replacement removes only the trailing horizontal whitespace.

Can this be done without lookbehind? I may use an engine where lookbehind support is limited, but I still want whitespace-only lines preserved.

[assistant]
Yes. Capture the content before the trailing spaces or tabs, then replace the whole match with that capture. To support LF, CRLF, CR, and a final line without a terminator, use:

```regex
([^ \t\r\n])([ \t]*)(?=\r\n|\r|\n|$)
```

Replace with:

```text
\1
```

In Python:

```python
import re

pattern = re.compile(r"([^ \t\r\n])([ \t]*)(?=\r\n|\r|\n|$)")

def strip_trailing_space(text):
    return pattern.sub(r"\1", text)
```

The first capture must be a non-space, non-tab, non-line-ending character. Therefore, a whitespace-only line has no match and remains unchanged. The line ending is only checked by the lookahead, so it is preserved. In replacement APIs that use `$1` rather than `\1`, use the syntax required by that engine.

I’m also working with a tool that has no lookahead. Is there a practical fallback, and what limitations should I expect?

[assistant]
A common fallback is to match each complete line and capture the content plus its line ending, then replace the line with the captured content after removing trailing spaces or tabs in a second step. If the tool supports alternation but neither lookaround, this single-pass pattern can work for ordinary lines:

```regex
([^ \t\r\n](?:[^ \r\n]*[^ \t\r\n])?)[ \t]*(\r\n|\r|\n|$)
```

Replace with:

```text
\1\2
```

It preserves the line ending and does not match whitespace-only lines. However, the pattern is more complicated and may behave differently in engines where `$` can match before a final newline or where captures in optional groups are handled unusually.

The most portable approach is usually two passes:

1. Split the input into lines while retaining each line ending.
2. For each line, remove only a final run matching:

```regex
[ \t]+$
```

3. Leave the line unchanged when its content consists only of spaces or tabs.

Pseudocode:

```text
for each line including its ending:
    separate content from ending
    if content contains a non-space/tab:
        content = replace final [ \t]+ with empty
    output content + ending
```

Without lookahead or lookbehind, preserving several line-ending styles and distinguishing whitespace-only lines generally requires either captures with careful grouping or line-by-line processing.
