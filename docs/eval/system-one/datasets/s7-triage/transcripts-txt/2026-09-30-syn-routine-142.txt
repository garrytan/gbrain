[assistant]
Yes. Run these commands:

```bash
command -v pg_config || true
pg_config --version 2>/dev/null || true
dpkg -S "$(command -v pg_config)" 2>/dev/null || true
```

The first command prints the executable’s path if it is on `PATH`. The second prints its version if it can be run. The third identifies the Debian package that owns that file.

You can also search common locations without requiring it to be on `PATH`:

```bash
find /usr /usr/local -type f -name pg_config -perm /111 2>/dev/null
```

If all of those produce no useful output, it is probably not installed. You can check the package database directly:

```bash
dpkg -l | grep -E '^(ii|rc)\s+libpq-dev\s'
```

An `ii` line means `libpq-dev` is installed. An `rc` line means it was installed previously but is currently removed.

Is there a quick way to verify that the installed module loads and reports its linked PostgreSQL library?

[assistant]
Yes. Use the interpreter from the active virtual environment:

```bash
python -c 'import psycopg2; print(psycopg2.__version__); print(psycopg2.__libpq_version__)'
```

A successful result will look similar to:

```text
2.9.9 (dt dec pq3ext)
160003
```

The first value is the Python package version and the integer is the linked `libpq` version encoded as major, minor, and patch components. You can also verify exactly which interpreter and package location are being used:

```bash
python -c 'import sys, psycopg2; print(sys.executable); print(psycopg2.__file__)'
python -m pip show psycopg2
```

This only tests importing the extension and inspecting its linked client library. It does not connect to a database or require a PostgreSQL server to be running.

For future setups, would installing `psycopg2-binary` avoid all these system packages?

[assistant]
Usually, yes. `psycopg2-binary` provides a prebuilt wheel for many common Python and platform combinations, so it generally does not require `pg_config`, a compiler, PostgreSQL headers, or OpenSSL development headers:

```bash
python -m pip install psycopg2-binary
```

For a clean test environment, you could create another virtual environment and install only that package:

```bash
python -m venv /tmp/psycopg2-test
source /tmp/psycopg2-test/bin/activate
python -m pip install --upgrade pip
python -m pip install psycopg2-binary
python -c 'import psycopg2; print(psycopg2.__version__)'
deactivate
rm -rf /tmp/psycopg2-test
```

The binary distribution is convenient for local development and simple applications. If you choose it, do not install both `psycopg2` and `psycopg2-binary` in the same environment because they provide the same import name. For a source build, keep `libpq-dev`, a compiler, Python development headers, and any headers reported by the build available.
