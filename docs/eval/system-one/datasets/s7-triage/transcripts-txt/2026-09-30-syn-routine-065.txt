I also noticed that some IDs on `Summary` are numeric while the corresponding values on `Data` are text. Is there a way to make the formula handle both issues without editing the source data first?

[assistant]
Yes. A robust option is to normalize both sides inside the formula by converting IDs to text and removing ordinary spaces. In newer Excel versions, you can use:

`=LET(id,TRIM($A2&""),ids,TRIM(Data!$A$2:$A$500&""),IFERROR(INDEX(Data!$E$2:$E$500,XMATCH(id,ids,0)),""))`

Here:

- `$A2&""` converts the Summary ID to text.
- `TRIM` removes leading and trailing ordinary spaces and reduces repeated spaces between words.
- `XMATCH` searches the normalized Data IDs.
- `INDEX` returns the description from column E.
- `IFERROR` returns a blank if no normalized match exists.

If the spaces came from pasted data and are nonbreaking spaces, `TRIM` may not remove them. In that case, use `SUBSTITUTE` as well:

`=LET(id,TRIM(SUBSTITUTE($A2&"",CHAR(160)," ")),ids,TRIM(SUBSTITUTE(Data!$A$2:$A$500&"",CHAR(160)," ")),IFERROR(INDEX(Data!$E$2:$E$500,XMATCH(id,ids,0)),""))`

This is an array calculation, so it works best in Excel 365 or Excel 2021. Fill it down from `H2`.

The diagnostic shows that the source value for one row is `00127`, and the Summary value is also displayed as `00127`. However, `TYPE` returns 1 for both cells. The cells have a custom format of `00000`. So those two are actually the same numeric value, correct?

[assistant]
Correct. If both cells contain the numeric value 127, the custom `00000` format only displays that value as `00127`; it does not store the leading zeroes. A formula comparing those cells treats them as equal to another numeric 127, regardless of whether the other cell is displayed as `00127` or `127`.

To preserve `00127` as distinct from `127`, the source values need to be stored as text, or you need a separate text key with the required width. For example, if every ID should be five characters and numeric values are valid, a normalized key could be:

`=TEXT(A2,"00000")`

But be careful: that intentionally makes numeric 127 into `00127`. It is appropriate only if the leading-zero format is part of the ID definition. If an actual text value `127` must remain different from text `00127`, formatting both with `TEXT` would erase that distinction.

For the current formula, decide whether the ID rule is:

1. Numeric identity: 127 and 00127 are the same.
2. Text identity: 127 and 00127 are different.
3. Fixed-width identity: all valid IDs are five characters, so 127 is normalized to 00127.

The lookup formula should match that rule consistently on both sheets.
