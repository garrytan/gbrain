What if I want the script to split the subtotal, tax, and tip as separate components, while still distributing cents evenly?

[assistant]

You can allocate each component in cents with `divmod`. For each row, every person gets the quotient, and the first few people get one additional cent for the remainder.

```python
from decimal import Decimal, ROUND_HALF_UP

subtotal = Decimal("146.80")
tax = Decimal("13.21")
tip_rate = Decimal("18")
people = 4

tip = (subtotal * tip_rate / Decimal("100")).quantize(
    Decimal("0.01"), rounding=ROUND_HALF_UP
)

components = {
    "subtotal": int(subtotal * 100),
    "tax": int(tax * 100),
    "tip": int(tip * 100),
}

shares = [0] * people
rows = {}

for name, cents in components.items():
    base, remainder = divmod(cents, people)
    row_shares = [
        base + (1 if i < remainder else 0)
        for i in range(people)
    ]
    rows[name] = row_shares
    shares = [a + b for a, b in zip(shares, row_shares)]

print(rows)
print(shares)
print([f"${c / 100:.2f}" for c in shares])
print(sum(shares))
```


That is mathematically consistent, but the first person receives two row-level extra cents. To make final shares as even as possible, you need to choose which people receive each remainder strategically.

Can you modify it so the extra cents are assigned to people with the currently lowest totals?

[assistant]

Yes. For each component, start with the equal base amount, then assign its leftover cents one at a time to the people whose running totals are currently lowest. This balances the final totals better, although ties can still be resolved by position.

```python
from decimal import Decimal, ROUND_HALF_UP

subtotal = Decimal("146.80")
tax = Decimal("13.21")
tip_rate = Decimal("18")
people = 4

tip = (subtotal * tip_rate / Decimal("100")).quantize(
    Decimal("0.01"), rounding=ROUND_HALF_UP
)

components = [
    ("subtotal", int(subtotal * 100)),
    ("tax", int(tax * 100)),
    ("tip", int(tip * 100)),
]

running = [0] * people
allocation = {}

for name, cents in components:
    base, remainder = divmod(cents, people)
    row = [base] * people

    for _ in range(remainder):
        lowest = min(running)
        index = running.index(lowest)
        row[index] += 1
        running[index] += 1

    running = [total + base for total in running]
    allocation[name] = row

print(allocation)
print(running)
print([f"${c / 100:.2f}" for c in running])
print(sum(running))
```

A clearer implementation updates the running total for every person after the row is fully assigned:

```python
running = [0] * people

for name, cents in components:

        index = min(range(people), key=running.__getitem__)
```

The key point is that the running totals must be updated after each component, so later leftover cents can be directed to people who are behind.

I see a possible issue: when there are multiple lowest totals, `min` always picks the first one. Is there a simple way to rotate the tie-breaking so the same person isn’t favored?

[assistant]

Yes. Keep a rotating starting position and search from there when choosing among tied lowest totals. This makes ties move across the people instead of always selecting index zero.

```python
from decimal import Decimal, ROUND_HALF_UP

subtotal = Decimal("146.80")
tax = Decimal("13.21")
tip_rate = Decimal("18")
people = 4

tip = (subtotal * tip_rate / Decimal("100")).quantize(
    Decimal("0.01"), rounding=ROUND_HALF_UP
)

components = [
    ("subtotal", int(subtotal * 100)),
    ("tax", int(tax * 100)),
    ("tip", int(tip * 100)),
]

running = [0] * people
allocation = {}
start = 0

for name, cents in components:
    base, remainder = divmod(cents, people)
    row = [base] * people

    for _ in range(remainder):
        lowest = min(running)
        candidates = [
            (start + offset) % people
            for offset in range(people)
            if running[(start + offset) % people] == lowest
        ]
        index = candidates[0]
        row[index] += 1
        running[index] += 1
        start = (index + 1) % people

    running = [
        total + base
        for total, base in zip(running, [base] * people)
    ]
    allocation[name] = row

print(allocation)
print([f"${c / 100:.2f}" for c in running])
print("Cents sum:", sum(running))
```

There is one subtlety: if you increment `running[index]` immediately and then add the base later, the selected person’s running total temporarily includes only the extra cent. That is fine if the base is added to everyone afterward, but it is easier to avoid confusion by build­ing the row first and updating all totals once.

Here is the cleaner version:

```python
running = [0] * people
allocation = {}
start = 0

for name, cents in components:
    base, remainder = divmod(cents, people)
    row = [base] * people

    for _ in range(remainder):
        lowest = min(running)
        for offset in range(people):
            index = (start + offset) % people
            if running[index] == lowest:
                row[index] += 1
                start = (index + 1) % people
                break

    running = [old + new for old, new in zip(running, row)]
    allocation[name] = row
```

This preserves exact totals and rotates tie choices while keeping the final amounts as balanced as possible.
