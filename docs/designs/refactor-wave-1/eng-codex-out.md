1. **High — W1-core already contains dialect-specific behavior; inventory cannot be limited to W1-extended.**  
   PGLite code-edge writes batch below 30,000 parameters because exceeding the driver limit can corrupt the session ([code-edges.ts:9](src/core/pglite-engine/code-edges.ts:9)); Postgres constructs a single batch ([code-edges.ts:29](src/core/postgres-engine/code-edges.ts:29)). Postgres fact insertion also probes `vector` versus `halfvec` and acquires transaction-scoped advisory locks ([facts.ts:60](src/core/postgres-engine/facts.ts:60)). Selecting either engine’s implementation as canonical can therefore break the other backend.  
   **Fix:** Inventory all five core domains before committing their scope. Define explicit capabilities for bind limits, embedding casts, and locks, with boundary-size and concurrent-write tests gating each conversion.

2. **High — The executor contract omits affected-row metadata.**  
   `executeRaw` returns only `rows` on PGLite ([pglite-engine.ts:6006](src/core/pglite-engine.ts:6006)). Core-domain methods depend on metadata outside those rows: code-edge insertion uses `affectedRows` ([code-edges.ts:51](src/core/pglite-engine/code-edges.ts:51)), while Postgres fact expiration uses `result.count` ([facts.ts:128](src/core/postgres-engine/facts.ts:128)). A rows-only executor can successfully mutate data while reporting zero changes or `false`. The proposed binding matrix would miss this.  
   **Fix:** Specify an internal result envelope containing rows and affected-row count. Test empty updates, successful updates, conflict-skipped inserts, and mixed batches. Preserve the public `executeRaw` contract separately.

3. **High — A4’s prepare-mode prescription does not preserve direct-Postgres behavior.**  
   `resolvePrepare()` normally returns `undefined` ([db.ts:82](src/core/db.ts:82)), but vendored `unsafe()` defaults to `prepare: false` ([index.js:119](vendor/postgres/src/index.js:119)). Passing `{prepare: undefined}` also disables preparation because the driver checks property presence ([connection.js:238](vendor/postgres/src/connection.js:238)). Thus “pass `{prepare}` from `resolvePrepare(url)`” does not preserve formerly tagged queries. Conversely, forcing preparation globally changes existing unsafe-query behavior.  
   **Fix:** Track the original statement’s preparation policy and resolve the connection default explicitly. Test actual preparation behavior for default direct connections, explicit overrides, transaction handles, and PgBouncer—not merely successful query results.

4. **High — A3 proves scope binding, not isolation, and introduces an unacknowledged behavior change.**  
   Current fact reads delegate directly to their SQL dependencies ([postgres-engine.ts:4444](src/core/postgres-engine.ts:4444)); they do not all use `withScopedReadTransaction`. Requiring that wrapper adds transactions and RLS filtering when binding is enabled. Moreover, checking `current_setting('app.scopes')` while connected as a superuser proves no rows were denied. The repository already has a stronger non-bypass-role testing pattern ([shared-skills-rls.test.ts:14](test/e2e/shared-skills-rls.test.ts:14)).  
   **Fix:** Inventory existing scope boundaries and explicitly decide whether expanding them belongs in this behavior-preserving PR. Test with a non-owner, non-superuser, `NOBYPASSRLS` role; assert cross-source denial, concurrent-request isolation, nested rollback restoration, and connection reuse.

Engine initialization subsequently runs migrations that could mask a generator error ([pglite-engine.ts:1066](src/core/pglite-engine.ts:1066)).

6. **High — The CLI record does not model connection and teardown ownership.**

8. **High — Sync’s proposed interleaving tests omit checkpoint durability and finalization races.**  
   Checkpoint flushing coordinates pending paths, an in-flight flush flag, failed-batch restoration, and failure counters ([sync.ts:2446](src/commands/sync.ts:2446)). Finalization flushes checkpoints, deregisters signal cleanup, advances the pinned bookmark, and clears checkpoint rows ([sync.ts:3577](src/commands/sync.ts:3577), [sync.ts:3642](src/commands/sync.ts:3642)). Testing only phase completion versus watchdog/timeout does not protect these transitions.  
   **Fix:** Define terminal phase outcomes and a single owner for checkpoint and cleanup state. Add controlled failures/interleavings for checkpoint writes, worker completion, SIGTERM cleanup, bookmark advancement, and full-sync fallback. Assert durable state after restarting, not just returned status.
