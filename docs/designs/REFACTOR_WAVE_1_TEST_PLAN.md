## Affected Pages/Routes
- `gbrain --help`, `gbrain --tools-json`, `gbrain <unknown>` — CLI command table replaces the 62-case switch; output, exit codes and flag validation must be byte-identical to master goldens.
- Every CLI-only command (111 `CLI_ONLY` members) — dispatch phase (pre-connect engine-free vs post-connect) and thin-client handling (none / refuse / route-then-refuse) must equal master.
- `gbrain status`, `gbrain db-repair`, `gbrain pglite-repair`, `gbrain bootstrap`, `gbrain hook` — engine-free commands must still answer with the database unreachable.
- `gbrain sources writer|reconcile|add|...`, `gbrain takes add|update|supersede|resolve`, `gbrain capture|forget|call` — subcommand-level routing to the deferred persistence delegate must be unchanged.
- `gbrain doctor` (`--json`, `--fast`, `--fix --dry-run`, `--scope=brain`, `--source <id>`) on PGLite, Postgres and one degraded config — ordered check names, categories, statuses and normalized JSON identical.
- `gbrain sync` (full, incremental, working-tree, resume from checkpoint, timeout, stall) — phase breadcrumbs, checkpoint contents and result counts identical.
- `gbrain serve --http`: `/mcp` (GET/POST), `/token`, `/register`, `/revoke`, `/authorize`, legacy PRM path, `/.well-known/gbrain`, `/health`, `/admin/login`, `/admin/api/issue-magic-link`, `/admin/auth/:token`, `/metrics`, `/admin/api/*` (19 routes), `/admin/events`, `/admin` static + SPA fallback — global middleware order, per-route middleware chain and auth outcomes identical.
- `gbrain init` / any engine connect on PGLite and Postgres (direct and PgBouncer) — schema bootstrap, blob replay and migrations reach the identical catalog on fresh AND existing brains.
- `gbrain search` / `gbrain query` / MCP `search`, `query` — hybrid ranked `(id, score)` identical, cold and warm cache.
- `gbrain jobs work` / supervisor probe (cut-line) — 24 handlers registered in the same order; `registerBuiltinHandlers` importable from `src/commands/jobs.ts`.

## Key Interactions to Verify
- Store write inside `engine.transaction()` that then throws is rolled back, on PGLite and Postgres (engine-sql executor resolves the connection per call).
- A read that was RLS-scoped on master (23 `withScopedReadTransaction` sites) still binds `app.scopes` with `GBRAIN_RLS_SCOPE_BINDING=1`; a read that was NOT scoped on master still runs on the pool with no transaction.
- Repeated engine-sql call on direct Postgres reuses a named prepared statement; on PgBouncer transaction mode it does not; zero-parameter queries never use the simple protocol.
- Driver errors (23505, 57014, deadlock via `isDeadlockError`) reach callers with the same class, `.code` and message through the executor on PGLite, direct Postgres and PgBouncer.
- Abort signal forwarded only where the engine forwarded it on master; cancellation settles before the connection is reused.
- Existing PGLite brain created by master, opened by the branch: `initSchema` replays the generated blob and migrations without error and the catalog equals master's.
- Duplicate migration version after rebase: generator fails naming both files with the `git mv` recipe.
- Dropping `requireAdmin` from any route in any `serve-http-*.ts` module fails the admin-route guard with that module file:line.
- New command added through the table: accepted flag passes, unknown flag rejected, `--help` works without an engine.
- Sync phase await vs stall watchdog, and phase await vs timeout, in both completion orders: abort observed, checkpoint reflects only committed work.
