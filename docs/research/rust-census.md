# Rust engine census

Research map, pinned to `rust-engine/cli-members` at `dc06e84e08`. It runs every CLI command and every MCP tool on
three brains built from one synthetic fixture (`test/fixtures/rust-cli-parity-brain`): a Rust brain, a PGLite brain
(the reference) and a Postgres brain. For each command or tool it records whether the Rust answer equals the PGLite
answer, the refusal the Rust run ended on (member, capability and the file:line that asked), and the store members and
raw SQL the run touched. It then groups the failures into work packages of about one day, ranked by user impact, so
parallel lanes can take packages that do not touch the same files.

Regenerate with `bun run rust:build && bun scripts/rust-census/census.ts` (add `GBRAIN_CENSUS_PG_URL=<postgres url>`
for the Postgres arm; `--filter <name>` and `--only cli|mcp` narrow a run; `--from-json <file>` re-renders the report
and the packages without a rerun). The part between the GENERATED markers is rewritten; this introduction is kept.

## Summary

- 425 cases: 257 CLI cases over 241 commands (13 skipped on purpose: network, interactive, or engine-specific by
  design) and all 168 MCP tools. On Rust, 150 CLI cases and 83 MCP tools answer exactly as PGLite does; 72 CLI cases
  and 77 MCP tools refuse with `engine_capability_missing`; 22 CLI cases and 8 MCP tools answer differently with no
  refusal in the output. No case crashed or panicked.
- On the CLI, `import`, `search` and `extract all --source db` already match PGLite. `put`, `sync`, `get`, `list`,
  `links`, `backlinks`, `graph`, `timeline`, `tag` and `extract links --source fs` refuse. `query` answers, but a
  question that names an entity ranks with different scores: entity resolution (`src/core/entities/resolve.ts:246`)
  refuses, a fail-soft path catches it, and the entity boost is lost (P19).
- Two families explain most refusals:
  1. **Raw SQL in callers** (55 packages). A caller outside the engine runs `executeRaw` or `executeRawDirect`, which
     a Rust brain does not serve. Each package names the caller file; the fix is a typed store member (or an existing
     one) in place of the SQL. The largest is `src/core/persistence/page-visibility.ts` (P01), which every MCP page
     write reaches (`add_link`, `remove_link`, `delete_page`, `restore_page`, `add_tag`, `remove_tag`, `capture`,
     `append_page` and the takes writes).
  2. **Options a served member does not take yet** (21 packages). The member runs on Rust, but the caller passes an
     option the Rust shell refuses: `excludePrivate` on every MCP read (a stdio MCP caller is remote, so reads hide
     private pages), `temporal` on the link and graph reads, `resolveAlias` on `get`, `eligibility` on facts and
     timeline reads, `listColumnsOnly` on `list`. The privacy helpers already exist in
     `src/core/rust-engine/store-members/private-provenance.ts`; the members' option allow-lists do not admit the
     option yet.
- The put write path the CLI uses (`put`, `tag`, `untag`, `delete`, `restore`, `append`, `capture`, `timeline-add`,
  `revert`) ends on the consumer heartbeat in `src/core/persistence/consumer-heartbeat.ts`. Lane 7 owns that work, so
  the package (listed last) is marked owned. The MCP `put_page` ends earlier, on the large-page guard (P20), which is
  not in lane 7's list.

## How to read the tables

- **status**: `equal` (same exit and the same normalized output as PGLite), `refused` (the Rust run ended on
  `engine_capability_missing`), `differs` (a different answer or a named error with no capability refusal),
  `crash` (timeout, signal, panic text, or an error with no code), `skipped` (not run, with the reason).
- **decisive member** and **end site**: the refusal that reached the output. The tracer tags every refusal it sees with
  a sequence number, so the census can tell the refusal the user saw from the ones a fail-soft path caught on the way.
- **first refusal**: the first refusal the run built, caught or not. For a `differs` row with no refusal in the
  output, the packages use the first refusal that does not also happen in an `equal` case (a refusal that happens in an
  equal case is caught and harmless there, such as the fact-cache watermark in `src/core/facts/meta-hook.ts` that
  every MCP call reads).
- **Work packages**: score 10 for each hot command or tool a package blocks (put, import, sync, search, query, get,
  links and the MCP hot tools), 1 for any other. A raw-SQL package lists the caller file it changes; an option package
  lists the store-members file. Packages that change the same file are listed as conflicts: give them to one lane, or
  run them one after the other. A package marked with an owner is in flight in another lane: do not start it.

## Caveats

- One fixture brain, one invocation per command (two or three for the hot commands). A command that passes here can
  still refuse on another path, flag or brain shape. A refused case shows only the first wall: fixing it can expose the
  next refusal behind it, so a package's size is a floor.
- The census does not run work owned by other lanes on purpose. No case reached `searchVector` (lane 6), valid-time
  reads (lane 3), COLLATE reads (lane 4), spend tables (lane 5) or facts maintenance (lane 1) as its decisive refusal,
  because an earlier refusal stops the run first or the fixture has no embeddings. Only lane 7 matches a package.
- A refusal raised after an `await` inside the Rust shell loses its caller's stack frames; the census then names the
  first caller of that member in the run, which is right when one caller uses it.
- Some `differs` rows are expected differences, not bugs: `engine status` prints a PGLite lock field, `migrate` and
  `pglite-repair` describe PGLite data directories, `config` and `smoke-test` name the engine or a health score that
  follows from refusals elsewhere.
- Known boot race in `gbrain serve`, the same on every engine: the onboarding refresher's first check loads the
  active schema pack into the in-process pack cache, and it can finish before or after the case's tools/call. So
  `reload_schema_pack` answered `invalidated: [gbrain-base]` or `[]` by timing alone. The census sets
  `GBRAIN_NO_ONBOARD_NUDGE=1` for every MCP case, which turns the refresher off. The product fix (wait for the first
  refresh) is in TODOS.md as onboarding-refresher-pack-cache-race.
- The Postgres column compares Postgres with PGLite. It is advisory: most differences are engine-specific fields
  (data directory, lock, connection) and timings; the Postgres rows were not triaged.
