## 5. Scoreboard check and receipts

### 5a. What `check` does

- Entry point: `bun run eval:scoreboard check` (eval/runner/scoreboard-cli.ts:583) delegates to `bun eval/runner/scoreboard.ts check`.
- Recomputes, from committed rows only (campaign.json plus cells/<id>/rows.ndjson, answers.ndjson, judgments.ndjson): per-question values, pairwise cohorts, aggregates and comparisons (restricted wild cluster bootstrap-t for the headline set), Holm families, then scoreboard.json, scoreboard.md and the README headline block. Compares byte for byte with the committed text (eval/runner/scoreboard.ts header, lines 1-60).
- Checks the pin table in docs/comparison-systems.md against bundle lockfile and capability hashes (`checkPinTable`, scoreboard.ts:1269).
- Size budget: no file over 50 MB; receipt tree under 60 MB (`checkSize`, scoreboard.ts:1317).
- Receipt secret scan (eval/runner/q1/secret-scan.ts).
- Public verification without the receipt: `check --sums <SHA256SUMS>` or `check --commit <results-branch commit>` (checkSums scoreboard.ts:1216; receiptAtCommit :1236). Those commit hashes live on a results branch, not in this checkout.

What I ran (no paid calls, nothing written):

- `bun run eval:scoreboard check` in the checkout: failed, `Cannot find module 'gbrain/core/model-pricing'` from eval/runner/budget-ledger.ts. The front door imports the gbrain package, which is not installed (no node_modules; the three gbrain packages are GitHub pins in package.json lines 69-71).
- `bun eval/runner/scoreboard.ts check` directly: exit 0, output `scoreboard check: ok (pin table ok; no scoreboard receipts committed yet)`. So the generator passes without node_modules, but there is nothing to recompute. The Q1 cell receipts are in custody, and only aggregates are public.
- `git status` was clean afterward.

### 5b. Receipt content (what a Rust run would need to match)

Three receipt shapes exist in the repo:

1. BrainBench category receipt, `eval/schemas/receipt.schema.json` (schema v2, `$id` brainbench.dev). Required top-level fields: schema_version, benchmark_version, category, run_status, n_total, n_scored, completion_rate, errors, publishable, gbrain_version, gbrain_pin, started_at, finished_at. Also present: verdict, skip_reason, resolved_config, judge {model, temperature, rubric_version, seed}, hashes, data, product_package, execution {source_tree {sha256, files, git_head, dirty}, product {package, declared_pin, declared_sha, version, package_sha256, loaded_git_head}}, accounting {planned, attempted, scored, errors, misses, source}, cost, latency_ms, delivered_tokens.
2. Chronicle-run receipt, example docs/benchmarks/2026-10-04-auto-chronicle-rerun/receipt.json: kind, started, finished, bun version, gbrain {version, declared_pin, overlay}, gbrain_evals {git_head, dirty}, corpus {digest, pages, chronicle_shaped}, settings {arms, qa_arms, repeats, model, max_turns, questions, embeddings, mcp}, builds, cost {usd, input_tokens, output_tokens, basis, ledger, program_cap_usd, overshoot_usd}, event_loop_lag_ms.
3. Q1 scoreboard cell: campaign.json (kind `gbrain-evals/q1-campaign/v1`, cells, executes paths, images by digest, cap_usd, parameters), cells/<id>/receipt.json, run-config.json, rows.ndjson, answers.ndjson, judgments.ndjson, derived/hedge.ndjson, plus power.json, cost-speed.json and the generated scoreboard.json and scoreboard.md (eval/runner/scoreboard.ts:1-60).

Per-call records: `usage-receipt/v1` (docs/usage-receipt.md, defined in eval/runner/usage-receipt.ts). One record per attempted provider call: schema, lane, role (reader, think, judge, builder), question_id, replicate, attempt, model, response_model, status, error, from_cache, finish, answer (untruncated), usage {input_total, input_uncached, cache_read, cache_write, output_total, reasoning}, usage_raw, delivered (tokens, cl100k), request (effort, output limit, temperature, seed sent), response_meta, verdict_path. Normalizer: `normalizeUsage(usageSourceOf(model), raw)`. Anthropic `input_total` = input + cache_read + cache_write; OpenAI `prompt_tokens` already includes cache reads, so adding them double-counts.

Cost: `usageCost` in eval/runner/budget-ledger.ts settles cache reads and writes at their own prices; the ledger is `.budget/ledger.sqlite` (gitignored). Program cap defaults to $500 (eval/RUNBOOK.md:42).

Provenance fields that make a receipt comparable: gbrain version string plus declared pin and the loaded git head (product_package), gbrain-evals git head and dirty flag, data sha256 (corpus digest), resolved config (embedding model and dims, search mode, rerank on or off, budget tokens), judge model and rubric version and seed, per-call usage records, ledger USD, bun version, and start and finish times.

For a Rust run to produce comparable receipts: emit the same `usage-receipt/v1` line per model call (or at least per-role totals), the same receipt.json keys (gbrain_version, gbrain_pin, resolved_config, hashes, execution.product, cost), and keep a per-cell rows and answers layout so `check` can recount it. The check recomputes from rows, so rows and answers are the minimum.
