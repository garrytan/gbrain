## Runner details

### cat40 model ladder and Hard

- Entry file: `eval/runner/cat40-model-ladder.ts`. Helpers: `cat40/` (`arms.ts`, `loop.ts`, `gbrain-arm.ts`, `pg-arm.ts`, `hard.ts`, `hard-grep.ts`, `hard-ops.ts`, `hard-proxy.ts`, `rerank-pool-replay.ts`, `rerank-pool-proxy.ts`, `latency-replay.ts`, `firing.ts`, `analyze.ts`, `score.ts`, `rescore.ts`, `records.ts`, `types-filter.ts`, `reuse-check.ts`, `next-confirm.ts`, `dev-arms.ts`, `judge-hard.ts`, `arm_power.py`, `next_confirm_analysis.py`). Wrappers: `scripts/cat40-hard.sh` and `scripts/cat40-followups.sh` (the only repo-level scripts for this family; no `cat40` entry in package.json).
- What it measures: whether gbrain's advantage over simpler memory (fs, fs-acl, memory, pg, oracle, gbrain; `cat40/arms.ts:21-22`) persists across models, on the world in `eval/data/model-ladder-v1` (header of `cat40-model-ladder.ts`). Hard campaign adds a 50k held-out world with a primary endpoint of gbrain minus fs (`scripts/cat40-hard.sh` header).
- How it runs: `bun eval/runner/cat40-model-ladder.ts --models claude-sonnet-4-6,gpt-5.4 --arms oracle,fs,pg,memory,gbrain --budget-usd 100 [--families A,B] [--tasks A01] [--slots 3] [--gbrain <checkout>@<ref>] [--out eval/reports/cat40/<name>]`. Hermetic: `--scripted --arms fs,memory,oracle` ($0). Keyless slots: `--scripted --keyless-slots --arms gbrain`. Build slots: `--build-slots --gbrain-ref <sha> --slots 5 --budget-usd 10`. Hard steps: `scripts/cat40-hard.sh hello|status|preflight <step>|step <step>`, ledger `.budget/cat40-hard.sqlite`.
- Cost and wall time: protocol gives `fs` and `pg` cells about $0.05 and `gbrain` cells $0.02 to $0.30 (`docs/benchmarks/2026-10-02-model-ladder-protocol.md:227`). Hard runbook (`docs/benchmarks/cat40-hard/RUNBOOK.md`): freeze-check $114.61 (about 90 min), smoke $1.79 (about 20 min), slots-50k $12.04 (about 7.5 h), oracle-50k about 1 h, pg-50k about 5 h, memory-50k about 4 h. Ledger cap $1,794 (RUNBOOK line 11). Followups ledger cap $237 (`scripts/cat40-followups.sh` header).
- LLM keys: ANTHROPIC_API_KEY, OPENAI_API_KEY, PARTICLE_API_KEY (particle-1 through `providers/openai-compatible.ts`), VOYAGE_API_KEY (gbrain slot embeddings and rerank via `cat40/gbrain-arm.ts`). Offline: `--scripted` (hermetic, $0) and `--scripted --keyless-slots` (keyword-only slots, rerank probe skipped).
- Corpus: `eval/data/model-ladder-v1` and `eval/data/model-ladder-wide-dev/world.json` named in the header (not checked for presence in this checkout). Hard worlds are generated from seeds in the frozen knobs (`cat40/` plus `scripts/cat40-hard.sh`).
- gbrain imports:
  - `./gbrain-under-test.ts`: `gbrainSpecFrom`, `parseGbrainSpec` (spec parsing only, `cat40-model-ladder.ts:69`).
  - `./cat40/gbrain-arm.ts`: `GbrainArm`, `GbrainFsArm`, `GbrainPool`, `GbrainSlot`, `MeteringProxy`, `McpClient`, `rerankProbe`, `restoreProbe`, `coverageProblem`, `instructionsOverride` (`cat40-model-ladder.ts:74`, `cat40/hard.ts:15`).
  - gbrain methods reached over MCP (`McpClient.call` in `cat40/gbrain-arm.ts`): `entity`, `search`, `context_pack`, `put_page` (Hard only), `get_page` (`cat40/hard.ts`, `cat40/gbrain-arm.ts`).
  - `cat40/rerank-pool-replay.ts:548`: dynamic import of `<buildDir>/src/core/search/rerank.ts` (`capRerankDoc`) and PGlite from the build's node_modules, run inside `bun -e`.
- Coupling: CLI+MCP. `cat40/gbrain-arm.ts:93` spawns `bun <buildDir>/src/cli.ts serve --surface starter` (or `--surface full`) and speaks JSON-RPC over stdio (`listTools`, `tools/call`; `:137`). Slot snapshots and restores run as `bun -e` scripts that open PGlite directly from the build (`gbrain-arm.ts:412, 522, 530, 561`). `cat40/pg-arm.ts` is its own PGlite arm (tools `vector_search`, `keyword_search`, `save_document`, `get_document`) with no gbrain code. To run against another binary, the runner needs the `serve` command, the `tools/list` and `tools/call` names above, and the snapshot step replaced.
- Parity-gate fit: deterministic only in `--scripted` mode. Paid cells use LLM judgments, so not deterministic. Scripted mode is fast.

### failure causes (failure-causes/)

- Entry file: `failure-causes/cli.ts`. Library: `index.ts` (stable interface for the nightly loop and weekly report, re-exports taxonomy).

- How it runs: `bun eval/runner/failure-causes/cli.ts taxonomy [--write|--check]`; `bun eval/runner/failure-causes/cli.ts classify --manifest <sources.json> --root <name>=<dir> ... --out <labels.ndjson> [--failures-out ...] [--stress-out ...] [--counts-out ...]`.

## Cross-cutting observations

- Coupling is mostly in-process via dynamic `import(join(GBRAIN_DIR, 'src/...'))` (evidence-delivery, external-ideas, lifecycle-lite, budgeted-delivery c8k-product, graph-backend workers, cat41 container driver). The loader `evidence-delivery/gbrain.ts` `loadGbrain` (lines 85-100) is the shared entry point, and its module list is the de facto contract for every in-process study.
- Batch lane imports point at repo-root `node_modules/gbrain` (`batch/w10*.ts`, `batch/sources.ts`), which is the pinned package and not an overlay under test. These results describe the pin, not a candidate checkout.
- Two coupling styles for the same goal: `lifecycle/drivers.ts` (CLI and MCP through spawned `bun <build>/src/cli.ts`, with copied builds from `lifecycle/builds.ts`) is the only fully black-box driver family here. It is the closest model for a Rust-side CLI or MCP adapter. Its MCP framing is JSON-RPC over stdio or HTTP with protocolVersion `2025-06-18`.
- MCP tool names in use: `entity`, `search`, `context_pack`, `put_page`, `get_page`, `recall`, `remember`, `forget`, `list_pages`, `get_timeline`, `get_links`, `query`. CLI operations in use: `init`, `sources`, `sync`, `extract`, `embed`, `call <op>`, `jobs work`, `beliefs enable --source vault`, `serve [--surface starter|full] [--http --port]`.
- Engine methods called in-process across this group: `connect`, `disconnect`, `initSchema`, `getChunks`, `getConfig`, `setConfig`, `unsetConfig`, `executeRaw`, `deletePage`, `traverseGraph`, `traversePathsDetailed`, `now` (test seam), and `brain.disconnect`.
- Shared infrastructure outside this scope that every paid runner depends on: `budget-ledger.ts` (`startPaidRun`, `BudgetRun`, `ledgerStatus`), `paid-arm.ts` (`requirePaidArm`), `metering-proxy.ts` (`MeteringProxy`), `prereg.ts` (`attestPreregistration`), `receipt.ts` (`scrubMachinePaths`), `gbrain-under-test.ts` (`resolveGbrainUnderTest`, `importGbrain`, overlays under `.gbrain-overlays/`), `memory-qa/*` and `q1/*`. Their behavior was not traced beyond these call sites.
- Keyless modes exist for most groups (`--scripted`, hash embedder, `estimate`, `score`, `verdict`, `w10-rescore`, `failure-causes classify`, dry-run and gate scripts). Paid modes are guarded by `--paid`, `--budget-usd`, or `--budget-run-id`, and the ledgers use SQLite.
- Surprises: `cat40/gbrain-arm.ts` and `facts-absorb-gate.ts` both reuse `McpClient` from `cat40/gbrain-arm.ts`, so changes to that file affect cat41, facts-absorb and cat40. `lifecycle/slice.ts` has four callers outside scope (`n1-knowledge-update.ts`, `n5-forget-residue.ts`, `n6-postgres-http.ts`, `p5-brain.ts`).
- Coupling of `failure-causes/label.ts` uses a caller-supplied `ChatLike` client; the provider key path was not traced.
- Not verified: presence of `eval/data/model-ladder-v1` and other named data directories, and actual costs and wall times for most paid runs. Those are reported as "unknown" or as the figure from the cited docs.
