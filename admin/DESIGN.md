# PMBrain Admin Console 设计风格指南

> 本文件是 Admin Console 的长期视觉与交互基准。后续新增或优化页面时，必须先读取本文件，再开始设计或编码。

## 1. 设计定位

PMBrain 是个人知识中枢，不是通用数据大屏。界面应呈现“安静、精致、可信赖的知识控制台”：有适度科技感，但不炫技；信息密度较高，但阅读层次清楚。

关键词：**克制、清晰、精致、专业、轻科技感、有呼吸感**。

## 2. 第一原则：信息守恒

视觉优化不等于重做产品。开始改版前必须先列出现有页面的：

- 全部业务字段、状态、说明和数据范围；
- 全部操作入口及其原有行为；
- 一二级菜单关系；
- 空状态、异常状态和长文本状态。

除非需求明确要求调整功能，否则：

- 不删除、不截断、不合并原有业务信息；
- 不把原有信息替换成新概念；
- 不新增虚构趋势、虚构数据、无实际能力的按钮；
- 不为了布局整齐只显示前几项；完整列表应完整显示，或使用有明确入口的滚动/分页；
- 不改变按钮去向、业务流程、API、CLI、数据库或知识库数据。

本项目的默认改版方法是：**保留信息结构和功能，只升级图标、组件、间距、色彩、排版、边框、阴影和响应式表现。**

## 3. 页面结构

### 3.1 桌面框架

- 左侧导航约 252px，固定展示品牌、一级区块、页面入口和企微助手；不单独设置帮助中心入口。
- 右侧内容区可滚动，最大内容宽度约 1540px，常规留白 24–32px。
- 页面背景、卡片、卡片内局部块形成三级表面，不依赖厚重阴影。

### 3.2 首页信息顺序

```text
标题与系统摘要
  └─ 系统状态悬浮详情：数据库 / 知识结构 / 普通模型 / 向量模型 / 维度 / 自然语言状态
左侧：品牌主视觉 + 单行四项核心指标
右侧：跨越主视觉与指标层的运行状态
内容类型环图 + 数据源排行 + 最近调用
真实七日趋势 + 关键汇总
```

首页允许增加能帮助判断状态的摘要、增减、活动与趋势，但必须来自真实接口或真实日志。没有历史数据时显示“暂无对比数据”，不得生成装饰性假数据。

### 3.3 功能页面结构

- 功能页不复制首页仪表盘，也不为了视觉丰富新增无业务意义的指标或图表。
- 常规页面使用“紧凑页头 → 原有筛选或操作 → 主内容卡片”的顺序；页头高度约 58–72px，标题、说明和主要操作保持在同一视觉层级。
- 同类信息使用相同表面：主卡片 13px 圆角、细边框、短阴影；卡片内部区域使用页面背景或低一级表面，不继续叠加厚重卡片。
- 知识工作台保留主视觉、导入选项、知识助手和最近记录；知识库保留醒目的范围切换、筛选、表格、分页和详情抽屉；MCP 接入只保留教程入口、地址、凭证与隧道，不重复陈列接入步骤和客户端清单；请求日志保留筛选、明细展开和分页。
- 知识整理的品牌主视觉应保持紧凑，常规桌面短屏中优先让“开始整理”和“知识生长轨迹”进入首屏；不得为了主视觉牺牲核心操作。
- 系统分类只保留“设置”入口；任务监控和系统诊断不再作为用户侧页面或导航入口展示。
- 设置页首屏使用“外观偏好 + 主知识库源”的主次双栏，后续按知识整理、数据源、导出和模型快照顺序展开；相同信息不得通过重复的大号指标制造体积，表单开关和复选框必须使用统一控件尺寸。
- Admin 浏览器的外观偏好必须可直接切换并保存到当前浏览器；“跟随系统”读取浏览器系统偏好，浏览器显式选择不反向修改桌面端主题。
- 主知识库源只展示一份当前源名称与路径，用用途标签说明“默认导入”和“MCP 默认读取”，切换下拉与保存操作必须位于同一操作行，不再用三张同值指标卡重复表达。
- 知识整理设置的输出目录与本地 Markdown 开关使用同级内部表面，左右顶部、边框和高度对齐；区块级保存按钮统一放在标题栏右侧。

## 4. 导航规则

- “总体概览”是独立主入口。
- 一级分类使用小号静音标题，例如“知识”“集成”“系统”。
- 分类下的普通页面直接展示图标与名称，不制造无意义折叠。
- 只有确实存在父子关系时才使用二级菜单；当前系统分类只有“设置”，直接展示为一级入口，不再制造折叠层级。
- 当前项使用柔和紫色底、左侧强调线和较高字重；悬停只改变底色与文字色。
- 图标统一使用 `lucide-react` 的线性图标，约 1.7px 描边、圆角线帽；图标必须配文字，不再为普通界面图标手写 SVG。

## 5. 视觉语言

### 5.1 色彩

紫色只承担品牌与焦点；绿色、橙色、红色只承担状态语义。

| 语义 | 浅色 | 深色 | 用途 |
| --- | --- | --- | --- |
| 品牌 / 焦点 | `#6b5de8` | `#938aff` | 当前菜单、进度、强调 |
| 正常 | `#28a976` | `#55c89c` | 服务正常、完成 |
| 提醒 | `#f1833a` | `#ff9b57` | 待处理、即将到期 |
| 异常 | `#e35f6f` | `#ff7e8e` | 错误、失败 |
| 辅助蓝 | `#4784ed` | `#72a2ff` | 数据、向量、辅助状态 |

浅色主题：

- 页面 `#f7f8fb`，导航 `#fbfcff`，卡片以白色为主；
- 主文字接近 `#121826`，次文字使用蓝灰色；
- 边框约 `#e3e7ef`，阴影透明度低于 6%。

深色主题：

- 页面 `#0c121a`，导航 `#0f1621`，卡片约 `#141c27`；
- 主文字 `#e8eef6`，次文字使用低饱和蓝灰；
- 边框约 `#293544`，阴影用于分离表面，不制造发光感。

深浅主题必须保持同一结构、同一信息和同一语义；不能用简单颜色反转代替独立校准。

### 5.2 排版

- 字体使用系统无衬线字体链；模型名、ID、技术值可使用 `JetBrains Mono`。
- 页面标题 25–31px，字重约 780，轻微负字距。
- 区块标题 15–17px；正文 12–14px；辅助标签 9–11px。
- 核心数字 27–34px，并使用等宽数字特性。
- 英文眉题只用于区块语境，字号 9–10px，增加字间距，不作为主要标题。

### 5.3 间距、圆角与阴影

- 4px 为基础单位，常用 8 / 12 / 16 / 20 / 24 / 30px。
- 大面板圆角 13px；按钮和状态胶囊 9–10px；图标底 12px。
- 卡片边框始终存在，阴影轻且短；不要使用厚重玻璃拟态或大面积渐变。
- 卡片顶部 2px 语义色线可用于区分指标，但透明度要克制。

## 6. 核心组件

### 6.1 品牌主视觉

- 用柔和紫色渐变、细轨道和半露的发光知识星体作为签名视觉，不在装饰图形中放置字母。
- 视觉元素是装饰，不承载业务信息，不抢占标题阅读。
- 不使用无来源的 AI 脑图、人物插图或照片。

### 6.2 指标卡

- 保持“语义图标 / 指标名 / 数值 / 解释 / 对比状态”结构。
- 指标名与解释不能被图标替代。
- 只有真实比例才使用环形进度；不绘制假的迷你趋势线。
- 首页只选择四项最核心指标，在主视觉下方保持单行；错误、待处理、模型等信息整合到右侧运行状态。
- 增减使用绿色/红色与上下箭头共同表达；只有存在真实比较数据时才写“较昨日”。

### 6.3 分布与趋势

- 内容类型使用 `recharts` 环图，中心显示总数，旁边显示主要类型、数量和占比。
- 数据源使用图标、名称、条形轨道、数值结构，按真实数量排序。
- 数据源同时保留显示名称、ID 和 federated / isolated 状态。
- 长文本可以视觉省略，但必须提供 `title` 或其他可读取完整值的方式。
- 首页默认显示摘要；“查看全部”必须在当前卡片内展开真实完整列表，“收起”恢复摘要。
- 趋势图使用 `recharts`，必须标明时间范围和数据来源；当前首页趋势来自最近七天真实 MCP 请求日志。

### 6.4 状态摘要与悬浮详情

- 顶部状态胶囊只显示结论，不作为跳转按钮。
- 鼠标悬浮和键盘聚焦都应展开详情，展示数据库、知识结构、模型、维度等关键信息。
- 浮层靠边对齐、宽约 330px，分隔清晰；移开或失焦后关闭。
- 状态浮层使用 Radix Tooltip，保证鼠标、键盘、定位和 Portal 层级一致。
- 若确实需要跳转，应提供独立、有动词的入口，不把信息状态伪装成按钮。

### 6.5 按钮与交互

- 主按钮使用品牌色；次按钮使用描边或透明底；危险操作保持红色语义。
- 悬停反馈限制在底色、边框、颜色或 1px 位移。
- 所有控件必须有 `:focus-visible`；颜色不能是唯一状态线索。
- 支持 `prefers-reduced-motion: reduce`。

### 6.6 表格、筛选与表单

- 数据表格使用 38px 左右表头和 46px 左右数据行；表头使用静音文字与细分隔线，不使用大面积重色底。
- 行悬停只使用轻微表面变化；成功、提醒和错误继续使用绿、橙、红语义徽标。
- 搜索、下拉和输入框统一 38px 左右高度、9px 圆角；聚焦使用品牌色边框和低透明度焦点环。
- 复杂表格在窄屏中使用明确的横向滚动容器，不通过删除列解决布局问题；只有现有移动端规则明确隐藏的重复字段可以收起。
- 主按钮、次按钮、危险按钮保持各自语义；相同动作在不同页面使用相同组件规格。

## 7. 响应式

- 当前阶段以电脑端为主；宽屏完整展现，约 980px 以下减少列数。
- 768px 以下切换现有移动导航，内容卡片单列。
- 窄屏不得横向溢出，不隐藏核心数据；可隐藏重复的顶部摘要胶囊，但状态详情仍必须可访问。

## 8. 后续设计工作流

每次 Admin Console 设计改动按以下顺序执行：

1. 阅读本文件和最近项目台账。
2. 清点原页面全部信息与操作，记录哪些必须原样保留。
3. 判断是纯视觉修改还是功能/架构修改；纯视觉不得触碰底层。
4. 先完成结构与语义，再实现深色和浅色样式。
5. 检查浅色、深色、状态悬浮/键盘聚焦、长文本、窄屏和无横向溢出。
6. 运行 Admin TypeScript 检查与 `bun run build:admin`，同步嵌入资源。
7. Windows 安装包由用户最后执行 `bun run build:win`。

## 9. 禁止项

- 为了“像大屏”而添加假趋势、假图表、假活动数据；
- 用大量胶囊、渐变、发光和高饱和色制造廉价科技感；
- 把状态卡做成无提示的导航入口；
- 随意改变原页面内容、数字口径、按钮行为或信息顺序；
- 通过隐藏数据解决布局问题；
- 用 Emoji 代替正式界面图标。
