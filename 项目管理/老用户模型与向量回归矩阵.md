## 1. 保存普通模型会不会删高级模型？（1.0.86 / 方案 A 后）

| 配置层 | 配置键 | 桌面入口 | 保存「普通模型」时 |
|--------|--------|----------|-------------------|
| A. 高级模型（tier） | `models.tier.*` | 高级面板 · 任务层级 | **不会删** |
| B. Dream 阶段覆盖 | `models.propose_takes` 等 | 高级面板 · Dream 阶段 | **不会删**（可在高级面板改/清） |
| C. Dream 其它 | `models.dream.*` | 一般不暴露 | 仅 `resetAdvanced=true` 时删 |

### 结论

1. **任务层级与 Dream 阶段均属高级模型**，在同一面板配置、单独「保存高级路由」。
2. **保存普通模型只更新 `chat_model` / `models.default`，不静默删阶段覆盖。**
3. 清空阶段覆盖：在高级面板点「跟随推理任务」并保存高级路由。

## 2. 向量侧回归矩阵

| ID | 场景 | 期望 | 自动化 |
|----|------|------|--------|
| E1 | 模型未变，库内已有向量 | 覆盖率不变；只补 `embedding IS NULL` | `legacy-user-embedding-model-regression` 场景1 |
| E2 | `model` 为空 / 空白 | 保留向量，不清空 | 场景2 / 2b |
| E3 | 无冒号裸模型名，与当前 `provider:model` 的 model 段相同 | 保留 | 场景2c |
| E3b | 历史串含冒号被解析成不同 provider（如 `qwen3-embedding:0.6b`） | 按冲突停止，不清空 | 场景2d |
| E4 | 明确不同模型 | 停止向量阶段，零写入 | 场景3 / 3b |
| E5 | dry-run | 不因冲突阻断计划观察 | 场景4 |
| E6 | Dream / embed 契约 | 不得隐式 `invalidateMismatchedEmbeddingModels` | 契约用例 |
| E7 | 桌面启动/升级 | 不自动 align / 不自动重建 | desktop 场景E |
| E8 | 真换向量模型 | 需确认；取消则拒绝 | desktop 场景D |
| E9 | 用户取消确认 | 配置与向量均不变 | 主进程拒绝 + 渲染层 return（契约） |
| E10 | 99% 真实库深度整理后仍约 99% | 人工 / 夹具库（未并入 CI 重库） | 待补夹具 |
| E11 | Ollama 超时中断后续跑 | 已完成向量不二次清空 | 依赖 embed-stale 断点语义；待补专用夹具 |
| E12 | CLI `align-embedding-dimension --yes` 同维 | 当前仍可能因 targetModel 失效旧向量 | **已知残留风险，待加固** |

## 3. 模型路由回归矩阵

| ID | 场景 | 期望（定稿规划） | 当前 1.0.85 | 自动化 |
|----|------|------------------|-------------|--------|
| M1 | 仅 `chat_model` / `models.default` | 各任务继承普通模型 | 是 | model-config 既有 |
| M2 | 存在 `models.tier.*` | 保存普通模型后仍在 | 是 | desktop 场景A |
| M3 | 存在 `models.propose_takes` 等 | 高级面板可见可改；普通保存不删 | 是（方案 A） | desktop 场景B |
| M4 | 高级面板「跟随推理任务」并保存 | 清除对应阶段键 | 是 | UI + writeAdvancedModelConfig |
| M5 | 空阶段覆盖 | 继承 reasoning tier → default | 是 | advanced-model-config 读取 |
| M6 | Dream 报告展示各阶段实际模型 | 应显示 resolved model | 部分 phase 有 details | 待补 Admin 契约 |
| M7 | Desktop/CLI 同一 config 路径 | 读写同一文件 | 是 | desktop 场景F |
